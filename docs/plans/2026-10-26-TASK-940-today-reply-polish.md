## Approach and boundaries

Keep one workspace list read. A reply's successful answer immediately calls the existing taskRead.reload (a pre-write read cannot win). Only started/replayed answers arm a bounded poll. Reuse the existing task-page poll's timer/cleanup machinery rather than inventing a second 10-second/five-minute policy. Today observes the row's host-written report timestamp and miss timestamp because TaskRow has no fire/update identities. An unchanged report/ask is not completion; a changed report timestamp or new miss timestamp is. No synthetic TaskUpdate, new wire field, detail-fetch fan-out or hook-bus surface is needed.

Ticks must use taskRead.retry, joining a read in flight: list reads have a 15-second timeout, so reload every 10 seconds could continually supersede a legitimate slow answer. Preserve taskRead.reload for the immediate write-triggered refresh and expose retry as the separate poll-read callback through TodayView. TASK-959 can continue reusing reload for its task-page writes.

Keep the existing task-page useTaskPoll API/arrival rules intact through a small shared bounded-poll core or equivalent narrow extraction. Its update identity remains firedAt plus conversationId with existing clock slack; Today's completion snapshot need not pretend to carry that detail. Polls stop on new result, five minutes, explicit replacement or component unmount. Route changes/Working-tab changes unmount the affected Today groups; preserve existing task-page visibility behavior rather than adding document-wide polling policy. Latest callbacks live in refs so rerenders cannot reset a timer. Keep TASK-939 first-read checking and failure precedence unchanged.

Clear only a started/replayed sent receipt when the check-in it announced completes. Pass a minimal completion signal/token into TaskReplyBox from the owning poll/data; store the send's baseline so an old arrived state cannot erase a new Send receipt. Preserve drafts, focus, retry/request IDs and paused/not-allowed receipts. Apply to ordinary and Not yet/Reopen boxes where they announce a running check-in. Do not key-remount a box merely to clear its receipt. A timeout is not proof a check-in finished and must not clear it as completion.

Tasks metadata uses noRecentUpdate.at when a miss exists, otherwise task.reportedAt. This follows the task-page miss card and existing list ordering, without adding lastRunAt (active-hours skips can move it without a check-in). Keep Done timestamps and get-done step-count metadata intact. A report-less completed Updates entry uses no-recent-update and its accessible label, including an error and a successful run that omitted its report; never-reported task state keeps no-update.

Use the actual Settings field name in UI recovery: “What should {agent} do?”. The fixed backend/check-in transcript message has no agent name, so identify the same field as “What should … do?” in the agent’s settings. Keep BRIEF_TOO_LONG and the closed channel-web turn-error table identical; no cross-plugin production import or agent-name lookup is justified for this copy.
