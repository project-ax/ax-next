**Goal:** Ship the four follow-ups from TASK-1030 (#1114) and TASK-1033 (#1115). Items 1–3 each get a test that fails before the fix.

**Architecture:** Every change is internal. No hook signature, payload or `returns` schema changes, so there is no boundary review.

4. The repeat heartbeat's catch logs `faultLogFields(error)`.

**Tech stack:** TypeScript, vitest, @testing-library/react (jsdom) for channel-web, shadcn `Alert`.

**Spec:** the card (below), plus the decisions shard `.claude/memory/decisions/2026-11-03-TASK-1035.md`. The shard holds the evidence behind every call in this plan. Read it before you deviate.

> **Card.** (1) mcp-oauth `requireUser` still maps `forbidden`/`not-found` to 401. (2) Settings RoutineEditor shows a stale field mark on retry: `use-routine-draft` `submit()` clears `errorCode` but leaves `invalidField`. (4) The `repeat_heartbeat_failed` log should carry the fault code, as the drain logs from #1115 do. **Acceptance:** items 1–3 each have a test that fails before the fix.

## Design calls (where this plan departs from the card's wording, and why)

- **Item 1: `isUnauthenticated`, but NOT `answerRequireUserFailure`.**
  - The helper logs `{ hook, err }`, and `PluginError.toJSON` includes `message`. The bus wrap's "service hook 'auth:require-user' threw: …" would therefore reach the logger. mcp-oauth logs names and codes only (TASK-713), and `routes.test.ts:667-682` asserts exactly that for the auth stage.
  - The helper's `ctx` is also typed as the full core `Logger`. The injectable `deps.logger` is `{error,warn,info}` only, so it doesn't fit.
  - So: use core's predicate for the 401 arm, and keep the existing `mcp_oauth_route_failed {stage:'auth', ...errFields}` 500 arm.
- **Item 1, consequence: `'unauthenticated'` leaves `REFUSAL_CODES`.** No remaining `isReject` caller's hook (agents:resolve, agents:can-set-shared-credential, connectors:get) throws it.
- **Item 1, consequence: the three tests that model "signed out" with a thrown `reject()` now throw `codedError('auth:require-user','unauthenticated')`.** The real `HookBus.call` wraps a thrown Rejection as `PluginError{code:'unknown'}`, so production can't produce one.
- **Item 2: fix the source, not a second gate.** `submit()` calls the existing `clearErrors()`. `RoutineApiError.code` is never null, so a field with no code only ever came from `submit()`'s partial clear. TaskForm's `errorCode !== null` check stays (harmless), and its comment changes.
- **Item 4: `faultLogFields` from `@ax/core`, not routines' local `faultCode`.**
  - TASK-1036, running in parallel, is replacing `faultCode` in `webhook-handler.ts`.
  - `faultLogFields` also reads a `SafeToolError`'s real code. `lifetime.admit` rejects with `SafeToolError('unavailable')` while closing, and `faultCode` logs that as `invalid-payload`.
  - Leave the drain line (`plugin.ts:393`) alone: TASK-1036 owns it.
