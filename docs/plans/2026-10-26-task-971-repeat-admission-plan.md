## Implemented lifecycle and recovery

Migration17 is additive: private delivery metadata plus executor, lease, release and delivery identity on dispatches. It preserves schema16's immutable accepted `kind`. All webhook deliveries enter this one queue; receipt tables remain for management operations and never carry queue payloads. Dedupe keys are SHA256 hashes of validated IDs in the agent/task namespace. Settled IDs expire seven days after acceptance; unfinished bodies stay referenced and charged until terminal accounting, even after that date. Settled no-ID metadata is removed. Hard ceilings are2,048 IDs/task and10,000/owner; no unexpired accepted ID is evicted to make room.

Admission takes the existing shared agent fence, an owner-wide quota lock, then the definition lock. It checks the current revision, creator, Repeat kind, app-update method and all bounds before the blob facade writes. A transaction failure cannot leave an accepted ID; a blob written before a failed commit follows the existing blob collector's orphan grace. Claims take the agent fence, definition lock and delivery lock, reserve one immutable dispatch and count all unfinished sources under the definition lock. FIFO describes durable claim order per task, not completion order of parallel runs. Busy/paused task heads do not block other tasks.

Pause retains waiting bodies; authenticated retries of an accepted ID still acknowledge while paused. New deliveries to a paused task refuse. Resume permits unchanged execution configuration. Prompt, app-update method, conversation policy, silence policy, kind or owner changes invalidate waiting entries and record a fixed cancellation with no private prompt. Schedule, work hours and cosmetic edits preserve the independent app-update queue. A claimed run keeps its accepted creator/configuration and still passes live agent ACL and usage checks. Delete and agent retirement remove queue references inside their existing lifecycle fences; a late finish cannot recreate retired state.

Each host renews only its own Repeat leases every10seconds, with a120second lease. Graceful shutdown joins effects before releasing its reservations. Startup leaves live foreign Repeat reservations alone. Expired unbound claims are interrupted; a bound foreign claim needs authoritative conversation metadata showing no active session. Unknown/live metadata keeps capacity reserved and is retried after10seconds. Recovery rechecks both the expiry and the observed conversation under the dispatch lock so a concurrent heartbeat or bind invalidates a stale observation. An uncertain claimed delivery is accounted as interrupted, never replayed as another invocation. This favors keeping uncertain capacity occupied over duplicate external work; a foreign conversation that stays active needs its normal session termination before that slot can be recovered. Leases do not promise exactly-once external side effects across an arbitrary process suspension between a successful bind and an invocation.

Bodies and rendered prompts stay in the creator's private blob/conversation. Queued run history, routine last-error fields and invoke diagnostics use fixed messages; broad views expose only owner-relative active/waiting numbers. The Settings projection's reviewed key list explicitly permits this host-written count. The existing Refresh action updates the small waiting note.

Rollback: older binaries ignore the additive metadata but cannot drain acknowledged deliveries. Preserve the queue/blobs and restore this worker before claiming those updates ran; do not discard pending rows or drop migration17 as a rollback shortcut. Mixed deployment with older admission writers cannot enforce this new cap, so roll out the routines host as one version.

## Boundary review

- Alternate implementation: a SQLite-backed routines plugin or external scheduler can return the same active/waiting counts. A filesystem/object-backed blob provider implements the existing byte facade unchanged.
- Payload names that leak a backend: none. `delivery` contains only optional nullable strict nonnegative `active` and `waiting` counts, no queue IDs, hashes, owner IDs, blob references, SQL or executor details.
- Subscriber risk: no new event or backend discriminator. Older view producers may omit the optional field. Current get/list producers populate it only for the execution owner; task kinds and other viewers get null.
- Wire surface: routine view schemas stay in `@ax/routines-contract`; the existing routines-owned tools and Settings routes keep their established validation. No new IPC action or shared central schema.

## Security review

- Sandbox: new reach is limited to the existing creator-scoped blob put/get facade, reference holder and conversation metadata read. IDs are validated then hashed; blob refs are validated hashes, never paths/tokens. No process, environment, filesystem-path or destination capability is added. Agent-wide bearer and global credential policies remain restricted.
- Injection: external bodies retain the1MiB HTTP ceiling, signature/filter ordering and strict single-pass template substitution into an ordinary user message. Stored envelopes count actual UTF8 bytes against the8MiB owner ceiling. They never enter SQL text, shell commands, HTML, system instructions, status notes, operation receipts or diagnostic messages. Existing runtime permission/usage gates still constrain actions requested by an injected user message.
- Supply chain: N/A: no package manifest or lockfile change and no new transitive dependency.
