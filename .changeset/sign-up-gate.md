Close the open sign-up. Email-and-password sign-up and sign-in are off, and a password set before this release no longer works. Google ID tokens posted by a client are refused from now on (accounts already made that way stay until someone removes them). One identity gate now checks every Google and GitHub sign-up, account link and sign-in: the provider must have verified the email, the email must be inside that provider's allowed domains (one exception: an admin the operator appointed), and a sign-in to an existing account must come with that account's own email. Emails are compared as the provider spells them, ignoring only the case of plain letters, and an address with any character beyond plain ASCII is refused, so a look-alike letter can't pass for a teammate's address. The domain rule and the email rule apply to existing accounts too, at their next sign-in; sessions issued before this release keep working until they expire (up to 7 days). The link rule only applies from now on: a sign-in method attaches only to an existing account that is verified, or that is the setup wizard's admin waiting for its first sign-in. Links made before this release stay on file, including any made by a GitHub account holding an unverified copy of a teammate's email, but the email rule stops such a link from signing in unless GitHub vouches for the account's own email. Someone whose provider address changed since they linked it is turned away the same way; `deploy/GKE.md` 4i changes the account's email once the operator has confirmed it's them. The gate replaces a Google domain check that never actually ran on better-auth 1.7. The never-wired "Generic OIDC" provider option is gone from the admin form, and a leftover OIDC row can no longer take sign-in down. If you run an install older than this, run the account audit in `deploy/GKE.md` (4h) once to see what the open sign-up let in, and confirm the sign-in methods its section 5 lists with each person.
