## Findings

None of these block PR 2. Each one is a follow-up card.

1. **Today doesn't re-read after the check-in a reply started.** Today reads the tasks again when the reply is sent, which is before that check-in finishes. The row kept saying Needs you with the old ask until the next visit to Today, even after the check-in reported on track. By design ("It doesn't poll", `workspace-tasks.ts`), but Today could reuse the task page's "Checking in now…" poll. Minor.
2. **Tasks says "checked 19 hr ago" for a task that just missed.** A No recent update row shows the time of the last *report*, so a task whose check-in failed a minute ago reads "checked 19 hr ago". It should show the last check-in's time, as the task page's "Last check-in at 7:15 PM" does. Minor.
3. **"Shorten “What to do”" names a field that isn't labelled that.** The Settings field is "What should Default Agent do?" and the task page calls it "What Default Agent does". The brief-too-long fix (`task-miss.ts`) and the run error (`BRIEF_TOO_LONG`) both say “What to do”. Minor copy.
4. **The agent tells people to turn on Always Allow for `routine_fire_now`, which doesn't exist.** Ping relay's reports and asks repeatedly said "enable Always Allow for routine_fire_now so future check-ins proceed without a prompt", and that ask is what Today shows. Always Allow never covers firing. The held-call result or the tool description should say so, so the agent stops offering it. Minor.
5. **Approval copy for a fire-now.** The card says "Review the proposed routine change before allowing it." for `routine_fire_now`, which changes nothing. During the undo window after Allow once, the row reads "The approved routine operation has not completed. We’re checking its outcome.", which sounds like a failure when it's only waiting out the window. This is decision-queue copy that predates PR 2. Minor.
6. **Small copy nits on the task page.**
   - A missed check-in's Updates entry carries the "No update yet" pill. That's the never-reported label, beside a card that says "No recent update".
   - The reply box's "Sent. Default Agent started checking in." stays up after that check-in finished and after a later Check now.
7. **A task page polling across a host restart got one 404.** `GET /api/workspace/tasks/<agent>/<routine>` answered 404 once while the new host pod was starting (step 9's forced restart). The same request answered 200 afterwards, and the host log had no matching line. If a 404 lands on the task page itself, it could read the task as gone. Worth checking whether the route answers before the routines plugin is ready. Minor, and only reachable during a restart.
