- **2026-11-08 (#1153): sharding main's suite changed WHAT RUNS TOGETHER, and four wall-clock-budget tests failed on the first sharded run** — frame-guard `prepare-html-limits` (<1000 ms; got 1092/1176), attachments `content-origin-worker` (transform count +1), user-files-read `confined-read` (>=5000 race iterations; got 2932), routines-contract `report.test.ts` (5 s default timeout). Cause: the `web` shard co-located the three heaviest CPU users (channel-web jsdom, attachments Chromium, frame-guard budgets) and `--no-sort` started every package at once. The PR's own CI could not catch it: a PR that edits ci.yml runs the unsharded path. Fix: `web` at `--workspace-concurrency=1`, no `--no-sort`. **Lesson:** before regrouping test execution, list the suites that assert wall-clock budgets (`grep -rn "toBeLessThan(1000)\|toBeGreaterThanOrEqual(5000)\|milliseconds to answer"`) and keep them off runners with the heavy suites; and a CI-shape change whose path only runs on push needs a watched first run — say so in the PR.
