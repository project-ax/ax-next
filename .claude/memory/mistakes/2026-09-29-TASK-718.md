# TASK-718 — mistakes to avoid (2026-09-29)

- **A card that lists what ONE probe found is a lower bound, not the set.** The walk named seven tables after deleting one throwaway agent; the real count was seventeen agent-scoped tables with no cleanup (the seven, plus attachments_v1_files, skills x4, connectors_authored, host_grants, decisions, mcp_oauth_pending, memory_facts_v1), because only a table the walker's agent happened to write shows up. When a card names the leftovers of one run, scan the schema for the CLASS (`information_schema`, or a grep of every `CREATE TABLE`) before scoping.
- **A guard that greps for a statement counts prose that names it.** The first cut of the "every agent-scoped table is deleted from" guard matched `DELETE FROM session_postgres_v1_inbox` in a corruption error message, so a mutant that removed the real inbox delete survived. Count only where the statement is executed (`sql` tag, `.prepare(`, `.query(`, `deleteFrom(`) and strip comments. Mutate the thing the guard protects, not just the guard.
- **"An orphan row is tolerable" was written in four migrations as a design note and quietly became the product.** `@ax/conversations`, `@ax/skills`, `@ax/decisions` and `@ax/host-grants` all said a dangling row to a deleted agent "simply never resolves". True for reads, false for privacy: the words stayed on disk. When a comment justifies leaving data, ask who can still reach it by another route (a backup, a DB console, a data-subject request), not only whether the product reads it.
- **`HookBus.fire` runs subscribers in registration order, and a subscriber that awaits a pod delays all the rest.** The reclaim subscriber waited on the apiserver with no bound, so the new cleanup subscribers behind it were one hung request from never running. Bound the fire (`subscriberTimeoutMs`) when a subscriber does I/O against something that can stall.
- **The worktree guard refuses shell commands it cannot prove are not git.** Multi-line `python3 - <<EOF` blocks with regex-heavy text, and `sed` programs with `e` commands, were refused as "too complex". Use the Edit tool for source edits; put helper scripts in the task scratch dir and run them with `bash <path>`.
