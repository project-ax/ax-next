# TASK-720 — mistakes

- **2026-09-29: I merged the two halves of the "tell the person" feature in one change without a test at the seam between them.** The runner-side test asserted the refusal rides the assistant turn-end, and the channel-web test fired a single turn-end carrying it; both passed, and the feature did not work, because the runner emits a tool turn-end FIRST and the SSE subscriber closes on the first. A deep review caught it. Rule: when a value crosses two components, the test belongs at the seam (does the value that component A actually sends reach the consumer B actually closes on?), not one per side. Also: an existing test that asserts the broken shape is not evidence — it is the bug written down (`only the assistant turn-end carries it`).
- **2026-09-29: when I queued `mockResolvedValueOnce`/`mockRejectedValueOnce` to set up a multi-call test, I put them in the wrong order and wrote the test against the wrong call.** `mockRejectedValueOnce` takes the NEXT call, so my "first resync succeeds, second throws" test actually threw on the first and asserted a value the code could not produce. It read as a product bug for one run. Read the queue order explicitly (or use `mockImplementation` on call count) and say which call each queue entry is for in a comment.
