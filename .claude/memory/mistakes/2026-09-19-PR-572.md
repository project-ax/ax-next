# PR-572 — vitest 5: two vitest instances, one chai, silently broken `.rejects.toThrow()`

**The trap.** Under vitest 5, every `await expect(p).rejects.toThrow(msg)` in
`channel-web` failed with `but got ''` — the rejected Error never reached the matcher.
The value itself was fine (`instanceof Error`, correct `.message`, verified by probe).
Bare `.rejects.toThrow()` and *sync* `expect(fn).toThrow(/re/)` both still passed, which
makes the failure look like a flaky subset rather than one mechanism. 26 tests.

**Cause.** `@testing-library/jest-dom/vitest` is just `expect.extend(matchers)` on
whatever its own bare `import { expect } from 'vitest'` resolves to. pnpm installs
jest-dom **unspecialized** (`node_modules/.pnpm/@testing-library+jest-dom@6.9.1/` with
no peer-hash suffix and no `vitest` link of its own), so Node walks up and binds it to
the **workspace-root** vitest. `channel-web` runs a **different** vitest copy — vitest
is keyed by its `vite` peer, and channel-web pins vite 6 for the SPA build while the
root is on vite 8. Meanwhile `chai` **is** hoisted to one shared instance
(`.pnpm/node_modules/chai`). Both vitest copies patch that one chai, so `.rejects`
(which stashes the error in a chai flag) and `.toThrow` (which reads it) come from
different copies and the flag never crosses. Under vitest 4 the same double-patching was
benign; vitest 5 is where it bites.

**Fix** — one line in `packages/channel-web/vitest.config.ts`:

```ts
test: { server: { deps: { inline: ['@testing-library/jest-dom'] } } }
```

Inlining makes Vite transform jest-dom, so its `vitest` import goes through Vite's
resolver and lands on ours. **`resolve.dedupe: ['vitest','chai']` does NOT work** —
measured, still 5 failed. Externalized deps never reach Vite's resolver at all, so
dedupe has nothing to act on. Don't reach for dedupe here.

**Diagnostic that settled it.** Monkey-patch `expect.extend` in the setup file, then
`await import('@testing-library/jest-dom/vitest')` and check whether the patch was
called. It was not (`sawExtendCall: false`) — proving jest-dom held a *different*
`expect` object. Counting copies is faster than reading vitest internals:
`ls -d node_modules/.pnpm/vitest@*` (3 copies) and
`readlink node_modules/.pnpm/node_modules/chai` (1, shared).

**Generalizes.** Any `expect.extend` package + a version-split peer (vite here) can
produce this. If matchers *register* fine but assertion *plumbing* misbehaves, suspect
two runner instances over one shared chai before suspecting the matcher library.
