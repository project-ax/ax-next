# TASK-904 mistakes

- 2026-10-20: `pnpm --filter @ax/<pkg> test -- <file>` does NOT run one file. Under pnpm 10.33 + vitest 5 the `--` is passed through and vitest runs the whole package (a `-t` name filter is dropped too), so a "red" run you meant for one file is the full suite. Three implementers hit it independently from one plan's commands. Use `pnpm --filter @ax/<pkg> test <file>` (no `--`) or `pnpm exec vitest run <file>` from the package directory, and check the file count in the summary line.
- 2026-10-20: writing ` ` / ` ` into a TS regex or string with the Edit tool can land them as the RAW characters, while C1 escapes like `\u0085` stayed as escape text in the same edit. The shell's `grep` here is a ugrep wrapper, and `grep -P '\xNN'` byte patterns miss them silently. Check a file that must hold escape text with a code-point scan (`python3 -c "import sys;t=open(sys.argv[1]).read();print([hex(ord(c)) for c in t if ord(c)<32 and c not in '\n\t' or 0x7f<=ord(c)<=0x9f or ord(c) in (0x2028,0x2029)])" <file>`), not grep.
