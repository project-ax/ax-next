# TASK-446 — what the card got wrong, and the test-shape traps

- **PARTIALLY REFUTED premise.** The card said `AgentView` *and* `AdminShell`
  "render zero `h1`–`h3` at all". Measured in jsdom before the fix:
  - `AgentView` — **true**, `[]` headings on all four tabs.
  - `AdminShell` — **false**. Six of nine tabs already rendered one: `h2: Teams`,
    `h2: AI model keys`, `h2: Branding`, `h2: Sign-in methods`, `h2: Agents`,
    `h3: Installed` + `h3: Not installed`. What was true of all nine was
    **no `h1`**, and that Skills/Connectors opened at `h3`.
  The likely cause of the walk's reading: the probe landed on the default Skills
  tab while `SkillsAppStore`'s shelves were still loading, which renders nothing.
  **A live-browser "0 headings" reading can be a loading state, not a structure.**
- **`waitFor(() => expect(...))`, never `findByRole('heading')` as a gate**, in a
  test whose subject is a missing heading. The gate makes the RED run hang for the
  whole `testTimeout` (60s in channel-web) instead of failing in ~1s with a diff.
- **A heading test that loops over the headings it found is green on `[]`.** The
  guard has to report "renders no headings at all" as a violation in its own right,
  or it passes vacuously on the exact defect it was written for.
- **Two admin tabs (`Connectors`, `Routines`) throw under a bare `fetch` stub** —
  they read through `lib/*` modules (`listConnectors`, `listAuthoredPending`,
  routines defaults), so a `{connectors: []}` JSON body leaves `proposed`/`defaults`
  `undefined` and the body crashes on `.length`. Put the Connectors outline
  assertion in `ConnectorsTab.test.tsx`, which already spies those modules.
- **Shell-level and body-level headings live apart.** Admin tab bodies duplicate the
  pane title verbatim (`h1: Teams` over `h2: Teams`, same for AI model keys /
  Sign-in methods / Branding / Helper model / Agents). Pre-existing **visual**
  redundancy, not introduced here — a follow-up, not a heading-level bug.
