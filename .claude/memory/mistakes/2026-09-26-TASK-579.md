# Mistakes — TASK-579

| Date | Mistake | Lesson |
|---|---|---|
| 2026-09-26 | A test wrapped an async harness call in `vm.runInNewContext(expr, ctx, { timeout: 1_000 })` and passed the same 1000ms as the preflight budget. The vm `timeout` is a wall-clock watchdog over SYNCHRONOUS evaluation, and a subprocess spawn's sync half ran inside it. On CI it fired first twice, and a comment said the test "cannot flake the wrong way". | When hunting a private wall-clock deadline (TASK-537, TASK-549, TASK-579), `vm` `timeout`, `spawnSync`/`execSync` `timeout` and `AbortSignal.timeout` all count. Keep async work out of a vm-timed window (defer it to a microtask), and never give two clocks the same budget. A regression test for this must pin the old budget, or a bump-only "fix" turns it green. |
