- **2026-11-09: every chat visual failed ("This visual couldn't be displayed.") for a user running the Noir Safari dark-mode extension** — not reproducible in any clean browser (prod HTML, kind, Chromium/WebKit/Firefox all rendered). Noir loads `noirhelper.js` into EVERY frame as a page-world `<script src=safari-web-extension://…>` (extension scripts bypass the page CSP) and wraps `Element.prototype.attachShadow` via `Object.defineProperty(…, Object.assign({}, ourDescriptor, {value}))`; @ax/frame-guard had locked it `writable:false, configurable:false`, so the redefine threw a TypeError, the runtime's pre-ready `error` listener posted `ax-visual:error`, card failed. Fix: locks are `writable:true` (originals are unreachable in the realm, so nothing is weakened; still non-configurable) AND the runtime ignores errors not from the visual's own inline scripts (`document.currentScript` with a `src`; `*-extension://` filename or rejection stack). **Lesson:** when a sandboxed-frame bug won't reproduce, ask which extensions the user runs first — and an installed Safari extension's scripts are readable at `/Applications/<App>.app/Contents/PlugIns/*.appex/Contents/Resources/` (Info.plist `SFSafariContentScript`), which turned a guess into a proof.
