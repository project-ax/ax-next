# TASK-1082 — what bit us (mistakes)

- 2026-11-07 — T2 shipped `@ax/frame-guard` with a `build` script that copied `src/frame-guard.js` into `dist/` and an export map pointing at that copy. It passes on any machine that has run `pnpm --filter <pkg> build` (every local gate, including `pnpm --filter @ax/frame-guard build && test`) and would have failed in CI: CI runs only `pnpm typecheck` (`tsc --build` over project references) before the tests, which never runs a package's npm `build` script, so `dist/frame-guard.js` does not exist there. Dependents then die with "Failed to resolve import" (channel-web's `?raw`) or ENOENT (the Node loader). Found in T3 by reproducing CI: `rm -rf packages/<pkg>/dist && pnpm exec tsc --build packages/<pkg>`, then run the dependents' tests. Serve a non-TS asset from `src/` (export map + `files`) so the only build is `tsc --build`, as `agent-runner-core` did for its bootstrap after the same trap bit it twice. The Dockerfile `--filter` rule in `image-asset-packaging.test.ts` covers the image, not the test run.
