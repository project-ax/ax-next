# TASK-1082 — what bit us (mistakes)

- 2026-11-07 — T2 shipped `@ax/frame-guard` with a `build` script that copied `src/frame-guard.js` into `dist/` and an export map pointing at that copy. It passes on any machine that has run `pnpm --filter <pkg> build` (every local gate, including `pnpm --filter @ax/frame-guard build && test`) and would have failed in CI: CI runs only `pnpm typecheck` (`tsc --build` over project references) before the tests, which never runs a package's npm `build` script, so `dist/frame-guard.js` does not exist there. Dependents then die with "Failed to resolve import" (channel-web's `?raw`) or ENOENT (the Node loader). Found in T3 by reproducing CI: `rm -rf packages/<pkg>/dist && pnpm exec tsc --build packages/<pkg>`, then run the dependents' tests. Serve a non-TS asset from `src/` (export map + `files`) so the only build is `tsc --build`, as `agent-runner-core` did for its bootstrap after the same trap bit it twice. The Dockerfile `--filter` rule in `image-asset-packaging.test.ts` covers the image, not the test run.

- 2026-11-07 — T4: **`git commit --amend --no-edit` in a worktree the orchestrator also commits to rewrote the orchestrator's commit.** I had amended my own T4 commit five times (to keep it one commit between mutation rounds); the sixth time HEAD was the lead's "Log navigation-exfil review finding and scoping", landed 22 seconds earlier, so my three staged edits went into it and its sha changed. Caught because `git log --oneline -1` printed a message that was not mine. Repair, from the reflog: `git reset --soft <their original sha>` (their commit is byte-identical again, my edits stay staged), then commit mine separately. Before an amend in a shared worktree, run `git log -1 --format=%h:%s` and compare it with the sha you expect, or make follow-up commits instead; `git add -A` followed by an amend is also the combination that would sweep in someone else's uncommitted files.
- 2026-11-07 — T6: **my first kill-switch test passed when the purge was broken, so it proved nothing about the route it was written for.** It asserted "blank page + guard warning + no UDP". With the purge removed the bait iframe is itself the live child, `check()` kills the page, and all three assertions hold without the re-entrancy route ever running. Found by predicting the purge mutant's result before running it, not by the suite. Fix: the page logs from inside the callback with the child count it sees and the test requires that line. Rule: when a test can pass by two routes, make the page report which one it took.
- 2026-11-07 — T6: **a first green run of a new browser suite is not stability evidence; the load profile of the whole suite hid a 40% flake.** The ordinary-page anchor check passed 8 full-suite runs and one mutation pass, then failed 5 of 12 runs when one cell was run alone. The only sign in the full runs was ONE unexplained extra red in a mutation result (9 failures where I had predicted 8), whose message my harness had not kept. Rules: chase every unpredicted red at once; keep each failing test's message (not only the first) and the raw JSON per mutant; loop the smallest unit that contains the test (`-t` one cell, 12 runs) before calling a suite stable.
- 2026-11-07 — T6: **my mutation harness counted a mutant that did not compile as KILLED.** `if (false) {` makes TypeScript treat the block as dead code and drop the narrowing inside it (`Property 'attrs' does not exist on type 'ChildNode'`), the build failed, and "no tests ran" fell into the killed branch. The tell was the runtime (0.8 s, no test counts). Use a runtime-false condition TS cannot narrow on (`&& Math.random() < 0`), and give "did not build" its own verdict.
- 2026-11-07 — T6: **a surviving mutant was a missing probe, not a redundant lock.** Removing the `document.write`/`open` locks left all 242 tests green, and the first reading was "the locks are redundant" (true for a plain iframe: the observer sees it). The right question was "what can only this lock stop?": a closed shadow root written at run time, which the streaming parser builds and nothing in-page can see. One probe made the mutant die. Ask that question of every survivor before documenting it as defense in depth.
