# TASK-463 — mistakes to avoid (2026-09-26)

- **`git merge-tree --write-tree` exits 1 for BOTH a real conflict AND a missing object** ("not something we can merge", git 2.52). Branching on `rc != 0` → "conflict" (or `rc == 1` → "conflict") without first proving both objects exist (`git cat-file -e "$sha^{commit}"`) reports a conflict nobody measured. Found only because the new guard's fixture CONTROL asserted `rc(missing) != 1` and it went red. rc=0 is still a trustworthy "clean".
- **A remedy that always works can hide the wrong explanation for a month.** "Rebase-push creates the ci.yml run" worked every time because the rebase resolved the conflict — the actual cause. When a doc says "cause never diagnosed, known remedy X", ask what else X changes; a historical sweep (here: `code-scanning/analyses` refs/pull/<n>/head vs ci.yml runs, 666 heads, ~40 API calls) settled it in minutes.
