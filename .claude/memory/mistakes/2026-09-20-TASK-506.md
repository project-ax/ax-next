## 2026-09-20 — TASK-506 a test that never meets the production state is not coverage

- `2026-09-20` (TASK-506) — **Mistake: every fixture worktree in my new tests was UNLOCKED, but production agent worktrees are all harness-locked.** That is the entire reason auto-ship §7a uses `git worktree remove -f -f` — a single `-f` exits 128 on a locked tree. So the mutant `-f -f` → `-f` **survived the whole suite** while removing nothing in production (`continue` fires, `branch -D` never runs, worktrees accumulate). Caught by `ax-code-reviewer`, not by me, and not by 7 of my own mutants. Lesson: when a test drives a destructive command, ask what state that command meets in production before asking whether the assertion passes. `git worktree lock <wt> --reason 'claude agent (pid N)'` is one line in a fixture.
- `2026-09-20` (TASK-506) — **Mistake: I tested the sweep path only with a worktree present, so the `[ "$wt" = "-" ] && wt=""` normalization was unverified — for a state my own code creates.** The preserve path removes the worktree and keeps the branch, so the very next reconcile sees that branch worktree-less. Without the normalization, `git worktree remove "-"` errors, `continue` fires, and the sweep silently no-ops. Lesson: enumerate the states your own change *produces*, not just the ones it was written to handle.
- `2026-09-20` (TASK-506) — **MEASURED: the GitHub Actions runner image ships no `zsh`.** A `describe.runIf(commandExists('zsh'))` block added to prove the auto-ship skill's shell blocks behave the same under the production shell was **silently skipping in CI** while passing locally — a guard that only ever ran on the author's laptop. Found only because an `it.runIf(process.env.CI)` presence assertion turned CI red. Fixed by installing zsh in the test job (`.github/workflows/ci.yml`). Lesson: `runIf` skips are invisible in a CI summary; pair every environment-conditional suite with an assertion that the environment is what you think it is.
- `2026-09-20` (TASK-506) — **Pattern worth repeating: `MERGED=$(cmd | tr …)` captures the PIPELINE's status, which is `tr`'s, and `tr` always succeeds.** A failed `gh pr list` was therefore indistinguishable from "no merged PRs" — fail-safe but silent, and in this block that means every already-shipped branch is preserved forever. Capture the producer's status in its own `if !` before piping.
