# AXWM-3 mistakes

- 2026-10-16 GKE acceptance (fixture `ax-w2acc`, image `w2fixture-2aff55cb@sha256:ff6d5b70…`): a POOLED viewer could write its shared folder. `viewer-try` and `v2` landed on Filestore, while the helper's own mountinfo showed the bind `ro`. Cause: the helper binds rw and then runs `remount,bind,ro`. Mount propagation carries mount and umount events, not later per-mount flag changes, so the copy gVisor's gofer uses stayed rw. `/memory` uses the same two steps but is safe only because its SOURCE volume is mounted read-only, so the bind starts ro before it propagates. Unit tests simulate mounts, so they cannot see this. A cold viewer was fine (`nfs.readOnly` volume → EROFS). Lesson: never trust a remount to make a propagated bind read-only; bind from a source that is already read-only, and prove it on the real runtime.
