**Read this before acting on `mistakes.md:489` (TASK-373) or `mistakes.md:20` (TASK-319).**
Both root-archive rows prescribe *"`cp` the file to /tmp first and restore from the copy"*
as the safe probe restore. **That is the exact mechanism of TASK-406's near-miss:** a copy
writes back whatever the file looked like when the copy was taken, so a fix another agent
committed in between is silently undone, with a zero exit status and no output. R2 forbids
editing the archives, so the correction lives here.

The current rule is in `yolo-ship` SKILL.md Phase 4 (*Mutation testing: restore without
clobbering*), with two runnable blocks and an executable guard
(`scripts/__tests__/mutation-restore-protocol.test.js`). In one line: **a file copy is never
the restore; `git checkout -- <path>` is exactly right if and only if the path was
committed-clean before you mutated it,** and the blocks refuse rather than guess when it
was not. TASK-373's own narrower finding still stands — `git checkout --` on a *dirty* path
eats the uncommitted work. The remedy it drew from that is what changed.

## 2026-09-19 — TASK-468 — `git status` on a path git does not know looks exactly like "clean"

**The mistake, made in the very guard whose claim is that it fails closed.** The first
version of the mutation-restore precondition block was:

```bash
F="<the file you are about to mutate>"
if [ -n "$(git status --porcelain -- "$F")" ]; then ... exit 1; fi
echo "ok: $F is committed-clean"
```

`git status --porcelain -- <path git does not track>` prints **nothing** and errors — and
an empty result is byte-identical to "clean". So an agent that pasted the block **without
substituting `$F`** got `ok: ... is committed-clean` and went on to mutate on a guarantee
nothing had checked. Fail-**open**, in a fail-closed block.

**The rule:** an emptiness check on a command's stdout is only a safety check if you also
know the command SUCCEEDED. Either check the exit status, or check the precondition the
command assumes. Here: `git ls-files --error-unmatch -- "$F" >/dev/null 2>&1` first.

**Found by running the mutants, not by reading the block.** Reading it twice did not
surface it. The tell was constructing a fixture for a path that does not exist.

Two related facts that cost time the same day:

- **`git checkout -- <path>` restores from the INDEX, not from `HEAD`.** One stray
  `git add -A` between mutating and restoring and the mutant comes straight back, exit
  status 0, looking restored. Only a post-restore `git status --porcelain` notices.
- **A mutant that errors out is a no-op in a mutant's costume.** `cp "$BACKUP" "$F"` with
  `$BACKUP` unbound reported 3 red and looked informative; the copy had simply failed and
  left the file at HEAD — the right answer by accident. The honest mutant has to *succeed*
  at doing the wrong thing (`git show HEAD~1:"$F" > "$F"` -> 9 red).
- **A mutant you COMMITTED defeats the restore silently.** `git commit -am wip` after a red
  run is an ordinary habit; do it between mutating and restoring and `git checkout --` is a
  no-op, `git status --porcelain` is empty, and the restore reports success over a mutant
  that is now on the branch. The gate is to refuse a path that is *already clean* — "nothing
  to restore" is the dangerous state here, not the harmless one.
- **The CI runner has no zsh**, so `SHELLS` degrades to `['bash']` and it collects
  materially fewer tests than a macOS machine (335 vs 391 on one measured pair — an order
  of magnitude, not a figure to quote later; the count moves with every case added). Every
  `zsh` case in `scripts/__tests__/` is therefore a local-only result. Do not claim
  "verified under bash and zsh in CI".
- **`:(literal)` restricts wildcards, not scope.** `git … -- ":(literal)$F"` with `$F`
  **empty** addresses EVERY tracked file — `ls-files --error-unmatch` exits 0,
  `status --porcelain` lists them all, and `checkout --` reverts them all and exits 0. The
  bare `-- ""` form fails closed (`fatal: empty string is not a valid pathspec`), so adding
  literal magic *converted a refusal into a silent whole-worktree revert*. A directory is
  the same trap at subtree scale: `":(literal)sub"` matches `sub/nested.js`. Guard `[ -z ]`
  **before** building the pathspec — **and do not stop at a filesystem test.** `[ -d "$F" ]`
  is FALSE for a directory that has been deleted from disk, which is still a directory to
  git, so the whole-subtree revert comes straight back with the same `ok`-and-exit-0
  signature. **Ask git what the pathspec addresses, not the filesystem what `$F` looks
  like:** `ONE=$(git ls-files -- "$P")`, then refuse unless `"$ONE" = "$F"`. That one check
  subsumes empty, directory, and deleted-directory, and still permits the deleted-FILE
  mutant (`ls-files` answers from the index). Both holes were caught in review, on this
  branch, after I added the hardening that created the first one.
- **I broke this card's own rule while shipping this card, and the block caught what to do
  about it.** I applied mutant M15 to `SKILL.md` while that file carried an UNCOMMITTED fix
  of mine (the `core.quotePath` one). `git checkout --` would have restored the committed
  text and taken my fix with it — incident (3), exactly. The recovery is the one the doc
  prescribes for a path that is not committed-clean: **do not restore, reconcile by hand.**
  I re-applied the fix from the script that generated it and diffed to confirm. The lesson
  is not "be careful": it is that the precondition block exists *because* the careful
  version of me skipped it. Run it.
- **A byte-comparison gate is only as good as the spelling the other command chooses.**
  `ONE=$(git ls-files -- "$P")` compared against `"$F"` looks exact, but `ls-files` applies
  `core.quotePath` (default **true**) and prints `"caf\303\251.js"` for `café.js` — quotes
  and octal escapes included. An ordinary file, refused. `git -c core.quotePath=false`.
  Same family: it prints **cwd-relative** paths, so `./a.js` refuses too.
- **`some(/^exit 1$/)` is not "every refusal exits".** A block with three refusal branches
  satisfies it with one. Count the refusals and the exits and assert they are equal —
  otherwise the mutant gets widened to fit the test, which is measuring backwards.
