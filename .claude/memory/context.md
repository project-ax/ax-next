# Project context

Confirmed facts about ax-next. Not opinions.

- `2026-04-23` — Only `@ax/cli` and `presets/**` (the meta-packages that wire plugins together) may import sibling plugins; enforced by `eslint.config.mjs` `no-restricted-imports` overrides. All other inter-plugin communication goes through the hook bus. (Updated 2026-05-24: `presets/**` is on the allow-list too, not just the CLI.)
- `2026-04-23` — Storage hook payload contract is `{ key: string, value: Uint8Array }` — opaque bytes, no backend vocab. Any `table`/`bucket`/`rowid` field would leak.
- `2026-04-23` — pnpm 10 requires `pnpm.onlyBuiltDependencies` allowlist for packages with postinstall scripts (e.g. `better-sqlite3` prebuild-install). Without the allowlist, the build silently skips the postinstall and the package fails to load at runtime.
- `2026-04-23` — E2E tests invoke the CLI as `node dist/main.js <args>`, not `pnpm exec ax-next`. Shebang + `chmod +x` are present but tests use node directly to avoid pnpm bin-link flakiness.
- `2026-04-23` — Week 3 shipped as PR #2 (merged). Week 1–2 kernel shipped as PR #1.
- `2026-04-29` — Claude Agent SDK 0.2.119 encodes the project-dir name as `realpath(cwd)` with `/` → `-`, NOT the literal cwd string. On macOS `/var/...` becomes `-private-var-...`. Don't reconstruct the path; glob `<HOME>/.claude/projects/*/<sessionId>.jsonl`.
- `2026-04-29` — SDK 0.2.119 with `settingSources: []` still writes outside `<HOME>/.claude/projects/`: `<HOME>/.claude.json` (~20KB cache: GrowthBook flags, anon userID, migrationVersion, model-cost cache), `<HOME>/.claude/backups/.claude.json.backup.<ts>` (accumulates per spawn), `<HOME>/.claude/policy-limits.json`. None are secrets, but workspace persistence should ignore everything outside `.claude/projects/`.
- `2026-04-29` — SDK 0.2.119 jsonl entry types include non-turn records: `queue-operation`, `last-prompt`, `attachment` (e.g. `skill_listing` injected by the SDK even with `settingSources: []`). Any transcript parser must whitelist `user`/`assistant`/`tool`, not blacklist. (Updated 2026-05-24: the once-planned `runner:read-transcript` hook never shipped — Phase C was superseded by the 2026-05-01 workspace redesign. Transcripts are now read by `conversations:get` globbing committed `.claude/projects/*/<sessionId>.jsonl`. Stale code-comments still mention the hook in `packages/conversations/src/{types,store}.ts`.)
- `2026-04-29` — ax-next has no production data and never will need a schema migration that preserves rows. Existing `_v1` table suffixes (`conversations_v1_*`, `audit_v1_*`) are stable identifiers, NOT version pointers. ALTER TABLE in place is correct for every schema change; no v1→v2 split, ever. (See decisions.md 2026-04-29 entry.)

- `2026-07-30` — LongMemEval-S is ordered in **type blocks** (single-session-user 70 → multi-session 133 → single-session-preference 30 → temporal-reasoning 132 → knowledge-update 69 → **single-session-assistant 54**). Budget wall-clock separately from dollars; `--cap` must be set above projected spend or the run aborts and silently shrinks the denominator.

- `2026-08-02` — Assistant-content extraction FINAL (n=500, `bm25-full-assistant.jsonl`, $221.16): overall **66.2% → 75.8% (+9.6pp)** on the 488 questions both runs scored (76.0% on all 500). Both gates pass (multi-session 69.2% ≥65%; correct-refusal 88.0% ≥83%). **No type regressed.** single-session-assistant 25.9% → 83.3%; **temporal-reasoning 68.9% → 78.0% (+12 questions) — an UNFORECAST gain on a type this lever never targeted.** The temporal mechanism (temporal questions turning on assistant-supplied dates/durations/timelines) is an untested hypothesis, not a finding — a kept-workspace repro on 2–3 temporal flips is the cheapest way to settle it.
- `2026-08-02` — Long bench runs get SIGTERM'd (exit 143) by something outside the bench, repeatedly. `--resume` makes this cheap (a kill costs only the in-flight question), so the fix is a supervisor loop that relaunches the identical command until the JSONL hits the target row count — see `scratchpad/bench-supervisor.sh` pattern. **Never launch a multi-hour bench as a harness-tracked background task**; macOS has no `setsid`, so `nohup <cmd> &` from a foreground call is what survives. Budget **wall-clock separately from dollars**: n=500 is ~2.5 days (~9 min/question), while cost tracked its estimate within 2%.
- `2026-08-19` (PR 3, `@ax/agent-aisdk-runner`, PR #400) — The **second runner** ships: `ai@7`'s `ToolLoopAgent`, selectable per-agent via `agents.runner`, loaded in the CLI + k8s preset + container image. Facts worth carrying into PR 4–7:
  - **`ai@7` is pinned EXACTLY** (`7.0.70`, `@ai-sdk/anthropic@4.0.40`), matching how `@anthropic-ai/claude-agent-sdk` is pinned. `ai` now exists at TWO majors in the workspace — `channel-web` on v6 (browser) and this runner on v7 (Node sandbox). Deliberate; they never interoperate. `dependency-skew.test.ts` fails if a workspace-wide `ai` override appears.
  - **`TranscriptSource` is byte-shaped now**: `read(): Promise<Buffer|null>` / `write(): Promise<'accepted'|'unusable'>`. `'unusable'` IS the cross-runner demotion — it routes into the existing F2a branch, so core has no second branch for it.
  - **The aisdk transcript is ndjson with a header line** `{"v":1,"runner":"aisdk"}` and per-line `{role, uuid, message}`. The envelope is NOT cosmetic: `dropTurnFromJsonl` needs top-level `uuid`, `roleOfJsonlLine` (the B3 detector) needs `role`. Restored lines are re-emitted VERBATIM (`raw`) because `modelMessageSchema` strips unknown keys — re-serializing would force a whole-file resync every resume.
  - **`agentConfig.runner`'s real reader is a boot self-check**, not the demotion driver (the orchestrator comment predicted otherwise and was corrected). The transcript header drives demotion.
  - **The runner has NO `postbuild` script**, on purpose: `tsc --build` never runs a referenced package's npm scripts (the #397 trap). Its `dist/main.js` reaches the image because `@ax/cli` + `@ax/preset-k8s` declare it as a PROD dependency — `pnpm deploy --prod` copies the prod closure. Guarded by preset-k8s's `image-asset-packaging.test.ts`.
  - Compaction is still absent (PR 6/7), so a long session degrades — documented non-parity in the runner README alongside `TodoWrite`, cross-runner resume, SDK setting sources, and skill-declared in-sandbox MCP servers.
