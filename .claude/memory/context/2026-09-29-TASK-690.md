# TASK-690 — context (per-owner storage quota)

- 2026-09-29 (READ-FROM-CODE): prod runs `AX_PRESET=memory` (chart `deployment.yaml`, `serve.ts` refuses `k8s`), and `presets/memory` wraps `createK8sPlugins`, so a plugin added to the k8s preset loads in prod without a memory-preset edit. The prod workspace backend is `local` (`@ax/workspace-git`, one bare repo per agent at `<mountPath>/ws-<16hex>.git`, the id a one-way hash of the agentId) and `fs` blobs live in `<mountPath>/blobs/<sha[0:2]>/<sha[2:4]>/<sha>` on the SAME PVC. The PVC is 100Gi in prod but `gke-values.yaml` says 20Gi (overridden somewhere); memory facts are a separate 10Gi PVC and the NFS user-files share is written by the sandbox directly, so neither is on the host's write path.
- 2026-09-29: NOTHING ever frees storage. `blob:delete` has one caller (a replaced branding logo, unrefcounted); attachment/artifact rows have no delete path; conversation delete is soft; `agents:deleted` has no workspace or blob subscriber; git history keeps every blob. So no message may tell a person to "delete something". Orphan blobs are possible too: IPC `blob.put` (runner, 100 MiB cap) carries no ownership row, and `artifact.publish` is a separate optional call.
- 2026-09-29: the runner commit (`workspace.commit-notify`) is a JSON action, so the base64 thin bundle rides inside the 4 MiB `MAX_FRAME`: about 3 MiB of compressed objects per commit. Over that, the 413 is swallowed by `commitNotifyWithResync` as `kept` and persistence silently wedges (pre-existing, returned as a follow-up). `workspace:pre-apply` only sees the policy-visible slice (`.ax/**`, `.claude/**`, `CLAUDE.md`), so it cannot size the write from `changes`; `sizeBytes` is derived host-side from the decoded bundle.
- 2026-09-29: a `workspace:pre-apply` veto is answered `recoverable:false` (runner resets `--hard`) and the runner ONLY hands the reason to the agent for `recoverable:false`; keeping the files (`--mixed`) would need a wire change. A quota refusal therefore removes the refused turn's file changes and the reason says so.
- 2026-09-29: attachments upload (`POST /api/attachments`) writes Postgres BYTEA temp rows (25 MiB per file, 200 MiB pending per user, released at commit); the blob write happens at message-send (`attachments:commit` from `routes-chat.ts`), and its 100 MiB per-message check runs AFTER the write.
- 2026-09-29: skills stores hold a fixed `system` ctx for `blob:put` (ctx-free `writeTree`), so skill bundles (512 KiB each, unlimited count) were unattributable; `writeTree(files, ownerUserId?)` now carries the owner.
