# TASK-731 — context (a refused save is persisted; the final/idle refusal has a channel)

- 2026-10-02: SUPERSEDES the TASK-720 context line that says the save-refused notice is "Live only (not persisted; gone on reload), and the final/idle commit after the last turn-end still only logs". A refused save is now ALSO a `save-refused` display event in `conversations_v1_events` (`payload: { code }`, closed code only). The per-turn row is appended by `@ax/ipc-core` `persistEventTurnEnd` after the `turn` row, folded on the turn's reqId (both turn-ends of a tool-using turn carry the code), best-effort. The final/idle refusal rides `event.chat-end` `saveRefused` and is persisted with a host-minted `final:<uuid>` key. channel-web `buildThread` interleaves the rows by `createdAt` like `turn-error`; the live `done`-frame notice only bridges until the re-read and is suppressed once the thread holds `saveRefusedRowId(reqId)`.
- 2026-10-02 (READ-FROM-CODE): the final/idle commit is NOT only late/background writes. `commitTurnAndBundle` bundles `baseline..main`, so a per-turn save that came back `kept` (host unreachable / 5xx) rides the final flush, and a refusal there undoes files from replies the person already read. The flush only runs when the loop drains normally (cancel / idle-timeout); a loop that throws skips it entirely.
- 2026-10-02: `conversations_v1_events.event_kind` is CHECK-constrained, so a new display-event kind needs a migration, and `listEvents` used to THROW on an unknown kind (one odd row broke `conversations:get` for the whole conversation). It now skips unknown kinds. A rollback to a release before TASK-731 still throws on `save-refused` rows.
