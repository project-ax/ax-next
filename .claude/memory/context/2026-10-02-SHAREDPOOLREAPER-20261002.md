# Shared pool claim reaping regression

- Isolated GKE acceptance found two holes in the shared API's sweeper view: terminal claimed Pods retained their Sandbox owner reference, so the sweeper skipped their claim aliases; claims with a confirmed missing assigned Sandbox disappeared from the list entirely. After host restart a resumed Claude turn failed with proxy 407 in under one second, storage detached, but its claim remained.
- The fix exposes claim metadata for assigned Pod observations and exposes confirmed missing assigned Sandboxes as terminal claim observations. Retired deletions use the observed claim UID and preserve storage finalizers. Pending capacity, another pool prefix, missing Pods under an existing Sandbox, and API outages do not authorize reaping. Running sessions remain untouched. New regression tests exercise the real sweeper, plus same-name UID replacement.
- This does not restore credential-proxy registrations across host restart. The existing operational instruction remains: drain runners before host restart. Full transparent image-rollout continuity is separate from class-level replacement.
- Quota acceptance scope was explicitly chosen by the user: existing Git workspace and uploaded/published blob accounting. Hard quotas for arbitrary Bash writes to raw `/files` are a separate follow-up.
