# Shared-pool recovery fixes before final GKE gates

- The single-host chart explicitly rejects multiple host replicas. Shared sandbox plugin boot now UID-retires only claims in its configured prefix. Class-only initialization still preserves claimed sessions. In keepalive routing, an active session persisted by a previous host is retired if this process lacks its runner handle; the same durable conversation opens a fresh session/proxy registration. No proxy secrets are persisted or restored from runner state.
- The helper records a strict secret-free recovery intent on the protected Pod before any storage finalizer or bind. It contains existing storage identities/roles plus the trusted GKE machine UUID and native kernel boot UUID. Missing local ledgers recover conservatively and terminate the assignment instead of replaying consumed bootstrap credentials. A matching GKE VM identity with a different boot permits cleanup of uncertain old container status; a different machine or corrupt/foreign owner chain fails closed.
- Helper cleanup UID-deletes the owning claim before dropping Pod/claim storage finalizers, preventing controller recreation of a standby under a released claim. A current-boot ContainerStatusUnknown or Failed phase alone does not prove quiescence; cleanup needs genuine finished container timestamps or the matching-machine prior-boot fence. Existing helper RBAC gains namespaced Pod list and claim delete, plus one read-only host machine-identity file; runners gain no capability.
- Host/recovery regressions failed before fixes. Targeted package/build/chart validation and fresh isolated GKE verification are underway; no production shared-pool activation is authorized by these local results.
