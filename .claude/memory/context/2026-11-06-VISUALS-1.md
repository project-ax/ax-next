# VISUALS-1 — chat-visuals kind walk (context)

- 2026-11-06 — Chart.js resolves a function as a scriptable option only at the TOP level of an option. Inside a per-point array (`backgroundColor: data.map(() => fn)`) the entries are not called, the bar color resolves to undefined, and the canvas paints the default BLACK. The frame runtime's `ax.chartColor(name)` returns such a function (and ignores any second "alpha" argument), so the natural model idiom of highlighting one bar with a per-point array draws black bars in both themes. Found on the first claude-sdk walk; a frame-runtime fix needs a test that renders a per-point array of `ax.chartColor` values.

- 2026-11-06 (re-walk at 257d38938) — A Chart.js visual that loads while scrolled OFFSCREEN can initialize at a 0-width canvas (container 572x340, `chart.width === 0`), because the frame is render-throttled and Chart.js sizes before layout; its ResizeObserver path then sometimes never recovers, even after the frame is scrolled into view. The frame has already said `ready` (body has content), so the user sees a blank card with no failure state. Repro on kind: full page load of `/workspace`, open the conversation (thread opens scrolled to the bottom, chart above the fold), wait ~10 s, scroll up: 4/6 runs had 0-width charts, 2/6 stayed blank. A hard reload or in-app navigation usually hides it (it's timing-dependent), so loop the repro several times rather than trusting one pass. `chart.resize()` from inside the frame heals it at once.
- 2026-11-06 — The raw `ToolSearch: select:mcp__…` step row is NOT specific to show_visual: stored transcripts on kind show the same deferred-tool load for `ax-sandbox-tools__artifact_publish` (2026-11-01) and many `ax-host-tools__*` tools since 2026-10-23. It's the Claude Agent SDK's default deferral of MCP tools, and nothing in channel-web special-cases ToolSearch.
- 2026-11-06 — In dark theme, `--muted` is byte-identical to `--card` (`226.15 14.94% 17.06%`), so any agent-drawn tile/pill on `hsl(var(--muted))` inside a visual vanishes in dark while it reads fine in light. It's a palette fact, not a frame bug.
