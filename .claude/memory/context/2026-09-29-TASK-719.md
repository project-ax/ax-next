# TASK-719 — project facts (2026-09-29)

- **Deleting an agent now removes its git workspace repo and releases its ledger row** (TASK-719). `@ax/workspace-git` subscribes `agents:deleted`, tombstones the agent id in-process, removes `<repoRoot>/<workspaceIdForAgent(agentId)>.git` under that agent's write mutex, then fires the notify hook `workspace:deleted { agentId }`; `@ax/disk-quota` subscribes and deletes `source = 'workspace:<agentId>'` for every owner. This supersedes the TASK-718 context row that lists "the agent's git workspace repository" as NOT cleaned (that shard is frozen). A failed `rm` keeps the bytes AND the row and does not fire the hook.
- **Still never freed:** blob bytes (attachments, artifacts, skill bundles), and conversation delete by the user is still soft. Agents deleted BEFORE TASK-719 shipped keep an orphan repo on disk and a counted `workspace:<agentId>` row until an operator cleans them; repo dir names are a one-way hash (`ws-<16hex>`), so they cannot be found by scanning, only by hashing every live agent id and diffing.
- **A `PluginError{ code: 'rejected' }` from `workspace:apply` / `blob:put` is ambiguous without `reasonCode`.** `workspace:pre-apply` also carries the `validator-identity`, `validator-routine` and `validator-skill` vetoes, and both facades used to drop the veto's `source`. Since TASK-719 a veto may carry `code` (`reject({ reason, code })`) and the facades throw `PluginError.reasonCode`; disk-quota sets `'storage-full'`. `PluginError.code` stays `'rejected'`. A route recognises a quota refusal only by `instanceof PluginError && code === 'rejected' && reasonCode === 'storage-full'`, never by `err.plugin` or the message.
- **The workspace refusal sentence is written for the model** ("this turn's file changes were removed... let the person know"). No screen may show it to a person; each route sends its own fixed sentence with `413 { error: 'storage-full', message }`. Mapped now: chat send, `/settings/skills*`, IPC `blob.put` / `skill.propose` / `workspace.commit-notify`, Rules, agent identity, routines save + delete. Still raw: the bootstrap seed (swallowed, agent silently skips the identity interview), the memory exporter (background), authored-skill promote (400 with code `rejected`).
- **`AX_SKILLS_BUNDLE_ROOT` was dead** (the preset stopped reading it in #229, the chart still set it) and is gone. `workspace.storage` reads 100Gi in `gke-values.yaml` to match prod; the prod override itself lives in an operator's gitignored local values file, so it is not visible in the repo.
- **Read from code, not run:** `attachments_v1_artifacts.artifact_id` is the PRIMARY KEY and is `sha256.slice(0, 16)` (`packages/attachments/src/handlers.ts`), but `upsertArtifact` only handles a conflict on `(conversation_id, path)`, so publishing the same bytes under another path or in another conversation should hit the PK. Verify with a real Postgres before fixing.
- **Blob GC constraints (why it is not built):** no plugin can answer "is sha X still referenced?" (attachments, skills x4 tables, branding each keep their own; no hook takes a sha); the fs and s3 `put` has an "already stored, do not rewrite" fast path that does not touch mtime, so a `put` of identical bytes racing a `delete` succeeds and then loses the file; IPC `blob.put` writes rowless blobs by design.
