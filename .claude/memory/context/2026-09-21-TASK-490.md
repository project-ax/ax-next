# TASK-490 — facts measured while building the `@ax/memory` observer

**The pinned extraction prompt is `06414f62`, NOT `f4752a79`.** The dem-memory
design doc (`docs/plans/2026-09-18-dem-first-memory-design.md` §3.0), the rung-3
handoffs and every epic card say the extraction prompt is "pinned at fingerprint
`f4752a79` and carried verbatim". Measured over
`dem-memory/src/engine/retain.ts` at `3fae262e`, reproducing
`dem-memory/bench/extraction.ts`'s own `promptShape()` and
`extractionFingerprint()`:

- prompt-only `sha1(EXTRACTION_SYSTEM_PROMPT + buildExtractionPrompt('',''))[0:8]`
  = **`e7466bf4`**
- prompt+model, `.update('z-ai/glm-5.3-flash:nitro')` = **`06414f62`**

`f4752a79` names the generation BEFORE `confidence` was removed from the schema,
tuple, DB column, extraction prompt, evidence table and CLI on 2026-09-17 — the
removal `context.md` and `decisions.md` already record as having deliberately
re-keyed the cache `f4752a79` → `06414f62`. **Carrying the prompt verbatim and
pinning it at `f4752a79` are mutually exclusive**, and there is no text anybody
can write today that hashes to `f4752a79` without re-introducing the deleted
line. A card that says "verbatim at `f4752a79`" is asking for two different
things; take verbatim.

**The engine already owns batch idempotency and atomicity, so the observer owns
neither.** `@ax/memory-facts-contract`'s `RecordInput.batchKey` writes nothing
and returns the ORIGINAL rows on a repeat, and a batch is all-or-nothing. What
`@ax/memory` actually owns is *what goes into the key*.

**`batchKey` is scoped by TENANT (`agentId`), not by owner.** The design's
shorthand is `conversationId + content hash`. With a team agent that is a silent
data-loss bug: two people can produce the same transcript, and the second
person's batch then matches the first's, writes nothing, and returns rows
stamped with somebody else's `ownerUserId` — rows their own owner-scoped recall
can never see. `ownerUserId` has to be in the hash.

**`chat:end`'s transcript is already text-only, but nothing says it has to
stay that way.** `@ax/agent-runner-core`'s `chatEndHistory`
(`packages/agent-runner-core/src/run-runner.ts`) pushes only `{role, content}`
and replaces a turn's `contentBlocks` with a `[N blocks]` marker, so tool
results and attachment bodies do not reach `chat:end` today. That is a
PRODUCER's behaviour, not a contract — `AgentMessage.contentBlocks` is part of
the type. A consumer that wants the guarantee has to filter on its own side.

**`optionalCalls` is the shape for a provider a plugin can live without.**
`packages/core/src/bootstrap.ts` `verifyCalls` fails the boot for a missing
`calls` producer and deliberately does not check `optionalCalls`; the entry is
still a real call-graph edge for ordering and cycle detection when a producer IS
present, and its `degradation` string is required prose.

**`@ax/memory-facts-sqlite`'s table is `memory_facts_v1`, and `schema.ts` is not
exported from the package index** — a test that needs a second connection has to
name the table itself.
