## 2026-10-03 — TASK-756: Connector health hardening (Retry cooldown, transient-vs-auth, shared reconnect marker)

Supersedes TASK-741's "Known limitation (team agents)" and its F1/F2 accepted findings (2026-10-03-TASK-741.md).

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-10-03 | **Card premise corrected: a "shared" connector credential is AGENT-keyed, not workspace-keyed.** The OAuth callback writes a team agent's token at vault scope `agent` (ownerId = agentId) and a personal agent's at scope `user`. So the shared marker is keyed (agent, connector). | Read from mcp-oauth routes.ts callback (`writeScope`). Nothing writes an OAuth token at global scope. | Key on workspace (rejected: no such vault scope for these tokens). |
| 2026-10-03 | **`credentials:resolve:<kind>` input gains `scope` + `ownerId` of the row it resolved (additive).** @ax/mcp-oauth reads it to pick the marker owner: scope `agent` with an ownerId → agent marker; anything else (user, global, absent) → per-user marker as before. | The resolver cannot tell a shared token from a personal one any other way; the vault already knows (it re-stores refreshes under the same pair). Vault vocabulary only — no backend leak. TASK-741 rejected widening for one consumer; this card makes the consumer load-bearing. | Copy the write scope into the token blob (rejected: second source of truth for the scope). |
| 2026-10-03 | **New table `mcp_oauth_v1_needs_reconnect_agent (agent_id, connector_id)`, additive; the per-user table is unchanged.** Store API takes a `MarkerOwner` union. Callback clears by write scope (agent → agent marker for every member; user → the signer's). | Additive migration, no PK rewrite. TASK-741 shipped 10-03 and has not been deployed to prod (rev19 is 09-29), so no legacy per-user rows written for agent tokens need migrating. | Rewrite the existing table's PK to (owner_kind, owner_id, connector_id) (rejected: riskier migration for no gain). |
| 2026-10-03 | **`mcp-oauth:status-batch` takes optional `agentId` and returns `shared: string[]` ⊆ `needsReconnect`. A connector with BOTH a personal and a shared marker reads as personal.** | The vault walks user → agent, so a person's own row is the one their use reaches first; it is theirs to fix. | Report both (rejected: the rail shows one reason). |
| 2026-10-03 | **Known limitation: an agent marker shows for a member who ALSO has a working personal row for that connector** (their resolves never reach the agent row). | Harmless direction (a stale icon fixed by the action it offers); knowing it would need a vault read per row on render. | Probe the vault per row (rejected: "no per-row probes on render"). |
| 2026-10-03 | **Rail copy: personal → tooltip "Your sign-in expired"; shared → "Team sign-in expired"; Reconnect dialog says "The team sign-in to X expired … everyone using {agent} can keep using it." Row/retry carry optional `sharedSignIn: true`.** Details view keeps neutral "Sign-in expired". | Card: say "your sign-in" when personal. "Team" is plainer than "shared" for a non-technical reader (ux-design self-review). | Add a new health word (rejected: ripples through every health consumer). |
| 2026-10-03 | **describe-tools: only `credential-not-found` or a NeedsReconnectError (by name, on the error or its bus-wrapped cause) is `needs-auth`. Any other credential failure THROWS `credential-unavailable` and stores nothing.** | All describe-tools callers already catch and degrade to "can't list right now"; the Retry route answers 502 → "We couldn't check X just now. Please try again." Storing `unknown` would overwrite the last real answer. | Return status `unknown` (rejected: Retry maps unknown → ok, the exact misreport the card names; a stdio-only connector is also `unknown`). |
| 2026-10-03 | **Retry cooldown: 30 s per (user, connector), in-process, in channel-web's retry route. Inside the window: same agent → the last check's result (a burst shares the in-flight promise; a failed check is answered 502 again); other agent → that agent's stored health. The sign-in marker is always read fresh. Map bounded at 1000 keys.** A 404/400/503 never starts the window. | Card asks per user+connector. A fresh marker read means a reconnect shows at once. Per replica only — a bound, not a global rate limit. | Key per (user, agent, connector) (rejected: N agents = N probes of one server). Shared-store cooldown (rejected: YAGNI at MVP). |
| 2026-10-03 | **Deferred: Reconnect on a team agent always signs in at agent scope, so a member whose expired sign-in is PERSONAL (a user-scope row, reached first) is not fixed by it.** Pre-existing (TASK-741). | Fixing it means a user-scope sign-in from the team agent's rail; begin without agentId is gated on connector ownership and may refuse workspace connectors — needs its own card + test. | Pass no agentId for personal markers (rejected inside this card: unverified begin-route authz). |
| 2026-10-03 | **Implemented inline (4 slices over one contract) rather than a subagent per task.** | Tightly coupled: the hook field, the marker owner and the rail flag must agree. | subagent-driven-development. |
