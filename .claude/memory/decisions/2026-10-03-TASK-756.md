| 2026-10-03 | **Security flag verified as REAL, two holes: (a) a multi-server connector could list server A, then hit a credential blip on server B; the F1 fix then forgot the cooldown entry, so A could be probed without limit. (b) `?refresh=1` on the tools routes (channel-web + connectors admin) forces describe-tools with no cooldown at all.** | Read the code: the old loop read a server's credential and listed it before moving to the next server; `force: true` was honoured on every call. | — |
| 2026-10-03 | **Fix (a): describe-tools reads EVERY server's credential (pass 1) before any listing (pass 2), so `credential-unavailable` guarantees no server was asked. Fix (b): a force throttle in describe-tools itself, keyed (user, connector), 30 s, bounded at 1000 keys: inside the window a forced call is served as an unforced one (cached row while fresh, otherwise one TTL-governed check). A credential blip clears its own entry.** The route-level cooldown stays for Retry's answer semantics (failure caching, burst sharing). | describe-tools is the one chokepoint every forced check passes through, so the bound holds whichever route asks. | 2026-10-03 | **Per-process state accepted.** N replicas allow at most N forced probes per window per (user, connector), a small fixed multiple that does not grow with how hard a client pushes. A restart resets it once. Each probe stays authenticated, ACL-gated, SSRF-guarded and limited to a 10 s deadline. | A shared-store limiter is not worth it at MVP. | DB- or Redis-backed limiter (future card if replica count grows). |
| 2026-10-03 | **Residual: a user can author N connectors pointing at the same URL and force each one once per window.** | That bound scales with the user's own connector count (authoring is not free, and every connector must be on an agent they can see).
