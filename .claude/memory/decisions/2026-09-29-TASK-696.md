| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-09-29 | **Each OAuth token carries the client it was issued to: the token blob and the pending-authorization row gain OPTIONAL `clientId` / `clientSecret`; redeem (callback) and refresh (resolver) use those, and only a blob/row WITHOUT `clientId` falls back to the shared `mcp_oauth_v1_clients` row.** | `begin` re-registers a DCR client every time and upserted it over one row keyed `connectorId\|authServerUrl`, so redeem/refresh used whichever client registered LAST. MEASURED-BY-PROBE: on a strict RFC 6749 AS a second connect of the same team connector, or a second user's connector with the same slug, killed the first token's refresh with `invalid_grant`; two overlapping begins failed one callback. Carrying the client on the token removes the shared mutable state instead of racing it. | Insert-if-absent shared client (the card's option 2): needs race handling, redirect-uri/scope keying and a stale-client story, and still shares one client across users of a slug. Per-begin client row keyed by a random suffix: same fix with a table that grows by a row per begin and a second lookup at refresh. |
| 2026-09-29 | **`begin` stops writing the shared client row; `putClient` is deleted. `mcp_oauth_v1_clients` and `getClient` stay as a READ-ONLY legacy fallback.** | Back-compat is the point: if new begins kept upserting the shared row, a post-deploy connect would still break a token minted BEFORE the deploy (which has no `clientId` and reads the row). Not writing it leaves every legacy token exactly as good as it was. `putClient` with no production caller would be dead code (Half-Wired policy). | Keep the upsert "for rollback safety": keeps clobbering legacy tokens; rollback after new connects degrades to a clean needs-reconnect anyway. |
| 2026-09-29 | **A dead credential is recognised by a typed, duck-typed check on the SDK error (`errorCode` in {`invalid_grant`, `invalid_client`, `unauthorized_client`}, or the matching class `name`), not by `message.includes('invalid_grant')`. No `instanceof`.** | The SDK's message is only the AS's `error_description`, which usually does not contain the code, so `/status` said 500 `status_check_failed` instead of offering Reconnect. The SDK can be loaded twice in a pnpm tree, which makes `instanceof` unreliable; `errorCode` is the SDK's public getter. The card asked for `invalid_grant` only; the implementer flagged (and the SDK's own `auth()` confirms) that `invalid_client` / `unauthorized_client` are the same class of "credentials dead": since each token now refreshes as its OWN DCR client, a long-lived token can outlive a client the AS expired, and that would otherwise read as a permanent 500. Reconnect is the right remedy for all three (a new begin re-reads the connector config, so it also fixes a rotated pinned secret). Everything else stays transient: rethrow, never wipe the refresh token. | `instanceof InvalidGrantError`: brittle across duplicate SDK copies. Keep the substring as a fallback: it is exactly the spurious-match / missed-match pair being removed. `invalid_grant` only (the card): leaves the expired-client case as a silent 500. |
| 2026-09-29 | **`begin` purges pending rows older than the TTL (best-effort, warn on failure).** | The pending row now holds a confidential client's secret in plaintext; abandoned begins were never deleted (the row only died on a callback). A row older than the TTL can never be redeemed (`consumePending` rejects it), so deleting it is behaviour-neutral. | Encrypt the secret into the pending row: no key plumbing in this plugin, and the vault-encrypted copy is the one that lives long. Leave the leak: same class as the code_verifier that already lingered. |
| 2026-09-29 | **No reuse of a persisted client across begins (card item 2 skipped); no UI change.** | Not needed once each token carries its own client; DCR churn at the AS is unchanged (one registration per begin). `/status` already maps `needs-reconnect` to the Reconnect button (`ConnectorOAuthConnect.tsx`), so fixing the server-side classification is the whole UI fix. | Reuse keyed by (connector, AS, redirect URI, scope): a real saving but needs the race handling and stale-client story above. |
