# TASK-690 per-user storage quota

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-09-29 | Card premise CONFIRMED (no per-owner limit on any write path) but with two facts the card lacked: nothing ever frees blob bytes (`blob:delete` has one caller, a replaced logo; attachment/artifact rows cannot be deleted; conversation delete is soft; agent delete touches no repo or blob), and the runner commit path already has an accidental ~3 MiB per-commit cap (JSON action, 4 MiB `MAX_FRAME`, base64 bundle) | Read every write point (workspace commit-notify, in-process `workspace:apply` writers, `attachments:commit`, IPC `blob.put`, skills bundle stores, branding). Consequence: the friendly message cannot promise "delete something", it says ask for more room | Copying the card's example message ("delete something or ask us") would be false |
| 2026-09-29 | Unit = per OWNER, one budget for git workspaces + blobs. Personal agent workspace charges its owner user; team agent workspace charges `team:<id>`; blobs charge the acting user. Default 1024 MB hard limit, warn at 80%, stored as `settings:disk-quota` (admin-editable, no env var) | They share one volume so they share one budget. 1 GiB x 100 people = the 100Gi disk, real use sits far below. Per-agent limit is bypassable (`/api/agents/bootstrap` is uncapped) so it must sum across agents | Per-agent (bypassed by making more agents); separate workspace and blob budgets (two numbers to explain, same disk) |
| 2026-09-29 | Workspace bytes are MEASURED (new service hook `workspace:usage {} -> {bytes}` in workspace-git-core, allocated bytes over the repo dir, re-measured after each applied write and by a periodic sweep over personal agents); blob bytes are LEDGERED at `blob:put` time as `(owner, sha256) -> size` | A git repo grows by history and loose-object block overhead, so a running sum of bundle sizes drifts from the disk; measuring self-corrects and backfills repos that pre-date the feature. Blobs have no owner and are never freed, so an append-only ledger is exact | Sum bundle sizes at pre-apply (drifts, double-counts a parent-mismatch retry); backfill blobs by reading `@ax/attachments` tables (cross-plugin read; no such hook) |
| 2026-09-29 | Enforce workspace writes by adding an optional `sizeBytes` to the existing `workspace:pre-apply` payload (both the runner commit path in ipc-core and the `@ax/core` `workspace:apply` facade fire it); enforce blob writes by making `blob:put` a facade (`blob:pre-put` veto, `blob:put-internal` in the backends, `blob:stored` notify), exactly like `registerWorkspaceApplyFacade` | pre-apply is already veto-capable on both write paths and already answers the runner with a reason it hands to the agent; a facade makes the blob chokepoint unbypassable for every current and future caller (4 callers today) instead of a check each caller must remember | A new `quota:*` service hook every caller must call (a future caller forgets it); refuse at `chat:start` (blocks read-only use, adds a third gate, and the write-time truth is what the card asked for) |
| 2026-09-29 | Quota refusal on the runner commit path reuses the pre-apply veto answer (`accepted:false, recoverable:false`), so the runner resets `--hard`; the reason reaches the agent only on the mid-turn flush before a host tool | `rejectionReason` is only returned for `recoverable === false`, and the runner uses it only in `flushPreconditionMessage` (host tools). The ordinary END-OF-TURN save drops the reason (`result.outcome`/`parentVersion` are all `run-runner.ts` reads), which I found late by reading the call site instead of trusting the comment in `commit-notify-resync.ts` that calls this "the only channel by which the agent can learn". Keeping the files (`--mixed`) would re-bundle and re-refuse every turn and needs a runner wire change | New `recoverable`-with-reason wire field; surfacing the end-of-turn reason to the person (runner change, follow-up) |
| 2026-09-29 | ALSO gate `chat:start` (reason `storage-full`, sentence in channel-web `ERROR_LABELS`) once a person is full; it fails OPEN, unlike the write gates | Because the end-of-turn refusal is silent, the person's next message is where they can be told, in the same banner surface the spend gate uses; it also stops running an agent whose work cannot be saved. Fail-open because it exists for the message, not the disk (the write gates fail closed). Cost accepted: a full person cannot chat, including read-only questions, until an admin acts; nothing they do frees space so the alternative is silent loss | No `chat:start` gate (silent loss at the end of a turn, violates the card's "friendly message in the UI"); gate `chat:resume` too (its writes hit the write gates; not needed) |
| 2026-09-29 | The gate is not a reservation; N simultaneous writes by one owner can each pass. Overshoot is bounded by concurrent writes x per-write size (about 3 MiB per commit, 25 to 100 MiB per upload), and the next check refuses | A reservation needs a row per write plus cleanup on every failure path; this is a volume guard, not billing | Advisory lock plus reserve/commit (kept out: complexity for a guard whose failure mode is a few tens of MB over) |
| 2026-09-29 | The gate fails CLOSED (catches its own errors and rejects); the meters never throw | `HookBus.fire` reads a throwing subscriber as a clean pass (TASK-692 lesson), so a naive throw fails open | Fail open (a storage outage would silently disable the guard) |
| 2026-09-29 | Blob writes from a non-person ctx (`system`: branding, the skills stores today) are not attributed and not refused; skills stores are changed to pass the owning user so user-authored skill bundles are attributed | 512 KiB x unlimited skills per user is a real fill path; branding is admin-only and 1 MiB | Leave skills unattributed (a hole), or cap skill count (a separate product decision) |
| 2026-09-29 | Blobs uploaded before this ships are NOT backfilled; workspace repos are (sweep). Deleting an agent does not free its repo and it stays counted. `@ax/workspace-git-server` does not register `workspace:usage`. All returned as follow-ups | No hook lists a user's attachments and reading `@ax/attachments` tables from another plugin is banned; a workspace delete hook and a blob GC do not exist | Building a GC in this card (separate design: reference counting across four tables) |
| 2026-09-29 | Review round 1 (ax-code-reviewer, sha f94ec470c858867fe988dc53622d9af4f1845abb), Important: the blob meter charged LOGICAL bytes while the workspace meter charged ALLOCATED bytes; the fs backend keeps one file per blob, so a runaway agent looping `blob.put` with tiny distinct artifacts costs a block and an inode each while metering ~100 B. FIXED: every blob is charged in whole 4 KiB units, at least one (`blobCharge`), at both the gate and the ledger write | Same currency as the workspace meter; caps a person at ~262k tiny blobs at the 1 GB default; over-counts on S3 (errs safe) | Per-owner object-count cap (a second number to explain); make the fs backend report allocated size (backend vocabulary in `blob:put`'s output) |
| 2026-09-29 | Review round 1 Minor: team agents are never swept (`agents:list-personal-owners`). ACCEPTED as a documented gap + follow-up | Per-write metering charges `team:<id>` correctly and repos mostly grow, so the next write self-corrects; a fix needs an owner-bearing team agent listing that does not exist | Sweep all `agents:list-ids` (owner unknown) |
| 2026-09-29 | Review round 1 Minor: refusal sentences carry the owner's used/limit byte counts to the (untrusted) model. REJECTED | The numbers are the owner's own usage (for a team agent, the team's, which that team's own agent already lives inside), a byte count is low-value to exfiltrate, and the person-facing send sentence is more useful with them; removing them from a string shared by the UI and the runner path would cost the person information for a theoretical gain | Split the wording into an agent variant without numbers and a person variant with them |
| 2026-09-29 | Review round 1 Nit: `team:<id>` and raw user ids share one column. ACCEPTED as is | better-auth user ids are opaque random strings, never `team:`-prefixed; a second `owner_kind` column would touch every query for a theoretical collision | Add an `owner_kind` column |
