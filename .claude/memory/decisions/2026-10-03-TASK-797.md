## 2026-10-03 — TASK-797 admin OAuth client secret readable by any signer

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-10-03 | **Refuted the card bullet "credential plan lists the client-secret ref at global". The secret gets its own rule in `credential-authz.ts`; `deriveCredentialPlan` is unchanged.** | The plan is also the connect-flow prompt list (ConnectorConnectDialog, add-connector, ConnectorsTab), the attach credential gate, mcp-client describe-tools' slot resolver (sends values to MCP servers) and the delete purge. Listing the secret there would prompt every user for it and put it on value-sending paths. | Add a plan entry with a "not a slot" flag (rejected: every consumer would need to learn to skip it; one missed consumer leaks). |
| 2026-10-03 | **Rule: a global read of `account:<id>:OAUTH_CLIENT_SECRET` is allowed iff `getSoleSharedById(user, id)` returns the connector, one of its oauth slots has exactly that `clientSecretRef`, the ref is NOT also a credential-plan ref of that connector, and the owner `isAdmin === true` at read time. Any ref with that tag is decided ONLY by this rule.** | `getSoleSharedById` = shared + unambiguous + what this user resolves (TASK-711's predicate), so a same-id private connector or two sharers deny. The plan-collision deny is what keeps the secret out of the credential proxy even if some connector names a slot `OAUTH_CLIENT_SECRET`. | `getAvailableById` (rejected: also returns a private own row). |
| 2026-10-03 | **The bus cannot pin the calling plugin: `AgentContext` has no caller identity and `HookBus.call` records none; any plugin can mint a ctx with agentId `@ax/mcp-oauth`. Not enforced; the guarantee rests on the plan-collision deny + the proxy fold dropping `OAUTH_CLIENT_SECRET` slots.** | Measured by reading `packages/core/src/context.ts` and `hook-bus.ts`. | Key off ctx.agentId === '@ax/mcp-oauth' (rejected: forgeable, and begin must not use that agentId anyway — see next row). |
| 2026-10-03 | **`begin` reads the client secret with `agentId: ''` (user -> global, no agent step).** | With the placeholder `@ax/mcp-oauth` agentId, TASK-711's agent authz says yes for a SHARED connector and then the blob store throws on the ownerId grammar, so the walk never reached global. `''` is the convention the `status` route already uses. A client secret is never stored on an agent. TASK-712's ref check still bounds which refs are dereferenced. | Keep the placeholder (rejected: the non-admin signer can never resolve the global secret). |
| 2026-10-03 | **Editor scope helper: global when keyMode is workspace (unchanged) or when the editor runs in admin mode AND the connector is shared; otherwise user.** | `/admin/connectors` is admin-gated and owner-scoped, so admin mode = the author is an admin. A PRIVATE admin connector's global secret would be unreadable even by its owner (getSoleSharedById denies), so private stays at user scope. | Write global for every admin (rejected: breaks the admin's own private connectors). |
| 2026-10-03 | **Migration detection = a USER-scope row with the connector's `clientSecretRef` in `/settings/credentials` (the admin's own list). Saving a new secret writes global, then deletes the user copy.** | Exactly the card's condition ("secret still at user scope"); one cheap owner-scoped call; no global listing needed. | `/admin/credentials` global presence (rejected: heavier and answers a different question). |
| 2026-10-03 | **`connectors:delete` also purges the connector's own client-secret ref (user scope always, global only with purgeGlobal).** | A global secret is new state this card creates; without the purge it outlives the connector and a later same-id admin connector would silently inherit it. | Leave it (rejected: lingering company-wide secret). |
