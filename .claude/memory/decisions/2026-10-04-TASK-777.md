# TASK-777 — @ax/blob-gc in report mode + blob:list (Blob GC 2/5)

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-10-04 | `@ax/blob-gc` is loaded in the k8s preset only; NOT in the local CLI runtime (`packages/cli/src/main.ts`) | `ax serve` already boots `@ax/preset-memory` → `createK8sPlugins`, so the k8s preset IS the CLI's server path. The local `ax` chat runtime has no blob store, no `database:get-instance` (sqlite storage only) and no http plane, so the plugin's hard calls could not be satisfied there and nothing in it ever stores a blob | Load it in main.ts too (fails `verifyCalls`; would need a blob store + Postgres there first) |
| 2026-10-04 | `blob:list` paging: `next` is present iff the page is full (`items.length === limit`) and equals the last sha; a final page may be empty | Lets fs stop walking as soon as it has `limit` items without peeking ahead, and s3 the same without an extra request; callers loop until `next` is absent. Same contract on both backends | Peek one item ahead to know whether more exist |
| 2026-10-04 | Discovery lists only `state: 'live'` in this card; the design's "page retired, mark unseen retired" half of step 1 is left to TASK-778 | `blob:list { state: 'retired' }` always answers `[]` until retire exists; calling it now is code that can only ever do nothing | Call it now for symmetry |
| 2026-10-04 | `last_put_at` is written from the plugin's injected JS clock, and a re-put uses `GREATEST(old, new)` | Tests step past the grace window with a clock; GREATEST means a replica whose clock lags can only lengthen a blob's grace, never shorten it (the data-loss direction) | DB `now()` (untestable without sleeping); plain overwrite |
| 2026-10-04 | The last COMPLETE sweep's report is persisted under storage key `blob-gc:last-report` (storage:get/set), not in memory and not a third table | The card fixes the tables to exactly D4's two; an in-memory report is only on the replica that swept; storage is already a hard call (settings) | Third table; in-memory only |
| 2026-10-04 | An aborted sweep writes no report (the admin line keeps showing the previous complete one) and logs `blob_gc_sweep_aborted { candidates, rejected, missing, failed, malformed }` at error | A partial count would understate what is reclaimable; the abort is the line an operator acts on | Write a partial report |
| 2026-10-04 | Admin route is `GET/PUT /admin/storage/cleanup` (settings + last report); `mode` accepts only `'report'` (`z.enum(['report'])`, so TASK-778 adds one literal) | Same `/admin/storage` prefix as disk-quota's Storage tab routes; a URL is not hook-payload vocabulary | `/admin/storage/blob-gc` |
| 2026-10-04 | Local review round 1 (ax-code-reviewer, sha 5265209f08957b03a99e06f380dda73835ec344e, plain no-name dispatch, ~13 min): APPROVE, no Critical/Important. ACCEPTED as-is: (1) Minor: an aborting sweep keeps the admin line on the last good report with no staleness signal (`report.at` is not rendered); it fails closed, and the operator walk (TASK-778 / 723d) is where it matters, so it is handed forward; (2) `retentionMs` / `retired_at` are stored but unread until TASK-778 (setting shape stability, design D8); (3) a `pg_advisory_unlock` that itself throws would leave the lock on a pooled connection (practically unreachable; a dead session releases it) | Each is a stated report-mode tradeoff; none can lose data | Render `report.at` and an abort status now |
| 2026-10-04 | Every sweep fires `blob:collect-refs` at least once, with `candidates: []` when nothing is old enough, and upserts answering holders into the GC's OWN roster table | Same as TASK-776's disk-quota pass: otherwise the roster only grows on a sweep that already has candidates | Only fire with candidates |
