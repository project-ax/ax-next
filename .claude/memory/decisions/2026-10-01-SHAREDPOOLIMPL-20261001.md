# Shared-pool implementation boundaries

- Implement shared capacity per execution configuration, never per agent. Build credential-free standby templates with force-shared disk emptyDir, existing gVisor placement/hardening, Disallowed env injection and Unmanaged controller networking; bind agent identity only to the claim/activation. Session deadlines belong to claims, not standby age.
- The trusted helper uses existing NFS exports and binds only the authorized agent's source. UID-pinned owner-chain checks and independently supplied host-authorized agent identity are required; accepting a resolver subPath alone would let a malicious resolver select another agent. Keep source-key derivation single-homed in the allowed pure sandbox-protocol library, preserving memory's public re-export and stored layout.
- Bootstrap is a private expiring local file transported through the mutually authenticated helper, consumed before model work. No custom encryption or runner listener is needed. Failures preserve recovery/finalizer state; a successful umount exit code alone is insufficient without mountinfo verification.
- Helper startup retains image tini and uses flock --no-fork so SIGTERM reaches Node and the durable ledger is exclusively owned. Helper updateStrategy stays OnDelete pending accepted restart semantics. Drain claims/ledgers before removing helpers on rollback.
- Shared runners must not receive NFS network reach. Kubernetes NetworkPolicies are additive, so preserve any legacy cold-path NFS allowance in a separately selected policy excluding the shared-standby label; another restrictive policy would not cancel the old allowance.
- This is an opt-in prototype until the rebuilt image, real NFS durability, kernel mount behavior, finalizer/kubelet teardown ordering and node drain pass isolated acceptance. Current managed session permissions prevent that remaining deployment work; no approval prompt can change the restriction.
