Per design §9 and card TASK-1094, the **first producer of `'external'`/`'shared'` is TASK-1094**, so a squash at 1093 still leaves the external and shared branches with nothing reaching them. | The half-wired policy says naming a window doesn't close it. | 2026-11-12 | **`'external'` means a person with no access to the agent is present. `@ax/core` gains `isAttendedTurn(ctx)` (absent or `'user'` → true; routine, external or unknown → false) and `audienceOf(ctx)` (unknown → `'shared'`).** Consumers that ask "is someone with access here" use the helper. Routine-only features (`routineRun`, `routineRetire`, `spawnSkips`, the routines gates) keep `=== 'routine'`, which already excludes external. | One definition, exhaustive by construction, fails closed. The card's grep criterion ("no remaining not-routine = attended") then reduces to the routines refusals. | Sprinkle `=== 'routine' \|\| === 'external'` at each site (drifts). A `sourceOf` normalizer (YAGNI: ctx is typed and built by host code). |
| 2026-11-12 | **Decisions: `attendanceFor` returns `'unattended'` when `ctx.source === 'external'`, before the conversation-origin lookup. It does NOT use `!isAttendedTurn`.** | AW-6 (2026-08-21) made the conversation's channel the source of truth for attendance and deleted the `ctx.source === 'routine'` guess. Keeping routine on origin respects that. A Slack channel thread mixes attended and external turns in one conversation, so only a per-turn signal can be right for external. The override is in the safe direction (the host replays). | `!isAttendedTurn(ctx)` (would quietly move routine attendance off origin). A new conversation origin per channel (can't express a mixed thread). |
| 2026-11-12 | **`audience` crosses the runner boundary exactly as `source` does (the TASK-181 chain): sandbox-protocol → sandbox-k8s/subprocess → session-inmemory/postgres (new nullable TEXT column) → `session:resolve-token` → ipc-core auth → both listeners.** Both session normalizers fail closed: unknown source → `'external'`, unknown audience → `'shared'`. | Memory's capture (`chat:end`/`chat:turn-end`) and its tools (`memory_recall`, `memory_note`) run on an IPC-rebuilt ctx, so a field that doesn't ride the session record isn't there. Measured: today `z.enum(['routine','user'])` in both `SessionResolveTokenOutputSchema`s would reject a stored `'external'` (every IPC call fails), and a `z.object` returns schema strips an unknown `audience` (fail-open). | Derive audience from the conversation row (extra read on every call; the design binds it to ctx). Pass it on the IPC frame (forgeable by the runner). |
| 2026-11-12 | **The orchestrator's warm-session reuse requires the session's spawn mode `(source, audience)` to match the turn's.** An idle mismatch retires the session (reason `turn-mode-changed`). A busy mismatch ends the turn `terminated` / `conversation:busy`. A session this process didn't open routes only a default-mode turn. | The session record is written once at spawn, so an external turn queued into an owner's session would get its identity tools and attended approvals, and a private turn queued into a shared session would be captured as shared. channel-web can't hit the refusal: web conversations are always the default mode, and channel-web already 404s user posts into routine conversations. | Queue into it as routines do today (privilege escalation). Wait for the busy turn to finish, then retire (concurrency complexity; TASK-1094 serializes per thread anyway). |
| 2026-11-12 | **Facts storage: a nullable `audience TEXT` column on `memory_facts_v1` in both engines; NULL means private (legacy).** New rows are stamped `'private'` or `'shared'` explicitly, as the card and design ask. `FactRecord.audience` is echoed. The recall filter accepts only `'shared'` with strict equality, so NULL never matches, and it is pushed into the listing and every SQLite ranked channel plus hydration. Postgres has no `query` path. | Mirrors `ownerUserId` ("never post-filter a widened pool"). Accepting only `'shared'` avoids an `IS NULL OR = 'private'` meaning. No CHECK constraint, matching the session `source` column, so a forward deploy can't wedge. FTS5 and vec0 shadow tables don't change: filtering is by join or base-table lookup. | A boolean `shared` column. Stamping only shared rows (the card says stamp every one). A separate table for shared facts. |
| 2026-11-12 | **@ax/memory gets one read choke point, `recallFacts`, which adds the scope last and THROWS if a shared read returns a row not stamped shared. It also gets one write choke point, `recordFacts`, which stamps from ctx and throws on a person-subject statement in a shared turn.** Every engine read in a shared turn is scoped, including the observer's twin and retraction reads, so a shared turn behaves as if private rows don't exist. | Measured: both engines' `validateRecallInput` silently drop unknown fields, so an engine without support would return private rows to a channel. The backstop turns that into an error. `memoryReadScope` was not reused, because it also scopes the exporter and the forget/correct writes, which must stay unscoped by audience. | Fold audience into `memoryReadScope` (would make the `/memory` export shared-only for every session). Make engines read `ctx.audience` ambiently (the exporter's cached ctx would scope the private export). |
| 2026-11-12 | **The speaker rule is a deterministic post-filter, not a prompt change. In a shared turn, drop or refuse any statement whose subject, trimmed and lowercased, is `user` or starts with `user:`.** The observer counts them (`speakerFacts`, skipped reason `only-speaker-facts`). `memory_note` refuses with a model-readable "nothing saved". | `extraction-prompt.ts` is fingerprint-pinned (`e7466bf4`, "do not reword"). The rule is broad where the speaker rewrite is narrow, because over-dropping loses a fact while under-dropping pins one on the wrong person. Refusing `user:*` also stops a channel planting facts under the owner's `user:<id>` profile key, which would flow shared → private. | Reword the extraction prompt (forbidden). Drop by `sourceRole: 'user'` (would lose the work facts the design keeps). Drop profile slots (`lives_in`…) as "personal" (judgment-laden; would lose `works_at`/`role` work facts). |
| 2026-11-12 | **`conversationOf(external)` returns the conversation (a real thread); routine stays unattributed. An unknown source is unattributed.** | TASK-616 excluded routines because their hidden per-fire conversations inflated the skill-reflection recurrence gate. An external Slack thread is a real conversation the owner can read, and attribution feeds the owner's per-conversation feed. Residual: external threads count toward recurrence. Skill proposals from the reflection routine still pass the propose gate. | Leave external turns unattributed (loses the per-thread feed; a mixed thread would attribute only its attended turns). |
| 2026-11-12 | **A shared session gets no `/memory` file view: memory's `sandbox:memory-mounts` returns zero mounts for a shared owner, and sandbox-k8s now accepts zero (no memory volume).** | Production provisions the export (deploy/GKE.md), and it holds every fact the agent has, which would bypass the recall filter. The design says shared turns are filtered except for instructions and files, and the export is memory. Memory decides, so sandbox-k8s learns nothing about audience. | A second shared-only export tree (YAGNI). Have sandbox-k8s skip the call for shared owners (puts memory policy in the sandbox provider). |
| 2026-11-12 | **Planner extension, which Vinay can veto: external turns can't author skills. The `skill.propose` IPC handler refuses `ctx.source === 'external'` with a fixed sentence. The catalog isn't hidden.** | `classifyProposal` makes an authored, clean-scan skill `active` with no human (`skills/src/propose-gate.ts:34-35`), and `skill_propose` is an always-on broker tool. An outsider in a channel could permanently change the team agent's instructions, the same class of edit design §2 forbids for identity. Routine sessions stay allowed (skill-reflection). Hiding the tool is hygiene, not the boundary (YAGNI). | Force external proposals to `pending` (an owner may rubber-stamp untrusted text). Leave it to TASK-1094 (the stack would ship the hole). |
| 2026-11-12 | **The slice-6 connector skip (go without needs-reconnect connectors instead of failing the turn) applies to external turns too.** | Nobody present in an external turn can sign in again, and the `connector-needs-reconnect` error would show a passer-by the owner's connector state. | Keep it routine-only (one expired connector fails every channel turn). |

| 2026-11-12 | **Residuals accepted and written into the PR security note.** (1) The extractor may name the speaker from the sender label (`alice\|lives_in\|…`), which the subject filter can't see. (2) Slot closure is tenant-wide, so a private statement can close a shared one: the shared turn just stops asserting it and never sees the new value. (3) The `pending` degraded flag counts the whole tenant (1 bit, as owner scope does today). (4) Audience must be constant per conversation, because incremental extraction batches turns under the latest trigger's ctx; TASK-1094 must key conversations so. (5) External turns use the owner's standing approvals and consents, by design §1/§2. (6) Shared-turn notes keep `agent` provenance. (7) A Fix on a shared memory saves the correction as `private`, so shared turns lose that fact (fail-safe; a follow-up if Vinay wants owner fixes to stay shared). | Each would cost a disproportionate change (partitioned closure chains, per-turn audience in the transcript, UX for editing shared knowledge) for a small, documented risk. | Partition closure by audience; store audience per transcript turn; inherit the corrected row's audience. |
