# Decisions — TASK-781 (cap the remaining wire reason/note fields; one surrogate-safe clamp)

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-10-04 | **The shared clamp is `clampCodeUnits(text, max)` in a new `@ax/core/src/clamp.ts`, exported from the core index.** `hold()` and `tool-pre-call` both use it; `clampReason` is gone. | Every host producer (ipc-core handlers, `hold()` in core) already depends on @ax/core, so no new edge and no cross-plugin import. A file with no imports, so it stays cheap. | Put it in ipc-protocol (core's `hold()` cannot import ipc-protocol — wrong direction). Leave `channel-web/src/lib/attachment-name.ts`'s copy alone: the browser bundle does not import the core index, and it truncates by a different rule (keeps an extension). |
| 2026-10-04 | **Named caps live in `@ax/ipc-protocol`, all derived from `HOLD_NOTE_MAX` except the commit label:** `PRE_CALL_REJECT_REASON_MAX`, `WORKSPACE_COMMIT_REJECT_REASON_MAX`, `SKILL_PROPOSE_REASON_MAX` = `HOLD_NOTE_MAX` (2000); `WORKSPACE_COMMIT_REASON_MAX` = 200, shared by the JSON request and the `workspace.commit-bundle` query (which already had a literal `.max(200)`). | Model-facing prose gets one budget (the existing reject-arm comment already said "same number as the hold note on purpose"). The commit label is a short machine label the runner fixes (`turn`, `user-message-wait`); 200 matches what the binary carrier already enforced, so the two carriers cannot disagree. | One generic `WIRE_REASON_MAX` (loses which field a cap belongs to); leave the JSON request uncapped (the two carriers drift). |
| 2026-10-04 | **Clamp at the host handler that builds the wire body, not inside each subscriber/plugin** — `workspace-commit-notify.ts` clamps `pre.reason` and both `parent-mismatch: ${err.message}` reasons via a local `clampRejectReason`; `skill-propose.ts` clamps `out.reason`. The commit LABEL is not clamped (its producer is the runner's constant); the schema cap refuses an oversized one with a 400. | Same pattern `tool-pre-call` set: the handler is the one place every plugin-authored string passes before the response `safeParse`, so a too-long reason degrades to a shorter reason instead of a 500. The `workspace_pre_apply_rejected` log line keeps the full reason (logs are not the wire). | Clamp in each pre-apply subscriber / in @ax/skills (N places, misses the next subscriber). |
| 2026-10-04 | **`decision-resolved` note gets the `HOLD_NOTE_MAX` import but no producer clamp.** | Its only producer (`@ax/decisions` `delivery.ts`) sends a host-authored constant sentence (`decisionApprovedNote()` / `decisionDismissedNote()`), so there is nothing unbounded to clamp. | Clamp anyway (dead code). |
| 2026-10-04 | **Implemented inline rather than one subagent per task.** | Four small, tightly-coupled edits (~6 files); dispatch overhead would exceed the work. Review still goes to `ax-code-reviewer`. | Subagent-per-task (the skill default). |
| 2026-10-04 | **Reviewer nit rejected: "the `share HOLD_NOTE_MAX` test passes against a hard-coded 2000".** Kept as is. | True, and no runtime test can tell `HOLD_NOTE_MAX` from a literal of the same value. The test still guards the real hazard (HOLD_NOTE_MAX and the wire caps drifting apart), and the three caps tests next to it fail on the unfixed code. A source-text grep would be the TASK-392 vacuity class in a different costume. | Source-scanning test for the literal. |
| 2026-10-04 | **Accepted skew: a NEW runner talking to a ROLLED-BACK pre-781 host could reject a >2000-char veto/scan reason** (ipc-client parse → non-retryable INTERNAL). Documented in the PR, no code change. | Same-or-newer hosts always clamp first; old-runner/new-host (the supported direction) is safe because the old schema is looser. Only rollback plus an oversized plugin reason hits it. | Leave response schemas unbounded (loses the wire guard the card asks for). |
