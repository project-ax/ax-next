## 2026-10-30 — TASK-993 meter `/files` toward the storage quota; over quota blocks uploads, not chat (planner)

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-10-30 | **New host-internal service hook `sandbox:user-files-usage { agentId } -> { bytes }`, registered by `@ax/sandbox-k8s` and `@ax/sandbox-subprocess`. Its TS types live in `@ax/sandbox-mount-protocol` beside `sandbox:read-user-files`. `@ax/disk-quota` declares it in `optionalCalls` and reads the answer structurally (no import), the way it reads `workspace:usage`.** Boundary review: alternate impl = a storage backend that reports per-directory usage itself (a quota-capable NFS server, or an object store summing an agent prefix for a bucket-backed `/files`); leaking names = none; subscriber risk = none (service hook, one caller that reads only `bytes`); not an IPC action. | The providers already own "where does this agent's `/files` live" (`sandbox:resolve-mounts` + the host read root), so the meter sits next to `sandbox:read-user-files`. Only `agentId` is needed, so the input is not the full session `owner`. | Owner-shaped input copied from read-user-files (rejected: the providers use only `owner.agentId`); types in `@ax/core` (rejected: the provider-facing user-files family lives in mount-protocol). |
| 2026-10-30 | **The meter counts ALLOCATED bytes (`st_blocks * 512`, falling back to `st_size` only where `blocks` is not a number) of every entry under the agent's root, directories and the root itself included. Symlinks count as themselves and are never followed; hard links are counted once per name.** | Same currency as the TASK-690 workspace meter (allocated bytes) and the blob ledger's 4 KiB units, and capacity is what the Filestore alert protects. Counting directories matches `du`. Hard-link double counting can only over-charge the agent's own owner (errs safe). | Logical sizes of regular files only (the brief's suggestion; rejected: a flood of tiny files or empty directories would cost nothing); inode dedup for hard links (cut: a Set that grows with the tree, for a self-inflicted over-count). |
| 2026-10-30 | **The walk is a new `measureConfinedUserFiles(root, limits?, clock?)` in `@ax/user-files-read`, built on the same `/proc/self/fd` discipline as `readConfinedByWalk`: every child directory is opened relative to the held parent descriptor with `O_RDONLY | O_DIRECTORY | O_NOFOLLOW`, every entry is `lstat`ed through that descriptor, names are read as Buffers (so a non-UTF-8 name is still counted), `.`/`..` are skipped explicitly, and only directories are ever opened. Bounded by `{ maxEntries: 1_000_000, maxDepth: 64, maxMs: 120_000 }`; hitting a bound returns a lower bound with `complete: false`, which the provider logs.** | The tree is written by an untrusted agent on an export that holds every tenant. workspace-git-core's `measureDirBytes` (lstat by path, then readdir by path) has exactly the check-then-use window W3b measured leaking into a sibling subtree, so it cannot be reused here. Service handlers get no abort signal, so the time bound keeps a walk inside the hook's 180 s timeout instead of running on after the call gave up. | Reuse `measureDirBytes` (rejected: follows a folder swapped for a symlink); spawn `du` (rejected: process spawn capability, platform-dependent flags, still follows nothing safely across a swap); entries cap only (rejected: on slow NFS the call would time out and the walk would keep going). |
| 2026-10-30 | **Error contract. Throw (never 0) when: the agent has no user-files mount (`home-unavailable`, TASK-992's code); the k8s host read root is unset (`user-files-usage-unavailable`, no pod); the agent's root exists but cannot be opened or listed; the root is missing AND its parent (the export itself) is missing. Answer 0 when the agent's own directory does not exist yet but the export does. Errors below the root make the reading partial, not an error.** | Refines the card's "a missing/unreadable home reports an error rather than 0". "Missing home" in TASK-992's vocabulary is "no mount", and that is an error. A per-agent directory that does not exist yet is an agent that has never had a session (the providers create it at session open), and `@ax/user-files-read` already treats that case as "wrote nothing" (`VANISHED_ERRNOS`; k8s test "an agent that has never written anything reads as absent, not an error"). Checking the parent keeps a missing export (the TASK-403 failure) from reading as everyone at 0. Errors below the root are the agent's own doing (e.g. `chmod 000` on a folder); failing the whole reading would let an agent switch its meter off with one command. | Literal reading: a missing agent directory is an error (rejected: a warning per never-used agent every sweep, and a row that can never go back to 0); a missing export reads as 0 (rejected: the TASK-403 lie). |
| 2026-10-30 | **No pod-per-call realization of the meter. k8s without `sandbox.filestore.hostReadPath` throws `user-files-usage-unavailable`, and `/files` is not metered there. Documented in values.yaml's `hostReadPath` note, the k8s config doc and the disk-quota degradation text. No chart default change.** | A short-lived pod per turn end and per agent per sweep is far more than a meter is worth. Prod and kind both set `hostReadPath: /user-files` (TASK-899, TASK-992). Turning the read-only host mount on by default is a security widening the chart deliberately leaves to the operator. | `du` in a one-shot pod (rejected: cost, and the pod path has TASK-915's check-then-read gap); make `hostReadPath` required (rejected: a human's security call, not this card's). |
| 2026-10-30 | **New ledger kind `agent-files`, source `agent-files:<agentId>`.
