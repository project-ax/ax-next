# Shared pool architecture constraint

- The user requires shared warm capacity across agents. Per-agent pools are rejected even with caps and idle expiry. Execution-class pools may differ by image, runner, resources, or required sidecars, but agent identity must not be a pool key.
- Recommended proposed storage mechanism is late binding of the existing agent-specific Filestore subtree through a trusted node helper and gVisor force-shared emptyDir propagation. This preserves live POSIX file behavior; copying user files into session scratch and uploading them at session end would change durability and concurrent visibility.
- After adding a trusted node helper, prefer authenticated delivery of a one-use private bootstrap file through that helper over adding a second runner listener and a custom encryption protocol. The runner must remove configuration before model work and preserve the existing child-process environment filtering. The synthetic mechanism is verified; authentication and production lifecycle still require implementation and acceptance.
