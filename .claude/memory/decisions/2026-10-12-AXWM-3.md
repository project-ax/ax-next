# AXWM-3 — W2 shared folders, implementation

Spec: `docs/plans/2026-10-12-w2-shared-folders-design.md`. Plan:
`docs/plans/2026-10-12-w2-shared-folders-impl.md`. Built via `/yolo-ship`
(standalone, no board card).

| Date | Decision | Rationale | Alternatives |
| --- | --- | --- | --- |
| 2026-10-12 | Do NOT auto-merge. W2 ships as a draft PR marked "merges only with W3's first slice", taken to review-clean + CI-green and stopped there. | Spec §4/§9 and Vinay's review-1 finding 6: W2 merges as ONE squash with its first production caller (#978 precedent). The W3 spec does not exist yet, so there is nothing to squash with. yolo-ship's Phase 7 auto-merge is overridden by the spec. | Merging W2 alone behind a named window (rejected in review 1); building W3's slice now without a spec (rejected: it is a product decision). |
| 2026-10-12 | One branch, one draft PR against `main`, the spec's three stack layers as commit groups — not three stacked PRs. | A PR whose base is not `main` gets no `ci.yml` run (measured, TASK-463), so stacked PRs would never prove CI green; the squash is one unit anyway. W3's slice stacks on this branch. | Three stacked PRs (no CI on the upper two). |
| 2026-10-12 | aisdk runner: shared paths are NOT added to `recognizedRoots`. | Spec §3.6 says add them, but `recognizedRoots` is the set of roots under which a top-level `.ax/`/`.claude/`/`CLAUDE.md` is RE-ROOTED onto `/agent` (`governed-paths.ts` `findGovernedSegment`) — adding them would cause exactly the re-rooting §3.6 forbids. The aisdk file tools already accept any absolute path (`builtins.ts` `resolvePath`). A test pins "not re-rooted". Spec corrected in this branch. | Following the spec literally (wrong). |
| 2026-10-12 | Folder ownership lives only in the grants table (`role='owner'`, unique partial index per folder); `shared_folders_v1_folders` has no `owner_agent_id`. | Invariant 4 (one source of truth): the spec had owner in both the folder row and the owner grant. Dropping the column also removes the tombstone problem (a tombstone would otherwise keep a deleted agent's id, tripping the whole-schema cleanup check). | Keep both and null the column on tombstone. |
| 2026-10-12 | `@ax/shared-folders` calls `sandbox:delete-shared-folder` UNDECLARED, guarded by `bus.hasService`. | Declaring it closes a call-graph cycle (shared-folders → delete → locate in resolver → `shared-folders:authorize-mounts`), which bootstrap rejects even for optionalCalls. TASK-809 precedent in `@ax/agents`. | Declaring resolver→authorize as undeclared instead (spec says the resolver lists it in optionalCalls). |
| 2026-10-12 | "Both presets" = k8s + memory (memory wraps `createK8sPlugins`). The dev CLI preset does not load `@ax/shared-folders`. | The plugin needs `database:get-instance`, which only `@ax/database-postgres` provides; the CLI runs on sqlite with no `@ax/agents`. Without the plugin the localdir resolver emits no shared mounts (spec §6 "resolvers emit nothing without the plugin"). | A sqlite store for the CLI (YAGNI). |
| 2026-10-12 | `AX_SHARED_FOLDERS` is NOT added to the warm-pool bootstrap env allowlist. | Pool sessions refuse shared folders (spec §3.8), so the variable never reaches a pooled runner; widening the allowlist would grant reach nothing uses (invariant 5). | Allowlisting it now. |
| 2026-10-12 | `isValidSharedFolderId` + its zod schema live in `@ax/sandbox-protocol`. | Plugins may import `@ax/sandbox-protocol` at runtime (eslint allowlist); `@ax/sandbox-mount-protocol` is type-only for them. One validator for resolvers, providers, the orchestrator schema and the plugin. | Per-package copies like `agent-id.ts`. |
| 2026-10-12 | Until W3, the orchestrator gets `sharedFolderIds` through a plugin option `sharedFolderIdsFor(ctx, {agentId, conversationId})`, default none. | Something must exercise the record/reap path in tests; W3's slice replaces the option's source with the conversation's project. The stack never merges without it. | No seam (orchestrator path untestable until W3). |
| 2026-10-12 | Subprocess provider stamps HOST paths in `AX_SHARED_FOLDERS`; k8s stamps `/shared/<id>`. | Subprocess has no mount namespace — the runner sees host paths, the same as `AX_USERFILES_ROOT` there. | Symlinking `/shared` on the dev host (needs root). |
