# Decisions — TASK-1100 (MCP directory: @ax/connector-directory, registry sync, search hook, admin route)

Plan: `docs/plans/2026-11-09-task-1100-connector-directory-plan.md`. Design: `docs/plans/2026-11-09-mcp-directory-connectors-design.md`. Planner rows, 2026-11-09. Registry facts below were MEASURED against the live registry and its OpenAPI on 2026-11-09, not recalled.

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-11-09 | **List endpoint is `GET /v0.1/servers?limit=100&version=latest` (+ `updated_since`, `cursor`), not `/v0/servers`.** One row per server name = its latest version. | The aggregator guide (registry `main`, 2026-11-09) names `/v0.1/servers` and says: keep the same `updated_since` while following every `nextCursor`, save a new checkpoint only after all pages applied, keep a small overlap, incremental results include deleted servers. The live OpenAPI confirms `include_deleted` is "always true when updated_since is provided" and results are ordered by name, then version. `version=latest` returned 0 `isLatest:false` rows in 1,800 sampled. | `/v0/servers` (still served, same shape; the guide documents v0.1). No `version` filter (rejected: every superseded version comes back as its own row). |
| 2026-11-09 | **Checkpoint = OUR clock's sync start time, written only after the last page applied; the next sync asks for `updated_since = checkpoint - 10 min`.** | The guide's recipe. Remote timestamps are untrusted: a hostile or broken subregistry sending a far-future `updatedAt` would freeze every later incremental sync if the checkpoint came from response data. Re-fetching 10 minutes of overlap is idempotent (upsert by name). | Max `updatedAt` seen (rejected: lets response data set our checkpoint). No overlap (rejected: commit-order and clock skew lose updates). |
| 2026-11-09 | **Row cap is 100,000, not the card's "e.g. 20,000".** At the cap, NEW names are skipped (updates and deletes still apply) and one warn line is logged per sync. | Measured: the first 600 pages (60,000 latest entries) held 40,135 entries with a streamable-http/sse remote, and the list was not finished (`us.*`). Because pages come in NAME order, a 20,000 cap would have stopped the first full sync at `io.github.E...`, silently dropping every later namespace (`net.*`, `org.*`, the rest of `io.github.*`). 100,000 is ~2.5x today's remote set; realistic rows are well under 1 KB. | 20,000 (rejected, measured). No cap (rejected: the design's DB-bloat defense). Prefer domain rows at the cap (deferred: needs real pressure first). |
| 2026-11-09 | **Per-request and per-run bounds: limit=100 (registry max), 4 MiB decoded body per page via `capResponseBody` (`packages/core/src/response-cap.ts`), 30 s per request, 30 min per run, at most 2,000 pages, a repeated cursor fails the run.** | Largest measured page 300,945 bytes (typical ~78 KB); 600 pages took 170 s and the crawl was not yet finished. The caps only exist to stop a hostile or broken registry, so they sit well above measured values. Copies the shape of `fetchAnthropicModels` in `packages/llm-anthropic/src/models-available.ts` (paged GET, page cap, never throws) but uses the shared body cap instead of a hand-written one. | mcp-client's 2 MiB / 10-page caps (rejected: sized for a tool list, not a 60k-entry crawl). |
| 2026-11-09 | **Egress capability = one operator-configured origin: `https:` only, no userinfo/query/fragment, validated at construction when enabled (`PluginError` `invalid-config`, boot fails loudly). Redirects are refused (`redirect: 'manual'`, any 3xx is a `redirect` failure). Page URLs are built with `URLSearchParams` so a hostile `nextCursor` is only ever a query value. No per-IP SSRF vetting.** | https protects listing integrity: a MITM on http could forge "verified domain" listings that admins trust. Refusing redirects pins the origin. The URL is operator config, not user input, and a self-hoster may legitimately point it at an in-cluster subregistry, so private-IP refusal (mcp-client's guard) would break the documented alternate impl and add undici/ipaddr.js. The host NetworkPolicy already allows any destination on 443 (`deploy/charts/ax-next/templates/networkpolicies/agent-runtime-network.yaml`); other ports are dropped in prod, noted in values.yaml. | Allow http (rejected: integrity). `redirect: 'error'` (rejected: surfaces as a generic TypeError, harder to classify). Copy mcp-client safe-fetch (rejected: overkill for operator config, blocks in-cluster subregistries). |
| 2026-11-09 | **Registry JSON is parsed with hand-written, bounded type checks per entry (at most 16 remotes and 32 headers looked at per entry), not zod.** Zod stays for OUR hook contract only. | `packages/core/src/response-cap.ts` records that zod over a large junk body can build hundreds of MB of issues; per-entry hand checks cost nothing on junk and let one malformed entry be skipped without failing the page (mcp-client `normalizeTools` precedent). | Zod `safeParse` per entry (workable, but a hostile entry with 100k nested junk headers still builds a large issue list). |
| 2026-11-09 | **Row semantics: every latest entry either upserts its row or DELETES any stored row with that name.** Delete when: `status: 'deleted'`, no usable http remote (package-only, stdio, templated/non-https/oversized URL), or a required field fails (version empty/over 255/has surface-rewriting chars). Skip (touch nothing) when the entry has no valid name or says `isLatest: false`. | An incremental sync must also remove a server whose NEWEST version dropped its remote; "don't insert" alone would keep the old row forever. A name is the only key, so an entry without one can't touch anything. A non-latest version says nothing about the latest. | Only skip on insert (rejected: stale rows survive). Delete on `isLatest:false` (rejected: would delete live servers). |
| 2026-11-09 | **`auth`: `'key'` when the chosen remote declares exactly one distinct (case-insensitive) REQUIRED credential header, i.e. `isRequired: true` AND (`isSecret: true` OR the name is `Authorization`); `keyHeader` = that name only if it passes the same rule as `headerName` in `packages/connectors/src/types.ts` (RFC 7230 token characters, at most 64). Two or more distinct required credential headers: `'key'` with no `keyHeader`. Otherwise `'none'`. `'signin'` is NEVER derived from the official registry.** | The live OpenAPI's `Transport` is `{type, url, headers, variables}`: there is no OAuth/authorization declaration, so the card's "signin when the remote declares OAuth" has nothing to read. Measured: Notion, Linear, Atlassian, Stripe, Figma and Canva (all OAuth) declare NO headers, and so do keyless servers; 119 of 272 sampled headers are OPTIONAL secret keys whose descriptions mostly say "omit to sign in with OAuth". `'none'` therefore means "the listing declares no required key", never "no sign-in": the remote connector form discovers OAuth from the address itself (`discoverOAuthHosts` in `packages/channel-web/src/components/settings/RemoteMcpConnectorForm.tsx`), so the label never changes what gets saved. `'signin'` stays in the contract (design + card) for a source that can state it, such as the Boundary review's curated list. Multiple required headers can't be one prefilled key row, so we don't pretend. Reserved header names are still refused at save by the connectors refine (no mirror here: one source of truth). | `'signin'` for every no-key listing (rejected: claims sign-in for keyless servers, the "never claim on a guess" rule Decision 5 uses for proof). Parse descriptions for "OAuth" (rejected: untrusted free text). Probe each server's well-known metadata (rejected: egress to tens of thousands of arbitrary hosts from the host). Change the enum (rejected: the card and TASK-1101 plan against three values). |
| 2026-11-09 | **`publisherProof`: a namespace starting `io.github.` (case-insensitive) with one GitHub login after it (`[A-Za-z0-9-]{1,39}`) is `'account'`, publisher = the login. Else, a namespace that is already lowercase, has 2 or more LDH labels and an alphabetic or `xn--` TLD is `'domain'`, publisher = the labels reversed. Everything else is `'account'`, publisher = the namespace as written.** `io.github` is checked first. | Matches the registry's auth endpoints (dns, http give reverse-DNS; github-at, github-oidc give `io.github.<login>`). Checked first because `github.io` would otherwise read as a domain. Uppercase non-github namespaces never upgrade (only `io.github.*` had uppercase in the sample). `ac.inference.sh` becomes `sh.inference.ac` (INFERRED: consistent with a DNS proof of `inference.ac`, which the registry lets cover sub-namespaces). | Lowercase-then-classify (rejected: upgrades an odd namespace on a guess). Registrable-domain via a public-suffix list (rejected: new dependency, nothing needs it). |
| 2026-11-09 | **Ranking: domain tier first; then match rank 0 = the publisher has the query as a whole dot-label, 1 = title equals, 2 = title starts with, 3 = title contains, 4 = id or publisher contains, 5 = description only; then lower(title), then id. Match is `strpos(lower(col), lower($q))` in parameterized SQL.** Title falls back to the id when the listing has none. | Measured: Notion's, Stripe's and PayPal's official listings have NO title, so a third party's domain-proven listing titled "Notion" would outrank Notion's own under title-only ranking; rank 0 puts `notion.com` first for "notion" while `notion-tasks.io` never matches it. `strpos` is a literal substring, so `%`, `_` and backslash need no escaping (no LIKE-escape helper exists in the repo). Seq scan over at most 100k rows is fine for an admin-only, typed search. | ILIKE with an escape helper (rejected: more surface, same result). A generated `search_text` column or pg_trgm index (rejected: YAGNI at this size; pg_trgm needs CREATE EXTENSION). |
| 2026-11-09 | **Pagination: our cursor = base64url of `{"o": offset}` (offset 0..100,000), limit default 20, clamped to 1..50; `nextCursor` only when a further row exists (fetch limit+1).** A bad cursor is `invalid-payload` with fixed text. | The card requires our own opaque cursor; offset is enough for an admin "show more" over a ranked list that only changes hourly. | Keyset over (tier, rank, title, id) (rejected: four sort keys, one being query-dependent). |
| 2026-11-09 | **Hook output adds `enabled: boolean`; the route passes the hook's body through field-by-field and synthesizes `{enabled:false, entries:[], syncedAt:null, stale:false, verifiedOnly:false}` only when the service is absent.** | The plugin is the one source of truth for whether it is on (invariant 4). Without the field the route would answer `enabled: true` for a directory the operator turned off. One wire shape in every case. | Route hardcodes `enabled: true` whenever the service exists (rejected: wrong when configured off). |
| 2026-11-09 | **Never synced = no entries, whatever rows exist; `stale` = last attempt failed AND a successful sync exists.** | A first sync that fails on page 7 leaves a partial copy; serving it under "List updated: never" contradicts Decision 9's empty state. | Serve partial rows (rejected: dishonest freshness). |
| 2026-11-09 | **Source change: the sync-state row stores the registry base URL; a different configured URL clears every mirrored row and the state in one transaction before a full sync.** | Pointing the plugin at a subregistry is the named alternate impl; without this the old source's rows and checkpoint would leak into the new one (its incremental sync would miss everything older than the old checkpoint). | Keep rows and reconcile after a full crawl (rejected: needs per-row seen-tracking; YAGNI). |
| 2026-11-09 | **No advisory lock: an in-process "join the sync already running" guard only.** | The chart pins the host to one replica (`ax-next.validateHostReplicas`) with `strategy: Recreate` (`deploy/charts/ax-next/templates/host/deployment.yaml`), so two hosts never overlap. blob-gc's lock is "for efficiency, not for safety" and would pin a pooled connection for a multi-minute crawl. | Copy `withSweepLock` from `packages/blob-gc/src/plugin.ts`'s store (rejected: no second replica exists). |
| 2026-11-09 | **Registry text is cleaned at sync with the `@ax/core` helpers, in THIS order: `replaceSurfaceRewriters` from `@ax/core/surface-text` first (controls including U+0000, bidi and zero-width become a space; the single-owner guard forbids a local copy; Postgres TEXT refuses U+0000, so one bad listing would otherwise fail its page on every sync), then `toWellFormedText` (lone surrogates), whitespace collapsed, then `clampCodeUnits` (title 120, description 500). The reverse order leaves U+FFFD where a NUL was. A version is never rewritten (TASK-1102 compares it): one with a surface-rewriting or non-well-formed character drops the listing instead. URLs: rejected if the raw string has whitespace, surface-rewriting chars, `{` or `}` (templated: 15 of 1,519 sampled remotes, and Node's URL parser ACCEPTS `{` in a host), userinfo, a non-https scheme, or an `href` over 2,048; stored as the WHATWG `href` (an IDN homograph shows as punycode).** | Display-safe, store-safe, and a hostile listing can only drop itself. | Strip only C0/C1 (rejected: lets Trojan-Source bidi through). Keep the raw URL string (rejected: the parser silently drops a newline inside a host, so raw and connected host could differ). Reject IP-literal hosts (rejected: connect-time guards in mcp-oauth and mcp-client own SSRF, and an in-cluster subregistry may list internal hosts). |
| 2026-11-09 | **Disabled = manifest `calls: []`, no database, no timers, no fetch; the hook answers the fixed off body.** The registry URL is validated only when enabled. | Lets the off path run with no Postgres, so the preset canaries and every hand-built config boot it for free; a disabled directory never touches its URL. | Always migrate (rejected: a database dependency for a feature that is off). |
| 2026-11-09 | **Env default is OFF; the chart turns it ON.** `loadK8sConfigFromEnv` follows the preset's convention (`(env.X ?? '').toLowerCase() === 'true'`), so an unset `AX_CONNECTOR_DIRECTORY_ENABLED` is off; the chart stamps `"true"` from `connectorDirectory.enabled: true` (default). A hand-built `K8sPresetConfig` without `connectorDirectory` builds the plugin disabled. The plugin factory's own default stays `enabled: true` (card). | This is the first host plugin with a TIMER-driven outbound fetch. 20+ preset tests boot `createK8sPlugins`/`createMemoryPlugins` from fixture env or hand-built configs (prod-bootstrap boots everything on real Postgres for minutes); env-unset-on would make each of them call the real registry 10 s after boot. Off-unless-said keeps every existing test network-free with zero fixture edits, and a local `serve` without the chart makes no surprise egress. | Env unset = on (rejected: real network from the test suite). Push the plugin only when enabled, like credentials-admin (rejected: the card wants the plugin configured from env and its off path reachable; the route's "service absent" branch would then be the only off path). |
| 2026-11-09 | **Wiring: pushed unconditionally right before `createConnectorsPlugin` in `presets/k8s/src/index.ts` (memory preset inherits it; the CLI loads no connectors). Added to `PLUGINS_TO_DROP` in acceptance + multi-tenant-acceptance (consistent with `@ax/connectors`), to the exact plugin list in preset.test.ts, and to prod-bootstrap's `REQUIRED_PROD_PLUGINS`. NOT added to usage-limits / disk-quota drop sets: it needs no http and, disabled, no database.** `connectors:directory-search` goes in @ax/connectors' `optionalCalls` (no cycle: the directory calls nothing of connectors). | Card + measured preset layout. `optionalCalls` documents the soft edge at the manifest, like the tool-policy routes. | Conditional push (see previous row). Undeclared hasService call (rejected: only justified when declaring would close a cycle, as for `connectors:describe-tools`). |
| 2026-11-09 | **The route `GET /admin/connectors/directory` is adminOnly, validates `q` (at most 200 code units) and `cursor` (`^[A-Za-z0-9_-]{1,64}$`) before the hook, uses a fixed page size of 20, and calls the hook even for an empty `q`** (the UI shows "List updated N min ago" before anyone types, Decision 6). **`directory` joins `RESERVED_CONNECTOR_IDS` in `packages/connectors/src/store.ts` AND its mirror in `packages/tool-connector-propose/src/plugin.ts`.** | The card's "register it before `:id`" premise is false: `packages/http-server/src/router.ts` `match()` tries exact paths first regardless of registration order. The real consequence is the `authored` one: a GET exact path shadows `GET /admin/connectors/:id` for a connector with that id, so no NEW connector may take it. | Rely on registration order (rejected: order is irrelevant). A different path shape such as `/admin/connector-directory` (rejected: the card and design fix the path). |
| 2026-11-09 | **Tests never reach the network: every fetch goes through an injected `fetchImpl` (the repo's convention: llm-anthropic, llm-openrouter, embeddings). Pure modules (normalizer, registry client, contract, disabled plugin) are Docker-free; store/sync/search/plugin use one `new PostgreSqlContainer('postgres:16-alpine')` per file (host-grants / blob-gc pattern). The preset composition test uses the KEEP-list pattern of `presets/k8s/src/__tests__/blob-gc-report-acceptance.test.ts` and calls the captured route handler.** | CI pre-pull and the out-of-process timeout guard both key on that literal image; captured handlers prove route -> hook -> table without a listener. | A real local HTTP fake registry (rejected: https-only origin; fetchImpl is the established seam). |
| 2026-11-09 | **A full crawl (no checkpoint, or one our clock has gone back past) first empties the mirror and resets the state to never synced, in one transaction (`store.reset`): the same reset a source change does.** Whole-branch review finding. | The full list (no `updated_since`) leaves deleted servers out; only an `updated_since` list names them. Rows already stored when a full crawl starts (a first crawl that failed part way keeps its pages, unserved; or the clock-went-back branch, served) were never re-checked, and every later incremental asks from after the deletion, so a server the registry deleted in between was served forever. Nothing correct is lost: the never-synced rows were not served, every server still listed comes back in the crawl, and the clock-back case is treated like a source change (empty until the crawl completes). | `include_deleted=true` on a full crawl (rejected in review: two mechanisms for one rule, and it still trusts every removal to show up as a `deleted` status). Mark and sweep, deleting what a complete crawl did not see (rejected: per-row seen-tracking, the YAGNI the source-change row already turned down). |
