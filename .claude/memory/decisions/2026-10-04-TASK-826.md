# TASK-826 — aisdk runner connector (HTTP MCP) support (2026-10-04)

- Connector `.mcp.json` loader moved claude-sdk → `@ax/agent-runner-core` (`loadProjectedMcpServers`, `CONNECTOR_TOOL_NAMESPACE_RE`); output is runner-neutral `{url, headers?, bundle}`; claude-sdk keeps a thin `McpServerConfig` adapter under the old name (its `main.ts` + real-SDK e2e unchanged).
- aisdk connects one `@modelcontextprotocol/sdk@1.30.0` Client per connector at session start (eager, parallel, 10s bound each), through `createProxyFetch` — the SAME dispatcher as the model. Closed in a `finally` around the session-scoped turn loop (`run(ctx)` is per SESSION, not per turn).
- Names: record key `mcp__<ns>__<tool>` (transcript/label parity — channel-web's `connectorToolLabel` keys on the name alone, no runner work needed), `wrapWithPolicy` name `mcp.<ns>.<tool>` (policy parity). Over-long/illegal names are SKIPPED, never mangled.
- TASK-736 F4 is now live and fixed: denied `mcp.<ns>.<tool>` are not offered on aisdk.
- `isError` MCP results throw (failed tool call), matching host-tools. Thrown transport errors are clipped to 4 KB; upstream text in log lines is JSON-escaped + truncated (TASK-783 code-only-logs rule).
- Session tool budget: `MAX_TOOLS_PER_SESSION = 128` (OpenAI-compatible function limit) minus non-connector tools; whole connectors past it are dropped in SORTED-namespace order (deterministic, not settle order) and their Skill note fires. Without it, an aisdk agent on an OpenAI-family model with a big connector fails every turn — and the host projects connectors regardless of runner, so existing aisdk agents with connectors start loading them on deploy.
- Gotcha: MCP SDK `resetTimeoutOnProgress` is INERT unless `onprogress` is passed (no progressToken is sent otherwise). Pass `onprogress: () => {}` + a `maxTotalTimeout` ceiling.
- Gotcha: the MCP SDK's `listTools` zod-validates every tool (`inputSchema.type` literal `'object'`) — one malformed tool fails the WHOLE list, so the connector is dropped, not just that tool.
- Gotcha: the SDK puts whole HTTP response bodies into error messages (`Error POSTing to endpoint: ${text}`) — never forward/log `err.message` from it unbounded.
- TASK-761's `runnerLoadsConnectors` allow-list now includes `'aisdk'`.
- Skill tool: `MCP_UNAVAILABLE_NOTE` → `MCP_NOT_LOADED_NOTE`, shown only for a bundle whose servers didn't connect (or were dropped by the budget).
- Known gap (follow-up): no re-initialize after the server drops the MCP session (404) — that connector stays broken for the warm session.
