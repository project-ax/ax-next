# Decisions — CIMDNAME-1 (OAuth client name follows branding)

- Third-party consent screens showed "AX" while prod branding is "Canopy AI". `@ax/branding` now registers `branding:get` → `{ name: string | null }`; `@ax/mcp-oauth` lists it in `optionalCalls` and uses it for `client_name` in the CIMD document AND the DCR registration body (DCR previously sent no name at all). Fallback "AX" when branding is absent, unset, or the read throws — a branding failure must never block a sign-in.
- Rejected: mcp-oauth reading the `settings:branding` storage key directly (two plugins on one row — invariant 4) or importing `@ax/branding` (invariant 2).
- The name is admin-entered free text shown on someone else's consent page: `oauthClientName` strips \p{Cc}/\p{Cf}/U+2028/2029 (bidi overrides could reorder consent text), collapses whitespace, caps at 64 code points. Known cost: ZWJ emoji sequences split.
- CIMD doc sends `Cache-Control: public, max-age=3600` so renames propagate. Existing DCR registrations keep their old name until AX registers again — accepted, no migration.
- Gotcha: a ` ` written through a file-writing tool lands as the literal LINE SEPARATOR character, which terminates a JS regex literal (TS1161 "Unterminated regular expression literal"). Write the escape sequence as text.
