# Decisions — SIGNINS-4 (agent-owned connector sign-ins, slice 2c: agent-proposed connectors go to admins)

Shard id `SIGNINS-4` covers slice 2c. Spec: `docs/plans/2026-10-07-agent-owned-connector-sign-ins-design.md`; plan: `docs/plans/2026-10-07-agent-owned-sign-ins-slice2c-plan.md`.

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-10-07 | **The in-chat connector approval card was removed, not made informational.** The `connector_propose` reply tells the model "Sent to your workspace admin…", and the model tells the person. | Cards replay on reconnect and re-fire every turn, so an informational card would need a new lifecycle for no gain. An old persisted card in the chunk buffer must still not crash or render a dead Connect button. | Keep the card as a read-only "request sent" notice (rejected: new lifecycle, no gain). |
| 2026-10-07 | **Approval is creating a SHARED connector, and that clears every request with its id** (`connectors:upsert` with `created && visibility === 'shared'` → `clearAllById`, best-effort/logged). No grant, no approved-caps rows, no auto-attach. Dismiss (`DELETE /admin/connectors/authored/:id`) clears without creating. | One source of truth: the live connector is the approval. People add it to their agent from Connectors. | An approve endpoint that promotes a draft (rejected: that was the confused-deputy path the slice removes). |
| 2026-10-07 | **The `connectors.propose` hold stays; the `connector_propose` freshness digest was dropped.** | The hold throttles agent spam into the admin queue (each request needs a human-approved held call). A replayed call now only writes a draft and can't replace a live connector, so the freshness check guards nothing. | Drop the hold too (rejected: unthrottled queue). |
| 2026-10-07 | **Skills cap-migration no longer creates connectors, and `skills:approved-caps-set` is deleted.** Cap-migration still strips the legacy capabilities block so manifests parse; approved-caps rows are legacy data that still display and revoke. | No non-admin path may create a connector. Owner: "I don't care if existing skills are broken." | Migrate legacy caps into admin-owned connectors (rejected: creates reach no admin chose). |
| 2026-10-07 | **`POST /admin/connectors` is create-only** (`createOnly` hook flag, set by the route, stripped from bodies; PATCH re-asserts `createOnly: false`). The store write is atomic: `ON CONFLICT … DO UPDATE … WHERE deleted_at IS NOT NULL`, so it may resurrect a tombstone but a live row → no row back → `connector-id-taken` (409). | Against a confused deputy: "Set it up" from an agent's request must never overwrite a connector the admin already has with agent-chosen reach, including a live row that appears between the pre-read and the write. keyMode immutability still holds: a live row can't be reached by a create, and a tombstone may come back in either mode (TASK-827). | Rely on the route pre-read alone (rejected: race). |
| 2026-10-07 | **"Set it up" carries only what the editor shows, with an Alert listing the rest; Sharing is fixed to Shared.** | Hidden carryover would smuggle reach the admin never saw (packages, header names, client-secret refs); silently narrowing would hide that the request asked for more. | Carry the whole proposal (rejected: hidden reach); drop extras silently (rejected: silent narrowing). |
| 2026-10-07 | **Clears, dedup and queue hiding are shared-only.** Only a SHARED create clears requests; `install-authored` answers `active` only for a live SHARED id; the queue hides an id only when it's live as SHARED. | Cross-tenant: a private connector resolves nobody else's request, and answering `active` for someone's private id would leak that it exists. | Any-visibility match (rejected: cross-tenant clear and existence leak). |
| 2026-10-07 | **No non-admin path creates a connector.** Admin routes create; agents file requests; skills cap-migration and the old card approve path are gone. | Invariant #5 — the only way reach appears is an admin choosing it. | — |
| 2026-10-07 | **Pending drafts that already exist surface in the queue with their age** ("Requested 2 weeks ago", `relativeDay(updatedAt)`); no boot clear. Old `active` rows are inert. One malformed draft is skipped and logged (`connectors_authored_pending_skipped_row`, owner + id), not allowed to fail the whole queue; the SPA shows an Alert with Retry on any failure but a 404. | Admins can Dismiss stale ones; a boot clear would silently drop real requests. A queue that fails for every admin because of one user's row, then renders as "nobody asked", is the worst failure mode. | Boot-time clear of pre-2c drafts (rejected by controller ruling). |
| 2026-10-07 | **The reserved id `authored` is refused on create paths only** (`assertConnectorIdCreatable`: upsert with no live row, install-authored), not in `validateConnectorId`. `connector_propose` mirrors it with a fixed model message. | The admin queue route `/admin/connectors/authored` would shadow a connector with that id, but a pre-existing `authored` connector must stay readable, editable, deletable and answer `connectors:live-ids`. | Reserve in the shared validator (rejected: breaks reads/deletes of an existing one). |
