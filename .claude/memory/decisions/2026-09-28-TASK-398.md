# Decisions — TASK-398 (concurrent testcontainer starts starve)

| Date | Decision | Rationale | Alternatives |
| --- | --- | --- | --- |
| 2026-09-28 | Cap concurrent container STARTS host-wide with symlink slots in `$TMPDIR/ax-testcontainer-start-slots`. The cap lives in test-harness `startTestContainer`, and a slot is held only while `start()` runs. | Every container start goes through that one wrapper (115 call sites). A local full gate runs 4 packages at once, each with a fork per core. Baseline measured on an idle host: 27 postgres containers at peak, 23 in `health: starting` together. An in-process semaphore cannot bound separate vitest forks. A symlink is created atomically with its holder token (`pid:nonce`), so a slot is never half-written. | Lower `fileParallelism` per package does not bound across packages or builders. A shared postgres container changes 100+ suites' isolation. A longer timeout feeds the starvation. Reaping only treats the residue. |
| 2026-09-28 | Queue wait is bounded at 40s and named. Waiting is announced through `warn`, and giving up throws "…never started: this is queueing on a loaded host, not a container failure". | Hook budgets in the repo are 60s or 120s, and the harness cannot see the caller's budget. A bound below the smallest one means the named error beats vitest's "Hook timed out". It also means a start that gave up never runs after its hook is gone, which is one way an orphan is made. | Excluding the wait from the hook budget is impossible from inside the hook. A log line alone would still leave a late start able to orphan a container. |
| 2026-09-28 | Stale slots are reclaimed when the holder pid is dead (`kill(pid,0)` ESRCH) or the slot is older than 10 min. A `<slot>.reclaim` marker serializes reclaimers, and the slot is re-read before unlinking. | A killed run must not wedge later runs. Without the marker, two reclaimers of the same stale slot could delete the fresh slot one of them just took. | Plain mkdir+pidfile has a window where the pid is unwritten. flock is not available from Node without a native dependency. |
| 2026-09-28 | Default is 4 slots, set with `AX_TESTCONTAINER_START_SLOTS` (1–64). The wait is set with `AX_TESTCONTAINER_START_SLOT_WAIT_MS`, and the directory with `AX_TESTCONTAINER_START_SLOT_DIR` (tests only). | The measured before/after numbers are in the PR body. | — |
| 2026-09-29 | Review (ax-code-reviewer, APPROVE at 6396680) findings 2-4 accepted as documented windows, not fixed: a never-settling start holds its slot until the fork exits or 10 min; a cross-user shared slot dir surfaces a raw EACCES (loud, not named); >10-min live holder can over-admit by one. Finding 1 fixed as a comment: the 40s wait is not a hard guarantee under 60s hooks because the preflight's 45s ceiling shares the budget. | All are loud or self-healing and in line with the "loud failure, 4 slots" ruling; none reachable under current hook budgets except via a pathological daemon. | Shrinking the wait to fit 60s-45s=15s would turn ordinary queueing into failures. |
