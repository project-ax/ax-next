## 2026-11-05 — VISUALS-1 chat visuals (planner)

Plan: `docs/plans/2026-11-05-chat-visuals-plan.md`. Spec: `docs/plans/2026-11-05-chat-visuals-design.md` (approved by Vinay as-is).

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-11-05 | **Route A needs no new artifact-row, hook or IPC field.** The "visual" marker is the tool name (`show_visual`, or `mcp__ax-sandbox-tools__show_visual` from the claude-sdk runner) plus its result shape `{ artifactId, title, summary }`. Title and summary live only in that tool result. The artifact row is the existing shape: `mediaType: 'text/html'`, `displayName: 'visual.html'`, re-publish key `path: 'visuals/<sha256>.html'`. | Nothing reads a row-level marker: `buildThread` and the live path read the tool result, and the download route serves by id. A row copy of title and summary would be a second source of truth (invariant 4) with no reader (YAGNI). `artifact.publish`'s `path` is already documented as an opaque re-publish key that never leaves `@ax/attachments`. | Add `kind/title/summary` to `ArtifactPublishRequestSchema`, `artifacts:publish-blob`, the store and a migration (boundary review, a migration and a second copy, all for no reader). |
| 2026-11-05 | **The `show_visual` descriptor ships from `@ax/tool-artifact-publish`.** The one plugin registers both descriptors, and the executor sits beside the artifact executor in `@ax/agent-runner-core`. | It is an artifact publication, and the plugin is already loaded by both presets (`cli/src/main.ts:329`, `presets/k8s/src/index.ts:1306`) and booted by the Phase 3 canary. That closes the invariant 3 reachability with no new package, tsconfig ref, preset edit or image change. | A new `@ax/tool-show-visual` package (package, tsconfig, presets, CLI and runner-image wiring for no isolation gain). |
| 2026-11-05 | **The parent page gets a one-directive CSP, `frame-src 'none'`, as a meta tag in `packages/channel-web/index.html`.** | The design's "no network" box has a hole: the frame's own CSP cannot stop the frame from navigating itself (`location.href = 'https://x/?data'`, `<meta http-equiv=refresh>`, a link click). Only the embedder's `frame-src` can, and the sandbox flags cannot. The app embeds no other iframes (grep). srcdoc does not go through fetch, so per spec it is not subject to `frame-src`. The hostile browser test's positive control proves this in Chromium. | Accept the leak. Reset the frame on a second `load` event (detection after the request already left). A separate sandbox origin (infra). |
| 2026-11-05 | **`GET /api/files` serves active-content media types (`text/html`, `application/xhtml+xml`, `image/svg+xml`, `text/xml`, `application/xml`) as `application/octet-stream`.** It keeps `attachment` and `nosniff`. | Visuals are the first `text/html` rows ever: the extension map in `artifact-publish-executor.ts` has no `.html`, and uploads refuse svg/html. The precedent (decisions.md:2787) is never to serve agent-authored text/html from our origin. The frame reads the bytes with `fetch().text()`, so the header costs nothing. | Rely on `content-disposition: attachment` alone. |
| 2026-11-05 | **The visual guidance goes in the tool description, not `communicationNote()`.** This covers when to use it, the hsl(var()) colors, the preloaded Chart.js, no network, the 100 KB limit and "say the takeaway in your reply text". | The text exists only when the tool does, so a denied or absent tool leaves no dangling prompt. The claude-sdk sandbox bridge drops property descriptions (`sandbox-mcp-server.ts:33-48` `shapeFromInputSchema` → `z.unknown()`), so everything must be in the top-level description. | A system-prompt section (dangling when the tool is unavailable). |
| 2026-11-05 | **The activity phrase is the descriptor's `activityPhrase: 'Making a visual'`.** There is no edit to `activity-phrase-map.ts`. | That map is built from catalog descriptors (`buildActivityPhraseMap`). The design's "add an entry to activity-phrase-map.ts" was stale (fixed in plan Task 15). `stepDetail` already picks `title` (DETAIL_KEYS), so the step reads "Making a visual: <title>". | — |
| 2026-11-05 | **Libraries: `chart.js` 4.5.1 and `html-to-image` 1.11.13, exact pins, as channel-web devDependencies.** They are imported with Vite `?raw` into the srcdoc only, so they never execute in the app's realm. chart.js's `exports` map hides `dist/chart.umd.min.js`, so a Vite alias resolves it through `createRequire`. | Both are MIT, with no install scripts. 4.6.1 was published 2026-10-22 (two weeks old) and 4.6.0 is absent from the registry time list, so we take the year-old 4.5.1. Raw-string vendoring means a compromised library still runs only inside the opaque-origin box. | A CDN (forbidden). Copying UMD files into src (no lockfile integrity). modern-screenshot as a fallback if html-to-image fails under an opaque origin. |
| 2026-11-05 | **Fonts: a Latin subset of the app's own Inter 4.001 TTFs at 400, 500 and 600.** WOFF via fonttools `pyftsubset --layout-features='*'` keeps `cv11` and `tnum`. The files are committed and inlined as `data:` URIs with Vite `?inline`. Mono is the chat's system stack (`.ax-md code`: `ui-monospace, SFMono-Regular, "SF Mono", Menlo, monospace`), so there is nothing to inline. | Measured: the 400 subset is 30,820 bytes, against 325 KB for the full TTF (about 1.3 MB base64 per frame for three weights). WOFF needs only zlib, while WOFF2 needs brotli tooling. Same files, so the metrics match the app exactly. | Full TTFs. @fontsource/inter (a different Inter build). WOFF2. |
| 2026-11-05 | **The summary is shown only in the failure state, and as the iframe's accessible description (sr-only, `aria-describedby`).** The agent's reply text carries the takeaway. | Titles and memory read reply text, not tool input (verified: `conversation-titles/src/prompt.ts:71-73`, `memory/src/transcript.ts:134`). A visible caption would repeat the reply text. | A visible caption under every visual. |
| 2026-11-05 | **Live path.** `streamReply` tracks show_visual call ids and forwards a parsed `ThreadVisual` through a new `onVisual` callback (never the raw output or input). AgentView keeps live visuals as their own `pending-visuals` message until the post-turn re-read lands, deduped by artifactId, with the stream's conversation id. | `onDone` clears live state before the re-read lands, and for a new chat `detail.conversationId` is still null. Without this, the first visual of a new chat would blank out, then remount. | Show visuals only after the re-read (the design asks for live). Attach visuals to the `pending-agent` message (remounts in the done→re-read gap). |
| 2026-11-05 | **Theme handling.** Tokens are read from `getComputedStyle(document.documentElement)`, so `index.css` stays the single source. A theme change posts variables and never rebuilds the srcdoc. The frame sets `color-scheme` to match the parent, which avoids the opaque iframe backdrop browsers paint on a scheme mismatch. The Chart.js theme plugin resolves `var(--x)` strings in color options. | Models will write `hsl(var(--chart-1))` into Chart.js options, and canvas cannot parse them, so the bars come out black. That is the "jarring" failure Vinay named. | A static token table in TS (a second source). Reload the frame on theme change (the design says no reload). |
| 2026-11-05 | **Chart palette tokens `--chart-1..5` in all three `index.css` blocks**, each at least 3:1 (WCAG non-text) against `--background` and `--card`. Light: `242.71 63.03% 58.63%`, `173 80% 29%`, `28 90% 42%`, `340 70% 47%`, `201 90% 37%`. Dark: `245.33 100% 82.35%`, `168 60% 50%`, `38 92% 60%`, `340 85% 72%`, `199 88% 62%`. `theme-contrast.test.ts`'s `tokensAfter` regex is widened to `--[a-z0-9-]+`. | Measured worst cases: 3.75 light (`--chart-3` on `--background`) and 5.75 dark. The existing regex `--[a-z-]+` silently skips digit-bearing names, so without the widening the new test would read `undefined`. | Fewer colors. Deriving from `--primary` only (too close together). |
| 2026-11-05 | **The hostile-content test is a Playwright test in channel-web, gated on a locally installed Chromium.** CI installs no browser. The kind walk repeats a hostile visual in the real app. | jsdom enforces neither CSP nor sandbox. `playwright` is already in the lockfile (presets/k8s). The harness uses the real `buildVisualDocument` output and the real index.html CSP. | jsdom-only assertions (prove nothing about enforcement). Adding a Chromium install to CI (a cost and CI change, raised to Vinay). |
