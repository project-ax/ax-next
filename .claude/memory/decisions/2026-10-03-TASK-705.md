| 2026-10-03 | **`@ax/credential-proxy` bypassMITM raw tunnel: an `established` flag (set in the `net.connect` callback, where the 200 is written) decides the cleanup audit. Not established → audit `status: 502`, 0/0 bytes, NO `blocked` field, and answer the client `HTTP/1.1 502 Bad Gateway` + end (it used to get a bare hang-up and the audit said 200). Established → unchanged 200 audit with byte counts.** | The audit status now mirrors what the client was actually told. A refused/unreachable upstream is a network failure, not a policy block, so it takes the same shape as the catch path's DNS-failure 502 — `mapBlockedReason` returns undefined and the `event.http-egress` payload is unchanged in shape (no hook-surface change, no boundary review). A client that disconnects before the upstream connect completes also lands in the 502 branch: no tunnel was ever delivered, so 200 would be false either way. Error message / errno is deliberately NOT put in the audit (it carries the resolved IP:port; nothing downstream reads it). | A new `blocked: 'upstream_connect_failed: …'` reason: would need a new `blockedReason` enum value mirrored in audit-log/chat-orchestrator types for an event that is not a block. A distinct status for client-abort-before-connect (e.g. 499): nonstandard, and no consumer distinguishes it. |
| 2026-10-03 | **Bypass raw tunnel also tears down on a client `'end'` BEFORE establishment (`clientSocket.once('end', () => { if (!established) cleanup(); })`); after establishment `'end'` is left to `pipe()` as a legitimate half-close.** | MEASURED while writing the reviewer-requested client-hangs-up test: the http server's CONNECT sockets are half-open, so a client FIN emits `'end'` but never `'close'` — with a black-holed upstream (192.0.2.1) the proxy recorded ZERO audits and held both sockets until the OS connect timeout. Pre-existing (unfixed code did the same, then audited a false 200). | Cleanup on `'end'` unconditionally: would truncate half-closed live tunnels. Add a connect timeout: separate concern (reviewer finding 2, follow-up). |
