# Decisions — TASK-828 (turn error names every connector with a dead sign-in)

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-10-04 | **The card's premise needed a producer change: `proxy:open-session` stopped at the FIRST failed ref**, so the orchestrator only ever had one failure to name. The proxy now tries every ref and throws once. ONE failure → the TASK-783 error unchanged; SEVERAL → an outer `credential-resolve-failed` (diagnosis.envName = first) whose `.cause` is an `AggregateError` of every per-ref named error (its own `.cause` = the first resolver error, so old chain walks still land). | Keeps every existing reader working (outer code + envName + chain unchanged) and uses the standard JS container for "several things failed" — no `@ax/core` change, nothing non-plain stuffed into `diagnosis` (its doc says plain/bounded). | Orchestrator pre-checks each connector (double resolve, extra OAuth refreshes); `diagnosis.envNames` only (orchestrator could not tell a dead sign-in from a vault blip per connector); a proxy-side classifier (a second copy of `isNeedsReconnect` in another plugin). |
| 2026-10-04 | **Orchestrator reads the aggregate ONLY as the direct cause of the outermost `credential-resolve-failed`.** | Node's dialer throws its own `AggregateError` for multi-address connect failures; finding "any AggregateError in the chain" would read a resolver's network errors as credential failures and drop a `NeedsReconnectError` above it. Unit-tested. | Any AggregateError in chain (rejected, above). |
| 2026-10-04 | **Turn is a reconnect if ANY failure is reconnect-shaped**; every such connector is named, deduped by id, in proxy order. A provider-key failure next to a dead connector now reports the connector (was: whichever came first). | The connector is the part the person can fix now; whatever is left surfaces on the retry. | First-failure-wins (the old behavior, order-dependent). |
| 2026-10-04 | **New plural reason `connectors-need-reconnect`** ("Some of this agent's connectors need you to sign in again. Open Connectors, reconnect each one, then retry."), in `CONNECTORS_TAB_REASONS` so the live strip keeps its Open Connectors button. Single case keeps `connector-needs-reconnect` + `Connector: X` byte-for-byte. | "One of … reconnect it" above "Connectors: Gmail, Linear" contradicts itself. Card requires the single-connector message unchanged — a separate code is the only way to fix the plural without touching it. | Reuse the singular code with a plural detail line (self-contradicting copy). |
| 2026-10-04 | **Cap 3 names, then "and N more"; each name via `connectorLabel` (control/format stripped, 64 code points + …).** | Card asks for a small cap; 3 keeps the line short under a one-sentence label, and the Connectors tab marks every one anyway. `connectorLabel` is #913's convention (the card says `clampCodeUnits`; `connectorLabel` already clamps, by code point, which never splits a surrogate). | 10 (the prompt line's cap — too long for a UI line). |
| 2026-10-04 | **`proxy:rotate-session` still fails fast.** | A rotation failure only retires the warm session; the next turn's fresh open reports every dead sign-in. Out of scope. | Aggregate there too (no reader would use it). |
| 2026-10-04 | **Implemented inline, not subagent-per-task.** | Three small coupled edits; same call TASK-783 made. | — |
