| 2026-11-17 | **Planner: the card's premise holds and is understated. Five write paths reach past memory from an outsider's (`source: 'external'`) turn with no outsider check: the agent's `/files` home (mounted read-write, and it is HOME and cwd), `artifact.publish` (incl. `show_visual`), routine writes relaxed by the connector's routine consent, cold-start catalog requests, and `conversation.store-runner-session` (scoped by user, not by the session's conversation).** 8 tasks: 5 sensitive, 2 integration, 1 mechanical. | Five Explore sweeps (tools, files, artifacts, IPC + host side effects, turn-context composition), each verified against the code. TASK-1091 audited `source` CONSUMERS; paths that never branch on `source` were never asked. | Return blocked (nothing here is a human-only call: each refusal mirrors a decided rule). |
| 2026-11-17 | **The rule: an outsider's turn may change nothing the agent later reads as its own (memory, files, artifacts, routines, skills, identity, connector requests). What it does in connected apps stays governed by the connector's approvals, which design §1/§2 and the settings copy already disclose. Things only people read (Today rows, the `:external` thread, titles) are held for, or shown to, the owner.** Every gate asks `isOutsiderTurn(ctx)` (fails closed on an unknown source, keeps routines). | The integrity argument TASK-1094 F1 made for memory ("a lasting prompt-injection path from the least-trusted speaker into the most trusted context") applies to every store a later private turn reads as the agent's own. Data a third-party app returns is tool output, untrusted at every hop (invariant 5), never the agent's own state. | Key on `audienceOf` (would also lock members' channel turns). `!isAttendedTurn` (refuses routines). Correct the copy instead (leaves the paths open). |
| 2026-11-17 | **Files: an outsider's session gets `/files` READ-ONLY. sandbox-k8s `open-session.ts` passes the resolver's existing `readOnly: true` input when `isOutsiderTurn(input.owner)`; the pod-spec realizer already mounts a readOnly NFS volumeMount and skips the chown init.** Reads stay (design: files readable in every turn). | `/files` is the SDK's HOME and cwd (`agent-claude-sdk-runner/src/main.ts:429,470`), `/files/bin` is on PATH in every later session, HOME dotfiles (`.npmrc`, `.ssh/config`, repo `.git/hooks`) are picked up by tools, and `.skill-draft/` feeds `skill_propose`: a lasting code-execution path, not only prompt injection. The provider grants session capabilities (invariant 5) and the knob exists ("never widens, only narrows"). | Resolver decides, like memory's `sandbox:memory-mounts` (two resolvers to change; the provider already owns the session's grants). No `/files` mount (breaks the design's readable files and TASK-992's required home). Correct the copy. FOR VINAY: a reversible product call like F1 (one condition in open-session). |
| 2026-11-17 | **Shared pool: a read-only `/files` pod never takes a warm standby. `createSharedPoolSessionApi`'s `createNamespacedPod` routes it to the direct path; open-session also leaves it out of `pooled`.** Accepted cost: an outsider's first turn in a thread cold-starts a Sandbox. | Production runs shared pools (Helm rev 32, 2026-10-02), and the storage helper bind-mounts `user-files` read-write whatever the pod's `readOnly` says (`storage-node/engine.ts` remounts only `memory` ro): without the guard the read-only decision is silently void in production. | Teach the helper a read-only user-files bind (privileged component, host-helper protocol change, version skew, GKE acceptance): follow-up card. |
| 2026-11-17 | **Runner prompt: pod-spec stamps `AX_USERFILES_READONLY=1` when the realized user-files mount is read-only; agent-runner-core parses it (`'1'` or unset, anything else is `InvalidEnvError`) and swaps the three files notes for one read-only note, dropping the skill-authoring note.** | Otherwise the prompt tells the model "everything you want to keep goes there" for a home every write to fails, and it would claim to have saved files. Explicit env mirrors `AX_USERFILES_ROOT`/`AX_MEMORY_ROOT`. | Probe writability at boot (implicit; root ignores mode bits in tests). Leave the prompt (false instructions). |
| 2026-11-17 | **Artifacts: `artifact.publish` refuses every outsider publish, visual or not, first thing in the handler (`hookRejected`, fixed sentence).** | The artifact list (titles, paths) enters every spawn's system prompt, agent-wide, private turns included (`attachments/src/artifacts/augment.ts:64-88`); a publish can add a version to a privately made artifact by path or `artifactId`, and share links serve it; the wire allows `artifactId` with `visual: true`, so visuals can do it too. Outsiders can't open the web app the Slack link points at, so nothing of value is lost. | Refuse non-visual only (leaves the `artifactId` and path-collision routes). Hide only (not a gate). |
| 2026-11-17 | **Routines: `routine_create/update/delete/fire_now` are refused from outsider turns in `@ax/routines` `prepare()` (runs at `tool:pre-call` priority -100 and again at execute), before input validation and ACL reads; `recordRefusal` skips outsider refusals. Reads (`routine_list/get`) stay.** | Routine consent is keyed on `ctx.userId` (the connector) and relaxes a repeat-routine create and any non-brief edit to `allow` (`tool-policy/src/plugin.ts:700-707`, `routines-contract/src/tools.ts:135-153`): an outsider's text would become a repeat routine that later runs unattended as the connector. Refusing before validation means a malformed call gets the refusal, not a field error that invites a retry (TASK-1091's connector_propose rule); skipping `decisions:reject-unstarted-routine-call` means an outsider's turn can't mark the connector's own pending routine decision failed. | Never let consent relax for outsiders (holds outsider-authored briefs in the connector's Today: the queue spam TASK-1091 refused for connector_propose). |
| 2026-11-17 | **Hide the six newly refused tools from outsider catalogs: TASK-1091's `proposalToolScope` becomes `outsiderToolScope` over `OUTSIDER_REFUSED_TOOLS` (`PROPOSAL_TOOLS` + the four routine writes + `artifact_publish` + `show_visual`). `withBrokerDefaults` unchanged.** | TASK-1091's settled pattern is refuse + hide (decisions row 24). Without hiding, every outsider chart request calls `show_visual`, uploads a blob, and fails. Hiding is hygiene: `disallowedTools` is runner-side only, the host refusals are the gates. | Refuse only. |
| 2026-11-17 | **Cold-start catalog requests (`search_catalog`/`request_capability` miss → `catalog:submit`) are skipped for outsider turns in `fireColdStartSubmit`; the miss still reaches the model.** | Same harm class as `connector_propose` (admin queue, outsider-worded, filed as the connector), which TASK-1091 refused. It doesn't feed a private turn, but leaving it would make the outsider rule inconsistent. | Allow it (admin-triaged, non-promotable). |
| 2026-11-17 | **`conversation.store-runner-session` refuses any conversation but the session's own (`refuseUnboundConversation`), for every session.** | The store scopes only by `user_id`, so an outsider session's runner could bind a runner session id onto the connector's private conversation (any agent's); that id is later joined unvalidated into a filename in that conversation's next pod (`agent-claude-sdk-runner/src/jsonl-transcript-source.ts:154`), e.g. writing the private transcript into `/files`, which outsiders can read. The runner only ever names its bound conversation, so nothing legitimate breaks. | Outsider-only check (any runner has the same cross-conversation reach; the helper's rule is general). Validate the id at use (follow-up, defense in depth). |
