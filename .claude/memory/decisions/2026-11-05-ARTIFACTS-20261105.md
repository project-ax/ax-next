## 2026-11-05 — ARTIFACTS-20261105 agent artifacts implementation plan (planner)

Plan: `docs/superpowers/plans/2026-11-05-agent-artifacts.md`, for the spec `docs/superpowers/specs/2026-11-05-agent-artifacts-design.md` (approved 2026-11-05). It has 17 tasks: 13 sensitive, 4 integration, 0 mechanical. Task 17 is the `(walk)`. The id `ARTIFACTS` that the dispatch asked for is refused by `scripts/memory-write-target.sh`, which needs `<letters>-<digits>`, so this shard uses the date-suffixed form (precedent: `FILES-20261001`).

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-11-05 | **Plugin home: grow `@ax/attachments`.** New code goes in `src/artifacts/`. `attachments_v1_artifacts` evolves in place into the agent-scoped head table, and `attachments_v1_artifact_versions` is added. | The migration, the download ACL for old chips, the `blob:collect-refs` answer and the `conversations:purged` subscriber already live here. A new `@ax/artifacts` would have to read another plugin's table (or add a `list-legacy`/`clear-legacy` hook pair on attachments, the `connectors:list-legacy-defaults` precedent). It would also need a delegation hook for old-chip downloads, a new package, and preset holder-pin churn. All of that buys nothing at MVP. | A new `@ax/artifacts` that takes the table over (rejected: more hooks and wiring, the same mapping problem). |
| 2026-11-05 | **Cross-chat lookup: operating notes, via `system-prompt:augment:optional:artifacts` → `{ context }`.** Newest 50, capped at 8,000 chars. Titles and paths are JSON-quoted and framed as data. Publishing never fires `system-prompt:augment-changed`. | The spec prefers notes. The W1 contract (`packages/core/src/system-prompt-augment.ts`) already says `context` may carry agent-written text that the provider frames as information, and memory recall does the same. An `artifact_list` tool would be invisible to every non-wildcard agent: the admin API refuses the wildcard scope, so team agents carry explicit `allowedTools`. Firing augment-changed on publish would respawn the very session that published. | An `artifact_list` host tool (rejected: tool-scope gap, plus a new policy rule and verdict pins). |
| 2026-11-05 | **Second origin: a dedicated `node:http` listener owned by `@ax/attachments`.** Default port 9091, its own container port `content-http`, a Service port, and a second Ingress rule. Routes: `GET /`, `GET /v/:token`, `GET /d/:token`. No cookies, no session, no bus hook for redeeming. | `@ax/http-server` can't be loaded twice: there's a duplicate-plugin and a duplicate-service check. Host-header routing on the shared listener would serve `@ax/static-files`' `GET /*` SPA fallback and every `/api`, `/admin`, `/auth` route on the content host. Precedents for an extra listener: `@ax/ipc-http` and `@ax/credential-proxy` (own port + Service). Keeping token verification inside the plugin that signs tokens keeps the capability off the bus. | A second http-server instance (impossible). Host-header routing (exposes app routes). A channel-web-owned listener (would need an `artifacts:redeem-view-token` bus hook). |
| 2026-11-05 | **Content-origin config.** Env `AX_CONTENT_ORIGIN` (required), `AX_CONTENT_PORT` (default 9091), `AX_CONTENT_FRAME_ANCESTORS` (required, comma list). Chart: `contentOrigin.{publicOrigin, frameAncestors}`; the render fails and prints `--set` when unset, or when the content host is the ingress host or under it. GKE adds a second ManagedCertificate `ax-next-content-cert` on the same static IP. kind: content at `http://127.0.0.1:9091`, app at `http://localhost:9090`. | Cookies aren't port-scoped, so a second `localhost` port would get the app's session cookie; `127.0.0.1` is a different cookie host and site. The `--reuse-values` pin follows the TASK-992 pattern. A separate certificate avoids re-provisioning the live one. The hostname needs DNS: **check with Vinay before deploying**. | Reuse `http.allowedOrigins` as frame-ancestors (rejected: empty on kind, and setting it there turns on CSRF origin checks). |
| 2026-11-05 | **View token.** `v1.<b64url(JSON{a,n,p,l,e})>.<b64url(HMAC-SHA256)>`, ≤600 chars, TTL 300 s. Purpose `view`/`download` is bound to the route. A link-minted token carries a share-code binding (22 chars of sha256(code)) and is valid only for the current version. **Key: 32 random bytes per process, never persisted.** | The host is single-replica (the chart refuses more, TASK-617), and the minter and the listener are one process. So no secret to provision, back up, rotate or leak, and a restart only expires ≤5-minute tokens. The binding makes link-off, rotate and restore take effect immediately even for outstanding tokens. | HKDF from `AX_HTTP_COOKIE_KEY` (works multi-replica, but couples to the cookie key; kind's key is all zeros). A new chart secret (more plumbing, nothing gained single-replica). |
| 2026-11-05 | **Legacy migration (C3): in place, in this order.** (1) DDL. (2) Copy each legacy row into version 1, then drop the legacy columns. (3) Backfill `agent_id` through a new host-only `conversations:agent-ids`, which includes soft-deleted and hidden chats, and delete heads whose conversation row is gone. (4) Set NOT NULL and create the indexes. A mapping failure fails init and is retried on the next boot. The media type is re-derived from the legacy path, so `.html` stops being octet-stream. | No existing hook maps every legacy row: `conversations:get` and `get-metadata` are owner-only, skip soft-deleted chats, and refuse a publisher who lost team access. A row with no conversation row is unreachable today, because the download needs `conversations:get`. Non-additive: the GKE runbook says back up first. | Skip unmappable rows (rejected: under D12 a soft-deleted chat's artifacts are still the agent's). Copy into new tables, then drop (rejected: the rename/copy dance adds nothing in-plugin). |
| 2026-11-05 | **Share-page agent name: new host-only `agents:get-display-name` (no ACL).** `artifacts:resolve-share-code` calls it as an `optionalCall`; `agentName` is null on failure. | A link holder isn't a member, so `agents:resolve` refuses, and memory bans synthetic actors through it. Storing the name on the artifact would be a second source of truth that goes stale on rename. | Use the artifact creator's id with `agents:resolve` (rejected: a synthetic actor, and the creator may have left the team). |
| 2026-11-05 | **Quota (C4): charge the agent owner when the runner puts a blob.** ipc-core's `blob.put` resolves the agent and calls `blob:put` with `{ ...ctx, userId: quotaOwnerKey(agent) }`. `recordSessionBlobPut` keeps the original ctx. Versions store `quota_owner`, and the `blob:collect-refs` answer uses it. `quotaOwnerKey` moves to `@ax/core`, and disk-quota adopts it. | Today the member pays at put time. A holder answering `team:<id>` alone would pin the member's charge forever (disk-quota rule 2). The ctx override has precedents: `skills/src/blob-bundle-store.ts:131-138` and the routines webhook. One kernel spelling of `team:` keeps the three plugins in agreement. | An explicit `chargeTo` field on `blob:put` and its pre/post payloads (cleaner contract, but a core facade change). Re-attributing at publish (the gate would still check the member). |
| 2026-11-05 | **Pruning releases the reference immediately; quota comes back only when blob-gc purges.** That means enforce mode, about 7 days by default, and never in report mode. §9.7 is pinned by a moved-clock test in `blob-gc-enforce-acceptance.test.ts`. The walk checks that 20 versions remain and that the dropped sha is gone from the versions table. | disk-quota releases a charge only after `blob:stat {restore:false}` returns `{found:false}`. A walk can't wait 7 days, and the bounds on grace (≥1 h) and retention (≥1 d) prevent a short cycle on kind. | Release charges on prune (rejected: the bytes are still on disk). |
| 2026-11-05 | **Publish semantics.** Re-publishing by `artifactId` moves `source_path`, or answers `conflict` when another artifact of the agent holds that path. The next version is `MAX(version)+1`, never `current+1`. Size comes from `blob:stat` and the media type from the path. The returned title is the stored one (C5). Concurrency: `INSERT … ON CONFLICT (agent_id, source_path) WHERE source_path IS NOT NULL DO NOTHING`, then `SELECT … FOR UPDATE`. | A restore can point backwards, so `current+1` would collide. Host-derived size and type keep "media type from our stored row" true against an untrusted runner. Two teammates' chats on one team agent can publish the same path at once. | Trust the runner's `mediaType`/`size` (rejected: `.html` maps to octet-stream there, and both are caller-steerable). |
| 2026-11-05 | **Tool I/O.** Input `{ path, title, artifactId? }` with title required. Output `{ artifactId, version, title, kind, extension, url: ax://artifact/<id>, path: <relative> }`. There is no `displayName`, `mediaType` or `sizeBytes`, so `attachmentBlockFromArtifact` returns null and no chip duplicates the card. `path` stays because auto-attach dedupe (`generated-files.ts:246`) keys on it. | `kind` and `extension` come from the host, so the chat card needs no client-side media-type table. Legacy results without `version` keep rendering as download chips. | Let the runner keep appending attachment blocks for publishes (rejected: chip and card for one file). |
| 2026-11-05 | **"Download all": server-side, store-only ZIP from the app origin.** `application/zip` + `attachment` + `nosniff` + `private, no-store`. In-repo writer (`zlib.crc32`), caps 256 MiB / 500 files, names sanitized so no zip-slip. | No zip library in the repo, and a new dependency would mean a supply-chain walk for one button. A client-side zip would need CORS on the content origin. The tokens are single-artifact by spec, and app-origin attachment downloads have a precedent (`/api/files`). | Content-origin "all" token (rejected: breaks single-artifact, single-version). Sequential per-file downloads (rejected: not a zip). |
| 2026-11-05 | **Share code: 24 CSPRNG bytes as 32 base64url chars (192 bits), plaintext under a unique partial index.** `ensure` is race-safe (`UPDATE … WHERE share_code IS NULL`, then re-read). Never logged, not even a prefix. `/api/shared/*` is limited to 30/min per person with an in-memory sliding window. | Copy link must hand back the same code each time, so it can't be hashed at rest. onboarding's limiter keys by IP (one global bucket without `AX_TRUST_PROXY`), so it's the wrong key for a per-person limit. | 16 bytes (meets ≥128 bits with no margin). Hashing at rest (breaks Copy link). |
| 2026-11-05 | **CSP: the spec's string with `<self>` written as `'self'`; no self-hosted JS libs in this cut.** The tool description tells the agent to inline every script, style and image. SVG and downloads get the sandboxing CSPs (the `@ax/branding` precedent). `Referrer-Policy: no-referrer` goes on every content response, and `referrerPolicy="no-referrer"` on the iframe and img. | Pinned libs were a placeholder in the spec. Without them, `'self'` grants nothing, because every path needs a token. no-referrer stops the token leaving in a `Referer` when a viewer clicks an outside link inside a shared page. | Ship Chart.js etc. on the content origin (deferred until a real dashboard needs one). |
| 2026-11-05 | **Python libraries.** `container/agent/python-artifact-libs.{in,txt}`, generated with `uv pip compile --universal --python-version 3.11 --generate-hashes`. Installed with `uv pip install --require-hashes --no-deps --only-binary :all:` into `/opt/ax-python-venv-template`, after `Dockerfile:292-293` and before `USER 1000:1000`. `MPLCONFIGDIR=<scratch>/.matplotlib` and `MPLBACKEND=Agg` in `buildToolCacheEnv`. | The spec's "pure-Python wheels" is wrong: matplotlib with numpy, pillow, kiwisolver, contourpy and fonttools, and python-docx's lxml, are per-architecture binaries. The image runs on amd64 (GKE) and arm64 (kind on Apple Silicon), and the runtime stage has no compiler. Without `MPLCONFIGDIR`, matplotlib writes `~/.config/matplotlib` into `/files`. The versions are chosen and recorded by the builder. | Unpinned `pip install` (rejected: supply chain). |
| 2026-11-05 | **Sign-in return for `/a/<code>`.** `signInWithGoogle(callbackPath)` sends that path only when it exactly matches `/^\/a\/[A-Za-z0-9_-]{32}$/`, else `/`. App.tsx renders the share page before `WorkspaceShell`, so its URL rewrite never runs there. | There is no return-to today (`callbackURL: '/'` hard-coded), and `WorkspaceShell` rewrites unknown paths to `/workspace`. An exact pattern rules out open redirects. | A general `returnTo` param (rejected: open-redirect surface for one route). |
