# Decisions — TASK-628 ("Used N memories" chip under answers)

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-09-27 | **Count only `memory_recall` tool results, not the injected block.** | `system-prompt:augment` runs once at chat start with no per-turn refresh (`augment.ts` header), so every answer "used" it equally; attributing it to one answer is a claim nothing backs. The card allowed the block only "if attributable". | Count both (dishonest per-answer), or show the block on the first answer only. |
| 2026-09-27 | **`@ax/memory` writes a per-conversation "recall receipt" to `storage:*`; new service `memory:recall-receipts({conversationId})`.** | Measured: the persisted tool result is model-visible text with no statement ids; the browser never receives tool outputs; `call.id` on the claude-sdk host path is `idGen()` (host-mcp-server.ts), not the SDK tool_use id, so a decisions-style join by tool_use id is impossible; IPC `ctx.reqId` is per request, not the chat reqId. | Put ids in the evidence table (changes the tuned model format, costs tokens); engine table (two backends + migrations for a display record). |
| 2026-09-27 | **Attribute a receipt to an answer by time**: after the exchange's user turn `createdAt`, onto the LAST agent/steps message of that exchange. | Both clocks are the single host's; the only join key the transcript and the tool path share. A live turn with no committed answer attaches to nothing until the next thread read. | Ordinal join (Nth call ↔ Nth receipt) — breaks on failed/unpersisted calls. |
| 2026-09-27 | **Row state across reloads comes from bounded per-subject history reads** (≤10 subjects, `memory:recall` about + activeOnly:false); not found → no state shown. | There is no by-id read in the engine; adding one is a contract change across two backends. Fail-soft means an old closed row may show Fix instead of "since" — the Fix then no-ops on a closed id, which the engine already tolerates. | Engine `ids` filter (follow-up if this proves lossy). |
| 2026-09-27 | **Since-states: retracted → "Fixed since", replaced → "Updated since", forgotten → "Forgotten since".** | `replaced` is also what an ordinary later extraction produces, so calling it "Fixed" would claim a person corrected it. "It changed" Fix → replaced → "Updated since" is still true. | Card's literal "Fixed since" for every Fix. |
