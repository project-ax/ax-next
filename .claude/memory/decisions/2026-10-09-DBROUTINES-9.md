# DB-backed routines Task 9 — human adapters

- Settings routine CRUD is structured, agent-scoped and revision/request-ID bound. The HTTP adapter derives the real authenticated person and scoped agent context; it never uses a team owner as the execution actor and never touches workspace hooks. Raw service views are wrapped only by HTTP. Static consent, receiver and defaults paths precede item paths.
- Default catalog writes accept canonical interval-only fields, preserve omitted global enabled, and check the existing name identity before an update upserts anything. Existing auth:get-user service administration uses the raw user object.
- Routine credential destinations carry authored opaque routineId, not a file path. All three ref helpers and captured fixture vectors agree on routine:<agentId>:<routineId>:hmac; authored colon IDs and arbitrary ref/scope/owner bodies are rejected. Routine HMAC settings routes are absent; the existing admin gate precedes the human lifecycle service for both set and delete. Neither operation becomes an agent tool.
- Pending cleanup is checked under the existing revision/definition lock before testing whether HMAC remains configured. A current-revision form after failed HMAC removal now reports cleanup-pending rather than validation. Stale revision and deleted-row failures still take precedence. The real REST regression also proves actual delayed credential settlement precedes concurrent HMAC removal and cleanup.
- HTTP errors revalidate SafeToolError code/field and regenerate safe text; arbitrary messages and unrecognized secret-bearing field names are never reflected. Clients retain ISO date strings and carry logical request IDs supplied by callers. CredentialSlotRow obtains routine names and revisions from an authorized routine lookup, then passes that revision to the secret form. Model grant destination typing is narrowed to its existing account/skill families.
- This is an intermediate cutover commit: Task 10 migrates legacy routine screen consumers to routineApi and ISO formatting; Task 11 removes retired synchronization files. It is not independently deployable.
