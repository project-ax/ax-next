# DB-backed routines Task 8 — live runtime

- Scheduler, manual service dispatch and the single POST `/webhooks/:token/*` route now consume store-accepted opaque routine/revision dispatches. The stored UUID request identity correlates turns; the existing PendingFires map owns only transient turn correlation. Shared default conversation external keys remain the unchanged `default:<catalog id>` identities.
- Schedule advance is revision-conditional and writes scheduling timestamps only. Terminal history/status/warnings flow exclusively through guarded `finishDispatch`. Exact `agents:resolve` not-found invokes the same purge/credential-cleanup/pending-removal helper as agent deletion; forbidden keeps the routine and records failure. A purged agent's later turn cannot resurrect any state. Other claims from a purged agent are skipped without aborting the batch.
- Startup, before new work, marks abandoned accepted dispatches as interrupted errors without invoking them. This retains the documented single-host dispatch scope. Approval recovery distinguishes this terminal failure from an unknown in-process dispatch and from an already acknowledged acceptance whose eventual turn failed.
- Webhook lookup is request-time token-to-agent plus DB path lookup, followed by current revision acceptance and real stored-owner execution ACL. Raw path spelling, 1 MiB bodies, JSON/forms, SHA256/SHA1 HMAC, optional prefixes and event filtering are covered through the registered handler. HMAC refs are host-derived; no file sync, cached row/router map, token rebind listener or model token service exists. One unregister handle is kept for shutdown.
- The retired physical sync/parser module and old file-sync canary/tests still need Task 11 removal/migration. Do not infer package-wide green from the focused runtime gate. Runtime TypeScript diagnostics are gone; remaining package diagnostics are solely in sync.ts.
