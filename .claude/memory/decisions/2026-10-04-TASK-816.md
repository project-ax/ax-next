## 2026-10-04 — TASK-816 drop stdio MCP servers everywhere

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-10-04 | **stdio MCP is removed from every surface: connectors, connector drafts (`connector_propose`), the sandbox wire schema + runner `validateMcpEntry`, both runners' projection, host-side `@ax/mcp-client`, the `ax mcp` CLI, the channel-web editor and the mocks.** Connectors and the projection are `http` only; `@ax/mcp-client` keeps `streamable-http` + `sse`. Reads stay strict: one schema per surface, no stdio arm, no lenient-read "legacy" UI state. | An stdio server is third-party code we fetch and run on every session start (in the sandbox for connectors, ON THE HOST for mcp-client). It also made the host unable to list tools (rail showed `unknown`) and doubled every MCP code path. The product already moved to admin-defined remote connectors. Design: `docs/plans/2026-10-04-drop-stdio-mcp-design.md`. | Keep a lenient reader so old rows still parse (two schemas per surface, a "legacy" state forever). |
| 2026-10-04 | **Stored stdio rows are HARD-DELETED by boot sweeps, not migrated.** `@ax/connectors` init (`stdio-sweep.ts`): reads RAW JSONB, deletes live connectors + drafts (`capability_proposal`) that carry an stdio server; live rows get the same cleanup as `connectors:delete` (key purge + `connectors:deleted` so tool-policy drops its verdict rows) via a factored-out `purgeConnectorState`. `@ax/mcp-client` init (`stdio-sweep.ts`): runs BEFORE `loadConfigs`, purges the row's env credential slots, tombstones `mcp-server:<id>`, drops it from `mcp-server-index`. Both are idempotent and log counts/ids only. The connectors sweep logs `connectors_stdio_swept` / `connectors_authored_stdio_swept` with `count` on EVERY boot (including `count: 0`); only the mcp-client sweep logs solely when it removed something (a quiet boot must stay quiet; the CLI preset loads mcp-client). | One-time, idempotent, no new schema state. Purge runs before the hard delete so a crash between them leaves the row for the next boot. A GLOBAL key ref carries no owner, so the connectors sweep skips the global purge when another owner's surviving live connector shares the id (the key may be theirs) and still announces the removal. NOT reversible; accepted by Vinay. Agent `connector_attachments` / `connector_exclusions` ids dangle like after any normal delete (resolution already ignores unknown ids). | Migrate rows to a "disabled" state (needs a schema arm we are deleting); soft-delete (leaves the rows the narrowed schema refuses to parse). |
| 2026-10-04 | **`skill-broker/src/tools/capability-freshness.ts` is DELIBERATELY UNCHANGED.** It still hashes `command` / `args` / `env` into the digest. | The digest is compared against STORED digests: dropping those keys would change every approved skill's digest and mark them all stale. For http entries the keys are absent and hash as empty values, which is harmless. | Drop the keys from the digest (mass re-approval for no gain). |
| 2026-10-04 | **The `mcp-env` credential `Destination` kind is removed (`@ax/credentials` refs + fixtures, the admin destination route's switch and zod union, channel-web `refForDestination` + `CredentialSlotRow`). `mcp-header` stays.** The admin destination route now answers 400 to an `mcp-env` destination (tested for POST and DELETE). | `mcp-env` only ever held a stdio server's env secret and its consumer is gone. `refForDestination` only BUILDS refs, nothing parses them, so already-stored `mcp:<id>:env:<name>` rows are inert opaque strings; the mcp-client sweep still purges the ones its stdio rows declared. `presets/k8s` acceptance still writes a raw `mcp:task21-srv:env:API-KEY` ref through `credentials:set` as a store-cascade fixture — left, it never touched the Destination kind. | Keep the kind "just in case" (dead vocabulary on a credential-writing route). |
| 2026-10-04 | **The aisdk-runner connector card is now HTTP-only and unblocked.** This change was its prerequisite. `agent-aisdk-runner/src/skills-index.ts` and `tools/skill-tool.ts` comments were left for that card to replace. | The aisdk runner only ever needs http, so it ships one MCP transport, not two. | |
| 2026-10-04 | **`interrupt-processes.ts` and `interrupt-real-sdk.e2e.test.ts` keep their stdio-spawn handling; `deploy/MANUAL-ACCEPTANCE.md` "MCP-bundled skill (Phase B)" only had its stdio bits swapped for `transport: http`.** | `interrupt-processes.ts` also guards SDK-internal children, so removing it is a separate question. The Phase B scenario still uses a skill `capabilities:` block, which the skills parser has rejected since TASK-100 — the whole scenario predates that and needs a rewrite or retirement on its own card. | Rewrite the scenario here (scope creep). |
| 2026-10-04 | **`packages/test-harness/src/__tests__/helpers/json-rpc-stdout.ts` (+ its test) is deleted.** The 2026-09-26 TASK-537 patterns shard still points at it; that pointer is now stale. | Its only user was the stdio MCP e2e this change replaced with a streamable-HTTP stub; nothing else imported it. | Keep an unused helper for some future hand-rolled JSON-RPC child test (half-wired). |
