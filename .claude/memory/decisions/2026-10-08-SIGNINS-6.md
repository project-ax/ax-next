# Decisions — SIGNINS-6 (agent-owned connector sign-ins, slice 4: "Signed in as")

Shard id `SIGNINS-6` covers slice 4. Spec: `docs/plans/2026-10-07-agent-owned-connector-sign-ins-design.md`; plan: `docs/plans/2026-10-07-agent-owned-sign-ins-slice4-plan.md`.

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-10-07 | **No `openid`/`email` add-on when the connector requests no scope at all.** | Asking for only `openid email` would shrink the provider's default grant and break the connector. Cost if wrong: such connectors show "Signed in by … on …" instead of the account. | Always add the identity scopes (rejected). |
| 2026-10-07 | **`email` is added only when `scopes_supported` lists BOTH `openid` and `email`.** | `email` is an OIDC scope. Cost if wrong: none. | Add `email` whenever listed (rejected). |
| 2026-10-07 | **status-batch `signIns` reads only `kind: 'mcp-oauth'` rows**, and only a ref that is exactly `account:<id>`. | A single-slot api-key connector stores its key at bare `account:<id>`. Cost if wrong: an OAuth row of another kind shows no identity. | Any kind at `account:<id>` (rejected: a key is not a sign-in). |
| 2026-10-07 | **The signer label (`byName`) is the display name for everyone; the signer's EMAIL only for a workspace admin or the signer themself; anyone else gets `null` ("someone").** | It is the first non-admin email surface: keep cross-user email exposure minimal. Cost if wrong: members see "someone" for signers with no display name. | Fall back to the email for every viewer (rejected: leaks). |
| 2026-10-07 | **DCR registration includes the identity-augmented `requestScope`.** | `ensureClient` registers a fresh client on every begin, so leaving it out only creates a register/authorize mismatch. Pinned and published (CIMD) clients never register: unchanged. | Register the plain scope (rejected). |
| 2026-10-07 | **`invalid_scope` on an authorization that carried the add-on persists a skip flag; `begin` leaves the add-on out while it exists.** Table `mcp_oauth_v1_identity_scope_refused`, keyed **(agent, connector, auth server)**; the pending row records `identity_scope`; the popup reason stays `sign-in-failed`. | Strict providers self-heal after one failed sign-in. Cost if wrong: one failed sign-in per agent on a strict provider. | Never add the scopes (rejected: loses the account); retry automatically (rejected: hidden second popup). |
| 2026-10-07 | **SECURITY: the skip flag is keyed by AGENT, not connector-wide.** The callback's `error` arrives through the browser, so anyone holding a state for their own sign-in can forge `invalid_scope`; connector-wide, that switched identity capture off for every agent on it. Now a person can only affect an agent `begin` already let them sign in on. Cleaned on `agents:deleted` and `connectors:deleted`. | Found by a background security review during the fix wave. Cost if wrong: one failed sign-in per agent on strict providers. | Connector-wide flag (rejected: cross-tenant poisoning). |
| 2026-10-07 | **The callback logs the provider's RFC 6749 §4.1.2.1 error CODE** (a registered value, else `other`), never `error_description`; **one `mcp_oauth_identity` info line** per callback with `source` (`id_token`/`userinfo`/`none`) and a fixed `reason`, never the account or a token. | The operator can tell why no account showed without any untrusted text in logs. | Log nothing (rejected: undiagnosable); log the description (rejected: provider-authored, can echo user data). |
| 2026-10-07 | **An `email` with `email_verified === false` is skipped** (falls through to `preferred_username`, then `sub`); absent or non-boolean keeps it. | Anyone can type an address they don't own; many providers never send the claim. | Require `email_verified === true` (rejected: drops most providers). |
| 2026-10-07 | **Account labels strip Cc, Cf, every Bidi_Control and U+2028/U+2029; the UI also wraps provider text in `<bdi>`.** | Display-only untrusted text must not reorder or hide what's around it. | Strip only the classic bidi controls (rejected: misses zero-width/format chars). |
| 2026-10-07 | **Spec deviation, accepted: rows show only "· account"; "Signed in by … on …" lives in the details view** (spec says the row). | Keeps rows compact. Cost if wrong: one more line in the row. | Show both in the row (rejected). |
| 2026-10-07 | **`shortDay` keeps the native `Intl` short date and only reorders English to day-first ("7 Oct").** | The English copy reads "on 7 Oct"; re-gluing parts broke ja/zh ("10月7日"). | Fixed day-month for every locale (rejected: the bug). |
