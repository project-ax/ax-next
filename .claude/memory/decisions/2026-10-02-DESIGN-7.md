# Connector sharing and attachment defaults

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-10-02 | Remove Workspace settings from the Remote MCP editor. New manual definitions default to shared, personal credentials, and default attachment off. Editing omits hidden sharing/default flags and preserves credential mode. | The editor configures the integration. The user explicitly limited the new defaults to newly created connectors and requested that existing settings be preserved. | Retroactively publish private definitions or disable existing defaults; rejected by the user. |
| 2026-10-02 | Shared definitions support authenticated list/get/resolve, with server-derived ownership permission. Mutations remain owner-only; personal vault entries stay per-user. Workspace credential authorization checks the definition owner’s current admin role. Owned ids win; multiple foreign shared rows with one id fail closed. | The previous shared flag did not widen owner-scoped reads. Making definitions available must not grant permission to edit another owner’s configuration or resolve their personal credentials. | Broaden the owner-only lookup used by writes and credential cleanup; unsafe. |
| 2026-10-02 | New registry records require explicit agent or skill attachment unless deliberately marked default. Store-managed requiresAttachment preserves the legacy implicit owner attachment for pre-existing records. | The orchestrator previously attached every listed owned connector even when defaultAttached was false. Sharing the list without filtering would silently enable everyone’s definitions. | Remove all legacy implicit attachment; would change existing behavior. |
