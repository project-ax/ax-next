| 2026-11-25 | **Search rules.** Signed-in only (auth-better's `requireUser`). `q` is trimmed, 2–64 code points, else 400 `invalid-query`. It matches the start of any word of the display name, ignoring case, with `starts_with(lower(btrim(name)), lower(q)) OR strpos(lower(btrim(name)), ' ' \|\| lower(q)) > 0`: no LIKE, so `%` and `_` are plain characters. It never matches on email and never returns it. Answers are `{id, displayName}` only, at most 10, ordered by name, each name fenced (`replaceSurfaceRewriters`, whitespace collapsed, 80 code points), and rows that fence to nothing are dropped. 60 searches a minute per person: sliding window, 10 000 people tracked, then 429 `rate-limited` with `retry-after: 60` (the shared-artifacts shape). Every answer is `cache-control: private, no-store`. There is no `email_verified` filter. | Matching on email but not returning it is still an oracle: "does vinay@… exist, and what's their name?". Word starts are how people search a name. Two characters keep the first request useful. Ten results fit a picker and bound a scrape to 600 names a minute per person. Every user row is an AX account by `isAxAccount`'s own rule (`agents/src/acl.ts:170-217`), so a verified-only filter would hide people the sharing writes accept, such as the wizard admin before first sign-in. Fencing stops a bidi-spoofed name from impersonating a colleague in a sharing picker. | Substring match (noisier, and "rch" finds Archer). Min 3 characters ("Al", "Bo" fail). 30 a minute (adding 10 people while typing hits it). ILIKE with escaping (auth-better avoids LIKE, `plugin.ts:681-682`). Filtering to verified emails. |
