# TASK-486 — decisions

## The runner-immutable guard goes on the commit path, not on `workspace:pre-apply`

`memory/system/rules.md` (the human memory tier) was writable from the runner
sandbox and landed unseen: the runner stages its whole `/agent` tree, `memory/`
is not in `WORKSPACE_GITIGNORE_ENTRIES`, `filterToPolicy` does not match the
path, and `workspace:apply-bundle` lands the FULL change set. Confirmed
statically 2026-09-20 (five-file chain re-read in-tree); end-to-end
exploitability stays INFERRED by product-owner scope decision.

Two shapes were on the table. We took the commit-path guard. The three reasons,
in the order they actually decided it:

1. **A pre-apply subscriber cannot tell runner-originated from host-originated.**
   The payload is `{changes, parent, reason}`. The only discriminator is
   `reason` — and `reason` comes straight off the runner's own
   `WorkspaceCommitNotifyRequest`. An allowlist on it (`reason ===
   'memory:rules:write'`) hands the sandbox the key to its own lock. Origin has
   to be *structural*: decided by which code path is executing. The commit
   handler IS the runner-originated apply path; there is no other.
2. **The Rules UI save goes through the same hook.** `memory:rules:write` →
   `applyTierChanges` → `workspace:apply` facade → fires `workspace:pre-apply`.
   A subscriber veto would have broken the Save button. Pinned by a new test in
   `core/src/__tests__/workspace-apply-facade.test.ts`.
3. **Widening `POLICY_PREFIXES` / `POLICY_EXACT_PATHS` has blast radius far
   outside the pre-apply hook.** `agent-runner-core/src/governed-paths.ts`
   re-roots *every* path matching those constants into `/agent`, and three
   validators (skill, identity, routine) receive the widened batch. Adding
   `memory/**` would also push every consolidation flush through the validators.
   The policy-visible set is now pinned by a test so a future widening is a
   deliberate act.

## Scope: `system/rules.md` only, not `memory/**`

`user.md` / `recent.md` / `map.md` are the AGENT's own memory and the
consolidator regenerates them end-to-end each pass, so a sandbox write there
does not persist. `rules.md` is the one file nothing ever rewrites — which is
exactly what makes it the durable vector.

## Refuse, not strip

Stripping is not mechanically available on this path: `workspace:apply-bundle`
takes the runner's opaque bundle, not a change list, so there is no set to
subtract from. The refusal reuses the existing veto shape
(`accepted:false` + `recoverable:false` + `discardPaths`), so the runner reverts
exactly that one file to baseline and keeps the rest of the turn (TASK-287),
and the next turn's re-stage cannot re-submit it and wedge the agent.

## One literal, two enforcement points

`RUNNER_IMMUTABLE_PATHS` lives in `@ax/core`'s `workspace-policy.ts` because
`@ax/ipc-core` may not import a plugin (Invariant 2) and that module is already
where workspace path policy lives (Invariant 4). `@ax/memory-strata`'s
`HUMAN_TIER_TIER_PATHS` now derives FROM it, with a drift pin in
`human-tier.test.ts` that re-runs the old derivation and fails if a second
human-owned file is added on one side only.
