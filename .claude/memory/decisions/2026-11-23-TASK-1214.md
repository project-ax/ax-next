# TASK-1214 decisions — agent tools picker (planner)

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-11-23 | The picker's names come from a new `GET /admin/agents/tools` in `@ax/agents`, next to `GET /admin/agents/models`. It is `requireUser`, not admin-only, and adds a `tool:list` entry to `@ax/agents`' `optionalCalls`. | No route exposed `tool:list` to the SPA. The workspace rail reads it only to build permission rows. `AgentForm` sits in user Settings, where every signed-in person manages their own agents, so an admin-only read would break the form for everyone else. `@ax/tool-dispatcher` calls nothing, and `tool:register` (same producer) was already an optional edge, so no cycle and no change to init order. | A BFF route in channel-web (rejected: splits the agent-admin API across two plugins). Admin-only (rejected: non-admin owners lose the picker). |
| 2026-11-23 | Wire shape `{ tools: string[]; builtins: string[] }`: names only, in catalog order. `mcp.`-namespaced names and any name failing `TOOL_NAME_RE` are dropped. No producer, a throw, or a reply without a `tools` array all answer 503 `{ error: 'tool-catalog-unavailable' }`, never an empty list. | Form saves drop names the catalog lacks, so an empty list from a failed read would delete every saved host tool. The rule is to subtract only what a successful read proved. `mcp.<configId>.*` names are scoped by `mcpConfigIds`, never by `allowedTools`, and carry per-tenant config ids. | Return descriptors with descriptions (rejected: YAGNI; descriptions are written for the model). 200 with `[]` when there is no producer (rejected for the reason above). |
| 2026-11-23 | The built-in names offered are the six both runners ship (`Bash Read Write Edit Glob Grep`), as `RUNNER_BUILTIN_TOOLS` in `admin-routes.ts`. `TodoWrite`, `Skill`, `ToolSearch` and `WebFetch` are not offered. | Built-ins never appear in `tool:list`. tool-policy's sandbox floor and `@ax/agent-aisdk-runner`'s `builtins.ts` name the same six. The claude-sdk runner loads its extras whatever the list says, and TASK-1200 denies `WebFetch`, so listing any of those does nothing. | Derive them from tool-policy `providedBy: 'sandbox'` rows (rejected: a policy table is not a catalog, and TASK-1207 is changing those rows in flight). Keep the list in the SPA (rejected: what an agent's list may hold is `@ax/agents`' knowledge; the SPA only presents it). |
| 2026-11-23 | Grouping is a presentation step in the SPA (`lib/agent-tool-areas.ts`): Files and commands (the built-ins), then Routines, Memory and The web (by name prefix), Sharing what it makes (`artifact_*` and `show_visual`), and Other tools. Areas show only names the catalog returned. | `ToolDescriptor` has no area field. Adding one means changing core, ipc-protocol, the dispatcher schema and `validateDescriptor`, plus every registration, which is out of proportion for a picker. A tool that matches no prefix still appears, under Other tools. | An `area` field on `ToolDescriptor` (rejected: four-place change, YAGNI). Grouping on the server (rejected: labels are presentation). |
| 2026-11-23 | The picker never offers tools the chat orchestrator adds by itself: `search_catalog`, `request_capability`, `skill_propose`, `connector_propose` (`ALWAYS_ON_BROKER_TOOLS`), `update_identity` and `complete_bootstrap` (`identityToolScope`), and `routine_report` and `routine_read_update` (`ROUTINE_RUN_TOOLS`). They are kept in the SPA as `AUTOMATIC_TOOLS`. They still count as known, so a saved list that has them is never flagged and keeps them. | Ticking any of them does nothing, because the orchestrator adds them at session open. An unticked box for one would also tell the owner the agent lacks a tool it has. Vinay's standing direction is to hide plumbing and show only problems. If the copy drifts the harm is mild: at worst one extra box that does nothing, or a tool that can no longer be offered. | Show them as normal boxes (rejected: no effect, and they understate reach). Show them locked (rejected: identity and routine-run tools are conditional). A new orchestrator hook (rejected: an agents → orchestrator edge would close a cycle, and the scope is too big). A cross-reference comment in `orchestrator.ts` (cut: CI would run the orchestrator's tests for a comment). |
| 2026-11-23 | The Routines group is the six routine-management tools (`routine_list/get/create/update/delete/fire_now`), not the card's "five". | The catalog has eight `routine_*` tools. `routineToolKind` (routines-contract) calls list and get "read", and create, update, delete and fire_now "write"; report and read_update are run-only and hidden. `routine_fire_now` always asks for a once-only approval, and someone asking "run it now" needs it. The card's five was the walk's hand-typed working list (TASK-1205 #6), not a considered definition. | Five only (rejected: leaves fire_now alone under Other tools). All eight (rejected: run-only tools are refused outside a check-in). |
| 2026-11-23 | A saved name that is not in the catalog or the built-ins is shown in an Alert ("…isn't a tool we have… Saving removes it"), and saving removes it. This happens only after a successful catalog read. **Save is not blocked.** This departs from the builder's lean, which was to block Save until removed. | TASK-147: the combined Save was once over-gated, and blocking an identity edit over a stale tool name repeats that class of bug. `AppGrantEditor` already says "No longer offered. Saving removes it." for the same shape. Unknown names match nothing, so dropping one changes no capability. The acceptance criterion is met literally: an unknown name can't be saved and can't be picked. While the list is loading or after a failed read, nothing is proved and the list is saved unchanged. | Block Save until removed (rejected: over-gates unrelated edits). Keep and warn only (rejected: the card says to reject, and junk would stay). |
| 2026-11-23 | The built-ins stay pickable as "Files and commands", with the hint "Picking them changes nothing; pick them if this agent needs no other tools." The TASK-147 tools gate is unchanged. | `allowedTools` never gates a built-in in either runner (Explore trace: claude-sdk `tools: ALLOWED_SDK_BUILTINS`; aisdk `buildBuiltinTools`). But an empty list is the wildcard sentinel, so a restricted agent with no host tools needs some entry, and existing lists hold these names (Fern: `Bash, Read, Write, Edit`). The hint makes no claim about reach that could be false (the Bash ability switch lives elsewhere). | Don't offer them and fill with the six when the list is empty (rejected: changes the gate semantics and existing rows). Offer them with no hint (rejected: an unticked Bash says the agent can't run commands). |
| 2026-11-23 | An existing agent saved with no tools (the wildcard) shows "Right now this agent can use every tool, because none are picked. Picking any limits it to just those." The bare-stays-bare PATCH still omits the tool fields. | Most agents are wildcard (bootstrap and onboarding create them that way). With no explanation, an owner who ticks Routines silently restricts the agent to only that. | No line (rejected: the picker understates a wildcard agent's reach and invites accidental restriction). |
| 2026-11-23 | An area box is ticked only when all of its tools are ticked. There is no indeterminate state. | The installed `ui/checkbox.tsx` draws the same check icon for `indeterminate`, so a partly ticked group would look fully ticked. The tool boxes underneath already show what is partly picked. | Edit the shared Checkbox primitive (rejected: outside the card's scope). |
| 2026-11-23 | No server-side rejection of unknown names in `POST`/`PATCH /admin/agents`. | An unknown name grants nothing, so this is a UX problem, not a security one. Server checks would tie every write to the catalog being present and to the built-in list, and would break existing rows and the many tests that create agents with made-up names. | Validate in the zod schema (rejected for the reasons given). |
| 2026-11-23 | Stale lines fixed: the `lib/admin.ts` header SECURITY NOTE (L16-18, "every endpoint… guarded… by the admin role check"; `/admin/agents` is requireUser and owner-scoped), and the `admin-routes.ts` allowedTools comment (L99-103, which named `mcp__…`, `WebFetch` and `Skill` as entries). | The first would lead a reader to make the new read admin-only. The second implies `allowedTools` gates built-ins and MCP names, and neither is true. | Leave them (rejected: yolo-ship rule 5). |
| 2026-11-23 | Tiers: route = sensitive (requires `security-checklist`: manifest edge plus a new read surface); AgentForm wiring = sensitive (it writes tool lists and keeps no history); client, pure rules and changeset = mechanical; picker component = integration. | The route and the save rules are the two places a mistake becomes lost reach or exposed data. | — |
