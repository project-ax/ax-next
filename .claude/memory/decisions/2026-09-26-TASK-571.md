# Decisions — TASK-571 (Teams settings list read `.name`/`.members` off a `{ displayName }` wire)

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-09-26 | Bug is REAL and worse than "blank": `lib/admin.ts` `listTeams()` returns `(await res.json()).teams` unmapped, `@ax/teams` `serializeTeam` sends `{id, displayName, createdBy, createdAt}`, so `TeamList` threw `Cannot read properties of undefined (reading 'length')` on `t.members.length` for the first real team (measured: the real-shape test reddens on main with exactly that TypeError). Two more readers had the same drift: AgentForm's team picker (`{t.name}` → empty `<option>`s) and `agentCaption` (team name silently dropped). | The SPA's `Team` type came from `mock/admin/teams.ts`, a shape no server sent; every SPA fixture was that mock shape (one via `as unknown as Team[]`), so the tests agreed with the mock and not the server. | — |
| 2026-09-26 | One source of truth: `@ax/teams` exports `AdminTeamWire` (declared next to `serializeTeam`, which now returns it); channel-web adds `@ax/teams` as a workspace dep + tsconfig ref and TYPE-imports it (`lib/admin.ts` `export type Team = AdminTeamWire`); the mock re-exports the same type. | Invariant #2 allows type-only cross-plugin imports (eslint `allowTypeImports`), same pattern as `@ax/routines`' `DefaultRoutineSummary`. The wire schema lives in the owning plugin's dir (boundary-review rule). Vite erases type imports, so no runtime coupling. | A new shared `*-protocol` package — rejected, one interface does not earn a package. Remap in `listTeams()` to `{name}` — rejected, keeps two shapes. |
| 2026-09-26 | TeamList drops the member count and shows "Created <date>" instead; copy says "the teams you're in". | The list route (`teams:list-for-user`) carries no member list and answers "my teams", not "all teams"; members are the team-admin-gated `GET /admin/teams/:id/members`. Adding counts means a hook/wire change for a placeholder page (YAGNI). | Extend the list wire with `memberCount` — deferred as a followup if product wants it. |
| 2026-09-26 | Implemented inline instead of per-task subagents. | ~15 files of 1-3 line edits; subagent overhead exceeded the work. | — |
