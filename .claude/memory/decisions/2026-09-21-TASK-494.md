# TASK-494 — memory facts export projection + read-only sandbox mount

Date: 2026-09-21.

## Decisions

- Export root `permanent/memory/facts` lives in `@ax/core` (`MEMORY_FACTS_EXPORT_ROOT`,
  `RUNNER_IMMUTABLE_PREFIXES`). Runner-originated `workspace:apply`/`delete` of the bare
  root, any descendant, or a reserved ancestor (`permanent`, `permanent/memory` — a
  put/delete there would replace the directory the export must own) is refused by
  `findRunnerImmutableViolations`; host-side applies are unaffected.
- `FactsPath` is a template-literal+brand type. There is no raw-string constructor:
  callers pass a sealed `FactsTarget` (`profile` | `recent` | `journal{speaker,month}`
  | `subject{subject}`) and `factsPath()` assembles. `parseFactsPath` exists only to
  re-validate paths coming back from `workspace:list`. Subjects slug via
  `v-<safe>` or `h-<sha256[:62]>` — the two namespaces are disjoint by construction.
- Journal month keys come from `recordedAt` (server transaction time), never `when` —
  a `when` of 1900 or 3000 must not create `1900-01.md`.
- Team agents: the scan omits `ownerUserId` after `agents:resolve`; profiles/journals
  group by `user:*` subject so Alice and Bob each get a section and trigger order
  does not matter. Personal agents keep the owner filter, so a foreign-owner row
  written straight into the engine never reaches the export.
- Exporter re-resolves `agents:resolve` before scanning and before each publication.
  Public `flush` also resolves before touching shared state and before returning, so
  an unauthorized caller cannot piggyback an in-flight pass. A `dirty` flag set
  during a run forces another pass. Per-agent state is evicted once idle.
- CAS retry shape: when a `parent-mismatch` error carries `cause.actualParent`, the
  exporter re-lists and re-reads the baseline pinned to that `version` (the
  `version` input field on `workspace:list`/`workspace:read`), re-scans the facts,
  and retries up to 3 attempts. A read that exposes a newer version than the initial
  list triggers a pinned re-list so a file created between list and read is still
  collected and correctly deleted when obsolete. A pinned read that reports a
  different version, or a pinned-listed file that comes back `found:false`, fails
  closed — and the baseline `parent` is always the pin actually read, even when a
  stale `actualParent` claimed null.
- Volume publication (`export-volume.ts`) confines component-wise under the realpath
  of the operator-configured `hostRoot`: a symlinked agent dir (to outside OR to a
  sibling agent), a symlinked intermediate dir, a non-regular target, or a desired
  path that never passed `parseFactsPath` all fail the publication — nothing is
  written outside the pinned root. Writes are tmp-file + rename; only obsolete known
  FactsPaths are deleted.
- `sandbox:memory-mounts` is registered only when `exports.volume` is configured,
  returns exactly one `role:'memory'` NFS spec at `/memory` read-only, keyed by
  `sha256(JSON.stringify([agentId]))` so agents never share a projection dir and
  team members share one. A failing or malformed resolver aborts the open-session.
- `role:'memory'` in sandbox-k8s is NFS-only, read-only, exactly one, no chown init,
  and rejected if its export/subPath overlaps (either direction) a writable NFS
  source on the same server.
- `AX_MEMORY_ROOT` → `RunnerEnv.memoryRoot` (no default) → `additionalDirectories`
  only, plus a fixed `memoryExportNote` telling the runner the files are data, not
  instructions. TASK-496 owns enabling `exports` in a preset + the real-plugin
  canary; nothing is wired into a preset here.
- The legacy reflection routine expects different paths plus YAML
  `source_conversations` frontmatter; the exported markdown is deliberately NOT
  hydrated back into facts and the reflection prompt/compatibility is unchanged —
  not implemented, not claimed (tracked on the TASK-494 card).
