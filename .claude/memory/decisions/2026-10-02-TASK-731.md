# TASK-731 — a refused save survives a reload; the final/idle refusal gets a channel

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-10-02 | Card premise CONFIRMED from code: `saveRefused` reaches `persistEventTurnEnd` (ipc-core) and is dropped there (only `{blocks}` is appended as a `turn` row); the SSE `done` frame is never buffered; the final/idle refusal only writes stderr | Read `event-turn-end.ts`, `sse.ts` 485-510, `run-runner.ts` ~1797 | - |
| 2026-10-02 | Card claim REFUTED in part: "a save can only be refused on a turn that wrote files, i.e. a turn that has a turn-end" does not make the final/idle refusal channel-less in practice. The final flush bundles `baseline..main`, so an earlier per-turn save that came back `kept` (host unreachable / 5xx) rides it, along with late/background writes. Those ARE files from replies the person read, so the final refusal gets a channel rather than a "none, by design" comment | `git-workspace.ts` commitTurnAndBundle bundles baseline..main; `commitNotifyWithResync` keeps on transport errors | Declare no channel and say so in code (loses exactly the kept-then-refused files silently) |
| 2026-10-02 | Persist as a new display-event kind `save-refused` in `conversations_v1_events` (the TASK-66 display log that already carries `turn-error` / `permission-card` and that `conversations:get` projects to `displayEvents`). Payload `{ code }`, a closed code only. Per-turn rows fold on the turn's reqId (both turn-ends of one turn carry the code, so they collapse to one row positioned after the assistant turn); final/idle rows get a host-minted unique key | One source of truth for host-only thread rows already exists and reload already interleaves `turn-error` rows by time (TASK-498). A closed code keeps the wording in the client, like turn-error reasons | New column on conversations (one slot, loses history); kv store (not on the thread read); synthetic transcript line (corrupts SDK resume); reuse `turn-error` (wrong register, marks a finished reply as failed — TASK-720 rejected it) |
| 2026-10-02 | The per-turn row is written by ipc-core `persistEventTurnEnd` (already awaited before the turn-end ack, ctx-scoped conversationId), AFTER the turn row, best-effort (log + swallow) | Persist-before-ack means the row is durable before the `done` frame, so the post-done re-read already has it. Swallowing: a throw here would 5xx a turn-end whose turn row already landed, and a runner retry would duplicate the turn row | A conversations `chat:turn-end` subscriber (not ordered before the done frame, so the re-read could miss it); re-throw (duplicate turn rows on retry) |
| 2026-10-02 | The final/idle refusal rides the existing `event.chat-end` as an optional `saveRefused` (same closed enum); ipc-core persists it as a `save-refused` row before firing `chat:end` | `event.chat-end` is sent right after the final flush and is the only runner→host event left; an optional field is backward compatible (the schema is a non-strict z.object, an old host strips it). No stream is open then, so the row is seen on the next read | New `event.save-refused` IPC event (a whole new wire action for one field); a reqId-less `event.turn-end` (closes any open stream on the conversation by the conversation-only match, and fires title/routine subscribers at shutdown) |
| 2026-10-02 | Live + durable de-dup: the live client-only notice is kept for the gap between `done` and the re-read, and is not drawn once the durable thread holds the row for that turn (matched by a shared row-id helper keyed on the reqId) | Without it the re-read would draw the notice twice | Drop the live path entirely (the done frame field becomes half-wired); clear the live notice when the re-read lands (loses it if the persist failed) |
| 2026-10-02 | `listEvents` skips (logs) an unknown `event_kind` instead of throwing | Today an unknown kind throws and breaks `conversations:get` for the whole conversation; a future kind or a rollback past this one should cost one row, not the thread. A rollback to a release BEFORE this one still throws on `save-refused` rows (one-way door, stated in the PR) | Leave strict read (every future kind is a rollback hazard) |
