# Decisions — TASK-624 (Fix asks: did this memory change, or was it never right?)

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-09-27 | **Refuted the card's `at` premise.** The card says retracted rows are "excluded from point-in-time (`at`) recall". There is no `at`: `@ax/memory-facts-contract`'s `RecallInput` has none and `@ax/memory`'s `types.ts` says in as many words that it is deliberately absent. The temporal surfaces that DO exist are (1) the `(about, slot)` chain re-settle and (2) the facts export's month journals, which render closed rows as `value (until <day>)` for the agent to read. "Never right" is implemented against those two. | Building `at` to satisfy a sentence would be a hook-surface change with no consumer (design §4.2 keeps it off the agent tool). | Build `at` recall — rejected, no consumer; ignore the temporal half — rejected, the export would keep calling a mistake a past truth. |
| 2026-09-27 | **"It was never right" = an explicit retraction of the old row FIRST, then the human write.** The engine already models this exactly: `memory:facts:supersede` closes with `closed_by = NULL`, drops the row from the chain replay, and re-opens whatever it had closed, so the next human write closes THAT predecessor. Boston → Seattle (wrong) → fix to Denver leaves Boston closed by Denver and Seattle retracted: Boston's validity runs straight to Denver, Seattle is never in the chain. | Reusing the TASK-448 retraction machinery means zero new closure rules in either backend. | Record first, then retract — the new row closes the old one by slot and `supersede` only acts on ACTIVE rows, so the retract would be a no-op and the row would read "Replaced". |
| 2026-09-27 | **Engine stores the distinction as `neverTrue`** (`SupersedeInput.neverTrue?: boolean` → `FactRecord.neverTrue?: true`, column `never_true`). Not `retracted`: the engine's prose already calls every explicit supersede a "retraction" (Forget included), so reusing that word for the narrower meaning would make two meanings of one word in one file. The product layer maps it to `closure: 'retracted'` (the UI badge word TASK-623 reserved). | A Forget and a "never right" are both explicit closes; only the second is a claim the value was never true. A stored bit is the only way History can tell them apart later. | Encode never-true as `until == when` (a zero-length validity interval) — implicit, and loses the retraction date the badge shows. |
| 2026-09-27 | **New product hook `memory:correct {id, about, relation, value, reason: 'changed' \| 'never-right'}`** rather than a `reason` on `memory:remember`. Provenance stays implied by the hook (hard-coded `human`); `rejectPrivilegeFields` applies. `reason` is REQUIRED on the hook: the UI defaults to "It changed", the hook does not guess. | `remember` has no notion of WHICH row is being corrected, and never-right needs the id. A separate verb keeps `remember`'s contract (and its callers: Undo, canary) untouched, which also keeps TASK-630's Undo path clean. | `reason` + `replaces` on `remember` — overloads the plain-save door; two UI calls (forget then remember) — non-atomic at the network edge and the reason never reaches the server. |
| 2026-09-27 | **Failure window accepted:** retract-then-record is two engine calls. If the record fails after the retract, the old memory is retracted and the new one unsaved; the dialog keeps the text and says so. A retry converges: the second retract is a no-op (the row is no longer active) and the record lands. | The engine has no cross-hook transaction and adding one is out of scope. | Pre-validate the value in `@ax/memory` — a second validator for the engine's rule (invariant 4). |
| 2026-09-27 | **"It changed" on a SLOT-LESS row still leaves the old row active** — the same as today's Fix, because a slot-less row is inert (closes nothing, closed by nothing). Not fixed here; returned as a follow-up. | Fixing it needs an engine "close X by Y" verb, a separate hook change. | — |
| 2026-09-27 | **Export drops never-true rows** from every file (profile, recent, journals, subject pages). They were never true, so no "what did I say in March" read should find them. Forget-closed rows are unchanged. | The export is the agent's temporal read. | Render them with a "(never right)" marker — the agent would still read the value as a statement. |
| 2026-09-27 | Added shadcn `radio-group` (new dep `@radix-ui/react-radio-group`, same radix family already pinned). | Card asks for a two-option radio; `ToggleGroup` has pressed-button semantics, not radio. Invariant 6 says add the primitive via the CLI rather than hand-roll. | ToggleGroup type=single — wrong a11y role. |
| 2026-09-27 | Review round 1 (ax-code-reviewer, no `name`, ~11 min, sha 955898d3139c8c073bb5b05890aca7dc3830e681): **APPROVE**, 3 Minor + 1 Nit, none changed. Accepted as documented: (1) the never-right failure window; (2) never-right on an already-closed id is a silent no-op retract plus a successful write — same no-oracle shape as `memory:forget`, and not reachable from the UI (Fix renders on active rows only); (4) `id` is validated but unused on the `changed` path — it keeps one input shape and is where a slot-less "changed" close would hook in. (3) is handed to TASK-630: an unforget that re-opens a row must clear `never_true`, or a later slot closure mislabels it `retracted`; and the Fix receipt (`kind: 'updated'`) carries no row, so an Undo on Fix needs the corrected id threaded through. | The reviewer could not run postgres or the canary locally (Docker); the builder's gate did, with `DOCKER_HOST=unix:///Users/vpulim/.orbstack/run/docker.sock` — postgres 212 passed / 10 skipped, preset-memory 56/56. | Re-dispatch for the minors — they are properties, not defects. |
