# TASK-778 — Blob GC 3/5: retire/restore/purge + enforce, remove blob:delete

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-10-04 | `blob:stat` gains an optional input `restore?: boolean` (default true). `restore: false` reports a retired blob's size WITHOUT moving it back. `@ax/disk-quota`'s `bytesGone` passes `restore: false` | Design D3 makes `blob:stat` restore on a live miss. disk-quota (#910) calls `blob:stat` on exactly the unheld shas the GC retires, so a restoring stat would move every retired blob back to live each reconcile: bytes never purged, charge never released, retire/restore ping-pong forever. A non-restoring probe that counts "retired" as "still there" keeps disk-quota's rule intact (release only once bytes are GONE, i.e. after purge) | Make stat never restore (breaks `artifacts:publish-blob`, which must revive a retired sha it is about to reference, and the GC's held-path restore); a separate `blob:exists` hook (more surface for one flag) |
| 2026-10-04 | Enforce retire order per sha: conditional row update first (`state='live' AND last_put_at < cutoff` → retired), then `blob:retire`; a retire that throws reverts the row and fails the sweep | A re-put landing between collect-refs and retire refreshes `last_put_at`, so the conditional update skips it and the blob is never moved. A row-retired/blob-live leftover is harmless: purge only deletes the retired key | Retire first, then mark (moves blobs a re-put just refreshed) |
| 2026-10-04 | Purge pass: held → `blob:stat` (restores) → row live, `last_put_at = now`; not held → `blob:purge` (retired key only) → delete the row only if it is still `retired` | A put or restore landing in between leaves a LIVE copy that purge cannot touch, and its row stays | Delete row unconditionally |
| 2026-10-04 | Report keeps `wouldRetire` / `wouldRetireBytes` (= candidates nobody holds this sweep) in both modes and adds `retired`, `restored`, `purged`, `bytesPurged`; `mode` is the sweep's mode. Channel-web is untouched | The admin line reads only `at`/`wouldRetire`/`wouldRetireBytes`; enforce copy ("Not removed yet" under enforce) is a follow-up card, and TASK-824 owns the line's staleness | Rename fields (breaks the UI parser) |
| 2026-10-04 | `blob_gc_report` is still logged, and `blob_gc_sweep { mode, discovered, candidates, held, retired, restored, purged, bytesPurged, aborted }` is added | Card item 6 names `blob_gc_sweep`; the operator walk (723d) reads `blob_gc_report` | Replace blob_gc_report |
