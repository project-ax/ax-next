# TASK-453 — the Activity feed's stale scope frame

- **Chose placeholders (skeleton rows), not blank and not hold-dimmed.** The
  card offered three behaviours. Holding the previous scope's rows cannot be
  rescued by dimming them: `ActivityFeed` DROPS the agent column when `agentId`
  is set, so the old rows render *unattributed* under the new agent's name —
  dimming says something about freshness, nothing about ownership. Blanking
  lands on the empty state, whose copy is a sentence ("The record of what Quill
  does is empty so far"), i.e. a claim we have read nothing to back. Only
  placeholders state the true thing: we are reading it.
- **`Skeleton` added via `pnpm dlx shadcn@latest add skeleton -c packages/channel-web`**
  (invariant 6). It was not previously installed; it is now.
- **The per-agent "What it did" tab CANNOT reach the stale frame.** `AgentView`
  is keyed on the agent id, so a switch remounts it, and the remount returns
  `Loading…` until its own `detail` read resolves — strictly after the feed's
  reset effect. So no `awaitingScope` prop is threaded into `AgentView`
  (Half-Wired policy); the tab lands in `ActivityFeed`'s own not-yet-loaded
  branch instead, which shows the same placeholders. Measured, not assumed: an
  `awaitingScope` recorder across Activity→agent/did recorded ZERO stale
  frames. If the `!detail` gate ever goes, the prop is needed.
- **The Activity subtitle ("N entries") is a counted claim too** and now also
  refuses the stale frame, same as `doneTodayFrom`.
- **#609's reviewer's "agent→agent `What it did` is unreachable" is an
  overstatement** — every `AgentView` renders a visible "What it did" tab
  trigger, so it was always two clicks. What was missing was the ONE-click path
  from the surface already about the record: a row's agent button on the
  Activity page now opens `tab:'did'` (`openAgentRecord`), while every other
  "open this agent" still lands on chat.
