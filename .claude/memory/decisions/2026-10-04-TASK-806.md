# Decisions — TASK-806 (skip never-signed-in connectors for the turn; owner decision A)

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-10-04 | **Pre-open partition in the orchestrator, right after `allConnectors` (effective ∪ skill-referenced) is built and BEFORE `foldConnectorCaps`.** A connector is skipped iff `credentials:has {ref,userId}` answers `present:false` for ANY of its folded refs. Skipped connectors contribute no hosts, no credential slots, no MCP servers, no installed entry. | The fold is where a connector becomes reach; filtering before it means a skipped connector cannot leak a host or slot into `proxy:open-session`. Verified the brief's INFERRED location: the runner's set is `connectorFold.installedEntries` → `sandbox:open-session.installedSkills`. | Filter after the fold (would need to unwind hosts/slots from shared Sets — error-prone). Filter only the effective set (skill-referenced connectors block the same way, so both). |
| 2026-10-04 | **Refs come from ONE derivation: `connectorCredentialRefs(c)` extracted from `foldConnectorCaps` and used by both.** Client-secret refs (TASK-797) are excluded there too. | Invariant 4 — a second copy of the `account:<id>[:<slot>]` rule would drift and ask the vault about rows the open never resolves. | Re-derive in the orchestrator (rejected: duplicate rule). |
| 2026-10-04 | **Fault posture: a `credentials:has` that throws, returns a non-boolean, or is not registered counts as PRESENT (connector kept).** Logged by error NAME only. | Card + security brief: a fault must never silently widen what is skipped. Keeping it reproduces today's behaviour (the open then fails/succeeds as before). | Treat a throw as absent (rejected: a vault blip would silently strip tools from every turn). |
| 2026-10-04 | **`needs-reconnect` untouched.** A rejected-refresh row still EXISTS, so `has` answers present, the connector is kept, the open throws `NeedsReconnectError` → `connector-needs-reconnect` as today. | Card scope: only "never signed in / no key" is skipped. | — |
| 2026-10-04 | **TASK-796/802 `signInReason`/`anyRefAbsent` + reasons `connector-needs-sign-in` / `provider-key-missing-connector-needs-sign-in` REMOVED from the orchestrator.** After the pre-open skip they are reachable only by a race (row deleted between the presence read and the open) or a throwing presence read, both of which read as `proxy-open-failed` like any other open failure. A missing provider key alone reads `proxy-open-failed` (pre-796 behaviour). | Card: "no dead branch". | Keep as a race fallback (rejected: dead in practice, and it doubled the presence reads on every failed open). |
| 2026-10-04 | **Client copy for those two reasons stays in `ERROR_LABELS` (reachable: turn-error rows persisted on prod since rev 35 replay on reload) but they leave `CONNECTORS_TAB_REASONS` (live-strip only; the live wire can no longer carry them).** | Card: "keep its UI copy only if still reachable". Replay IS a reader of persisted reason codes. | Delete the labels (rejected: an old conversation would replay as "The agent stopped unexpectedly"). |
| 2026-10-04 | **Agent is told via one line appended to `agentConfig.systemPromptAugment` (fresh spawn), names JSON-quoted after stripping control/format chars and clamping to 64 chars; the list is capped.** Normal mode only; NOT added to `systemPromptBootstrapAugment` (that is for person-authored, no-agent-writable content only — TASK-524). | The skip is decided on the fresh-spawn path and frozen for the session, exactly like the augment, so the line is true for the session's life. JSON quoting makes a name inert data: no newline/quote can break out. | A synthetic SKILL.md (rejected: discoverable-skill semantics, not a fact about the turn). |
| 2026-10-04 | **Warm session re-spawns once a skipped connector gets signed in.** The orchestrator remembers the skipped refs per session; on a routed turn it re-asks `credentials:has` for them and retires the session (`stale_session_respawn` reason `connector-signed-in`) if any is now present. Fault → no respawn. | Without it, the person signs in and the agent keeps saying "not signed in" until the warm session idles out — a regression vs. today, where the failed turn left no session and a retry picked the sign-in up. | Leave it to idle timeout (rejected: the notice's "Open Connectors, sign in" would not work on the next message). |
| 2026-10-04 | **Chat notice is derived client-side from the agent's Connectors rail (`health:'needs-sign-in'` rows), not a new SSE frame / subscriber hook.** Non-error, dismissible, "Open Connectors" button → the Connectors tab; names rendered as React text. | The rail's health IS the same `credentials:has` presence read for (caller, agent) (TASK-795) — one source of truth; no new hook surface (no boundary review); no SSE timing race (the skip is decided before the stream may be attached); survives reload. Reason codes never reach the UI. | New `chat:connectors-skipped` subscriber hook + SSE frame + chunk-buffer replay (rejected: ~6 files of wire for a fact the client already holds). |
