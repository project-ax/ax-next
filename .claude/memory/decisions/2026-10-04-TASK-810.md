# Decisions — TASK-810 (rail ignores the OAuth client-secret slot like the host; connector-card under the contract)

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-10-04 | **Filter in `credentialChecks` itself, so BOTH its callers change: the rail's needs-sign-in read AND the attach gate.** Both now skip a plan entry whose ref ends `:OAUTH_CLIENT_SECRET`. | The owner decision (Vinay 2026-10-04) is that the client secret is not a sign-in. The attach gate's job is "can this person use the connector" and the host runs the turn without that row, so requiring it at attach would refuse a usable connector — and the gate's `credentials:get` would be a resolving read of the admin's secret on a person's behalf, which is reach nobody needs (invariant 5). One function, one rule. | Filter only at the rail call site (leaves the gate and the rail disagreeing about the same connector). |
| 2026-10-04 | **Filter by REF suffix, not slot name** — exactly the host's test. | A lone slot named `OAUTH_CLIENT_SECRET` collapses to `account:<id>` (its own key, not the client secret); a name-based filter would drop it from the rail only. The #905 lone-slot fixture pins this. | Name-based filter (the card's wording, "skips the OAUTH_CLIENT_SECRET-named slot"): rejected, it would reintroduce drift. |
| 2026-10-04 | **Collapsed `connector-card.ts` onto the host's derivation rather than only testing it.** Extracted `connectorSlotRefs(connectorId, credentials)` in `connector-union.ts` (UNFILTERED, returns `{slotDef, ref, service, slotTag?}`); `connectorCredentialSlots` = it minus the client-secret suffix; `buildAuthoredConnectorCard` maps over it. | Same package (@ax/chat-orchestrator), so no cross-plugin import at all (invariant 2). Removes a copy instead of guarding it. The card must stay unfiltered: it SHOWS every slot and writes each key, so dropping the client-secret slot from the card would be a behaviour change nobody asked for. | Keep the private copy and only extend the contract test (keeps a fourth copy alive); filter the card too (hides a slot from the approver). |
| 2026-10-04 | **AND extended the #905 contract test to run `buildAuthoredConnectorCard`** (newly exported from the @ax/chat-orchestrator index, pure). The card's rows are reconstructed from `service` + `slotTag` — the address its write path builds — and it is handed the plan's refs as vaulted so every slot must report `haveExisting` (the read side of the same address). | Acceptance asks the contract test to cover connector-card.ts. Collapsing makes card == host by construction today; the test keeps it true if someone re-inlines a copy. | Test `connectorSlotRefs` directly (would not catch the card mapping service/slotTag wrong). |
| 2026-10-04 | **Contract restated as two groups, no per-fixture exception.** WRITERS (@ax/connectors plan, approval card) agree exactly; ASKERS (rail `credentialChecks`, host `connectorCredentialSlots`) agree exactly; askers = writers minus the `:OAUTH_CLIENT_SECRET` ref. The `hostRefs` override is gone; every fixture carries `refs` + `asked`. | The plan MUST keep the slot (the vault's global-read rule refuses a ref that is a plan slot), and the card writes it, so "full agreement" between all four is not achievable or desirable — the one honest reading of "no named exceptions" is that rail and host now agree with no carve-out. | Make the plan drop it too (breaks the TASK-797 second lock). |
