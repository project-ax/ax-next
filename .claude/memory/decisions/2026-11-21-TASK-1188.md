# Decisions — TASK-1188 (Slack: a team bot answers in private channels but never remembers them, design §4b.3)

Plan: `docs/plans/2026-11-21-TASK-1188-private-channels-plan.md`. Main at `8e92668bb` (TASK-1184 + TASK-1186 merged).

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-11-21 | **Builder planned inline instead of dispatching `ax-planner`, and implemented inline instead of per-task subagents.** | The builder had already read every file the card touches (channel-check, channels, capture-veto, channel-store recordThread, router job + bindBotChannel, answers step 8, manifest, agent-routes, AgentSlackBotChannels) before planning; a planner would re-read the same ~3k lines. The whole-branch `ax-code-reviewer` pass stays the adversarial check. | Dispatch the planner (about +30 min for the same reading). |
| 2026-11-21 | **"Private" means `is_channel === true && is_private`.** `connectable()` drops only its `!isPrivate` test. A conversation with `is_channel` false (a group DM, or a legacy private group created before March 2021) stays refused (`not-a-channel`). | `is_channel` already excludes group DMs and IMs; keeping it required means no new Slack flags to narrow. Legacy G-id private groups are a known gap (Slack documents them as `is_channel: false`). | Narrow `is_group`/`is_mpim` too (more untrusted-flag surface for a case no walk has seen). |
| 2026-11-21 | **Privacy is stored on the binding (`channel_slack_v1_channels.is_private`, default false), refreshed by every allowed check.** Bind writes it; the turn-start check and the Allow continuation update it when it changed. | The settings row needs it ("Private channels aren't remembered") without a Slack call per channel on every settings read; the capture veto needs the CURRENT state so public to private stops capture for every thread at once. | Ask Slack from the settings route (N calls per read, rate limits). Keep it only on the thread (the veto would miss threads with no turn since the change). |
| 2026-11-21 | **Capture is refused by the existing veto path: a thread whose turn (or Allow continuation) ran while private is sticky `not_remembered`, and any thread whose binding is private now is refused, both as `channel-not-remembered`.** recordThread ORs `b.is_private` and the caller's own `isPrivate` into `not_remembered` in its one statement. | Card: "the same veto path as the switch being off". Sticky per thread means private to public never later captures a thread whose transcript holds private-era words. | A distinct `channel-private` refusal reason (more surface; memory only logs it). |
| 2026-11-21 | **The `missing_scope` reading is unchanged: only a token lacking `channels:read` is "token-scope".** A bot that predates `groups:read` reading a private channel still gets `missing_scope`, a refusal (bind silent; a bound channel is disconnected once). | No team bot is deployed to prod; kind's walk bots get rebuilt. Extending the token-scope rule to `groups:read` changes TASK-1184's tested reading for a case that has no installs. | Treat a missing `groups:read` as token-scope (botUnavailable): better copy for a stale bot, more churn, no users. |
| 2026-11-21 | **The kept allowed answer (CHANNEL_CHECK_TTL_MS, 1 min) now carries `isPrivate`,** so a channel made private can still be captured for up to a minute. | TASK-1184 accepted the same minute for answering at all (and, before this card, for capture too), so this is no regression; it is written into the design's known gaps. | No cache (a mention flood becomes a workspace-wide rate limit). |
| 2026-11-21 | **The Allow continuation (`answers.ts` step 8) runs the same channel check (TASK-1184's named gap).** Refused: the prompt closes (`channel-not-allowed`); the binding is left for the next turn to remove. Unknown / token-scope: "try again" (prompt re-opens). Allowed + private: binding updated and the thread marked not remembered before the answer runs. | A prompt lives 24 h; the channel may have become Slack Connect or archived meanwhile. Removal and the "no longer allowed" line stay with the turn-start path, so one place disconnects. | Remove the binding from the click path too (two disconnect paths to keep in step). |
| 2026-11-21 | **A private-thread `not_remembered` may become a kept switch off at the next boot** (`migrations.ts` thread backfill keeps an off switch for a channel with no binding left where a not-remembered thread exists). Accepted, documented in §4b.3 known gaps. | Only reachable when a private channel's binding is removed before any boot kept its switch; the effect fails toward "off" (the safe side). A separate thread column for "private turn" would cost a second migration for an edge with no users. | A `private_turn` thread column the backfill ignores. |
| 2026-11-21 | **`recordThread` fails closed on `isPrivate`:** anything but a plain `false` from the caller counts as private (found when an untyped test fixture omitted it and Postgres got NULL). | A caller that didn't say must not let memory in. | Require it in SQL (NOT NULL error, no turn). |
| 2026-11-21 | **Private wins (security review, coordinator):** the check takes `knownPrivate`; a binding that says private never uses a kept public answer (Slack is asked; that fresh answer, asked after the binding was read, may clear it), and a public answer that a private one overtook in flight is returned as private. | A stale public answer (kept on another replica, or overtaken in flight) could otherwise `setPrivate(false)` over a newer private write and let a private channel be remembered. Costs one Slack call per turn only while the binding says private and the kept answer says public. | (2) a conditional UPDATE keyed on a checked-at column (new column, clock comparison across hosts); (3) never clear private from the turn path (a channel made public again would never be remembered again). |
| 2026-11-21 | **`is_private` from Slack: only literal `false` is public** (review F2). | Before, absent/null read as public through `flagged()`; public now lets memory in, so the one untrusted hop must fail closed. | Keep `flagged()` (absent = public). |
| 2026-11-21 | **Allow gate token-scope → `botUnavailable`, prompt released (review F4); binding gone at the privacy write → close as disconnected (F10).** | Same reading as the router: no retry fixes the token. | "Try again" (the first build's choice). |
| 2026-11-21 | **Outsiders' turns in a private channel stay as built, documented as a gap + follow-up (review F3).** The requester (a team admin) can read those conversations in the web app. | The card says the bot answers in a private channel it was invited to; who may read external transcripts is a product call outside this card. Nothing is captured into memory either way. | Refuse outsiders in private channels (new copy and behaviour no card asked for); hide the conversations. |
