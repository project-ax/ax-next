# TASK-825 kind-tooling guard test: grep -q + pipefail, not a lost PATH

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-10-04 | ROOT CAUSE is in the Makefile, not the harness: `kube-guard`/`gke-guard` read `config get-contexts` with `grep -Fxq`. `-q` exits at the first match; if the wanted context is not the LAST line, kubectl's next write gets SIGPIPE (141) and `.SHELLFLAGS := -eu -o pipefail` turns that into the REFUSING branch. Fixed with `grep -Fx … >/dev/null` (reads to EOF). This CORRECTS the 2026-09-30 row in `decisions/2026-09-29-TASK-720.md`, which guessed "a lost PATH prefix bypasses the shim" — the shim WAS reached; it answered correctly and was killed mid-answer | MEASURED in a Linux container (GNU Make 4.3): strace shows the stand-in's single `printf '%s\n' "$list"` makes TWO writes (bash line-buffers stdout); bare pipeline under load: `grep -Fxq` 45/4500 failures vs `grep -Fx >/dev/null` 0/4500; the real test file under 24 CPU hogs: 1/25 runs failed with the exact CI signature. Only the gke success case lists its match FIRST, which is why only it failed. macOS never failed because make 3.81 ignores .SHELLFLAGS (no pipefail) | Retry/skip (forbidden by the card); reorder the fake list so the match is last (hides a real bug — a real kubectl with many contexts hits the same SIGPIPE); drop pipefail from the guard (weakens fail-closed on a kubectl error) |
| 2026-10-04 | Made the regression check deterministic and OS-independent: the kubectl stand-in writes the context list one line at a time with a 0.2s pause and `trap '' PIPE`, records any EPIPE in `SHIM_EPIPE_LOG`, and exits 141 like a real kubectl. Success cases assert `brokenPipes == []`; a new case lists the kind context first. Against the old Makefile: red 5/5 on Linux, red on macOS too (via the EPIPE record, since macOS has no pipefail) | The race needed CI load to show; a pause makes "reader quit early" a certainty, and the EPIPE record does not depend on make honouring .SHELLFLAGS. Cost ~+3s on the file | Env-gated pause only in one new test (leaves the existing success case racy against a regression) |
| 2026-10-04 | Success-path assertions now use a `diag` message: make output + PATH head + `command -v kubectl` under the same env + the get-contexts answer + broken-pipe writes + recorded calls | The CI failure only printed make's REFUSING line, which pointed every reader (the card, the TASK-720 row) at the wrong layer | - |
