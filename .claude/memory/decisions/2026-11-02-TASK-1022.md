| 2026-11-02 | **The pre-flight is a `probe` query key on the two existing download routes. It is not HEAD, and it is not the chip status route.** | `@ax/http-server` has no HEAD. `HttpMethod` is GET/POST/PUT/PATCH/DELETE (`types.ts:4`), and a HEAD request gets a 405 (`plugin.ts:440`). TASK-1017 already turned HEAD down for this reason. The status route exists only for the conversation scope. It reads length 0, has no 413 by design, and runs on every chip mount and every turn, so it has to stay cheap. A query key keeps one handler, one ACL and one path validation. The router matches the pathname only, so the splat never sees the query. A `?` in a key arrives `%3F`-encoded inside the splat. | Add HEAD to `@ax/http-server`: a shared-infra change for one caller, which would also need HEAD's header and body semantics. | 2026-11-02 | **The probe is `sendUserFileDownload` itself, with `probe: true`.** Every pre-head read and check runs unchanged: the first range (≤ 1 MiB), the 1 GiB ceiling, the byte count, and the final check on a one-range file. At the point where the download would set its head, the probe answers `200 {downloadable: true}` instead. It never sets the download headers and never calls `bodyStream()`. | One code path, so the probe cannot drift from the download's answers, and a 409 found during the probe is said in words.
