| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-09-27 | **Two hooks: product `memory:unforget {ids} -> {restored}` over a new engine hook `memory:facts:reinstate {ids, ownerUserId?} -> {reinstated, resettled}`**, not a flag on `memory:facts:supersede`. | The product layer never talks storage; the engine owns closure. A separate verb keeps `supersede`'s "close only active rows" contract untouched. Supersedes TASK-623's "no un-forget exists, so Undo re-saves as the person" row. | `supersede {reopen: true}` — one hook meaning two opposite things; product-layer re-record with the old provenance — would need a privilege field on the write path and still mint a new id. |
| 2026-09-27 | **Reinstate only re-opens RETRACTIONS** (`closed_by IS NULL`, finite `valid_end`), clears `never_true` in the same UPDATE, then replays the row's `(about, slot)` chain in the same transaction. | Undo must put the store back where it was: the neighbour the retraction re-opened is closed again; a row that arrived meanwhile closes the reinstated one. A rule-closed row was never forgotten, so it is not a target. `never_true` must go or a later slot closure mislabels it (TASK-624 reviewer note). | Re-open without replay — leaves two active rows in a slot. |
| 2026-09-27 | **Scope = `memory:forget`'s** (owner on personal, tenant on team via `memoryReadScope`); **no server-side time window**. | Whoever could forget a row can bring it back; unforget restores the ORIGINAL provenance, never raises it, so it grants nothing a re-save could not. The UI's 10 s window is a UX offer, not a security boundary. | A server-side window — adds clock state for no capability reduction. |
| 2026-09-27 | **`memory:unforget` names `restored` ids** (unlike forget's `{}`); **the UI treats any 200 as restored.** | No oracle: an out-of-scope id is absent whether or not it exists. An empty `restored` in practice means "already back" (retry after a lost response, second tab), so "Remembered again" is true and the re-read shows the rest. | Treat empty as failure — a retry after a lost response would then fail forever. |
| 2026-09-27 | **`memory:facts:reinstate` is a HARD `calls` entry** of @ax/memory. | Both engines register it; an engine without it cannot keep Undo's promise. Unit stubs do not run verifyCalls, so no stub churn. | optionalCalls — would ship a silently broken Undo. |
| 2026-09-27 | Contract test: the provenance-immunity case records human+agent in ONE batch. | Two separate `record` calls in the same ms fall back to random-id replay order; a human row replayed AFTER a later-dated agent row is bounded by it (rule 2 reach is rank <= arrival). Flaked 1-in-N locally. Pre-existing honest limit documented on `resettleSlotGroups`, not introduced here. | Sleep between records — slower and still a timing assumption. |
| 2026-09-27 | Implemented inline rather than one subagent per task. | Five small, tightly-coupled tasks sharing one new type; coordination would cost more than the context saved. | Subagent-per-task. |
