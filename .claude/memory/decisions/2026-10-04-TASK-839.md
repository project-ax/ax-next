# TASK-839 — aisdk connectors re-initialize a dropped MCP session (2026-10-04)

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-10-04 | SUPERSEDES the TASK-826 shard's "Known gap (follow-up): no re-initialize after the server drops the MCP session (404)" — closed by this card. | That line is what filed the card; it is now false. | — |
| 2026-10-04 | Trigger = `StreamableHTTPError` with `code === 404` AND the failing connection's transport had a `sessionId`. A stateless server's 404 (no session) and every other status are plain failed calls. | The streamable-HTTP spec says only a 404 on a request carrying `mcp-session-id` means "session gone, re-initialize". MCP SDK 1.30.0's client has no 404 handling of its own (measured: the call throws `Error POSTing to endpoint: {..."-32001","Session not found"...}`). | Retry on any 404, or on any transport error: retries things the server may already have run. |
| 2026-10-04 | Retry the tool call exactly once after a successful reconnect. The policy wrap sees ONE call (one pre/post), not two. | The server refused at session lookup, before any tool ran, so the retry cannot double-execute. One retry bounds the loop. | Retry until success: unbounded against a server that keeps forgetting. |
| 2026-10-04 | The reconnect is single-flight per connector and is NOT re-listed (`initialize` only); bounded by the same `connectTimeoutMs` as the boot connect. One call's Stop stops that call waiting, not the shared reconnect. | Concurrent calls on one dead session should cost one handshake. The tool catalogue is fixed for the session; if a tool vanished on restart, the retry fails like any other call. | Re-list and rebuild tools mid-session: changes the catalogue under the model. |
| 2026-10-04 | A replaced connection is RETIRED, not closed: it closes when its last in-flight call settles, and `close()` closes every still-open connection (current + draining). | Measured: closing the stale SDK Client at once rejected a concurrent in-flight call with `MCP error -32000: Connection closed`, which is not a 404 and so was never retried. | Close immediately: kills sibling calls. |
