# TASK-692 per-user spend and rate limits

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-09-29 | Card premise REFUTED: model calls do NOT pass through `llm-*`. Agent traffic goes runner (sandbox) -> credential-proxy MITM byte pipe -> provider; `llm:call:*` only serves host helper calls (titles, memory extraction, skill safety scan) | Read `credential-proxy/src/listener.ts` (`handleMITMConnect`: raw pipe, no response parsing, audit once per CONNECT tunnel) and both runners' `provider.ts` / `main.ts` | Meter in the proxy (needs an HTTP/1.1 response framer + gunzip + SSE parse in a file TASK-687 is editing; failure mode is breaking ALL model traffic) |
| 2026-09-29 | Split the card's one "chokepoint" into gate + meter. Gate = `chat:start` veto (every turn from every entry point passes `agent:invoke`); meter = runner-core `EndTurnInput.usage` REQUIRED (`TurnUsage \| null`) -> `event.turn-end` -> `chat:turn-end`; `null` is charged a flat assumed cost | No single point both sees every call and knows its usage; the type-required field is what makes "a new runner can't skip it" true at compile time, and the assumed cost makes a lying/absent report never free | Optional usage field (a new loop silently skips it); runner-side enforcement (runner is untrusted) |
| 2026-09-29 | Rolling 24h / 1h windows over per-minute buckets in Postgres, not calendar-day counters | Calendar reset lets a user burn the cap at 23:59 and again at 00:01; one indexed range query answers both windows | Redis-style counters (no Redis here); per-day rows (reset abuse) |
| 2026-09-29 | Cap is estimated USD (tokens x built-in price table), unknown models priced at the top tier | Operators think in dollars and a token cap is 15x apart across models; over-count beats under-count for an abuse control. Cache read/write tokens carried separately because cache reads are 10% of input price and would otherwise over-count 10x | Token cap (uncorrelated with the bill); admin-editable prices (YAGNI) |
| 2026-09-29 | Defaults: $5.00/day/user, 60 turns/hour, $0.25 assumed per unreported turn. Stored as `settings:usage-limits`, admin-editable in a UI tab, no env var | Brief: conservative admin-changeable defaults, no deploy. Sonnet-class agentic turn is roughly $0.05-0.20, so $5 is ~25-100 turns/day | Higher defaults (blocking power users on day one is cheaper than a surprise invoice) |
| 2026-09-29 | Admit check fails CLOSED and runs in a per-user advisory-lock transaction | `bus.fire` isolates a throwing subscriber, so a naive throw would fail OPEN on a money control; the lock stops two simultaneous messages both slipping under the cap without serialising different users | Fail open (silent unmetered spend); global lock (one user blocks everyone) |
| 2026-09-29 | Claude-sdk usage: sum per-API-response usage from `assistant` messages de-duplicated by message id (max per field), reset at each `result` | The SDK's `result.usage` may be cumulative across the streaming query and cannot be verified from the types; per-message ids are deterministic. Multi-block responses are several SDK messages with the same id and usage | Delta of `result.usage` (wrong if per-turn); `total_cost_usd` (claude-sdk only, not uniform across runners) |
| 2026-09-29 | Kill switch = a suspension row checked at `chat:start` + best-effort interrupt of the user's in-flight turns via `conversations:list` + `agent:interrupt` | No credential-proxy change; works after a host restart because the in-flight set is read from conversations, not memory | Proxy session revoke (touches TASK-687's file) |
| 2026-09-29 | Review finding (ax-code-reviewer, Important): a `decision-resolved` wake-up (queued by `@ax/decisions` on approve, dismiss or expiry) starts a turn WITHOUT `agent:invoke`, so `chat:start` never gated it. Fixed with a new veto subscriber hook `chat:resume`, fired by `deliverResolution` as the decision's OWNER before it queues; usage-limits judges it like a start (counts as a turn). A refusal returns `{ delivered: false, reason: 'refused' }`: the agent is not woken, and the expiry sweep treats it like any delivery nobody received, so the host replay STILL makes the approved call | The design note claimed "every turn passes agent:invoke"; grep of `session:queue-work` producers showed `decision-resolved` was the only other turn starter. Round 2 of the review showed my first version (skip the replay on `refused`) was inconsistent: the cold-agent path (`no-session`) never reaches the gate and unattended decisions replay on the host without `deliverResolution` at all, so a paused account got its approved call run anyway depending on timing, while a legit over-cap person's approval would be silently stranded (`delivered_at` already claimed). The gate stops MODEL TURNS (spend); a call a person already approved is not spend. Skip removed; the residual (one approved call per hold created before the pause) is documented | Gate the replay too via a read-only suspension check (would strand approvals of over-cap people; needs another hook); skip replay on `refused` only (inconsistent, the version round 2 rejected); gate inside the runner or at `session.next-message` (runner untrusted / bigger change) |
| 2026-09-29 | Kept `USER_ID_RE` (`^[A-Za-z0-9][A-Za-z0-9_.@-]{0,127}$`) on the suspension route despite the reviewer's charset-coupling note | It is the platform's own user-id charset (`@ax/credentials` enforces the same regex on every `credentials:get`), so an id outside it already breaks the product elsewhere | Relax to a length + control-char check (would let a malformed id into a URL path) |
| 2026-09-29 | Added "It's a safety limit, not a bill: models we don't recognize are counted at a high rate" to the daily-limit help text | Reviewer: non-Claude models (all OpenRouter slugs) are priced at the top tier, so the $5 default trips early on a cheap-model fleet; an admin needs to know why and that raising the limit is the fix | A price-override setting (YAGNI until launch runs on a non-Claude model) |
| 2026-09-29 | NOT built (YAGNI, listed in the design note): per-user overrides, fleet-wide cap, admin-editable prices, user-facing usage page, charging abnormally-ended turns, proxy-side metering of direct provider calls from sandbox user code | Each is a follow-up card if launch shows the need; the proxy one is the known residual gap | none |
