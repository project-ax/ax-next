# Decisions — TASK-569 (approve while the held reply streams: continuation stream closed early)

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-09-26 | Root cause is the per-connection `chat:turn-end` subscriber in `channel-web/src/server/sse.ts`, which matched on `ctx.conversationId` ALONE. Approving mid-stream binds the continuation reqId B while the held turn still runs under reqId A on the same conversation; A's turn-end closed B's stream (walk: attach +44ms, FINISHED +1.28s). The orchestrator's "stream registry keyed by reqId" hypothesis was half right: the chunk/phase/turn-error subscribers already key on reqId; turn-end was the one that did not. | `conversations` compare-and-clears `active_req_id` on the payload reqId (A != B, so no clear) and the chunk-buffer evictor evicts by payload reqId, so only the SSE close was wrong. The runner (`agent-runner-core/run-runner.ts`, sole `event.turn-end` emitter) stamps the inbox entry's reqId on BOTH turn-ends (tool + assistant) and adopts the decision-resolved entry's continuation reqId. | Client-side fix (reopen on premature done) — rejected: the fault is server-side and a reopen would race a real done. Fix in the runner (defer the decision turn) — rejected: the runner already sequences correctly; only the close filter was loose. |
| 2026-09-26 | Match `payload.reqId` only WHEN it names one; a reqId-less turn-end keeps the old conversation-only close. | A reqId-less turn-end comes from a turn run dark (no stream addressed). Requiring a match there could leave a stream open forever (keepalive holds it), which is worse than the pre-fix behaviour. A test pins the fallback; a mutant that drops it reddens that test. | Strict reqId-only match — rejected: hang risk for any producer that omits reqId. |
| 2026-09-26 | Implemented inline (one production file, two tests), no per-task subagents; reproduced in `sse.test.ts` against the real handler + bus rather than on kind (dispatch forbade the cluster). | Single-file surgical fix; the unit harness uses the real subscriber, so the test is the fault itself. | Docker-backed stream-e2e — rejected: same subscriber, far slower, adds no signal. |
