# Decisions — TASK-625 (memory extraction during a conversation)

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-09-27 | Trigger = `chat:turn-end` (assistant role only) with BOTH card triggers: idle 2 min (`incremental.idleMs`) and every 4 completed user turns (`incremental.everyUserTurns`); `chat:end` takes the remainder. A "completed user turn" = a new `reqId` on an assistant turn-end (one reqId per user message; a missing reqId counts each turn — early pass is harmless). | The card settled the cadence. `chat:turn-end` is the only per-turn host hook (ipc-core fires it after the turn is persisted). reqId counting avoids a transcript read per turn. | Read `conversations:get` on every turn-end to count user turns (a DB read per turn). |
| 2026-09-27 | Source of turns for passes = `conversations:get` (display log), reading only `text` blocks of user/assistant turns. | `chat:end`'s `outcome.messages` has no ids and is per-session. The display log is append-only (no DELETE on `conversations_v1_events`) and holds the user turn (orchestrator persists it) and assistant turns, with the `turnId` the chat UI keys on. | Runner jsonl uuid on turn-end payload (not on user turns; UI never sees it). |
| 2026-09-27 | REFINES the card: `sourceTurnId` = `conversations:get`'s `turnId`, which @ax/conversations mints as the POSITION in the append-only display log (`${turnIndex}`). It does not shift (the log never deletes); the card's "not an index that shifts" worry is about per-session `chat:end` history indices. It is opaque to memory. | It is the only id the UI has for a message, so it is what TASK-626/627 can link to. | Change @ax/conversations' turnId to the event `seq` (UI/regenerate surface change, out of scope). |
| 2026-09-27 | Durable per-conversation cursor in `storage:*` (key `memory:observer-cursor:<conversationId>`, `{"next": n}`); incremental path requires conversations:get AND storage:get/set, else the legacy chat:end-only path runs unchanged (CLI). Unreadable cursor = failure event, no extraction. | An in-process cursor lost on host restart would re-extract under a new range/key = duplicates. Written after the record, so a lost write re-runs the same range = same batchKey = engine no-op. | In-process cursor only (duplicates after restart). |
| 2026-09-27 | batchKey for a pass = sha256(['turns', conversationId, owner, firstTurnId, lastTurnId]). Legacy chat:end key unchanged. | Card item 3; owner kept for the TASK-434 team-agent reason. | Hash content too (no benefit on an append-only log). |
| 2026-09-27 | Context turns (≤2) are shown to the extractor; the pinned prompt cannot be told to ignore them, so facts are attributed deterministically by word overlap (`attribution.ts`): dropped when a context turn scores STRICTLY higher than every new turn; ties go to the new turn; zero-overlap paraphrases are kept on the last new turn of the speaker's role. | "Prompt unchanged" + "context turns yield no statements" + "per-statement source turn" leave post-hoc attribution as the only option. A first version dropped only zero-overlap facts and the cost test caught context facts leaking back as duplicates via shared ordinary words. | Change the extraction schema to report a line number (breaks the pinned prompt); drop context entirely (card asked for it). |
| 2026-09-27 | Known residual: a new turn that only confirms a context turn ("yes, book that one") yields a fact whose words live in context, so it is dropped. | Price of the pinned prompt; bounded because the context turn's own facts were extracted by the previous pass. | — |
| 2026-09-27 | Fresh range for idle/turns passes ends at the LAST assistant turn; trailing unanswered user turns wait. `chat:end` takes everything. | Otherwise a user message persisted just before an idle pass would be split from its answer, and the answer-only next pass would skip as no-user-content (context user turns now count for that check). | — |
| 2026-09-27 | Cursor advances on every returned outcome (recorded / skipped / timeout / schema-failure — the legacy path already drops those batches); stays put on a throw (transcript read, provider, engine, cursor write). | Matches legacy drop semantics and bounds cost; transient infra failures retry on the next trigger. | Keep cursor on timeout too (unbounded retries of a too-long range). |
| 2026-09-27 | Paused user: idle/turns passes skip before reading anything (`skipped: paused`, debug); the chat:end pass always tries. | Only a resolved call clears the pause; skipping bounds error-event volume to one per session. | Attempt every pass (N error events per conversation). |
| 2026-09-27 | chat:end on the incremental path runs the final pass whatever the outcome kind. | The turns a crashed session persisted are real; the legacy path skipped terminated outcomes only because it had no transcript. | Skip terminated (loses those turns). |
| 2026-09-27 | `sourceTurnId` added to the facts contract + both engines (validated like conversationId: non-string rejected), stored and echoed; NOT added to `MemoryStatement` / `memory:recall`. | Card requires storing it; the UI consumer is TASK-626, which decides the read surface (likely a per-conversation feed hook). | Expose on memory:recall now (surface with no reader). |
| 2026-09-27 | Measured cost: a 10-exchange conversation with N=4 makes 3 extraction calls (turns@4, turns@8, chat:end remainder) vs 1 before; one call per trigger (+1 schema retry max, unchanged). Idle-only conversations: 1 call per quiet period. | Card acceptance asks for the number. | — |
