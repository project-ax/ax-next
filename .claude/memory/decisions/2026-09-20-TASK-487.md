# TASK-487 — `@ax/embeddings`: the producer for `embeddings:embed` / `embeddings:rerank`

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-09-20 | **The plugin is NOT added to `PROVIDER_ENDPOINTS` (`packages/core/src/providers.ts`), contradicting the card and design §6.2.** The credential ref is required plugin config instead. | `providers.ts:1-28` scopes that table to *"the one table both sides of the **sandbox** boundary read"*: `egressHost` is the **sandbox's** egress allow-list entry, `credentialEnvVar` is the `ax-cred:<32-hex>` placeholder env var **inside the sandbox**, `baseUrl` is what the **in-sandbox runner** dials. `@ax/embeddings` is host-side; no runner ever dials it, and it needs none of those three fields. Worse, a row there has two automatic, un-opt-out-able side effects: `chat-orchestrator/src/orchestrator.ts:106-124` derives `KNOWN_PROVIDERS` from `Object.values(PROVIDER_ENDPOINTS)` and re-exports it publicly, and `credentials-admin-routes/src/destination-routes.ts:114-120` derives the `{kind:'provider'}` credential-destination `z.enum` from `Object.keys(...)`. An embeddings row would therefore advertise itself as a known **LLM** provider. That is the Invariant-4 failure the table's own docblock is written to prevent, in the other direction. | (a) Add the row anyway, as the card says — REJECTED on the evidence above. (b) Add a new `Destination` kind (`{kind:'embeddings'}`) — REJECTED as out of scope: it spans `@ax/credentials`, `credentials-admin-routes` and `channel-web`, and the epic's preset+canary card is where credential seeding belongs. Filed as a follow-up. |
| 2026-09-20 | **There is no host-side egress lock to route through, so "routed through the existing egress lock" (design §6.2) is implemented as its enforceable half: fixed hosts from a closed in-code table + credential-store credentials + never `process.env`.** | `@ax/credential-proxy` *is* the egress lock, and it gates the **sandbox**: it MITMs HTTPS for runner subprocesses launched with `HTTPS_PROXY` + its CA (`packages/credential-proxy/src/listener.ts`), and the host widens its allow-list through `proxy:open-session` / `proxy:add-host`. Host-side plugins have no such wrapper — `@ax/llm-anthropic` constructs an SDK client directly, and `@ax/web-tools` does `cfg.apiKey ?? process.env.ANTHROPIC_API_KEY` with a raw SDK call (`packages/web-tools/src/plugin.ts:65,95-98`). Saying "we routed it through the egress lock" when no such host-side thing exists would be a false security claim in a security note. Stating the gap is worth more. | Route host-side traffic through the credential proxy — REJECTED as a large architecture change that this card cannot own, and the proxy's MITM CA is provisioned for sandbox clients, not the host. Filed as a follow-up. |
| 2026-09-20 | **Mode is decided by CONFIG, never derived from whether a credential happened to resolve.** No `embed`/`rerank` config ⇒ local-only for that hook; configured ⇒ remote, and a missing credential at call time **degrades** (the caller gets no answer and raises its own `degraded` flag) rather than silently falling back to the hash embedder. | The local/remote gap is 80.0% → 56.7% on the n=30 smoke. A fallback that quietly loses 23 points of accuracy is indistinguishable, from the outside, from working — which is exactly the failure design §4.4 makes `degraded` observable to prevent. A deployment that *wants* local-only says so. | Derive the mode from credential presence — REJECTED: it converts a misconfiguration into a silent quality regression. |
| 2026-09-20 | **`undefined` is the handler's "no answer", and no failure path throws out of the handler except a malformed INPUT payload.** | `packages/memory-facts-sqlite/src/producers.ts` guards with `== null` precisely so a nullish producer answer degrades instead of exploding — that `=== undefined` bug briefly turned one misconfigured provider into a deployment-wide **write** outage on TASK-434, because `embedTexts` is awaited *outside* the store transaction. Returning `undefined` is the shape its guard is already written for. A malformed *input* payload is the opposite case: that is a caller bug, and `invalid-payload` must stay loud (the same split `memory-facts-sqlite` draws). | Return `{vectors: []}` on failure — REJECTED: for a 1-text query the arity check degrades correctly, but it is a lie for the 0-text case and it says "here are no vectors" where the truth is "I could not answer". |
| 2026-09-20 | **Cohere rerank answers are required to cover every index exactly once, and a partial answer is refused rather than padded with zeros.** `top_n: documents.length` is sent explicitly. | `dem-memory/src/models/reranker.ts` pads: it allocates `new Array(n).fill(0)` and writes only the indices Cohere returned, so a default `top_n` silently scores the rest `0`. The consumer's own docblock (`producers.ts`, `rerankDocuments`) rejects that reasoning out loud — *"a partially-scored pool reorders on invented zeros, which is a worse answer than the fused order the caller already has"* — but it can only see arity, and the padded array has the right arity. So the check has to live on the producer side. A deliberate, documented divergence from the reference. | Port dem's padding faithfully — REJECTED: faithfulness serves the rung-4 replication only where the reference is right, and here it defeats a guard the consumer explicitly wanted. |
| 2026-09-20 | **No retry / backoff on either upstream call.** One attempt, aborted at `timeoutMs`. | The consumer enforces `EMBED_TIMEOUT_MS = 1_500` / `RERANK_TIMEOUT_MS = 2_000` and abandons the promise at that point. `dem-memory`'s embedder retries 4 times with `1000 * 2**attempt` backoff, reaching ~8s — every retry after the first would answer a caller that stopped listening seconds ago, while still paying for the tokens and still holding the socket. | Port the backoff — REJECTED as provably unreachable value under the caller's budget. |
| 2026-09-20 | **Vertex is the remote embedder and Cohere the remote reranker; exactly one fixed host each, no region config.** `us-central1-aiplatform.googleapis.com` and `api.cohere.com`. | The store pins `EMBEDDING_DIMENSIONS = 384` (`packages/memory-facts-sqlite/src/schema.ts:19`). Vertex `text-embedding-005` is Matryoshka and takes `outputDimensionality: 384`; Cohere's embed models are 256/512/1024/1536 and would not fit the `vec0` column. Vertex is also what rung 1 measured, and the ladder only works if rung 4 replicates rung 1. A free-text `region` would make the host caller-derived, which is the one property "fixed hosts" is about — so a second region is a one-line table edit, not a config field. | A configurable base URL — REJECTED: that is the raw-`fetch`-to-anywhere shape design §6.2 forbids. Multi-vendor embedder support — REJECTED as YAGNI and dimension-incompatible. |
| 2026-09-20 | **`model` and `projectId` are interpolated into the Vertex URL, so both get strict grammars and are rejected otherwise.** | They arrive from deployment config and (for `model`) from the hook payload, which the consumer fills from *its* config. "Deployment-supplied" is not "trusted": a `model` of `../../../other-project/...` is a path-traversal primitive against an API URL. Closed grammar over a free string, the same reasoning `providerEndpointFor` uses for its own-property check. | Trust the config — REJECTED. |
| 2026-09-20 | **The wire shapes move into `packages/embeddings/src/wire.ts` and are a structural PEER of `memory-facts-sqlite/src/producers.ts`'s copies, not a replacement.** | The card's boundary review says the schema of record moves into the producer's directory, and it should — but Invariant 2 forbids the engine importing our types, so the two declarations must stay duplicated by construction. Both files now name the other in a comment so the next reader does not "fix" the duplication by adding a cross-plugin import. | A shared `@ax/embeddings-contract` package — REJECTED: TASK-434 already hit the wall that `@ax/memory-facts-contract` cannot be imported as a value from plugin code (it depends on `vitest` at runtime), and a types-only package for four interfaces is not worth a build target. |
| 2026-09-20 | **This card deliberately does not wire the plugin into any preset (Invariant 3 carve-out), as the card instructs — and the better reason is not the card.** Wiring it in local-only mode *would* have been free of egress, so "it is not safe yet" is not the argument. The argument is that pointing `@ax/memory-facts-sqlite`'s `embedder` at a hash embedder turns the dense recall channel ON in the CLI, and hash-embedding dense recall is an **unmeasured** retrieval change. TASK-434 refused exactly this class of change by fiat ("an unmeasured retrieval change made at rung 2 would make the rung-4 number answer a different question"), and rung 4 is what this card exists to serve. The epic's preset + canary card owns the flip, with the measurement. | *Correction to an earlier draft of this row:* it claimed `@ax/memory-facts-sqlite` shipped un-wired under the same carve-out. **That is false** — `packages/cli/src/main.ts:38` loads it and `presets/k8s/src/index.ts:57` loads the postgres twin. What TASK-434 actually shipped un-wired is the *producer*, which is this card. `bootstrap.ts`'s `verifyCalls` skips `optionalCalls`, so an unregistered producer stays non-fatal at boot and the degraded state is the designed one. | Wire it here in local-only mode — REJECTED on the unmeasured-retrieval-change argument above, not on safety. Wire it here in remote mode — REJECTED outright: new outbound egress carrying user memory into a preset in the same PR that introduces the egress, with no canary to prove it. |
