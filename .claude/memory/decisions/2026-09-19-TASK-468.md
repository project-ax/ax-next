## 2026-09-19 — TASK-468 — the mutation-restore rule is a PRECONDITION, not a command

**Decision.** The rule agents follow when mutation-testing is:

> `git checkout -- <path>` restores exactly what you mutated and nothing else **if and
> only if that path was committed-clean before you mutated it.**

Not "use `git checkout --`". That sentence, prescribed after the first incident, is the
*recommended* restore for the agent that owns the worktree and committed first and the
*destructive* one for anyone else sharing the tree — and it is lossy even for the owner
when the file carries other uncommitted work.

**Per role, because the two roles must be told different things:**

| role | path state | do |
| --- | --- | --- |
| worktree **owner** | clean | mutate; restore with `git checkout -- <path>` |
| worktree **owner** | dirty | **commit it first**, then mutate |
| **subagent in someone else's worktree** | clean | **prefer not to** — "clean" is a snapshot, not a property, and the owner may be running a build that picks up your live mutant. If you must: announce the window, re-check immediately before restoring, and stop if the path is no longer dirty. |
| **subagent in someone else's worktree** | dirty | **do not mutate it** — you may neither commit someone else's WIP nor restore over it. Say so. |

**Is "commit before you mutate" sufficient?** From the owner's chair, yes — it covers all
four measured incidents. It is *insufficient as the stated rule* because it is actively
wrong for a subagent in a tree it does not own. State the precondition; "commit first" is
how the owner satisfies it.

**Evidence (4 instances, 3 mechanisms, all 2026-09-18/19):**

1. file-copy restore silently reverted another agent's **committed** fix (TASK-406);
2. a reviewer subagent sharing the builder's worktree `git checkout --`'d away **six of
   the builder's uncommitted edits** (TASK-471 owns the reviewer-side protocol);
3. two builders lost work to `git checkout -- <path>` reverting the **whole file** — one a
   25-line comment, one its entire uncommitted fix;
4. one reviewer kept `git status --porcelain` clean throughout by restoring from its own
   copy — achievable, but only because a human typed the hazard into its brief.

**What no restore protocol covers:** a second writer touching the path *during* the
mutation window — and note a second **reader** is enough to do damage, because the owner's
build can pick up your live mutant and the owner then debugs it as their own code
(TASK-426). The fix for that is one writer per window — TASK-471, not this card.

**Review findings taken, and why they changed the design** (ax-code-reviewer, 3 Important):

1. *Row 3 re-authorized the reviewer incident.* Accepted. A subagent in a clean shared tree
   is not safe merely because the path is clean; the row is now "prefer not to", with a
   re-check immediately before restoring. This also makes TASK-471 purely **additive**
   rather than a contradiction of this card.
2. *The blocks could not be run the way agents run them.* Accepted. Agent Bash calls do not
   share shell state and the restore fires a red test-run later, so the restore block now
   binds its own `F=` and carries the same "did you substitute `$F`?" hint. The structure
   check moved from "zero `F=` in the restore" to "exactly one per block".
3. *A **committed** mutant defeated the protocol silently.* Accepted, and it is the sharpest
   of the three: `git checkout --` over a committed mutant is a no-op that prints success.
   The restore now refuses a path that is **already clean** — stateless, no baseline file,
   and it also catches "someone else already wrote over my mutant".

Also taken: the `some(/^exit 1$/)` structure check was weaker than its name (it now counts
refusals and exits and requires them equal, and mutant M2 went back to its one-token form);
the incident-1 fixture had a dead write and now re-applies the mutant on top of the
sibling's commit, so it stands without its control; one templates.md assertion is labelled
"passes either way — a drift tripwire, not coverage"; `:(literal)` pathspecs close the
`[`/`*`/`?`-in-a-filename hole; the archive rows that still prescribe a `cp` restore are
superseded in the mistakes shard.

**Not taken:** nothing. Every finding was either applied or is recorded above as a
documented limitation (`assume-unchanged` / `skip-worktree` is named in the doc as an
unclosable hole, since nothing in the protocol sets it).

**Where it lives:** `yolo-ship` SKILL.md Phase 4 (rule + per-role table + two fenced
runnable blocks marked `# ax-mutation-restore: precondition` / `: restore`), and a bullet
in the auto-ship code-lane dispatch prompt. Before this, `templates.md` contained no
`git checkout --` text at all — the rule reached builders only as a per-run orchestrator
habit.
