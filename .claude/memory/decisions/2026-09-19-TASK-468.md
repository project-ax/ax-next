## 2026-09-19 — TASK-468 — the mutation-restore rule is a PRECONDITION, not a command

**Decision.** The rule agents follow when mutation-testing is:

> `git checkout -- <path>` restores exactly what you mutated and nothing else **if and
> only if that path was committed-clean before you mutated it.**

Not "use `git checkout --`". That sentence, prescribed after the first incident, is the
*recommended* restore for the agent that owns the worktree and committed first and the
*destructive* one for anyone else sharing the tree — and it is lossy even for the owner
when the file carries other uncommitted work.

**Per role, because the two roles must be told different things:**

| role | path state | do |
| --- | --- | --- |
| worktree **owner** | clean | mutate; restore with `git checkout -- <path>` |
| worktree **owner** | dirty | **commit it first**, then mutate |
| **subagent in someone else's worktree** | clean | mutate; restore with `git checkout -- <path>` |
| **subagent in someone else's worktree** | dirty | **do not mutate it** — you may neither commit someone else's WIP nor restore over it. Say so. |

**Is "commit before you mutate" sufficient?** From the owner's chair, yes — it covers all
four measured incidents. It is *insufficient as the stated rule* because it is actively
wrong for a subagent in a tree it does not own. State the precondition; "commit first" is
how the owner satisfies it.

**Evidence (4 instances, 3 mechanisms, all 2026-09-18/19):**

1. file-copy restore silently reverted another agent's **committed** fix (TASK-406);
2. a reviewer subagent sharing the builder's worktree `git checkout --`'d away **six of
   the builder's uncommitted edits** (TASK-471 owns the reviewer-side protocol);
3. two builders lost work to `git checkout -- <path>` reverting the **whole file** — one a
   25-line comment, one its entire uncommitted fix;
4. one reviewer kept `git status --porcelain` clean throughout by restoring from its own
   copy — achievable, but only because a human typed the hazard into its brief.

**What no restore protocol covers:** a second writer touching the path *during* the
mutation window. The fix for that is one writer per window — TASK-471, not this card.

**Where it lives:** `yolo-ship` SKILL.md Phase 4 (rule + per-role table + two fenced
runnable blocks marked `# ax-mutation-restore: precondition` / `: restore`), and a bullet
in the auto-ship code-lane dispatch prompt. Before this, `templates.md` contained no
`git checkout --` text at all — the rule reached builders only as a per-run orchestrator
habit.
