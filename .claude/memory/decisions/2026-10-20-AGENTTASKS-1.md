# AGENTTASKS-1 — Agent Tasks design; revert projects to post-W1

Source of truth: `docs/plans/2026-10-20-agent-tasks-design.md`. It holds the
design, the revert plan (§11) and the build order (§12). Start at its "Resume
here", not at the AX Work Model's.

| Date | Decision | Rationale | Alternatives |
| --- | --- | --- | --- |
| 2026-10-20 | Long-running agent work is one concept, **Tasks**, built by extending `@ax/routines`: kinds Stay on top of something / Get something done / Repeat a job (one choice), "when" as checkboxes (on a schedule, when another app sends an update), and every check-in ends with one host-bound `routine_report`. The app says Tasks; the code keeps `routines`. | The work-model plan (goals, projects, shared folders, an agent tasks plugin, a daily planner, delegation) was over-engineered for handing off and tracking long-running work. Routines already give the scheduler, real-owner identity, approvals and run history; what was missing was purpose, a report, and somewhere visible to see both. | A separate tasks plugin (needs its own scheduler or a second record per task); goals with counted/estimated measures and a judge model (replaced by "See what it did" plus a person confirming done); kinds as checkboxes (allows contradictions and brings back the per-update race). |
| 2026-10-20 | For "Stay on top" and "Get done", updates from other apps are batched nudges: one check-in at a time, everything since the last check-in in one brief, and a schedule that stays on as the full check. "Repeat a job" keeps one run per update, as webhook routines do today. | Per-update runs in parallel race (two runs can both reply to one ticket). Updates are hints and the other app is the source of truth, so a lost or repeated update only makes the task slower, and the full check bounds that. | Two tasks per job (a per-update job plus a sweep); event-only tasks with no schedule (can't tell a quiet day from a broken webhook). |
| 2026-10-20 | Keep W1 (#988) and build Tasks on it: the person-written brief goes in W1's `brief` section, active tasks go in `context` for ordinary chats. Revert W2/W3 (#989 and #991–#1001) and wipe production's database; no real users depend on production. | A trial revert applied with no conflicts and left code identical to `b61714c` apart from docs and memory. Keeping projects frozen taxes every prompt, every chat spawn and every sandbox/session change, and leaves known security gaps open. | Forward removal with a data move and staged column drops (about two weeks); keeping projects frozen. |
| 2026-10-20 | The revert PR restores `docs/` and `.claude/memory` from main after `git revert`, and adds a `Deleted in <ID>:` tombstone for the three kind evidence files that the AXWM-3 decisions shards cite. | A plain revert deletes 51 memory lines, which R1 rejects; `memory-cited-paths-exist` flags exactly those three citations once the files are gone. | A `Memory-Rewrite:` trailer (a human hygiene call, never an agent's). |
