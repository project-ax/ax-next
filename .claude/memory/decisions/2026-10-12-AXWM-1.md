# AXWM-1 — AX Work Model umbrella design, goals review, W1 spec

Source of truth: `docs/plans/2026-10-11-ax-work-model-design.md`. It holds the
status of W1–W13, a "Resume here" section, and the dated decisions table (§14).
Start there and update it at the end of every session.

| Date | Decision | Rationale | Alternatives |
| --- | --- | --- | --- |
| 2026-10-11 | Split AX into four concerns, each with one home: goals (why, hierarchical), agents (who), projects (where: flat shared folders at `/files/projects/<id>`) and knowledge (agent memory → project memory → company brain). | Everything keyed by `agentId` breaks once an agent juggles several projects or two agents share context. | Nested projects rejected: inherited permissions, moves and merged instructions each become a security question. |
| 2026-10-11 | Project context and project memory are plain files (`instructions.md`, `memory/`, `playbooks/`, `sources/`, `work/`), searched with bash tools. `@ax/memory` stays per agent and unchanged. | Claude-Projects simplicity; sharing comes free; no index to keep in sync. | RAG/index over project files and project facts in `@ax/memory` rejected. |
| 2026-10-11 | Projects narrow an agent's connectors, tools and skills and never widen them; goal autonomy settings follow the same rule. | A shared project or a goal must not grant reach the agent's owner didn't. | "Just do it" autonomy rejected: it would override the owner's tool rules. |
| 2026-10-11 | Tasks belong to agents (new `@ax/tasks`, W13). A project's task list is a view; cross-owner work is a suggestion the other owner accepts, held as an `@ax/decisions` record until accepted. | One task concept across chats, projects and goals; no shared pool, no claims. | A per-project task board with atomic claims (old W12) dropped. |
| 2026-10-11 | Goals (W6): the daily plan (W11) replaces a per-goal pulse routine; the judge runs inside `@ax/goals` on the host and checks evidence against project files and transcript tool calls; one measure per goal; connector-counted measures wait for W5's host-side `connectors:call-tool`. | Cost stays flat as projects grow; the judge reads records the host holds instead of the agent's description of them. | Judge as a hook subscriber rejected (verdict lives on the check-in goals owns). |
| 2026-10-11 | No lead agent per project; each person's primary agent writes one morning summary. | File history already removes the need for a single writer, and one summary per person avoids duplicate updates. | Lead agent that sends the project's digest dropped. |
| 2026-10-12 | W1 (draft spec): each plugin registers `system-prompt:augment:<name>`; the orchestrator finds them by prefix, calls them in parallel, and orders contributions by section (`rules` → `context` → `recall`); only `rules` reaches bootstrap mode. | The bus allows one provider per service; a `fire()` chain would let one plugin rewrite another's block and swallows throws. | Subscriber chain and a registry plugin rejected. |
