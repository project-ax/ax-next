# Decisions — SIGNINS-9 (agent-owned connector sign-ins, slice 7: every connector is shared)

Shard id `SIGNINS-9` covers slice 7. Plan: `docs/plans/2026-10-08-agent-owned-sign-ins-slice7-plan.md`.

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-10-08 | **Owner decision: every connector is shared and usable by agents; Private is removed.** No `visibility` anywhere in connectors types, schemas, store, hook payloads or channel-web; no Sharing control, no private notices. Supersedes the slice 5 ruling "private connectors aren't auto-shared". | Private connectors could never hold an agent sign-in or key, so the option only produced dead rows and an explanatory notice. Cost if wrong: an admin can no longer park a connector out of agents' reach (they delete it instead). | Keep Private and auto-share on attach (rejected by the owner in slice 5, then Private itself removed). |
| 2026-10-08 | **Second owner decision: existing connectors need not be preserved (nobody is using AX yet).** No boot step. The migration drops the `visibility` column and the `connectors_v1_connectors_shared` index. Image rollback to before slice 7 is unsupported. Duplicate live ids fail closed (`getSoleLiveById` needs exactly one) until an admin deletes one. | Supersedes the plan's marker-guarded dedup/flip boot step and the "column stays for rollback" ruling. Less code, no boot-time data rewrite. Cost if wrong: a vault with duplicate live ids blocks that connector until an admin deletes one. | Boot-time flip + dedup with the column kept (the original plan; rejected as unnecessary work). |
| 2026-10-08 | **skill-broker keeps `sharedKeyConsent: true` as a literal in `reachShape`**, though `connectors:resolve` no longer returns `requiresSharedKeyConsent`. | Approval digests for previously-shared connectors stay stable, so no stale-approval churn. Cost: one constant that looks vestigial. | Drop the field from the shape (rejected: every approval digest would change). |
| 2026-10-08 | **Deny codes renamed:** `not-the-shared-connector` is now `not-the-connector`, and `client-secret-not-the-shared-connector` is now `client-secret-not-the-connector`. `agent-store-refused` stays as the store-refusal code from `credentials:authorize-agent:account` with `purpose:'store'`; channel-web's own `visibility !== 'shared'` 403 is deleted and its copy is "This connector can't be added to agents right now. Ask a workspace admin." | "Shared" is no longer a distinguishing property. The store question can still deny (e.g. no live definition), so its code stays. | Keep the old names (rejected: they name a concept that no longer exists). |
| 2026-10-08 | **Deleting a connector always purges its agent sign-ins.** The purge is keyed by connector id, so a sign-in must never reach a surviving definition that shares the id. | Agent sign-ins are id-keyed; with duplicate live ids possible, leaving them would hand a deleted definition's sign-in to the survivor. Cost: deleting one of two duplicates also signs the agents out. | Purge only when no live row remains (rejected: it leaks sign-ins across definitions). |
| 2026-10-08 | **Attaching a no-auth connector is not checked for a sole live definition.** A legacy duplicate id can still be attached by an admin who owns one copy. | No credential is involved, so there is nothing to mis-route; accepted rather than adding a check. Cost: a duplicate id can be attached until an admin deletes one copy. | Check for a sole live definition on every attach (rejected: no credential at stake). |
