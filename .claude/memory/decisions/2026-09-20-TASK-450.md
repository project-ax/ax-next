# TASK-450 — the 3:1 non-text floor is a different criterion, not a lenient 4.5:1

**PR #647.** `StateDot.resting` / `StatusDot.empty` / `StatusDot.pending` all painted
`bg-ink-ghost` at 1.72:1 light, 1.67:1 dark. Fixed by splitting the token, not by
moving it.

## Decisions

- **`--ink-ghost` is now the composer send circle and nothing else.** The dots took a
  new `--state-quiet` (`240 4% 54%` light / `240 4% 45%` dark). The split, rather than
  a shared move, is because an **inactive control is exempt from WCAG 1.4.11 by name**
  — the send circle owes no ratio, so raising the shared token would have paid a bill
  only one of the two roles has. Third time `theme-contrast.test.ts` resolves
  "one token, two roles pulling apart" by splitting instead of averaging.
- **A new neutral is not automatically a duplicate of `--muted-foreground`.** The
  objection that blocked lifting `--ink-ghost` to 4.5:1 ("46%/53% vs muted-foreground's
  44/56 — the same colour twice") does **not** transfer to the 3:1 floor. 3:1 needs
  ~54% light / ~45% dark, which lands on the **far side** of `--muted-foreground` in
  each theme — lighter in light mode, darker in dark. Check the actual required value
  before reusing an argument written for a different floor.
- **Assert "quieter", not "lighter".** Because the direction flips between themes, the
  durable property is an *ordering* — `contrast(state-quiet) < contrast(primary)` and
  `< contrast(muted-foreground)` on the page. One assertion covers both themes and
  turns the visual judgement ("does a darker dot read as active?") into a test.

## Findings that refuted the card

- **A dot beside a text label is not the dot the criterion is about.** All four
  `StatusDot` render sites (`ProviderRow`, ×3 in `ConnectorsTab`) put plain-English
  copy immediately next to the dot, and the dot is `aria-hidden`. Redundant-with-text
  marks are decorative; 1.4.11 does not reach them. Only `StateDot` in
  `WorkspaceSidebar` (dot + agent name, nothing else) is a sole carrier. **Grep the
  render sites before accepting a 1.4.11 claim** — the component tells you the colour,
  only the call site tells you whether the colour is the only channel.
- **"Raise the ratio" and "add a non-colour channel" are not alternatives.** They
  answer different SCs — 1.4.11 (invisible) and 1.4.1/1.1.1 (colour-only, plus
  `aria-hidden`). A card offering them as either/or is describing two bugs.

## Pattern worth reusing

`theme-contrast.test.ts`'s habit generalised: **derive the list from the source, don't
maintain it.** The new section parses the dot classes out of `bits.tsx` and
`StatusDot.tsx` (`parseStateDotArms`, `parseVariantClass`, `bgFill`) and measures all
nine variants, so a reverted class fails with the true 1.72:1 rather than passing
because a constant in the test moved with the component. Mutation-verified both ways.

Also: **an anti-vacuity guard pinned as a COUNT rots.** `filesPainting('bg-ink-ghost')`
was `>= 3` and two of the three were the dots being moved — it would have stayed green
while they drifted back. Now an exact one-element set.

## Backdrops a dot lands on (five, not one)

`--background`, `--card`, `--muted`, `bg-muted/60` over the page (hover row), and
`--primary-soft` — the **selected** sidebar row, which is the tightest bound in both
themes and the one nobody thinks to check, because "selected" reads as a state of the
row rather than as a place a dot lives.
