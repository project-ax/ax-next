# Decisions — TASK-842 (runner reports a connector MCP auth failure to the host)

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-10-04 | **Card premise partly refuted (MEASURED, pinned CLI 2.1.119): the SDK never reports a 401.** A 401 on `initialize` shows up in `system/init` as `failed` (or `needs-auth` when OAuth discovery finds metadata), indistinguishable from a 500 (`failed` too). A 401 on `tools/call` leaves the server `connected` and returns an `is_error` tool result whose text is a zod error, not auth. So the runner cannot send "a status code"; it sends the namespace plus a closed status `needs-auth`/`failed`/`tool-error`. | Measured with a local MCP server answering 401 + `WWW-Authenticate`, through the real binary; now pinned in `connector-mcp-real-sdk.e2e.test.ts`. | Parse tool-result text for "401"/"invalid_token" (fragile; the text is the SDK's, not the server's). Poll `mcpServerStatus()` after a tool error (measured: still `connected`). |
| 2026-10-04 | **The report is a hint; the host re-checks.** `@ax/mcp-client` subscribes to `connectors:auth-failure-reported`, maps namespaces through `agents:resolve` + `connectors:list-effective`, and runs its own `describe-tools {force: true}`. Only a 401 the HOST sees reaches TASK-817's `credentials:get {rejected: true}` → refused renewal → needs-reconnect marker on the owner. | The runner is untrusted and its signal is coarse. Re-checking makes a lying runner harmless (a healthy server stays `ok`), reuses the existing cooldown (one check per (user, connector) per 30 s), updates the rail's inventory row, and needs no new marking surface. | Runner report → `credentials:get {rejected}` directly (an untrusted, imprecise signal would force renewals; `failed` also covers 500s). A service hook returning a verdict (the runner has nothing to do with one). |
| 2026-10-04 | **Fire-and-forget IPC event (`/event.connector-auth-failure`), not a POST action.** Subscriber hook, not a service hook. | The runner must never wait on a third-party check mid-turn. Events are the existing 202-then-fire shape; with no subscriber (CLI) it is a no-op. | POST action + new service hook (blocks the runner on describe-tools; needs a required/optional call entry in DISPATCHER_DEPENDENCIES). |
| 2026-10-04 | **Wire schema in `@ax/ipc-protocol/events.ts`, not in mcp-client.** | Every runner→host action/event schema lives there: the runner imports it, and a runner cannot import a host plugin. The card's "IPC schema lives in the owning plugin's directory" is the boundary-review wording; the as-built practice (and the architecture doc §4, which says both) is the protocol package. The subscriber re-validates structurally on its own side. | Plugin-registered IPC actions (no such mechanism exists; building one is a much larger card). |
| 2026-10-04 | **Alternate impl considered and recorded: detect the 401 in `@ax/credential-proxy`.** The host's MITM proxy sees every upstream response on a tunnel where it substituted an OAuth credential, so it could call `credentials:get {rejected}` itself: trusted, precise, covers both runners. | Not taken here: it adds response framing to every credential-injected tunnel in the security-critical MITM path (TASK-823 is editing it in parallel), and the card scoped the runner. Worth a follow-up if the runner signal proves too coarse. | — |
| 2026-10-04 | **Mapping via the agent's effective set misses skill-referenced connectors (TASK-92).** Such a namespace is dropped and counted (`connector_auth_report_unmatched`). | The effective set (attachments + legacy-owned) is the same union the session folds and needs no new hook. A skill-referenced connector still updates on its next rail/details check. Follow-up card. | A reverse namespace→connector lookup hook in @ax/connectors (new surface). |
| 2026-10-04 | **claude-sdk runner only; the aisdk runner is a follow-up.** | The card names claude-sdk-runner. The aisdk runner connects its own MCP clients (`tools/connector-tools.ts`), so it can see the real HTTP status and would report through the same event. | Both in one PR (doubles the runner work). |
| 2026-10-04 | **A connector tool error reports its server once per turn; held calls never.** `is_error` after the held-call substitution (TASK-260) is the signal. | Any connector tool error (a bad argument, a policy deny) also reports; the host's cooldown bounds the cost to one tools/list per connector per 30 s, the same as rail Retries. | Report only on auth-looking text (fragile, see row 1). |
| 2026-10-04 | **macOS gotcha in the real-SDK e2e: after a 401 the CLI calls `security find-generic-password`, which can block on a keychain prompt (no init within 200 s).** The test puts a `security` stub that exits 44 on the child's PATH, darwin only. | A sandbox has no keychain; the stub is the faithful setup, and without it the test hangs on dev Macs. | Skip the case on darwin (loses local coverage). |
| 2026-10-04 | **Implemented inline, not one subagent per task.** | Four small, tightly coupled edits (protocol → dispatcher → subscriber → runner), each test-first (TASK-817 precedent). | Subagent per task. |
