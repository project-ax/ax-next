# TASK-437 — decisions

## 2026-09-19 | Render four `TabsContent` panels with `forceMount`, not one plain `TabsContent`

**Decision.** `AgentView` now renders a `TabsContent` for *every* entry in
`WORKSPACE_AGENT_TABS`, each with `forceMount`, an explicit `hidden={v !== tab}`, and
children only on the open one.

**Rationale — read out of `@radix-ui/react-tabs@1.1.21`, not assumed.**
`TabsTrigger` sets `aria-controls={contentId}` **unconditionally**; there is no branch
on whether the matching content is mounted. `TabsContent` wraps itself in
`<Presence present={forceMount || isSelected}>`, which renders **nothing at all** when
its tab is inactive. So the obvious shadcn composition — one `TabsContent` for the open
tab — still leaves **three of four** `aria-controls` dangling. It would have looked like
a fix, and a test that only checked the open tab would have passed.

`forceMount` keeps all four `role="tabpanel"` elements in the DOM so every
`aria-controls` resolves, and because the children are supplied only for the open tab,
the three closed panels stay **empty** — no `AgentFiles` / `AgentMemory` /
`ActivityFeed` mount, so no extra reads. This is also the plain WAI-ARIA APG shape.

**Alternatives rejected.**
- *Drop `aria-controls` from inactive triggers* — means patching the shared
  `components/ui/tabs.tsx` primitive for every future consumer, and throws away the
  tab↔panel relationship the card actually wants.
- *`forceMount` with children on all four* — mounts three panels' worth of data
  fetching for nothing.

## 2026-09-19 | `hidden` must not be paired with a display utility on the closed panels

Tailwind preflight's `[hidden]{display:none}` and the `flex` utility have **the same
specificity**, and utilities are emitted after preflight — so `class="flex" hidden`
renders **visible**. The open panel needs `flex min-h-0 flex-1 flex-col` to give
`AgentConversation` its height, so the closed ones get **no** display class at all.
jsdom loads no CSS, so this is unprovable there as a *rendered* fact; the test pins it
structurally instead (a closed panel's `className` carries no display utility), which is
checkable and not vacuous.
