T4 (builder) rows.

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------|
| 2026-11-07 | **T4: `prepareArtifactHtml` ships only fixed points: a string is returned only when parse5's parse of it has nothing to cut, the guard already leads `<head>`, and `render(parse(s)) === s`.** Raw input bytes are never shipped unless they are themselves such a fixed point; at most 4 parse passes, then null. | Rebuilding from parse5's tree drops whatever parse5 refuses, and the browser parses only the canonical form. Measured: Chromium 147 keeps `<select><iframe>` / `<select><div>...` that parse5 7.3.0 (and 8.1.0) drops, so any "parse says clean, ship the original bytes" shortcut (including the "already has the guard, return as is" one) would hand Chromium an iframe. It also makes the function idempotent by construction. | Return `current` as soon as a parse finds nothing to cut (ships raw bytes for already-guarded input); byte-splice the guard in (implied-head offsets, same select hole). |
| 2026-11-07 | **T4: the injected script is the guard + `window.axFrameGuard(window,{onKill:...console.warn("blocked: this page tried to open a nested frame")});delete window.axFrameGuard;`; "already there" means the first child of `<head>` is a bare `<script>` (no attributes) whose text is exactly that.** A load-time check parses `<script>${text}</script>` with the real parser and refuses to load if the text does not come back as one inline script (catches `</script`, `<!--`, CR). | A copy that is not first, or has `type`/`async`/`nonce`, or edited text, does not count and a real guard goes in front. Exact match is what lets a saved-and-republished page not carry two guards. | Always inject (a second guard's locks fail harmlessly but the pages double in size); a marker attribute (agent-forgeable). |
| 2026-11-07 | **T4: refuse (null) rather than serve when it cannot keep the page the same: any U+0000 in the input, a CR that came from a character reference (`&#13;`), nesting past 512 elements, a doctype whose quirks mode cannot be written back (malformed doctypes set a tokenizer flag the tree drops), `<plaintext>` (the serializer's `</plaintext>` becomes page text and grows every pass).** Doctype is re-written with its public/system identifiers (parse5's serializer drops them). | 512 is where Chromium/WebKit stop nesting, so a deeper tree is shaped differently there than in parse5. Quirks mode is part of "renders as before". NUL: measured in Chromium 147, Firefox 148 and WebKit 26.4, which all skip a NUL while `<head>` is open (parse5 ends the head at it), so parse5's tree is not the browser's; no real page has one. `&#13;`: parse5's `isWhitespace` leaves CR out (it expects the preprocessor to have removed them all), so a CR from a character reference is text to parse5 and whitespace to a browser, and it ends a `<head>` in one and not the other; written back raw it would also read as LF. Both are refused, not patched. | Depth by RangeError (machine-dependent); emit a quirks-forcing bogus doctype (more code for a case no agent produces). |
| 2026-11-07 | **T4: matching is by element name in any namespace, DSD attrs stripped from any element named `template`, scripting ON.** | Same as a CSS type selector (visual-doc.ts); an svg `<iframe>` is inert today and one mutation round trip from not being. | HTML-namespace only. |

| 2026-11-07 | Security-review finding on prepare-html.ts (self-navigation via meta refresh / location to data: URLs): not fixed in T4; add framed+top-level navigation probes to T6; file follow-up card for top-level /v/ self-navigation | Framed case is already refused by the shell frame-src widened to <content>/v/ (index.html:9); top-level has no CSP control, and scrubbing meta refresh alone leaves script location=; dropping unsafe-inline breaks agent scripts | Top-level navigation exfil stays open until the follow-up lands |
| 2026-11-07 | **T5: the content origin hands `prepareArtifactHtml` at most 4 MiB (`MAX_HTML_TRANSFORM_BYTES`); bigger HTML is the same 404 with logged code `html_too_large`, never served untransformed. A null from the transform is the same 404 with code `html_unsafe`.** Both log route + status + fixed code + class name `HtmlRefusal` only (an Error subclass carrying the code, so `faultLogFields` reads it; message is fixed text). Prepared pages are cached in memory (16 entries / 32 MiB, LRU) keyed by the blob sha256, which `createArtifactServe` now returns as optional `ServedArtifact.contentKey`; refusals are cached too. | The transform is synchronous in the host process at ~0.15-0.2 s per MB (T4); the only hard size cap on the publish path is `DEFAULT_MAX_FILE_BYTES` = 25 MiB (configurable, `packages/attachments/src/types.ts`; the artifact publish hook itself only caps visuals), i.e. ~4 s per view and the agent picks the bytes. 4 MiB is ~0.7 s worst case and well above any real report/dashboard. The content hash is a better key than artifact id + version: the same bytes always prepare the same way, so it cannot go stale and shared bytes share an entry. `ServedArtifact` has no version key of its own, and a serve without `contentKey` (a test stub) is simply never cached. | Skipping the transform above the cap (would serve an unguarded page); a worker thread (new moving part; the cap + cache bound the cost); keying on artifactId+version (needs more plumbing and can be wrong after restore/delete). Residual: a cache miss on a ~4 MiB page still blocks the loop for ~0.7 s; at most 16 distinct such pages' worth of repeat views are saved. |
