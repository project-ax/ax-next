# Decisions — SIGNINS-7 (agent-owned connector sign-ins, slice 5: lookup flip + boot purge)

Shard id `SIGNINS-7` covers slice 5. Spec: `docs/plans/2026-10-07-agent-owned-connector-sign-ins-design.md`; plan: `docs/plans/2026-10-07-agent-owned-sign-ins-slice5-plan.md`. Core guarantee: no user-scope `account:` read or write anywhere.

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-10-07 | **Task 1 updated only @ax/credentials' own tests**; other packages broken by the flip/refusal were fixed by Tasks 2–4, each owning its package. | One PR; each task's own suite green at its commit. Cost if wrong: bisecting into T1..T3 shows red suites in other packages. | Fix every package in T1 (rejected: one giant commit). |
| 2026-10-07 | **The destination route answers 404 for the `account` kind** (one parameterised handler, same effect as deleting it) **and an admin user-scope `account:` write is 400.** | An extension beyond the plan, consistent with "no user-scope `account:` writer". Cost if wrong: none. | Delete the route outright (rejected: the handler is shared with other kinds). |
| 2026-10-07 | **The skill grant card still lets Connect proceed when only a connector (`account:`) key is missing.** | Blocking would strand a persisted card; the owner accepted that existing skills may break. Cost if wrong: a skill fails at use instead of at grant. | Block Connect (rejected). |
| 2026-10-08 | **Private connectors are NOT auto-shared.** They are left out of the rail's Add list (`availableConnectors`), explained on their Admin › Connectors row ("Private connectors can't be used by agents. Make it Shared to use it, or delete it."), and the remote form gained a Sharing choice that rides the existing PATCH (sent only when changed, so the server's owner-only rule decides and a non-owner relabel never trips it). Refusal copy names the cause: begin 403 `agent-store-refused` → "This connector can't be used by agents yet. Ask a workspace admin to make it Shared." | Agent-scope credentials need the sole SHARED definition (`credential-authz.ts`), so a private connector is dead after deploy; auto-sharing would widen reach. Cost if wrong: admins flip each private connector by hand. | Flip private → shared at boot (rejected: widens reach without the owner's say). |
| 2026-10-08 | **Sign in again asks the vault's STORE question first**, so a private connector still attached gets 403 `agent-store-refused` (the cause a person can act on) instead of 409 `not-on-agent`. A store "yes" then a read "no" stays `not-on-agent`. | Both are refusals; nothing widens. The client can't tell the two 409 causes apart, the server can. | Map `not-on-agent` to the private copy client-side (rejected: wrong for a connector really removed). |
| 2026-10-08 | **begin's 400 `oauth_client_secret_unavailable` is the client refusal `client-secret-missing`** → "This connector's client secret is missing. Ask a workspace admin to enter it again." The remote editor also shows "The client secret is missing. Enter it again so agents can sign in." when a custom client's GLOBAL secret row is absent. | A purged person-scope client secret otherwise reads as a generic "try again". | Leave the generic copy (rejected). |
| 2026-10-08 | **Deploy only after slice 6** (routine skip warning) as well as slice 5. | Routines run without connectors after the flip until slice 6 says so. Cost if wrong: deploy waits one slice. | Deploy slice 5 alone (rejected: routines silently lose connectors). |
| 2026-10-08 | **Admins can't delete leftover person-scope rows from the UI.** | They are unreadable after the flip; the boot purge removes them. Cost if wrong: orphan rows after a rollback. | Add an admin delete (rejected: UI for dead rows). |
| 2026-10-08 | **`credentials:purge-account` accepts `scopes: ['agent']` only**; 'user' and 'global' are `invalid-payload`. The boot purge of person-level rows calls the plugin's internal function (`purgeAccountRows`) with `'user'`, so no hook caller can reach a user-scope purge. | Capabilities minimized: the only user-scope caller is the plugin's own one-time boot step. | Keep 'user' on the hook (rejected: a reachable user-scope purge nobody else needs). |
| 2026-10-08 | **`mcp-oauth:status-batch` requires `agentId`** (schema `min(1)`); `userId` stays as is. `shared` always equals `needsReconnect` and is documented so. | Every sign-in is an agent's; an agent-less ask was a silent empty answer. | Keep it optional (rejected: hides a caller bug). |
| 2026-10-08 | **`ax credentials migrate --yes` skips `account:` refs** and prints "N connector credentials skipped — they now belong to agents." | It wrote person-scope `account:` rows straight through `storage:set`, past the vault's refusal. | Migrate them anyway (rejected: breaks the core guarantee). |
| 2026-10-08 | **The grant card's connector line is one sentence for both cases: "Add {svc} to this agent, or sign it in, from its Connectors tab."** | The card can't tell a connector already on the agent (only its sign-in missing) from one not added yet. | Two sentences keyed on attachment (rejected: the card has no attachment data). |
