# TASK-489 — decisions

## The slot normalizer ships as the synonym table ALONE, and `SLOT_DESCRIPTIONS` does not ship at all

Design §3.3 proposes an embedding nearest-neighbour behind the exact-synonym
table. It was measured at rung 0 (`docs/plans/2026-09-18-dem-rung0-report.md`
§2) and killed: calibrated on the table's own canonical keys — where the answer
is known by construction — the nearest slot disagrees on 6 of 32 (`first name`
→ `birthday` at 0.834), hand-checked precision at threshold 0.78 is 13.2% /
20.9%, and at ≥0.88 it maps nothing. So `@ax/memory` has no `@ax/embeddings`
dependency, and `packages/memory/src/slots.ts` has **no imports at all**.

The card's "what to port" list named `SLOT_DESCRIPTIONS`. I did not port it as a
runtime export. Its only ever role was as the killed stage's scoring surface, it
has no consumer, and shipping it would be a dead export under the Half-Wired
Code Policy that also hands the next reader the embedder's input already
assembled. The meanings survive as a table in the `SLOTS` doc comment.

Not exported either: any `via: 'synonym' | 'embedding'` discriminator. A
subscriber keying off it would break the moment the embedding half is correctly
never built.

## `SLOTS` is the single owner, and the guard for that is a source scanner

Design §3.3 and §4.1 say the slot list IS the profile whitelist — same constant,
not a copy. The profile-block consumer does not exist yet, so there is nothing
to point at `SLOTS` and no ordinary test can pin "one owner".

`slots.test.ts` scans every production `.ts` under `packages/` (comments
stripped, `__tests__` and `*.test.ts` skipped) and fails if **3+ distinct slot
names appear as string literals inside any 200-character window**. MEASURED
today: the densest run anywhere outside `slots.ts` is **2**, in
`packages/memory-facts-contract/src/index.ts`, where they are test data in
unrelated cases of the shared contract suite. A whole-file count would have
flagged that file; a window does not, and a copied eight-entry list is dense by
nature. A companion case asserts the scanner walked >100 files, because a
scanner that silently walks nothing is a green that means nothing.

## `PENDING_SLOT` is a local copy with a parity test, following `@ax/memory-facts-sqlite`

`@ax/memory-facts-contract` is not in `eslint.config.mjs`'s `crossPluginImports`
allowlist and ships the shared vitest suite, so it is a devDependency and only
`import type` is legal from `src/`. `packages/memory-facts-sqlite/src/pending.ts`
already set the precedent: re-declare the constant, pin it with a test that
imports the contract's value (test files are exempt from the rule).

The reserved value is unreachable from this normalizer — derivation is a
synchronous table lookup with no producer that could be unavailable, so there is
no deferral state to express. The constant exists only so "`pending` is never
reusable as a real slot" is testable.

## Live caution for TASK-493 (`memory_note`)

`memory:remember` now CLOSES rows, where before this card every statement it
wrote was inert. Its provenance is hardcoded `human`. Design §4.3 puts
`memory_note` at `provenance: agent` for exactly this reason, so the agent-facing
tool must not be wired onto `memory:remember` — that would let model output
close a person's correction under provenance immunity. Not a defect today
(nothing model-facing calls it yet); it becomes one the moment a tool does.
