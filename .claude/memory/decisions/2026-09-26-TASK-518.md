# TASK-518 — decisions

## The slot-vocabulary scanner moves from `@ax/memory` to `test:scripts` (finding 4: relocate, not accept)

The card offered two answers: relocate, or accept the cross-package reach and document it.
Reading `ci.yml` decided it. The PR `test` job runs `pnpm --filter "...[$BASE_SHA]"` —
affected packages plus their **dependents** — and `@ax/memory` is not a dependent of
`channel-web` (only `presets/memory` depends on `@ax/memory`). So the `channel-web` copy the scanner exists
to catch never ran it on the PR that added the copy: that PR merged green and the red
landed on main's full suite, or on the next unrelated `@ax/memory` PR. The card framed
the coupling as "someone else's package reddens ours"; the larger half is that the guard
fired on the WRONG PR. `pnpm test:scripts` runs unconditionally on every PR, so the guard
now lives at `scripts/__tests__/slot-vocabulary-single-owner.test.js`.

Chose `test:scripts` over the card's literal `test:eslint-rules`: both run on every PR,
but `eslint-rules/` holds tests of the ESLint config, while `scripts/__tests__/` already
holds repo-wide tree guards (`no-raw-nul-bytes`, `tsconfig-references`). Same property,
better neighbours.

## Mentions come from the TypeScript AST, not a regex

The TASK-489 regex under-read in three measured ways, each now a row in the test's case
table: `stripComments` ate string contents (`' // '` blanked the rest of the line, `'/*'`
... `'*/'` blanked everything between), and `\bx\s*:` missed `lives_in?: string`. The AST
counts string/no-substitution-template literals and identifiers in field-name positions
(object keys, shorthand, interface/class members, enum members, destructured bindings).
A file with parse diagnostics is reported as an offender (fail closed), and so is a
TypeScript that no longer exposes `parseDiagnostics`.

## Finding 2 fixed: every window is asked, not only the densest

`largestCopy` returns the largest window that reaches 3 AND contains `lives_in`. A test
row pins the masked case (a 4-word innocent cluster + a distant anchored 3-copy).

## Finding 1: the sub-copy weakness is stated, and pinned as a KNOWN MISS row

`'name' | 'role' | 'language' | 'timezone'` passes. Stated in the scanner header and in
`slots.ts`'s doc comment; kept (not "fixed") because the anchor is what stops ordinary
English words tripping a repo-wide guard.

## Finding 3: no pinned population count

The test asserts `> 500` and says "~1,000 at TASK-518" (measured exactly 1000 with the
new walk: tracked JS/TS under `packages/` + `presets/`). A pinned exact count would go
stale on the next PR — the TASK-489 "840" did.

## Population is `git ls-files`, not a disk walk

Deterministic and equal to what CI sees; an untracked scratch file in a dev tree can no
longer redden (or satisfy) it. Widened to `presets/` and to `.js/.mjs/.cjs/.jsx/.mts/.cts`.
