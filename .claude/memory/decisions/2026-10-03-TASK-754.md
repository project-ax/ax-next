## 2026-10-03 — TASK-754: freeze unset / default-on tool verdicts at copy time

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-10-03 | **Froze unset tools with a per-(agent, namespace) "copied" record in tool-policy (`tool_policy_v1_agent_copied_namespaces`), not with per-tool `hold` rows from the inventory** (the card's suggestion). A connector tool under a copied namespace with no override row evaluates as override `hold`. | The inventory is per (user, agent), 15-min cached, and a miss is a live `tools/list` (10 s/20 s); `@ax/agents` cannot declare `connectors:describe-tools` without a call-graph cycle (mcp-client calls `agents:resolve`). A tool the inventory never saw (never listed, added to the server later) would still follow the live default. The namespace record covers every tool, needs no network, and is atomic. | Per-tool `hold` rows from `describe-tools` at attach (rejected: network on attach, cycle, misses unlisted tools); cache-only inventory read (no hook returns every toolKey — `inventory-tool-titles` drops title==name). |
| 2026-10-03 | **Default-on connectors are copied by the orchestrator at session open** (`copyConnectorDefaultsForSession`, after `connectors:list-effective` + skill-referenced resolve, before the sandbox), with `onlyIfNotCopied: true`. | They never attach and no event fires when a connector becomes a default; fanning out to every agent on that flag flip is heavy and still misses agents created later. Idempotent: tool-policy claims the record with `ON CONFLICT DO NOTHING RETURNING`, copies only newly claimed namespaces, never overwrites a row, and skips the store entirely when its cache already shows the namespaces copied. Non-fatal: a failure leaves the live default (what the editor set, never wider). | Copy at `agents:created` (rejected: misses existing agents and later defaults); freeze lazily inside `tool-policy:evaluate` (rejected: evaluate also serves the rail's read-only listing — a write on a read path). |
