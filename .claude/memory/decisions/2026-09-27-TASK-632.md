| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-09-27 | **close-X-by-Y is an optional `by?: string` on `memory:facts:supersede`**, not a new hook. | Same verb as a retraction — close ACTIVE rows, `closed`/`resettled` output, same tenant+owner refusal shape — it only records a successor (`closed_by = by`, reads `replaced`). TASK-630 split `reinstate` out because re-opening is the OPPOSITE verb; this is not. No new hook means no preset/wiring churn. | New `memory:facts:replace` hook (more surface for the same verb); `record` statement field `replaces` (atomic, but threads a closure through batch/pending/idempotency paths). |
| 2026-09-27 | **`by` closes only ACTIVE, SLOT-LESS rows** (`slot IS NULL`); slotted and PENDING rows are refused (absent from `closed`). | A slotted/pending row's closure belongs to its `(about, slot)` chain: any later replay (`resettleSlotGroups` on supersede/reinstate/reindex) re-derives it and would silently erase an explicit closure. Also delivers "slot-ful rows behave exactly as before" by construction. | Allow slotted rows — explicit closure silently undone by the next replay. |
| 2026-09-27 | **`by` must be a row that still asserts something** (active or rule-closed, not a retraction), same tenant, same owner when owner-scoped; `by` + `neverTrue: true` is invalid-payload. | A retraction cannot replace anything; owner-scoping `by` too keeps an owner-scoped caller from pointing at a row it cannot see. A replaced row is not a retraction, so the two labels are exclusive. | — |
| 2026-09-27 | **`valid_end = max(X.valid_start, Y.valid_start)`**, compared in app code. | Rule closure ends a row at its successor's start; a correction's `when` is now, so it can precede a future-dated X — never write an `until` before its own start. App-side compare because postgres TEXT collation may not order ISO punctuation bytewise. | SQL MAX/GREATEST — collation-dependent on postgres. |
| 2026-09-27 | **Retracting Y later does NOT re-open X; `reinstate` does not re-open X either.** | Unlike a slot chain (inferred closure, TASK-448 re-derives it), this closure is a person's explicit statement that X changed — forgetting the new value does not make the old one current. Consequence for TASK-634 (Undo for Fix): a Fix-closed slot-less row has `closed_by` set, so `memory:facts:reinstate` will not re-open it; Undo needs its own engine path. | Re-open X on retracting Y — then Undo-of-forget(Y) leaves X and Y both active. |
| 2026-09-27 | **`memory:correct` 'changed' always sends `supersede {ids:[id], by:newId, …scope}` AFTER the record**; the engine decides. | The product layer does not know the old row's slot. Failure window: record lands, close fails → the pre-TASK-632 state plus an error. | Read the row first to decide — a second round trip and a race. |
