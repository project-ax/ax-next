# TASK-489 — decisions (Jev evaluation, 2026-09-28/29)

The code, reports and raw results of this work live on the unmerged branch
claude/jev-facts-memory-integration-r05nyf. By the owner's decision it is **not** applied to
main. Only these learnings are.

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-09-29 | **Jev (`typesafe/jev-1.13`, OpenRouter Decisions API) does NOT become the slot normalizer's second stage.** `deriveSlot` in `packages/memory/src/slots.ts` stays the exact synonym table. | Measured on 23.6k product-extracted relations. Jev fixes what the embedding stage got wrong: 32/32 canonical spellings (embedding 26/32), 22/22 known-bad relations answered `none`. But the precision of its own mappings is not clean at any threshold with real coverage: 55% at p ≥ 0.9 from the relation alone, 73.5% with the fact in view. The errors come in classes a threshold can't remove: speech acts about a role, someone else's role (`pilates_instructor` at 0.99), type-of (`is_company` → works_at), near-properties (`age` → birthday). A false positive closes a true fact. | Ship behind pending/reindex — REJECTED: that path makes an *unavailable* normalizer safe, not an imprecise one, and Jev's probabilities move by up to 0.12 between identical calls, so `reindex` would re-decide every row near the threshold. |
| 2026-09-29 | **Jev fact-link notes do NOT go into `memory_recall`'s evidence table.** | Pre-registered, forked, 3-repeat run on all 500 LongMemEval-S questions, links at p ≥ 0.9. GLM +0.20 pp [−0.47, +0.93], DeepSeek v4.1 flash +0.13 pp [−0.60, +0.87]. Forked runs gained and lost at nearly the same rate (15/12 and 17/15). Re-judging 100 answers flipped 0 verdicts. An earlier n=100 run's "4 fixed, 0 broken" was small-sample luck. Two harms were real: a note beside an adjacent number invites hedging ("25, or maybe 33"), and a "changed" note talks a model out of abstaining. | Ship evidence annotation — REJECTED on the measurement. |
| 2026-09-29 | **Where Jev may still fit: as a proposer, never a decider**, and only after its own measured trial. | What it is good at: refusing via an explicit `none`/`both_true` option; a stable choice (1/200 changed across fresh runs); precise pairwise judgements with both facts in view (57/60 links correct at p ≥ 0.9); ~$0.00002 and ~200 ms per call. What it is weak at: probability jitter; dates and quantities; batching several questions into one call shifts the probabilities. | Candidates: (1) proposer for a human "Still true?" review queue, where a wrong suggestion costs a click; (2) offline reviewer proposing synonym-table lines; (3) write-path classifiers that are regex today (self-report filter, persona text stored as user facts); (4) duplicate detection for display. |
| 2026-09-29 | **Any product use of Jev needs the security checklist first.** | Every call sends user facts to a third party (OpenRouter → TypeSafe). The Decisions API is marked alpha and has a shared 2,000-requests-a-minute limit, which a benchmark run hit. | Treat it like an internal call — rejected: that's data egress for a project whose selling point is being the secure option. |
| 2026-09-29 | **Benchmark banks live in `~/ax-bench-data/`, not under `~/.cache`.** 500 LongMemEval-S facts banks at `~/ax-bench-data/dem-lme500/`, plus a sha256-verified backup of the corpus at `~/ax-bench-data/longmemeval-s/`. | `~/.cache/ax-memory-bench` lost the rung-4 banks and other caches around 2026-09-28, and a reboot cleared `/tmp`. Rebuilding the banks costs ~$20 and ~3 h. The harness still reads the corpus from `~/.cache` (`scripts/memory-bench/cache.ts` hard-codes it), so restoring means copying the backup back there. | Keep them under `~/.cache` — rejected: already wiped once. |
