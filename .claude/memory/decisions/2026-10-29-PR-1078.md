# PR-1078 — minimal Agent Tasks pages (decisions)

- **2026-10-29.** Vinay rejected the first redesign (v1 Figma page "Tasks — redesign") as still too much text at the top level. The shipped rule is the v2 page "Tasks — redesign v2 (minimal)" in the Goals mock file (`QMFOa9v5Z5b67XWJdC51jJ`, node `26:1875`): only five things stay as words: the task name, the agent's own words (one sentence per card), the status pill, the one action the page wants, and the reply box. Everything else is an icon with a tooltip, a position, or one click away. Spec: `docs/plans/2026-10-29-agent-tasks-minimal-ui.md`.
- **The mocks use the shipped app's tokens** (Inter, violet, black primary from `index.css`), not the Goals mock's navy/IBM Plex palette. This is so they can be built with shadcn as-is. They live in a local variable collection "ax app (index.css)" in that file.
- **Every icon carries its sentence twice**: once in a tooltip and once as an accessible name or hidden text. The tooltip trigger drops `aria-describedby`, so it isn't read twice. This is the price of icon-first, so don't drop either one.
- **Needs-you list rows keep their short fact, with Reply after it.** The reviewer argued for it because the fact carries the late finish-date warning. This overrode the PNG.
- **"Task options" is gone.** Delete is in ⋯ behind a confirm that offers "Pause instead". The signing secret lives in the About › App updates row. The agent-wide routine consent became a link to agent Settings › Routines. The link is safe: anyone who can open the task passes the same `resolveAgentOr404` guard as that page.
- **The banner takes the first match** in the order Done > claim > missed check-in > ask. The ask still shows, muted with Reply, in the latest card when something else takes the banner.
- **Not changed, and possible follow-ups:**
  - the Today task group and the check-in transcript page (only their failure wording changed);
  - agent-written updates that leak tool syntax ("Called routine_fire_now (requestId: …)"), which needs agent/prompt guidance, not UI;
  - shared `Input`/`Textarea` don't style `aria-invalid` app-wide (only `InputGroup` does).
