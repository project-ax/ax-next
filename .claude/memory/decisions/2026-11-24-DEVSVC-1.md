# DEVSVC-1 decisions (dev services on demand + longer turns, branch feat/dev-services-on-demand)

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-11-23 | **`restart_with_services` swaps the sandbox inside ONE turn: the first runner segment's `chat:turn-end` is HELD, not broadcast.** ipc-core (the one emitter of `chat:turn-end`) fires a subscriber veto event `chat:turn-end-hold` first; the orchestrator vetoes only for the reqId it is restarting, and ipc-core then fires `chat:turn-segment-end` (only the orchestrator consumes it) instead. Web, Slack, routines, conversations and activity never see a phantom end. Host-authoritative: the runner can't claim a hold. (Rulings R27 → R28.) | The first segment must end normally (transcript save) but callers must see one turn (spec decision 5). One emitter decides, callers untouched. | (A) orchestrator rewrites the payload reqId first — depends on subscriber order. (B) wire reason `restart` and 5 callers ignore it — a missed one shows a phantom end. (D) two turns — contradicts the spec. |
| 2026-11-23 | **The hold check is a veto SUBSCRIBER, not a service hook** (R28 reverses R27's `chat:turn-end-held` service). | A service call ipc-core → orchestrator closes a bootstrap cycle in the local preset (ipc-server → orchestrator → sandbox-subprocess → ipc-server), which the kernel rejects at boot. A veto subscriber adds no call edge, and the pattern already exists (`memory:pre-capture`). Rule: when a lower plugin needs a yes/no from a higher one, reach for a veto subscriber before a service hook. | Service hook guarded by `bus.hasService` — still a static dependency edge, so still a cycle. |
| 2026-11-24 | **Runner/sandbox-protocol independence is deliberate: the runner keeps its OWN copy of a parser the host also has** (R34, `AX_SERVICE_FORWARDS`). Both copies share golden-vector drift tests (ARCH-11 style, like `installed-skills.ts`). Only `standby.ts` (the assignment endpoint) may import `@ax/sandbox-protocol` from a runner package; `mcp-server-drift` enforces it. | A reviewer's "standby imports it, so env.ts can too" was accepted without running the guard test and broke the invariant (R34 reverses the Task 3.4 I1 ruling). | Import the host parser (rejected: breaks the guard and couples runner releases to the protocol package). |
| 2026-11-24 | **Ship as two PRs** (R36): (A) per-agent limits / longer turns, then (B) services on demand (PR steps 1+3 squashed), stacked on (A). PR step 1 alone is half-wired. The kind walk is a separate `(walk)` card after both merge (R35). | Invariant 3 (no half-wired plugins); step 3 uses step 2's limits. | Four PRs per the plan (rejected: the first one ships unreachable code). |
| 2026-11-24 | **Mid-turn credential rotation every 5 minutes, not 30** (R37). | mcp-oauth refreshes only with <5 min left, so a 30-minute cadence leaves up to ~25 min of expired token in a 2-hour turn. | 30 (spec's first number). |
| 2026-11-24 | **Rebase onto origin/main 5e8fd3a76:** kept TASK-1217's `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS` floor and put `BASH_MAX_TIMEOUT_MS`/`API_TIMEOUT_MS` right after it; kept TASK-1212's `priorActivityAt` read, taken from the row AFTER the C1 opening-sandbox wait loop (and left null on a restart — nothing to report mid-turn). Long-command guidance no longer says "run it in the background and poll" (no `run_in_background` on claude-sdk after TASK-1217): explicit timeout, or shell `&` with output to a file. | Both sides' behaviour survives; the background-task mode the old wording named is gone. | — |
