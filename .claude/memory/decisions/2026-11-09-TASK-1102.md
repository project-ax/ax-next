# Decisions — TASK-1102 (MCP directory: record connector provenance from directory listings)

Plan: `docs/plans/2026-11-09-TASK-1102-directory-provenance-plan.md`. Design: `docs/plans/2026-11-09-mcp-directory-connectors-design.md` (Decision 8, Resolved question 4). Planner rows, 2026-11-09, every claim checked against the code on `237409916`.

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-11-09 | **Provenance rows are keyed by connector id alone, and the `connectors:deleted` subscriber deletes a row only on an explicit `idStillLive === false`.** | Connector rows are keyed `(owner_user_id, connector_id)` (`packages/connectors/src/migrations.ts:56`), ids are not unique across owners (legacy duplicates, the create race), and the delete event carries no owner (`ConnectorDeletedEvent`, `packages/connectors/src/types.ts:430-446`, which tells id-keyed subscribers to act only on `false`). `@ax/mcp-oauth`'s subscriber (`packages/mcp-oauth/src/plugin.ts:355-384`) is the precedent copied: non-empty string id or skip, `idStillLive !== false` keeps the row, never throw, return undefined. | Key by `(owner, id)` (rejected: the delete event cannot match it). Parse the owner out of `toolNamespaces` (rejected: opaque derived value, invariant 1). |
| 2026-11-09 | **The subscriber hook is `connectors:deleted`. No boot sweep for events missed while the directory was off or absent.** | It fires from every delete path: the admin DELETE, and both boot sweeps, through `purgeConnectorState` / `announceConnectorDeleted` (`packages/connectors/src/purge.ts`). The directory already inits before `@ax/connectors` (the existing `connectors:directory-search` optional-call edge), so its subscription is in place for the boot sweeps. A mcp-oauth-style boot sweep would have to call `connectors:live-ids`, a directory -> connectors edge that closes a cycle with connectors -> directory. | Boot sweep via an undeclared `hasService` call (rejected: YAGNI; the directory inits first, so it could not run at init anyway). |
| 2026-11-09 | **A malformed `fromDirectory` is ignored: the route strips it, the connector is created exactly as if it were absent (201), nothing is recorded, and one info line (`connectors_directory_provenance_malformed`, no client strings) is logged. A 400 comes only from the existing body rules.** Malformed = not a plain object with exactly the keys `directoryId` and `version`, each a non-empty string of at most 256 UTF-16 code units. The directory hook owns the exact caps (`ID_MAX` 200, `VERSION_MAX` 255) and refuses the rest with `invalid-payload`, which the route logs as a warn and swallows. | Provenance is invisible metadata the admin cannot see or fix in the UI; it must never cost them a save. The field never affects reach. One source of truth for the exact caps (the directory). | 400 on malformed (rejected: blocks a save over a field the admin cannot see). Mirror the hook's exact caps in the route (rejected: a second copy of the directory's limits with no test keeping them in step). |
| 2026-11-09 | **`connectors:directory-provenance-record` takes a fourth field, `serverUrl: string \| null` (the saved connector's single server address, null when it has none or several), and the directory computes `edited = serverUrl !== listing.url` at record time (raw string compare). This extends the card's three-field signature.** | The editor's Server URL field stays editable on a directory prefill (`RemoteMcpConnectorForm.tsx:793`), so an address changed BEFORE the first save would otherwise be recorded `edited: false`, the exact claim Decision 8 exists to prevent. Only the directory knows the listing's address and only the route knows the saved one, so the route passes the fact and the directory decides. The prefill copies `entry.url` verbatim and the form saves `draft.url.trim()`, so an untouched address matches exactly; a respelling reads as edited (over-claims edited, never under-claims, the `retarget.ts` posture). `connectorId` also comes from the upsert result, never the body. | Client sends `fromDirectory` only when the URL is unchanged (rejected: trusts the client for the one bit that matters). Always `edited: false` at create (rejected: dishonest). Call `connectors:get` from the directory (rejected: closes a call-graph cycle). |
| 2026-11-09 | **`version` is stored verbatim once it passes the sync's own `isUsableVersion` (now exported from `normalize.ts`); it is NOT compared with the mirror's current version. `directoryId` must exist in the mirror (`connector_directory_v1_entries`), else `{ recorded: false }`.** | The mirror holds only the latest version, so an older version cannot be verified; if a sync moved the listing on between prefill and save, the prefilled version is the true one and is what lets the follow-up say "a newer version is listed". A lying admin client can only make that cosmetic notice wrong; admins already define any connector they like. | Require `version === mirror.version` (rejected: loses provenance in the race window). Store the mirror's version (rejected: claims the newer version). |
| 2026-11-09 | **Turned off, the directory registers no provenance hooks and no subscriber; its manifest stays `{ registers: ['connectors:directory-search'], calls: [], subscribes: [] }`.** The route skips both calls via `bus.hasService`. Residual: a connector deleted while the directory is off or absent leaves its row. | TASK-1100 decided disabled = no database (`plugin-config.test.ts` and `preset.test.ts` pin that manifest); a stale row is keyed to a dead id, and every new remote connector id carries 8 random hex. The follow-up reader must treat a row as a hint for a live connector it is already rendering. | Keep a database in the off mode (rejected: reverses TASK-1100's no-Postgres off path). |
| 2026-11-09 | **PATCH marks edited when the ORDERED list of `mcpServers[].url` (missing = null) differs between the pre-edit `connectors:get` read and the committed upsert result. It never un-marks. PATCH also strips any `fromDirectory` from the body.** | The card's rule ("any `mcpServers[].url` changed"); adding, removing or reordering servers also means the connector no longer matches its listing. `pointsSomewhereNew` (`retarget.ts`) answers a different question (credential reach; an added server with no slot does not count), so it is not reused. A cross-owner admin PATCH re-submits the stored capabilities, so it can never mark. Stripping on PATCH keeps directory vocabulary out of every `connectors:upsert` payload. | Recompute `edited` against the listing on every PATCH (rejected: would need the listing URL per version). Reuse `pointsSomewhereNew` (rejected: wrong question). |
| 2026-11-09 | **Both provenance calls are awaited before the route answers, wrapped so a throw is logged (`connectors_directory_provenance_failed`, warn, `{ connectorId, hook, err }`) and never changes the status.** | Keeps the composition test deterministic (row present when the 201 returns) and costs one indexed SELECT + one upsert. | Fire-and-forget after responding (rejected: racy tests, unhandled rejections to guard). |
| 2026-11-09 | **Table `connector_directory_v1_provenance(connector_id TEXT PRIMARY KEY, directory_id TEXT NOT NULL, version TEXT NOT NULL, edited BOOLEAN NOT NULL DEFAULT false)`, created in the existing idempotent migration. No FK, no timestamps. A source change or full-crawl reset leaves it alone.** | Invariant 4 and the plugin's no-FK rule (the new-FK teardown trap does not apply). Timestamps have no reader. Provenance stays historically true when the mirror is re-crawled. | `recorded_at` column (rejected: YAGNI; an additive column is cheap later). Clear provenance on source change (deferred to the reader card). |
| 2026-11-09 | **Write-only until the "a newer version is listed" follow-up. Not a half-wired window.** | Design Resolved question 3 (human-approved 2026-11-09) sequences the reader as a follow-up. Both hooks and the subscriber have production callers in this PR, and recording has to start before the reader because provenance can only be captured at save time. | Hold this card until the reader exists (rejected: connectors saved in between would never have provenance). |
| 2026-11-09 | **Card premises corrected:** `ConnectorPrefill.fromDirectory` is not a "new optional field" (TASK-1101 added it; only `submit()` changes). The card's "subscriber builds its own ctx" does not describe `@ax/connectors`' `agents:deleted` handler, which logs through the fired ctx; this subscriber makes no ctx-routed service call, so it does the same. The TASK-1101 row "It is NOT sent with the save" is superseded here (that shard is append-only, R1). | Rule 5: the stale lines are fixed in the plan (`packages/channel-web/src/lib/connectors.ts:503-508`, design doc lines 69-70 and 146-147, `presets/k8s/src/index.ts:550-551`). | — |
