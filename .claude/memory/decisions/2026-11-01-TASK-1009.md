## 2026-11-01 — TASK-1009 scope runner `blob.get` to the session's own blobs

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-11-01 | `blob.get` (ipc-core `handlers/blob.ts`) serves a sha only if `attachments:list-for-conversation` for `ctx.conversationId` lists it. That hook already scopes rows to `ctx.userId`. Unbound session, empty binding, no uploads store, and unlisted sha all return the SAME `notFound('blob not found')` a missing blob returns. The refusal is decided before `blob:get` runs. A failed or out-of-shape lookup returns a sanitized 500. | The only runner caller (`agent-runner-core/materialize-uploads.ts`) gets its shas from `attachments.list`, i.e. this exact set, so it passes by construction. The binding comes from the bearer token, never the request body. | A new `attachments:references-blob` hook (rejected: it adds hook surface for a set the existing hook already returns, and upload lists are small); scoping to the agent owner across conversations (rejected: no caller needs it). |
| 2026-11-01 | Artifacts are deliberately NOT in the reference set. | The runner writes artifacts with `blob.put` and never reads one back over IPC (grep of every `callBinary('blob.get'` caller). Allowing them would be a grant nobody uses (invariant 5). | Include artifacts "for completeness" (YAGNI, widens reach). |
| 2026-11-01 | Lookup cost is one `list-for-conversation` per `blob.get`, so O(N²) rows for N uploads at materialization. | N is a conversation's upload count (small). A per-session cache would need invalidation when new uploads land mid-session. | Cache per session (rejected: staleness, more state). |
| 2026-11-01 | No `ax-planner` run, implemented inline (no per-task subagents). | One handler, the design is fully determined by the existing code, and the brief asks for frugality. The whole-branch `ax-code-reviewer` still runs. | Full planner + subagent pipeline (cost not earned for a ~70-line change). |
| 2026-11-01 | Added a canary step (presets/k8s acceptance "Phase 3 canary", step 5c) that drives the real ipc-core `dispatch` `/blob.get` against the real attachments and blob-store-fs plugins. It checks own conversation → 200 bytes, the same user's other conversation → 404, and that response equals the unknown-sha 404. | The unit tests use a fake bus. The canary proves the real hook answer shape passes `AttachmentsListResponseSchema` and that materialization's path still works end to end. Local Docker (OrbStack) did not respond, so CI runs it. | Unit tests only. |
