| 2026-11-21 | **Coordinator revision 1 (supersedes the "first link of an app id wins" store design and open question 1, app-id squatting): linking is a link-code handshake.**<br>**Mint:** a manager (`agents:can-manage-connectors`, `isAdmin: false`) mints a code in the Apps tab: `axl_` + 32 lowercase RFC 4648 base32 characters (20 random bytes, 160 bits). Only `sha256(code)` hex is stored. It lasts 15 minutes and is bound to `(userId, agentId)`. At most 10 open codes per agent; a mint sweeps expired codes and drops the oldest.<br>**Claim:** the platform calls `POST /api/apps-bridge/v1/links/claim {appId, appName, code}` with its OIDC token. AX checks the code, re-checks the minter's rights, then binds `(platformId, appId)` and burns the code in one transaction (`SELECT … FOR UPDATE`).<br>**Answers:** an already-linked app is `409 already_linked` and the code is kept. A malformed, unknown, expired or used code, or a minter who lost rights, is `403 link_code_invalid`, one answer for all. A claim repeated for the same app id with the code that made the link answers 200 (the link stores `link_code_hash`).<br>No free-typed app id anywhere in the UI. | The coordinator merged the platform side's review with open question 1. A link can't be made without a person with rights over the agent, and the platform can't attach an app on its own. The replay answer (my addition) makes a platform retry after a lost response safe without weakening single use. The rights re-check closes the 15-minute window after a demotion. | Link by typed app id (squattable, decided against).
