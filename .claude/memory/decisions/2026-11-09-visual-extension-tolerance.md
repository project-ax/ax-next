- **2026-11-09 (visual frames vs browser extensions), measured in Playwright Chromium 147 / WebKit 26.4 / Firefox 148:**
  - **WebKit mutes EVERY error inside a sandboxed (opaque-origin) frame**, the frame's own inline scripts included: `"Script error."`, filename `""`, no `error` object. Attribution by `event.filename` is impossible there. `document.currentScript` in the window `error` listener DOES name the throwing top-level script in all three engines (src set for a URL-loaded script, `''` for inline, null for timers/callbacks) — that is the attribution signal the visual runtime uses. Rejection stacks survive in WebKit.
  - **CSP `webrtc 'block'`**: unrecognized by all three — each logs a console error per document and none removes RTCPeerConnection. Don't add it.
  - **Process isolation**: real Chromium (`channel: 'chromium'`) already runs a sandboxed srcdoc frame out of process (a 2.5 s busy loop in the frame left the parent's 20 ms timer on time). Playwright's default headless shell and WebKit put both srcdoc and cross-site frames in-process. So moving chat visuals to the content origin for "OOPIF" buys nothing on Chrome (already isolated) or Safari (no site isolation); considered and NOT built.
  - `allow="camera 'none'; microphone 'none'; display-capture 'none'; geolocation 'none'"` and a matching `Permissions-Policy` header make no console noise in any engine.
