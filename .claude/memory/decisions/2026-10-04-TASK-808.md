## 2026-10-04 — TASK-808 remove connector "Set default"; convert existing defaults to explicit attachments

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-10-04 | **Card premise corrected: a connector default was OWNER-SCOPED, not "on for every agent of every person".** `store.listDefaults(userId)` went through `scopedConnectors` (`owner_user_id = userId`), and `connectors:list-effective` was called with the SESSION user, so a default reached only sessions run by the connector's owner — on any agent that owner could chat with. | Measured by reading `connectors/src/store.ts` + `scope.ts` + `chat-orchestrator/src/connector-union.ts` (`userId: ctx.userId`). The conversion's "every agent where it is effective today" is therefore "the owner's agents", not "every agent". | Treat the card's prose as the spec and attach to every agent in the workspace (rejected: that WIDENS reach to people who never had it, with no attach consent — the exact problem the card removes defaults for). |
| 2026-10-04 | **Conversion targets: the owner's PERSONAL agents, plus TEAM agents where the owner may manage connectors as a non-admin (team admin, TASK-798's rule). A team agent the owner is only a plain member of is SKIPPED with a log line.** | An attachment on a team agent reaches every member's runs (for a shared connector), which is wider than the default ever was (owner's sessions only). Doing it only where the owner could have clicked + Add themselves keeps the conversion inside what a real person could do. Workspace-admin status is not known to `@ax/agents` at boot (no `auth:get-user` dep), so the non-admin rule is the conservative reading. | Attach on every team agent the owner belongs to (rejected: widens reach for other members silently). Skip team agents entirely (rejected: the owner loses a connector they had on a team agent they administer). |
| 2026-10-04 | **The conversion lives in `@ax/agents` (owns attachments, exclusions, the 50 cap and the snapshot-on-attach helper) and reads/clears the flag through two transitional `@ax/connectors` hooks: `connectors:list-legacy-defaults` and `connectors:clear-legacy-default`.** | Invariants #2/#4: neither plugin reads the other's table. `@ax/agents` already has an optional `agents -> connectors` edge (`connectors:resolve`), so the new edges add no call-graph cycle; driving it from `@ax/connectors` would need an `connectors -> agents` edge and close a cycle (#863). | Drive from `@ax/connectors` with undeclared hasService calls (rejected: hides a real dependency). A shared SQL migration touching both tables (rejected: cross-plugin table write). |
| 2026-10-04 | **Runs at the end of `@ax/agents` init, awaited, wrapped so it can never fail boot.** The kernel inits producers of declared (optional) calls first, so `@ax/connectors`, `@ax/tool-policy` and `@ax/teams` are live by then. | The kernel has no post-boot event; this is "the first point both plugins are live". Awaiting keeps it deterministic for tests and avoids racing shutdown; with zero defaults (expected in prod) it is one query. | Fire-and-forget (rejected: races shutdown/DB teardown, untestable). A new kernel `ready` event (rejected: kernel change for a one-shot). |
| 2026-10-04 | **Order per connector: attach (row-locked, idempotent) → snapshot with `onlyIfNotCopied: true` → clear the flag ONLY if no transient failure occurred.** Deterministic skips (50-cap overflow, not allowed on a team agent) are logged and do not block the clear; a thrown hook / DB error leaves the flag set so the next boot retries. | Crash-safe and re-runnable: a re-run finds the attachment already present (no-op) and the snapshot already copied (no-op). `onlyIfNotCopied` keeps rows an agent already got from the first-session default copy. Snapshot runs even when the attach was a no-op, so a crash between attach and snapshot heals on the next boot. | Snapshot only when newly attached (rejected: a crash between attach and snapshot would never be healed). Never clear when anything was skipped (rejected: logs the same skip every boot forever). |
| 2026-10-04 | **Kept `copyConnectorDefaultsForSession` in `@ax/chat-orchestrator`; only its default-specific prose goes.** The card asked to remove "the first-session copy default-on connector verdicts path". | The helper runs over EVERY connector that reaches the agent without an attach — skill-referenced connectors and legacy-owned rows as well as defaults (its own doc names "a skill-referenced connector"). Removing it would regress TASK-754's freeze for those. | Delete it (rejected: regression for skill-referenced / legacy-owned connectors). |
| 2026-10-04 | **Admin routes reject a body carrying `defaultAttached` (any value) with a 400 for one release.** | Card: stale clients fail loudly. Rejecting any value (not just `true`) because the field no longer means anything. | Strip silently (rejected by the card). |
| 2026-10-04 | **A missing `teams:is-member` service during the conversion is TRANSIENT (flag kept), not "not a member".** | `teams:is-member` is a runtime-only, undeclared peer of `@ax/agents`, so the kernel does not order `@ax/teams` before it; init order then rests on preset array order. `teamConnectorRole` reads `no-service` as `none`, which would drop the team agent AND clear the flag — a silent loss. Personal agents still convert in that run; the next boot finishes the team ones. | Declare `teams:is-member` as an optionalCall (rejected: the existing comment deliberately keeps it undeclared; out of scope). |
| 2026-10-04 | **`upsert` writes `default_attached = false` on create (incl. resurrecting a tombstoned id); never otherwise.** | Otherwise re-creating a tombstoned, still-flagged connector id would revive the stale flag and the next boot would attach it everywhere. | Never write the column (rejected for that reason). |
