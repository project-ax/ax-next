# Decisions — SIGNINS-2 (agent-owned connector sign-ins, slice 2a: admin-only connector definitions)

Shard id `SIGNINS-2` covers slice 2a: `memory-write-target.sh` only accepts `WORD-n` ids, so `SIGNINS-2A` is refused. Slices 2b/2c on another day get their own dated shard.

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-10-07 | **Slice 2 is split into 2a / 2b / 2c.** 2a = admin-only definitions + nav. 2b = cleanup (detach-on-delete, purge markers on connector delete, boot deletion of non-admin connectors WITH purge authority). 2c = proposals go to admins. | Each piece is reviewable alone, and 2a's route/UI change doesn't wait on the data cleanup. | One slice-2 PR (rejected: too wide to review). |
| 2026-10-07 | **The stored `keyMode: 'personal'` value is NOT renamed; only UI copy changes.** | About 50 files plus a database CHECK constraint, and held `connector_propose` digests would look stale. The gain is cosmetic. | Rename the value (rejected on cost/benefit). |
| 2026-10-07 | **Id uniqueness is enforced only at admin create:** `connectors:upsert` takes `requireUniqueId`, and only `POST /admin/connectors` sets it (stripped from the body). A live row with that id under another owner → 409 `connector-id-taken`; tombstones never block; existing duplicates stay. | The body must never decide it (it would be an existence probe for other owners' private ids). Slice 1's survivor logic already handles duplicates that exist. | A unique index (rejected: existing duplicates, and tests build them through the hook). |
| 2026-10-07 | **Any admin may edit or delete a SHARED connector someone else owns; the write lands on the owner's row. But a non-owner admin's PATCH writes the STORED capabilities / keyMode / visibility and takes only name / description / usageNote from the body.** `changesOwnerOnlyFields` (normalized with `withCapabilityDefaults`) only chooses 403 `owner-only-change` vs 200. | Parser-differential lesson: a guard that compares the body to the stored row can read a field differently from the runtime (OAuth slot defaults, empty clientId). If the guard decided what got WRITTEN, any such difference would be a retarget. Writing the stored reach makes a guard mistake at worst a wrong 200/403. | Trust the guard and write the body (rejected after review: one mis-normalized field moves every agent's sign-ins and the shared key to a new host). |
| 2026-10-07 | **The `/settings/connectors` read routes stay (list + show).** The agent rail's Add list, the key dialogs and the skill editor read them as non-admins. `GET /settings/connectors/:id/tool-permissions` was removed: its only client is the admin editor. | Deleting the reads would break non-admin agent setup. | Remove the whole bundle (rejected). |
| 2026-10-07 | **The removed `/settings/connectors` writes answer 405 (Allow: GET), not 404.** `@ax/http-server`'s router answers 405 when another method is registered on the same path; a GET still shares `/settings/connectors` and `/:id`. Only `/:id/tool-permissions` (nothing registered) 404s. The dev mock does the same. | The first cut's comments, tests and mock all said 404, which production never answers. | — |
| 2026-10-07 | **Write bodies must be JSON objects (400 otherwise), on POST and PATCH, owner and cross-owner.** | A primitive reached the owner-only guard's `in` checks (500), and on the owner path was spread into the row. | — |
| 2026-10-07 | **Known interim gaps until 2b / 2c / 5:** (1) a non-owner admin who can't retarget can still delete and recreate the id with a new endpoint, and until 2b's detach-on-delete the agents attached to that id stay attached and pick up the recreated connector; (2) a non-admin can still bring a definition in through the authored-proposal approve path until 2c moves proposals to admins. | Both close in later slices of the same epic; 2a doesn't widen either. | — |
