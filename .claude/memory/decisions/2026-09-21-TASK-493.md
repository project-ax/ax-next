| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-09-21 | `memory_note` is a separate host tool that writes `provenance: 'agent'` via `memory:facts:record`, never through `memory:remember` | `memory:remember` is the human-correction write and must keep exclusive claim on the `human` tier — the immunity ordering `human > agent > extracted` only holds if no tool door can mint human provenance. Public input is exactly `{about, relation, value, when?}` with `additionalProperties: false` AND a runtime key whitelist, so smuggled `slot`/`provenance`/`ownerUserId`/`agentId`/`scope` fields are refused before `agents:resolve` is even called | Routing through `memory:remember` with a flag (leaks the tier boundary); trusting a model-provided slot/provenance (model could self-promote to human) |
| 2026-09-21 | The note tool emits no `batchKey` — two identical notes are two distinct rows | Notes are explicit statements, not extractor batches; dedup via content hash would silently drop a deliberate repeat. Slot closure still applies, so a repeat on a mapped relation closes the prior row but both rows remain in history | Reusing `buildBatchKey` (would suppress legitimate repeats); engine-side dedup (would mix concerns) |
| 2026-09-21 | The observer derives `slot` from `fact.predicate` via `deriveSlot()` in `toStatements` — same frozen synonym table as `memory:remember`, single vocabulary | One source of truth (SLOTS in slots.ts) for both human notes and extracted facts. Unknown relations stay slotless: stored and retrievable but inert for supersession — never `PENDING_SLOT`, because pending raises `degraded` on every recall with nothing to drain it. Model-emitted `slot`/`provenance` fields are parsed-then-dropped; derivation happens on our side only | LLM-emitted slots (unverifiable, self-promotable); approximate/embedding matching (over-closes facts); per-writer tables (drift) |
| 2026-09-21 | Shared-agent access semantics from TASK-495 apply unchanged to notes: personal agents owner-only, team agents all members share one store; writer's `ownerUserId` is stamped but never filters team reads | Authorization comes only from `agents:resolve` at call time — a non-member gets `{error: 'forbidden'}` with zero engine calls. `onFactsChanged` fires after a confirmed single-record return so the derived export stays consistent | Any caller-provided scope flag or cached membership (rejected — fail-closed) |
| 2026-09-21 | Note failures degrade inside the handler into `MemoryNoteResult` — `invalid-input`/`forbidden`/`memory-unavailable` — never throwing to the agent; failures log `memory_note_failed` (or `memory_no_llm_credential` at error level) with a static `reason` + agentId + `path: 'note'` only | An agent-visible tool must answer a typed failure, not a bus exception; logs carry no fact contents, no smuggled keys/values, no raw error messages (verified by test against a hostile key and a db-internal error string). A throwing log sink cannot break the degrade | Throwing `PluginError` to the tool runtime (leaks internals); returning ok on unverifiable record returns (silent loss — invalid-return instead) |
