| Date | Decision | Rationale | Alternatives |

| 2026-09-29 | **Conversations are hard-deleted with the agent (no retention).** | The only retention statement is the `@ax/conversations` migration header ("orphan rows are tolerable and can be GC'd later"), which is tolerated debt. Every per-conversation hook calls `agents:resolve` first, so a deleted agent's conversations 404 on every read; no view lists them; the delete dialog promises nothing. Public launch makes it a privacy question. | Keep and say so in the dialog: nothing in the product can show the kept history, so the promise would be empty. |
| 2026-09-29 | **Reclaim fix = run the reclaim pod as root with `drop ALL` + add `DAC_OVERRIDE`,`FOWNER` only, not a second root-only `rmdir` step.** | Reproduced locally: uid 1000 cannot unlink `/export/<agentId>` from the root-owned export root. Same shape as the runner's chown init (root + one capability, `no_root_squash` export). A two-step (uid 1000 empties, capability-free root `rmdir`) is tighter but an agent-made `chmod 000` directory would defeat the first step for good, and a pod-level failure in an init container reads as a null exit code. | Two-container split (rejected above). Chown the export root (touches every tenant). |
| 2026-09-29 | **Cross-plugin cleanup rides `agents:deleted`; conversation-keyed tables in other plugins ride a new `conversations:purged { conversationIds }`.** | Attachments has no `agent_id`; it may not read conversations' table. Pushing the purged ids after commit is order-independent, unlike a second subscriber that would need the conversation rows to still exist. | `conversations:list-ids-for-agent` service: needs the rows to survive until attachments has run, i.e. subscriber-order dependent. |
| 2026-09-29 | **Blob bytes behind attachments are left in place (follow-up card).** | Blobs are content-addressed and shared across users; deleting by sha256 needs a refcount authority across attachments and branding, and a check-then-delete race would break another tenant's file. Leaving a bounded orphan is the safe failure. The rows go, so nothing in the product can reach the bytes. | Refcounted delete inside attachments: still racy against a concurrent commit of the same sha. |
| 2026-09-29 | **Live-session handling: session-postgres terminates then deletes the agent's sessions (revoking the IPC token), chat-orchestrator kills the warm sandbox, conversations guards its append paths against a missing row.** | Nothing terminated a deleted agent's sessions; a warm runner kept its mount and credential-proxy session for up to 5 minutes. Subscribers run in init order, so no ordering between purge and terminate can be assumed; the append guard shrinks the resurrect window from "the rest of the turn" to one statement. | Assume subscriber order (fragile). Add a transaction across plugins (not possible over the bus). |
| 2026-09-29 | **Implemented Task 1 inline; Tasks 2-6 by parallel subagents on disjoint packages.** | Task 1 is a small change I already hold the full context for. The rest are independent packages with the same pattern. | Per-task subagents for everything. |
