# Decisions — TASK-633 (re-mention suppression honours retracted values)

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-09-27 | **Refuted the brief's "both backends where the logic lives".** Re-mention suppression (`rementionedSlotRows`) and the profile pick (`selectProfileRows`) live ONLY in `@ax/memory/src/profile.ts`. Both engines already emit `neverTrue: true` on every read path (`rowToFactRecord` in sqlite and postgres; contract cases pin scan + fusion history). No engine change was needed. | grep: the two functions appear only under `packages/memory`. | Add a backend filter — a second copy of the rule (invariant 4). |
| 2026-09-27 | **A retracted row (closed AND `neverTrue`) counts as REPLACED for re-mention purposes**, in both functions. A Forget (closed, no successor, no bit) still does not; a reinstate clears the bit, so a reinstated-then-forgotten row reads as forgotten. The bit only counts on a CLOSED row. | "Never right" rejects the value itself — stronger than a replacement. Same shape as TASK-602's rule, one helper (`isRetracted`) so recall and profile cannot drift. | Treat every closed row as replaced (rejected in TASK-602). |
| 2026-09-27 | **The person re-stating a retracted value is a `human` row and wins** — settled by existing code, not a new product call: `selectProfileRows` rule 1 (human authoritative) and `rementionedSlotRows` only drops OUTRANKED rows (a human row never is). Pinned by tests at both layers. | Brief asked to decide + test it; code already decides. | — |
| 2026-09-27 | **A lone re-mention of a retracted value still shows** (no fresh value in the slot): same fallback TASK-602 gave replaced values ("rather than showing nothing"); recall likewise drops only an outranked re-mention. Pinned by a test so a change is deliberate. Returned as a follow-up question, not built. | Changing it would diverge retracted from replaced handling and is a product call the card did not ask for. | Hide it entirely — would also block the extractor from ever learning the value again from the person's own chat. |
| 2026-09-27 | **Export profile reads never-true rows as history.** `buildFactsExport` drops them from every file (TASK-624), which also hid them from `selectProfileRows`' history — so the export profile could resurface a retracted value. They are now passed as history only (closed rows are never candidates, never rendered). | Third surface of the same bug; found while tracing the callers. | Leave the export alone — the exported profile.md would disagree with the injected block. |
