# TASK-982 — private task webhook addresses

- Build on merged TASK-981/TASK-986 (#1066, ece0ffad4), in an isolated worktree. TASK-982 is the complete address slice; batched inbox/timers/status remain TASK-983/984/985. No production operation is authorized.
- Schema18 adds private address-token and legacy-alias columns on routines' existing definition row. They never enter StoredRoutine, editable definitions, generic views, tools, approval/operation receipts or private payload blobs. Only the current owner with live edit authority can provision/read/replace through private setup services and authenticated HTTP; responses use no-store. Team emergency-stop authority grants no address access.
- Only existing webhook rows inherit legacy aliases at migration. Provisioning a random256-bit per-task token keeps that alias. Replace uses an address-specific version guard, changes no task revision/configuration, and revokes only that task's prior token and alias. Failed/unknown responses must reload current setup state; never blindly repeat rotation. New tasks and duplicates have no legacy alias and wait for owner setup. A migration repair preserves explicit revocations.
- The receiver discovers by task token or by the existing agent token plus a live task alias. Durable Repeat admission rechecks the proof while holding the definition lock; legacy admission also re-resolves the agent token. This fences a delivery authenticated before rotation without cancelling deliveries accepted before it. Keep the existing admission serialization before opening transactions to avoid the TASK-976 connection-pool deadlock.
- Owner reconciliation clears the token and alias atomically with ownership state. Removing the webhook clears both; deletion removes the row. Re-adding an app or reusing the path cannot restore prior reach. The old agent-wide management endpoints retain their original narrow gates.
- The editor uses only owner-scoped task setup, never the agent-wide token. New tasks and unsaved additions of app updates show Save first. Scope loaded data synchronously by both agent and task, so switching tasks cannot commit another task's bearer before effect cleanup. Confirmation explains task-local revocation; a lost response hides the previous URL until a fresh read.
- Rolling back the receiver below this implementation would ignore task-local legacy revocations. After cutover, preserve this receiver fence or stop webhook ingress before an older binary runs; schema columns alone cannot constrain old receiver code.
