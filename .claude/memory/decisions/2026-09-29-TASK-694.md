# TASK-694 decisions — pin the kind tooling to kind-ax-next-dev

| Date | Decision | Rationale | Alternatives considered |
|------|----------|-----------|------------------------|
| 2026-09-29 | Every kubectl/helm call in the `Makefile` goes through `KUBECTL` / `HELM` (`--context` / `--kube-context` `kind-$(KIND_CLUSTER)`), and every cluster-touching target depends on a `kube-guard` prerequisite that refuses BEFORE doing work when the kubeconfig has no such context. `reset-bootstrap` is included though the card did not list it. | A bare call acts on whatever the caller's DEFAULT context is; on this maintainer's machine that is the live GKE cluster. `reset-bootstrap` ("wipe bootstrap + admin/agent/credential rows") was the worst bare-call target on that machine, worse than the `rollout` that caused the incident. The guard matters for `make image`: without it a missing context fails only after the 90s docker build + `kind load`. | Only wrap the calls (no guard: a missing context still fails loudly at the first call, but after the slow work); a `use-context` step (rejected: mutates the maintainer's global kubeconfig, which the card forbids). |
| 2026-09-29 | `gke-deploy` now REQUIRES `make gke-deploy GKE_CONTEXT=<context>` and refuses a missing, `kind-*`, or unknown-to-the-kubeconfig context via `gke-guard`, before anything is built or pushed. Every cluster call in it names that same context. **Behaviour change: plain `make gke-deploy` no longer works.** | The card says the tooling must stop depending on the default context, and `gke-deploy` used to check the default and then use it (a check-then-use gap, and exactly the failure mode being removed). A committed default is impossible: the context name is deployment-specific and this repo is public (`scripts/__tests__/no-deployment-specifics-committed.test.js`). Explicit-required also lets the Makefile text guard have zero exceptions. Nothing in the repo invoked `make gke-deploy` except docs/comments, so no caller broke. | Resolve the current context once and pin to it (keeps the old one-word UX, but still "follows the default" and needs a bare read in the Makefile, i.e. a hole in the guard); leave `gke-deploy` on the default with its kind-refusing check (rejected: the check-then-use gap stays). |
| 2026-09-29 | The docs guard covers only the kind-facing docs (`k8s-acceptance-loop`, `chat-qa-sweep`, `deploy/kind/**`, `deploy/MANUAL-ACCEPTANCE.md`). `deploy/GKE.md` and `deploy/README.md` are deliberately out of scope. | GKE.md is for a real cluster and README.md is a generic "any cluster" install doc, where the operator picks the context and a fixed kind name would be wrong. GKE.md already opens with a "point kubectl at the cluster" step. | Pin every doc (rejected: wrong for real-cluster docs); pin none and only guard the Makefile (rejected: the incident came from copying the skill's snippets). |
| 2026-09-29 | In prose, an inline code span counts as a command only when it has 3+ words (`kubectl logs deploy/x`); a bare tool name or `tool verb` is a reference and is left alone. Prose that merely NAMED a command (`helm install ax-next`, `kubectl edit secret`) was reworded, not pinned. | Pinning every mention turned sentences into noise (`helm --kube-context kind-ax-next-dev uninstall + install`). Fenced snippets and runnable spans are what get pasted, so those are exact. | Pin all inline mentions (noisy); scan only fenced blocks (would miss the inline destructive command in MANUAL-ACCEPTANCE's fault walk). |
| 2026-09-29 | The committed test runs each target through PATH stand-ins for kubectl/helm/docker/kind/pnpm against a throwaway kubeconfig; it never runs a real kubectl. The real-kubectl proof was done once, ad hoc, against two loopback fake API servers (results in the PR). | The test must run in CI and on any laptop without a cluster, and must be structurally unable to touch a real one: stand-ins first on PATH, and the only server in the throwaway kubeconfig is a dead local port. | A real kubectl against fake servers in the committed test (port juggling + kubectl's discovery chatter makes it slow and flaky for what it adds). |
