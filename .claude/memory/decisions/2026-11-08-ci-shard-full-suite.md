# Decisions — CI full-suite sharding (#1153)

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------|
| 2026-11-08 | **main's full test suite runs as 4 parallel shards (`scripts/ci-test-shard.sh`: routines / web / agents / rest); PRs keep ONE job named `test` over affected packages.** | One 4-core runner spent ~22 min on `pnpm -r run test`, mostly the 6 slow packages queueing for the same cores; after #1152 (shared Postgres per file) routines alone was still 366 s there. The split is defined ONCE in the script; `rest` = every package not named, so a new package can't fall out — `scripts/__tests__/ci-test-shard.test.js` pins the partition against the live workspace and that ci.yml's push matrix lists exactly the script's shards. Lint/audit run on `pr`/`rest` only; Playwright + zsh skipped on routines/agents. The sharded path only runs on push to main: a PR that edits ci.yml runs the full suite unsharded in its one job. Bigger runner (paid; no code change) — kept in reserve. Splitting by test FILE (vitest --shard) — rejected: per-package setup repeats in every shard and Docker-heavy files would collide. |
