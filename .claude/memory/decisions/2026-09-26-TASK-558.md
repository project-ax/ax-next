# Decisions — TASK-558 (agent displayName bidi/control characters)

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-09-26 | The `@ax/agents` store write door (`validateDisplayName`) REJECTS a displayName containing any of `DISPLAY_NAME_FORBIDDEN` (C0, DEL, C1, U+061C, U+200B-U+200F, U+202A-U+202E, U+2066-U+2069, U+FEFF) with `invalid-payload`. | Stripping silently saves a name the owner did not type, and they only find out on read-back. A 400 names the problem when it can be fixed. Precedent: TASK-459 rejects C0/DEL/C1 in fact text at its write door. Both callers already map `invalid-payload` to 400 (admin route, `/api/agents/bootstrap`). | Strip at write (rejected: silent mutation of user input). |
| 2026-09-26 | The class is an exact twin of `@ax/channel-web` `REWRITES_THE_SURFACE` (fence-line.ts), including ZWNJ/ZWJ. | Card: include zero-width joiners if the existing fence strips them — it does. One rule, spelled twice (plugins cannot import each other, invariant 2). Known cost: an emoji ZWJ sequence (e.g. family emoji) or a Persian name using ZWNJ is refused. Accepted for consistency with every other fenced label; revisit only if a user hits it. | Narrower class allowing ZWJ/ZWNJ (rejected: diverges from the fence every other label uses, and ZWJ/ZWNJ enable look-alike names). |
| 2026-09-26 | Rows written before the door: fenced on READ in `rowToAgent` (`fenceStoredDisplayName`: each run -> one space, collapse, trim, empty -> 'Untitled agent'). No data migration. | `rowToAgent` is the single funnel for every store read, so every reader of `agents:resolve`/`agents:list` gets it — not one renderer. Rewriting user data in a migration is irreversible; a read fence is not, and the next save through the write door cleans the row (the fenced value passes the door). | Migration (rejected: irreversible, and the read fence covers display anyway). Render-side fence in channel-web (rejected: several readers, invariant 4 — TASK-480 decided the same). |
| 2026-09-26 | Admin route zod `displayNameSchema` gets the same refine, importing the regex from store.ts (same package). | Admin form gets the named error before the hook; one regex object, not a copy. | Rely on the store only (fine but the route already mirrors every other store check). |
