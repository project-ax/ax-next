# TASK-491 — `system-prompt:augment`, the always-injected memory block

Design §4.1. Four parts (Rules, Profile, Recent, Digest) from three store queries, no
embedding, no rerank, no model call, ~800-token soft cap.

## The card's premise was short by three engine fields — measured, not guessed

The card and `docs/plans/2026-09-20-rung-3-product-layer-handoff.md` §5 both put card E
("`system-prompt:augment` block") on card B alone. It is not buildable on B's surface.
As `@ax/memory-facts-contract` stood at `3fae262e`, `FactRecord` carried
`{id, about, relation, value, when, until?, provenance, closedBy?}` and `RecallInput`
carried `{about?, ownerUserId?, activeOnly?, limit, query?, poolSize?}` — so:

- **Profile** ("active rows, `about = user:<caller>`, **slot rows only**", rendered
  `- lives_in: Seattle (noted Mar 2024)`) had no slot filter and no slot on the row.
- **Recent** ("grouped by conversation") had no `conversationId` on the row, and
  grouping is not approximable without it.
- **Digest** needed nothing new.

So the PR adds three additive contract fields — `FactRecord.slot?`,
`FactRecord.conversationId?`, `RecallInput.slots?` — plus both backends and 9 shared
contract cases. A future card reading "build a §4.1 part" should check the engine
surface before assuming card B covered it.

## Decisions that are expensive to reverse

- **`slots` is pushed into the store's WHERE, not applied to returned rows.** Same
  argument as `ownerUserId`: a profile is ≤ 10 rows out of a tenant holding thousands of
  slot-less ones, so cutting the page first answers an empty profile to a person whose
  slot rows are merely older. Pinned by a `limit: 1` contract case on both backends.
- **`slots` + `query` is REFUSED, not ignored.** The filter is not plumbed through the
  fusion channels. An unfiltered ranked set dressed up as a filtered one is a wrong
  answer the caller cannot detect. Empty `slots: []` is refused too — "match nothing"
  and "do not filter" are opposite readings of the same payload.
- **The slot on the row is ECHOED, never re-derived from `relation`.** Derivation lives
  in `@ax/memory` (§3.3); a reader recomputing it would be a second copy of the mapping
  under another name.
- **The slot-constant collision with TASK-489 happened, and was resolved by deleting
  this card's copy.** Both cards were in flight and both created
  `packages/memory/src/slots.ts`. TASK-489 (#662) merged first with `SLOTS` **plus a
  guard test that scans every non-test `.ts`/`.tsx` under `packages/` and fails when 3+
  slot names appear within 200 characters of each other** — so a second copy is a failing
  test, not a silent divergence. The rebase took TASK-489's file wholesale and pointed the
  injected profile at `SLOTS`; `compareSlots` (render order) moved into `augment.ts`,
  where it belongs — `slots.ts` owns the vocabulary and the derivation, not how a block
  sorts them. **Two agents creating the same file is the predictable shape when two cards
  share a constant; the guard test is what made it cheap.**
- **Provenance is NOT flattened in the rendered block.** Rules is a separate section
  from a separate, sandbox-immutable source (TASK-486/#661); within the store every line
  carries its own `[human]`/`[agent]`/`[extracted]` tag under a key stating the three are
  not equally reliable. Two active rows CAN share a slot — §3.4 rule 3 closes a row only
  with equal-or-higher provenance — and the profile renders the higher-provenance one, so
  the immunity is not undone at render time.
- **One escaping helper with one owner**, `packages/memory/src/render.ts`. The
  `memory_recall` tool result and the export are separate cards and import it. Stripping
  line breaks is the LOAD-BEARING escape, not a formatting nicety: markdown structure is
  line-anchored, so a value that cannot hold a line break cannot become a heading, a list
  item or a fence. Pipes are escaped for row forgery; backslash is escaped BEFORE the
  pipe, or a trailing `\` swallows the escape.
- **Per-value truncation at 400 chars is a security control, not cosmetics.** The token
  budget bounds the block but not its shape: one 40,000-character value consumes the whole
  cap and evicts the person's real profile. Truncation makes the budget a budget over many
  rows rather than a race one row can win.
- **A rules provider that is ABSENT is a configuration state; one that THROWS fails the
  whole block closed.** Absent is `optionalCalls` on the manifest with its degradation
  spelled out. Throwing propagates, because injecting recalled observations while
  silently dropping the standing instructions that govern them is the worst outcome
  available.
- **`degraded` is rendered into the block and sits in the never-dropped tier.** §4.4: a
  signal, not a quieter answer. A non-string flag (TASK-515's open gap) is coerced with
  `String()` and shown rather than filtered out — dropping one would silently discard a
  degradation signal.
- **An owner-less session returns no contribution.** Checked with the kernel's
  `isOwnerlessId` up front rather than by catching `resolveOwnerUserId`'s refusal, so the
  canary and `ax serve` do not log `system_prompt_augment_failed` on every spawn for a
  configuration working as designed.
- **The digest's "count × recency" is defined as reciprocal rank** over the store's own
  recency order, `k = 60` — the engine's own RRF constant. Count-dominant with a recency
  tilt, and **clock-free**: a wall-clock decay was the obvious alternative and was
  rejected because a clock here makes the block untestable without freezing time.
- **`system-prompt:augment` is a single-provider service hook**, so `@ax/memory` and
  `@ax/memory-strata` cannot both load in one preset. §10.4's "one memory plugin per
  preset" is therefore enforced by the bus, not by a convention, and Invariant 4 holds
  trivially.

## Invariant 3 — stated, not dodged

`@ax/memory` is still in no preset and not reachable from a canary. The preset + canary
card at the end of the epic closes that window; this card did not widen it.
