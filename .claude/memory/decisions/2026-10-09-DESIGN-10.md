## Boundary review

- Alternate implementation: an in-memory or SQLite routine store can return the same optional enabled boolean.
- Payload field names that might leak: none added; `enabled` describes application behavior rather than storage or transport.
- Subscriber risk: no backend-specific fields added. Missing enabled fields retain historical enabled behavior.
- Wire surface: RoutineRowSchema remains in the routines plugin. Existing routine returns carry the optional boolean; no new service hook, IPC action, or token-bearing subscriber payload was introduced.

## Security review

- Sandbox: Skill attachment now admits the authenticated caller's private definitions as well as workspace definitions. Identity is forced from the session; agent ACL and owned-scope lookup reject unauthorized access. Receiver-token access retains the existing owner/admin service gate. No additional filesystem roots, network destinations/ports, processes, environment access, sockets or handles are granted; existing bounded workspace writes and bundle-path validation remain authoritative.
- Injection: Skill/routine content and API descriptions render through escaped React text and pass the existing manifest/path validators before workspace application. Enabled booleans use parameterized storage operations. URL previews combine the current origin, a validated authenticated token and the canonical server-validated route path; no untrusted string enters shell commands, raw HTML, SQL text, or privileged system instructions. Tokens stay local to the selected form and never enter subscriber payloads or logs.
- Supply chain: N/A: no package.json or lockfile changes and no new direct or transitive dependencies. Browser verification reuses the existing pinned Playwright dependency; dependency builds use the frozen installed workspace graph.
