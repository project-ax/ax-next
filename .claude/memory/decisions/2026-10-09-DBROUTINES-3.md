# DB-backed routines Task 3 — transactional lifecycle

- Routine schema v2 is one transaction under migration advisory lock `18427131`; only a schema still carrying `path` runs authored retirement. Fresh schema uses `routine_id`, and the completed version prevents any legacy seed/path SQL on later startups. Preserve default identity values and all `default:` fire identities, including history whose catalog entry was deleted. Before dropping `source_md`, retain the Strata seed's existing hash + exact seed-marker guard. Never derive a cleanup target from legacy JSON `secretRef`; capture only `routine:<agent>:<old-path>:hmac` with its real owner.
- Private store mutations require authenticated `actorUserId`; `ownerUserId` stays pinned on create and changes only through authoritative personal-owner reconciliation. Receipt table `owner_user_id` is the actor scope despite its schema name. `createRequestHash`, `updateRequestHash`, `deleteRequestHash`, and `dispatchRequestHash` hash the canonical public effect; exclude request ID (already in the receipt key), actor, pinned owner, clock, and authority flags. Mutations insert-or-lock the receipt, compare hash, and commit effect + validated result together. Matching replay precedes current-row/CAS checks.
- Cleanup discovery never authorizes a credential call. `runCredentialCleanup` locks definition then re-fetches/locks the current job, invokes a bounded callback without exposing the transaction, and removes the job only after success. Secret mutation uses the same definition/pending-job fence. Reconfiguration cannot overtake cleanup; an old discovered key retried after completion cannot delete a new secret. Emergency `{enabled:false}` remains available while cleanup is pending.
- Agent deletion has a durable `routines_v1_retired_agents` tombstone plus transaction-level advisory fence keyed by `hashtextextended(agentId,18427132)`: shared for mutations/dispatch acceptance/completion/default materialization/override writes, exclusive for purge. Order is agent fence → receipt/definition or dispatch locks; cleanup uses definition → job and remains drainable after purge. Purge deletes dispatches before fires and retains the tombstone, blocking requests that were authorized before deletion from recreating data afterward. This marker is not agent ownership truth; authenticated `agents:resolve` remains required at the service boundary.
- Dispatch acceptance commits a generated dispatch/req ID before invocation; finish locks the durable dispatch and records one terminal fire, updating only the matching definition revision and not overwriting a newer completion. Dispatch records survive routine deletion and are removed on agent purge. Later task adapters must use receipt lookup to avoid re-invoking a replayed dispatch and must supply bounded credential-hook effects.
- Intermediate cutover task only: legacy plugin/sync/fire/tick/webhook/index callers intentionally remain incompatible until Tasks 4/8/11. Do not reintroduce path/source-md shims to make them compile. Focused PostgreSQL suites are the current validation surface; final branch completion still requires full integration/canary gates.

- Canonical default interval seconds use bigint in Postgres: the contract allows durations above int32 seconds (e.g. `100000d`) while remaining within JavaScript Date bounds. Keep the storage range at least as wide as the validated contract. A real Postgres RED/GREEN regression pins this.
