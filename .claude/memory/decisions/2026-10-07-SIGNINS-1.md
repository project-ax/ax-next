# Decisions — SIGNINS-1 (agent-owned connector sign-ins, slice 1)

Shard id `SIGNINS-1`: the epic has no board card yet, and `memory-write-target.sh` only accepts `WORD-n` ids.

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-10-07 | **Slice order changed: the lookup flip goes last.** Slice 1 is the purge and delete cleanup. Flipping `account:` reads away from user scope comes at the end of the epic. | 22 test files in 7 packages assume person-level `account:` rows. Flipping first would turn the whole epic into one red diff. | Flip first, as the design doc's order had it (rejected: too wide a blast radius). |
| 2026-10-07 | **`credentials:purge-account {connectorId?, scopes}` → `{purged}` tombstones rows through `credentials:store-blob:list` + `put`. `scopes` may only be `user` or `agent`; `global` is refused (`invalid-payload`).** With `connectorId` it matches `account:<id>` and `account:<id>:*` only. The trailing `:` keeps `gmail` from matching `gmail2`. | Tombstones go through the existing blob seam, so a KMS or vault backend works unchanged. No caller needs `global`: a connector's company key is its own key, and `credentials:delete` purges it by ref. Slice 5's boot migration needs only `user`. | Hard delete through a new store-blob hook (rejected: widens the store seam for one caller). Allow `global` (rejected: more reach than any caller needs, invariant #5). |
| 2026-10-07 | **The purge swallows only unreadable-blob errors** (`decrypt-failed`, `invalid-ciphertext`, `invalid-envelope`) and tombstones those rows. Any other error is rethrown. | A blob the key can't read is dead weight left after a key rotation. A broken store entry is a real fault and must not be tombstoned without anyone reading it. | Bare `catch {}` (the slice-1 first cut; the final review flagged it). |
| 2026-10-07 | **Deleting a connector purges agents' sign-ins only when all three hold: the connector is SHARED, the delete has admin authority (`purgeGlobal`), and no other live SHARED connector with the same id survives (`hasLiveSharedById`).** The survivor check runs after the soft-delete. If the check throws, we log `connectors_delete_survivor_check_failed`, treat it as a survivor and keep the rows. The stdio sweep passes `purgeAgentSignIns: !shared`. | Agent rows are keyed by id alone, with no owner. Non-admins CAN create shared connectors today, because `admin-routes.ts` defaults visibility to `shared`, so a non-admin delete must not wipe them. Once the soft-delete has committed, a failed check that rejected the hook would make a retry return `{deleted:false}`, and the cleanup would never run. | Run the check before the soft-delete (rejected: a race with a concurrent delete). Let a throw reject the hook (rejected: the cleanup is lost for good). |
| 2026-10-07 | **Known gap, closed in slice 2: id reuse after a delete without authority.** A shared connector deleted without `purgeGlobal` leaves its agents' rows. A same-id re-upsert can then read them. `agent-credential-attachment.test.ts` pins this with a "KNOWN EXPOSURE" test. **Slice 2's boot step that deletes non-admin connectors must pass purge authority**, or it will leave exactly these rows behind. | Slice 2 detaches the connector from every agent on delete, which closes the read path. | — |
