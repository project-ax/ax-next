# TASK-488 — `@ax/memory` skeleton + `memory:recall` / `memory:remember` / `memory:forget`

The rung-3 product layer over the already-shipped `memory:facts:*` engines. Nine cards
(489–495, transitively 496/497) build on this hook surface.

## The three hooks, as shipped

| Hook | Payload → result | Provenance |
|---|---|---|
| `memory:recall` | `{query?, about?, activeOnly?, limit?}` → `{statements, degraded}` | read |
| `memory:remember` | `{about, relation, value, when?}` → `{id}` | `human` |
| `memory:forget` | `{ids}` → `{}` | `human` |

`@ax/memory` **orchestrates and does not reimplement the store** — every path is a
`bus.call` into whichever engine the preset loaded. No cross-plugin import in `src/`.

## Decisions that are expensive to reverse

- **Provenance is a property of WHICH HOOK was called, never a payload field.** No
  caller-facing payload carries `provenance`, and `memory:remember` **refuses** (does not
  ignore) a payload that sets one. Ignoring is the shape that reads as working: the caller
  gets a `200` and believes it took effect, and a test asserting the default passes
  identically whether the field was stripped or never supported. The refusal IS the
  assertion. Same treatment for `ownerUserId`.
- **`ownerUserId` is a SCOPE from `ctx`, never a hint from a caller** (the `@ax/decisions`
  phrasing). Reads are owner-scoped by default; the scope is pushed into the engine's own
  SQL predicate, never applied to rows that came back — a post-filter under a `limit`
  returns a short or empty answer to an owner whose rows were merely outranked. Design
  §6.1: "Never post-filter a widened pool."
- **Strict equality, so an UNOWNED row (`owner_user_id IS NULL`) is invisible to a scoped
  read.** Unowned is not provably yours. Treating an unstamped row as everybody's turns a
  caller that forgot to stamp a write into a cross-owner channel.
- **A foreign-owner id on supersede is REFUSED, meaning: not closed, absent from `closed`,
  nothing thrown** — deliberately the identical shape a foreign-TENANT id already had. One
  refusal shape, not two.
- **`resettleSlotGroups` stays TENANT-scoped on both engines** even though supersede is
  owner-scoped. A `(about, slot)` chain belongs to the tenant, so re-deriving it over one
  owner's rows would invent a second divergent set of closure rules. Owner scope decides
  what a caller may *retract*, not what surviving rows *mean*. Not reachable from
  `memory:forget` today anyway: `memory:remember` sends no `slot`, so its rows are inert.
- **An owner-less session is REFUSED, not partitioned.** `isOwnerlessId` — memory joins the
  refuse side (`workspace-git-core`, `skill.propose`, `connector_propose`) rather than the
  partition side the memory-strata index backends are on: a private per-session partition of
  a person's *memory* accumulates rows nobody will ever read back.
- **A routine run records under the ROUTINE OWNER's real userId.** `resolveOwnerUserId` does
  not branch on `ctx.source`, deliberately — a branch there is exactly where a
  `'system'`/`'anonymous'`/`''` owner gets invented.
- **`memory:forget` returns `{}` with no per-id outcome.** Saying which ids were refused
  hands a caller an existence oracle over other people's statements, and an honest caller
  can never hold a foreign id because `memory:recall` is owner-scoped.
- **`degraded` is `string[]`, not a copy of the engine's flag union.** The vocabulary is the
  engine's to grow; a local union here would be a second source of truth that silently
  dropped any flag a newer engine raised. Passed through verbatim — including the
  deliberate asymmetry where an empty store with no providers raises `'semantic'` but not
  `'ranking'`.
- **`at` is deliberately ABSENT from `MemoryRecallInput`** although design §2.2's hook table
  lists it. §4.2 keeps point-in-time travel off the agent-facing surface and neither engine
  implements it (`@ax/memory-facts-contract`'s `RecallInput` has no `at`). `activeOnly:
  false` is the supported neighbour — history, not time travel. Re-adding `at` is a
  hook-surface change and needs the engines first.
- **`kind` is declared on `MemoryStatement` but never populated.** No engine has a `kind`
  column. Declared now so the observer card can start storing it without a hook-surface
  change; a test pins the absence so nobody reads it as a bug.
- **No `batchKey` and no `slot` on the `memory:remember` write.** Idempotency keys exist
  because `chat:end` can fire twice; a person pressing "remember" twice means it twice. No
  slot means the row is inert for closure — under-closing, the safe direction. Not
  `PENDING_SLOT` either, because that raises `degraded: ['pending']` on every recall about a
  drain component that does not exist yet.

## Invariant 3 — stated, not dodged

`@ax/memory` is **not in any preset and not reachable from a canary** in this card. Handoff
§10.4 settled that it lands in its OWN new preset with its own canary and that `presets/k8s`
keeps `@ax/memory-strata` untouched — one memory plugin per preset, so invariant 4 holds
trivially. The preset + canary card at the end of the epic closes the window.
