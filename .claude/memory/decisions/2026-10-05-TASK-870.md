# Decisions — TASK-870

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-10-05 | The bypassMITM "leaves an established tunnel alone" test (`listener-bypass-connect-timeout.test.ts`) had a TEST race, not a product race. No `listener.ts` change. | Reproduced 5/5. The `node:net` mock scheduled a 300ms `setImmediate` busy-wait right after the listener's upstream dial. The client got `502 Bad Gateway`: the loopback connect finished during the stall, but the timers phase ran the 100ms connect timer before the poll phase delivered `connect`. In production the window is 30s (`UPSTREAM_CONNECT_TIMEOUT_MS`). Only a stall longer than the timeout itself reaches this, which is what a connect timeout means anyway. | Change the product so the timer re-checks socket state. Rejected: no product defect at a realistic stall length. |
| 2026-10-05 | Fix: the same TASK-865 fake-clock pattern. Fake only `setTimeout`/`clearTimeout`. The upstream holds its reply in an `answer` closure (it was a real 400ms `setTimeout`). Wait for the upstream to receive the client's bytes. Assert that exactly one timer was armed at the window on the fake clock and that `getTimerCount()===0`. Advance 4x the window, then answer. Poll audits with `setImmediate`. | Socket I/O, `setImmediate` and `Date` stay real. The connect timer is a plain global `setTimeout`, not `socket.setTimeout`, so TASK-876's `deferIdleTimers` is not needed here. The raw tunnel has no idle timer. | `deferIdleTimers`-style spy (wrong timer kind). Widen the window (still a race). |
| 2026-10-05 | The wall-clock `Date.now() - started > 2*window` assertion was replaced, not kept. | `Date` is real while the clock is fake, so the old assertion would only measure test speed. "The tunnel outlived the window" is now proven on the clock that drives the timer. The spy guard (timer armed on the fake clock) prevents a vacuous pass. The assertion is stronger, not weaker. | Also fake `Date` (pointless: the product reads `Date` only for `durationMs`). |
| 2026-10-05 | The stall injection is a measurement only and is not committed. Fixed test: 50/50 under the 300ms stall. Without the fix: 5/5 red. | Same call as TASK-865/876. A permanent stall hook in the mock would add a test-only branch for no extra coverage. The fake clock makes the window independent of wall time by construction. | Commit an env-gated stall. |
| 2026-10-05 | The sibling "answers 502" test in the same file stays on real timers. | A stall can only make it fail LATE (elapsed grows; the 502 still arrives). It cannot fail early, so it is not flaky in the race direction. This matches the TASK-876 survey. | Fake it too (would cost the `elapsed >= window` check). |
