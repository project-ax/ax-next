# Decisions — TASK-791 (first-run failure card once the agent exists)

| Date | Decision | Rationale | Alternatives |
|------|----------|-----------|--------------|
| 2026-10-04 | **App holds the created id (`flowAgentId`) across "Change name"; `FirstRunAutoCreate` reports it via `onCreated` and gets it back as `existingAgentId`, then PATCHes the name instead of POSTing.** | "Change name" unmounts the component, so its `createdAgentId` ref (TASK-709) cannot survive. App already owns the flow's other cross-mount state (`lastAgentName`). | Inline rename field on the failure card (a second name form; diverges from NewAgentCard). |
| 2026-10-04 | **Rename/delete go through `PATCH`/`DELETE /admin/agents/:id` via new `renameCreatedAgent` / `discardCreatedAgent` in `lib/auto-create-agent.ts` (httpFetch).** | Same server path as the admin editor: `agents:update`/`agents:delete` run `assertWriteAllowed` (owner or admin) and delete fires `agents:deleted` (TASK-787 held-inventory cleanup etc.). httpFetch keeps the 401 latch, which `lib/admin.ts`'s raw-fetch twins lack. | Reuse `lib/admin.ts` `patchAgent`/`deleteAgent` (no 401 latch). |
| 2026-10-04 | **Cancel deletes only the id this flow's own POST returned; DELETE 404 counts as done; any other failure keeps the card up with a message and does NOT call onBack.** | Never delete an agent picked from a list; never tell the person it is gone when it is not. | Go back on failure and leave the orphan silently. |
| 2026-10-04 | **Destructive-intent signal = inline muted copy ("Cancel removes {name}, so you won't be left with a half-finished agent.") shown only once an agent exists, plus "Removing…" busy label; no confirm dialog. Escape = the same Cancel (delete included).** | The agent is seconds old, bare (no conversation, nothing the user put in but the name). A confirm adds a step to a near-zero-loss action; the copy is on screen before the click. ux-design lens: direct, no jokes on deletion copy. | AlertDialog confirm (extra step, overkill). Escape = leave without delete (two different "Cancel"s). |
| 2026-10-04 | **Reachability note, not a blocker: in production the failure-after-create card is near-unreachable** — `hydrateAgentsOnce` catches everything and `onDone` only sets state, so the shared `try` rarely throws after the POST. Tests reach it by failing the hand-off hydrate once (the TASK-709 lever). Implemented anyway per the owner decision; it is cheap and defensive. | Card premise ("Change name creates a second agent") is true of the code path, just rarely hit. | Block as unreachable (owner already decided). |
| 2026-10-04 | **Implemented inline, not one subagent per task.** | Three small coupled edits in one package. Test-first assertions; two mutants (App not passing the id; Cancel skipping delete) redden 1 and 4 tests. | Subagent per task. |
