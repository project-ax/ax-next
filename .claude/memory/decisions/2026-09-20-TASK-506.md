## 2026-09-20 — TASK-506 auto-ship's abandoned-branch sweep is gated by an executable predicate, not prose

- `2026-09-20` (TASK-506) — **The sweep gate tests "is there anything on this branch that does not exist anywhere else?", not `git status --porcelain`.** The card (and `ax-next-76`'s recovery note) proposed a `--porcelain` check: non-empty ⇒ commit as WIP, empty ⇒ sweep. Measured against the four stalls of 2026-09-20 that predicate saves ONE of them. TASK-455 had 5 uncommitted paths (→ #650); TASK-482 (2 commits), TASK-479 (3) and TASK-498 (15 commits / 22 files, reviewer already run) all had a **pristine tree** and would have been deleted (they merged as #653/#654/#656). The shipped predicate is `dirty > 0 OR rev-list --count <base>..<branch> > 0`. | Rejected: bolting a second `rev-list` condition onto the `--porcelain` check — same coverage, but it reads as two special cases rather than one rule, and the next shape would need a third.
- `2026-09-20` (TASK-506) — **`scripts/auto-ship-sweep-gate.sh` is an executable script, not a paragraph in the skill.** `.claude/skills/**` is procedure other agents run verbatim, and a text-scanning guard that a comment can satisfy is not a guard (TASK-498's discipline scan, #640's grep hint that failed its own grep). The gate is pure git, no network, and `scripts/__tests__/autoship-sweep-cleanup-block.test.js` **parses the §7a fenced block out of the doc and runs it with `bash`** against real worktrees — a comment cannot commit a file and prose cannot delete a branch. | Rejected: a grep-the-skill-text guard only.
- `2026-09-20` (TASK-506) — **Exit codes are asymmetric on purpose: 0 = sweep, 10 = preserve, 2 = error, and ONLY 0 authorizes destruction.** An unreadable worktree, an uncountable rev-list or an unresolvable base all fail closed, so `if gate; then destroy; fi` is safe to write at the call site. | Rejected: boolean exit 0/1, which would have made an internal error indistinguishable from "nothing here".
- `2026-09-20` (TASK-506) — **The preserve path pushes the branch and then REMOVES the worktree, keeping the branch.** The card said to leave both in place. That makes the branch un-resumable: a fresh `isolation: "worktree"` builder physically cannot check out a branch another worktree already holds. Push first (a local WIP commit still leaves one copy, on a volume that has sat at 99%), then release the checkout only once the push succeeded and the tree reads clean — so cleanup still happens on the preserved card, just not to the branch. | Rejected: leaving the worktree (un-resumable); removing it before the push (single-copy sweep).
- `2026-09-20` (TASK-506) — **Refuted the brief's "a branch not pushed to origin is (defensively) work".** A branch with a clean tree and zero commits ahead of the base contains nothing unique whether or not it was pushed — "unpushed" is a durability fact about work, not evidence that work exists. `pushed=` is reported (the preserve path needs it) but never changes the verdict. | Rejected: treating unpushed as a third preserve condition, which would preserve every freshly-created branch forever.
- `2026-09-20` (TASK-506) — **The merged-PR lookup is a precondition of the gate, not an optimisation.** This repo squash-merges, so a shipped branch's commits are never reachable from `main` and `ahead` stays >0 forever (`merge-base --is-ancestor` called 49 of 51 worktrees unmerged). Without `gh pr list --state merged` in front of the gate, every already-shipped branch reads `preserve` and **nothing is ever swept again** — the opposite failure, which has already cost this repo a whole run of accumulating worktrees reddening `pnpm lint`. The gate itself stays pure-git so it is testable offline. | Rejected: putting the `gh` call inside the script (untestable without network, and the orchestrator already has the PR ground truth in hand).
