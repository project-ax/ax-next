| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-09-29 | **The credential-proxy listener AUTHENTICATES the caller by its per-session `Proxy-Authorization` token and gates egress on THAT session's allowlist / `allowedIPs` / `bypassMITM`. `findAllowingSession` (OR across every registered session) and `blockAttribution` (token as an attribution afterthought) are deleted.** | TASK-52 minted the token for attribution and explicitly left the gate alone; the gate was therefore "some session allows it", which on one shared proxy for all users lets B's prompt-injected agent egress to any host A allowlisted. The token was already carried by every client (measured, see the client probe row), so making it the authn input needed no runner change. | Bind by source IP / pod identity: brittle (k8s Service + gVisor, subprocess loopback). Per-session listener port or unix socket: a big topology change, and the card says the approach is decided (token). |
| 2026-09-29 | **Missing / malformed / unknown token -> `407 Proxy Authentication Required` WITH `Proxy-Authenticate: Basic realm="ax-egress"`, before the target URL is parsed, before DNS, before any upstream connect; audited `blocked: 'proxy_auth_required'`, unattributed; the plugin maps it to a NEW public `blockedReason: 'proxy-auth'`.** | A 407 with a challenge is not cosmetic: `git` (libcurl anyauth) sends its first request BARE, waits for the challenge, and retries with credentials (MEASURED-BY-PROBE, plain-HTTP and CONNECT). A bare 403 would lock every `git clone` out. curl/wget/python/npm/undici send the token preemptively. Authenticating before parsing means an unauthenticated caller gets no 400-vs-403 oracle about targets or allowlists. A distinct `blockedReason` keeps auth failures out of the 'allowlist' bucket, so the reactive-wall "Allow <host>?" card is never raised for them. | 403 for everything: breaks git. Reuse `'allowlist'` for auth failures: would coach the agent and raise wall cards for a non-allowlist event. Leave `blockedReason` undefined: security observers could not tell probing from upstream errors. |
| 2026-09-29 | **`SessionConfig.proxyToken` became REQUIRED (was optional).** | A session without a token can never authenticate, so it could never egress; the type now says so instead of leaving a silent dead end. The plugin always sets it. | Keep optional and treat "no token" sessions as reachable by anyone: that IS the old OR-across-sessions hole. |
| 2026-09-29 | **Token compare: `crypto.timingSafeEqual` against every registered session, no early exit, lengths pre-checked; scheme name matched case-insensitively (RFC 9110); username half ignored.** | A network-reachable comparison on a bearer secret should not leak how many leading bytes matched. Case-insensitive scheme avoids locking out a legitimate client for capitalisation. The token, not the username, is the secret. | Map<token, session> index: O(1) but the sessions Map is shared by reference with the plugin and with tests, so a second index is a sync hazard; the scan is over a handful of sessions. |
| 2026-09-29 | **`Proxy-Authorization` (and `Proxy-Authenticate`) are stripped before the plain-HTTP forward.** | It is hop-by-hop (RFC 9110 §11.7.2) and is now a live bearer credential; that leg is cleartext HTTP to the destination. Previously forwarded verbatim (pre-existing, harmless while attribution-only). | Leave it: hands each destination (and anything on the wire) a working credential for the session. |
| 2026-09-29 | **`bypassMITM` is now scoped to the CALLING session (was "any-bypass-wins" across sessions). Canary tokens stay aggregated across sessions.** | Any-wins let session A's config switch OFF credential substitution and canary scanning for session B's tunnel to the same host: the same cross-session influence as the allowlist OR, one branch further down. Aggregated canaries only ever over-block, and another session's canary turning up in this session's traffic is itself a leak signal, so narrowing them would be a regression. Both are dormant in prod today (nothing in the orchestrator sets either), so this is a zero-risk semantic fix. | Leave any-wins: cross-session downgrade left behind at the same boundary. Narrow canaries too: loses a defence-in-depth signal for no isolation gain. |
| 2026-09-29 | **Placeholder SUBSTITUTION (`registry.replaceAll` over every session's map) is left as is; noted at the MITM handler, owned by TASK-687.** | Reach and substitution are separate concerns and the card scopes this one to reach. Substitution stays safe today because placeholders are 128-bit random. | Bind placeholders to (session, host) here: real work, and it is the sibling card. |
| 2026-09-29 | **No runner / sandbox / bridge behaviour change; only their stale "attribution-only, never an authz input" comments were rewritten, plus the `'proxy-auth'` enum mirrored in `@ax/audit-log` and `@ax/chat-orchestrator` types.** | Audited every caller of the proxy: sandbox-k8s bridge mode (bridge forwards the header on HTTP and CONNECT), sandbox-k8s TCP direct mode, sandbox-subprocess direct mode; runners embed the token via `withProxyToken` (SDK subprocess + Bash-tool env) and undici `ProxyAgent` (`token` option in aisdk, userinfo in proxy-bootstrap.cjs, undici 6.29 parses userinfo). Dev-service sidecars get NO proxy env by design (pod-spec renderServiceSidecars), so they are deliberately tokenless and now cannot reach the proxy at all, which is the narrowest safe answer. The stub proxy in `@ax/test-harness` never fronts a listener. No legitimate tokenless caller found. | Runner fails loud when a proxy is configured but the token is missing: would make a 407 storm diagnosable at boot, but touches runner boot for every provider; filed as a follow-up instead. |
| 2026-09-29 | **Test hygiene: `listener-shutdown-race.test.ts` went vacuous under the new gate (its CONNECTs carried no token, so they 407'd at once and never entered the resolver / handshake / connect windows). Fixed by sending the token and asserting the window was entered (resolver called 4x, upstream accepted 4 sockets).** | The subagent that updated the CONNECT tests spotted that they still passed; a "does not crash" test that never reaches the crash site is a check that cannot fail. | Leave it passing: silent loss of a regression guard. |
