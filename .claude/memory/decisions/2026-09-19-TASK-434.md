# TASK-434 — full RRF recall on sqlite (sparse + dense + temporal, RRF, optional rerank)

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-09-19 | **The read-path embedder and reranker are injected as a HOOK NAME + optional model (`{ hook, model? }`), declared in the manifest under `optionalCalls` with a `degradation` string — not as a function handed in through plugin config.** | This is the in-repo precedent twice over: `presets/k8s` hands `@ax/memory-strata` `orchestrator: { hook: 'llm:call:openrouter', model }` rather than a client, and `@ax/llm-anthropic` declares `optionalCalls: [{ hook: 'credentials:get', degradation: '…' }]` and falls back cleanly when nothing registers it. It also answers the coupling the 2026-09-20 handoff §1 flagged: §3.3 puts the normalizer's WRITE-path embedder in `@ax/memory` (rung 3) while this card needs a READ-path one, and the handoff warned that picking a config shape in isolation may force a rung-3 rework. A hook NAME makes the two seams the same seam — both layers name one hook, one provider plugin serves both, one credential, one egress host — where a passed-in function would have produced literally the "two embedder seams, two layers" the handoff named. Invariant 2 also prefers it: the hook bus IS the inter-plugin API. | (a) Inject an `EmbedFn` closure via `MemoryFactsSqliteConfig` (dem-memory's own shape, so the most faithful port) — REJECTED: it is the shape the handoff predicted would need reworking, and it pushes provider/credential construction into every preset. (b) Register an embeddings hook in this plugin — REJECTED: the engine is a consumer, not a provider, and a store plugin owning provider egress violates Invariant 5. |
| 2026-09-19 | **No embeddings/rerank PROVIDER plugin ships in this card.** The hooks are declared `optionalCalls` and nothing registers them yet, so on a default boot the dense and rerank channels are absent and `recall` returns `degraded: ['semantic']` (and `['ranking']` once a reranker is expected). | This is not half-wired code (Invariant 3): design §4.4 makes degraded mode a first-class, observable product state, and the card still ships live reachable value with no provider at all — `query` goes from `invalid-payload` to a working **sparse (FTS5) + temporal RRF** answer. A real provider needs credential-store keys, egress-lock allowlisting and a `PROVIDER_ENDPOINTS` entry (design §6.5 also wants `google-auth-library` dropped for a bearer token + `fetch`), which is its own card with its own security review. | Ship a Vertex/Cohere provider inside this card — REJECTED: it triples the diff and puts new outbound egress carrying memory content in the same PR as a store rewrite. Ship nothing until the provider exists — REJECTED: that strands the sparse+temporal value the card already delivers. |
| 2026-09-19 | **`runFactsContract`'s factory gains a `capabilities` descriptor (`{ fusionRecall: boolean }`), and the existing "recall rejects `query` with `invalid-payload`" case becomes conditional on it.** sqlite declares `true`; postgres stays `false` until TASK-457. | The 2026-09-20 handoff §3.1 warned "both backends must stop rejecting it at the same moment or they diverge on the shared contract" — but TASK-457 is a separate card gated on this one, so a simultaneous flip is not available. A capability descriptor is the honest third option: ONE contract still runs on both engines, each asserting the behaviour it actually claims, and neither is silently exempted. TASK-457 then flips one boolean and inherits every fusion case for free. | (a) Move the fusion tests into a sqlite-only file and leave the contract asserting rejection for both — REJECTED: the rejection case would immediately fail on sqlite, so the contract would have to drop the assertion entirely and lose the postgres guarantee too. (b) Implement postgres channels here as well — REJECTED: that is TASK-457, it owns the `tsvector`-vs-`pg_trgm` and pgvector calls, and TASK-458 says pgvector's availability is still unproven. |
| 2026-09-19 | **Port RRF faithfully: `k = 60`, four→three unweighted channels, `score += 1/(k + rank + 1)`, ties broken by `id.localeCompare`.** The graph channel is dropped, not ported. | `dem-memory`'s `reciprocalRankFusion` is the measured artifact behind the numbers rung 4 will try to replicate; re-tuning weights here would mean rung 4 measures something other than what rung 1 measured. The graph channel was ablated at rung 0 — measured identical coverage on/off across three runs and two rerankers, returning any candidate on 2/100 questions — and was deleted from `dem-memory/src` in #587. The `localeCompare` tiebreak is load-bearing for test determinism; the in-repo bench copy (`memory-strata/test/bench/configs/c-rrf.ts`) omits it and is the worse model. | Weighted channels / tuned `k` — REJECTED: unmeasured, and it would invalidate the rung-4 comparison. |
| 2026-09-19 | **The shared RRF/channel constants live in `@ax/memory-facts-contract`, not in the sqlite package.** | TASK-457 has to produce byte-identical fusion behaviour on postgres or the two engines disagree in a way the contract cannot see (the Invariant-4 argument that already forced the `, id DESC` tiebreak into both backends). Sharing the constants is what makes that mechanical. They are internal constants, not payload fields, so Appendix B's "`RRF`, `vec0`, `FTS5`, `cosine` do not appear in any payload" still holds. | Duplicate them per-backend — REJECTED: that is the drift the tiebreak comment already warns about. |
| 2026-09-19 | **FTS5 rows are append-only and staleness is filtered by joining back to the base table at query time — `dem-memory`'s approach — rather than by triggers or delete-on-close.** | Closure (`valid_end`) changes constantly via `supersede`/`resettleSlotGroups`; keeping an FTS5 shadow in sync with those through triggers is a second source of truth for validity (Invariant 4). The join keeps the base table the sole authority. `memory-strata-index-sqlite` reaches the same place differently (it versions the whole FTS table rather than migrating it) because FTS5 has no `ALTER TABLE ADD COLUMN`. | Triggers on UPDATE/DELETE — REJECTED: duplicates validity logic. |
| 2026-09-19 | **FTS5 operator neutralization is mandatory and gets its own test.** Query text is untrusted (it reaches the engine from model/user input through `@ax/memory`). | `memory-strata-index-contract` already pins this class with a case proving a `-`-prefixed token is treated as a literal, not as boolean NOT — unescaped, `"-graduated"` inverts the match and returns every document LACKING the term. Design §6.3/§315 lists "FTS operators neutralized" as an injection control. `dem-memory`'s `buildFtsMatchQuery` already quotes and dedupes; it caps at 24 tokens, which I keep. | Trust the input — REJECTED, it is model output by construction. |
| 2026-09-19 | **`sqlite-vec` is pinned EXACT, not `^`.** | Design §6.5 says pin exact and audit the install path; the repo's only other native dep (`better-sqlite3` at exact `13.0.3`) already follows that rule, while the two existing `sqlite-vec` entries (`packages/memory-strata` devDep, `dem-memory`) are `^0.1.6` and are the exception, not the precedent. A caret on a package shipping prebuilt platform binaries is a supply-chain hole. | Match the existing `^0.1.6` — REJECTED: copies the pre-existing defect the design already called out. |
| 2026-09-19 | **The temporal channel ADMITS candidates, it does not merely rank them — `dem-memory`'s behaviour is kept, and my own plan was wrong to specify otherwise.** A `query` matching nothing therefore returns the tenant's most recent rows, not an empty answer. The contract case asserting "a term matching nothing returns empty" is dropped; the operator-neutralization case survives as an *ordering* assertion (`statements[0]` is the row containing the term), which discriminates under either model. | T1 caught that `MemoryRepository.temporal` is query-independent, so the plan's case contradicted a faithful port. Faithful wins for one reason that outranks my product instinct: the whole point of the ladder is that rung 4 replicates what rung 1 measured, and the accuracy gate (≥ 76.0%) was produced with the admitting channel. An unmeasured retrieval change made by fiat at rung 2 would make the rung-4 number answer a different question than the one it was designed to answer. **The design already anticipated this exact risk and assigned it elsewhere**: §4.2 says "hallucination over a thin table is the failure to expect; §8 rung 4 is where that gets measured." So it is not an open question I am ducking — it is a question the design has already routed to a measurement. | Ranking-only admission (my plan's version) — REJECTED as unmeasured, despite being arguably the better product behaviour: "memory has nothing about that" beats 15 unrelated recent facts as hallucination fuel. Filed as a follow-up to be settled by rung 4's numbers, not by argument. A middle option (admit temporal only when a relevance channel also hit) is the same objection — still an unmeasured deviation. |
| 2026-09-19 | **`indexFactRow` must not insert a duplicate FTS row for an id that already has one**, and its vector write must not swallow every error in a bare `catch {}`. Both were defects in T2's output, fixed in T3 rather than shipped. | The FTS insert was unconditional, so `reindex`'s backfill would index an already-indexed fact a second time; `searchFts` then returns that id twice and RRF sums `1/(k+rank+1)` **twice for one row**, corrupting the ranking this card exists to produce. "Append-only" was a decision about not tracking `valid_end` in the shadow table — never a licence for duplicate ids. Separately, the bare `catch {}` around the vector write swallowed a `vectorToBlob` dimension mismatch (a programming error) and a genuine store failure identically to the one case it was written for (extension absent), and left the caller unable to raise `degraded: ['semantic']` — defeating the §4.4 signal that is half the point of the card. | Leave the catch broad "because the dense channel is best-effort" — REJECTED: best-effort is about not failing the write, not about discarding the information that it failed. |
