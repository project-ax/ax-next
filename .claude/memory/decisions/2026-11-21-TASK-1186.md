# Decisions — TASK-1186 (Slack: team agents reach channels only through their own bot; design §4b.1, card A)

Plan: `docs/plans/2026-11-21-TASK-1186-remove-shared-channels-plan.md`. Design: `docs/plans/2026-11-09-channel-slack-design.md` §4b.1.

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-11-21 | **A mention of the shared bot in a channel gets one ephemeral line, shown only to an admitted sender** (`COPY.sharedBotInChannel`: "I don't answer in channels. To talk to your own agent, send me a direct message. To bring a team agent into this channel, invite its own bot with /invite."). It reads no binding, runs no turn and calls no `conversations.info`. It logs `slack_event_ignored {reason:'shared-channel'}`. The shared manifest keeps `app_mentions:read` and the `app_mention` event for it. | A person who invites or mentions the shared bot in a channel is trying to reach an agent there; silence would look broken. The line is the design's two sentences (§4b "What a person needs to know"). It reuses `answerAdmitted`/`answerMention`, the admitted-only pattern `channelNotConnected` already uses, so guests and other workspaces still get silence. The preset composition test (`:1080–1099`) already pins this call shape (`users.info` + `chat.postEphemeral`). | Ignore silently: confusing, and keeps nothing simpler. Drop `app_mentions:read` + the `app_mention` event so Slack never delivers channel mentions: the smallest grant, but the shared bot goes dark with no hint. |
| 2026-11-21 | **The shared manifest also drops `channels:read`** (six scopes: `app_mentions:read`, `chat:write`, `im:history`, `reactions:write`, `users:read`, `users:read.email`). | Once `connectChannel`/`listAvailableChannels` go, nothing calls `conversations.*` with the shared token. `router.ts` `bindBotChannel` and TASK-1184's channel check use the bot's own token, and the bot's manifest keeps `channels:read`. Invariant 5. The deploy's Disconnect + Connect sheds all three scopes at once, so this costs nothing extra. The brief allowed it: "keep channels:read only if something still uses it (check)". | Keep it, as the design text names only `channels:join` and `commands`: an unused grant. |
| 2026-11-21 | **The deletion is an every-boot `DELETE … USING channel_slack_v1_installs i WHERE i.kind = 'shared'`, appended after the two memory-switch backfills.** Thread rows and kept switches stay. | Placed after the backfills, a shared binding switched OFF leaves its OFF as the agent's kept switch, which a later bot's first bind reads. Placed before them, that OFF would be lost. That matters because prod hasn't run the TASK-1180 backfill yet: phase 2 isn't deployed. Every boot is idempotent, matches this file's style, and heals a row an older replica writes. Prod's host runs `Recreate`, so normally there's no overlap. The join is exact: it deletes only the shared install's rows, as the design says. Thread rows are the capture veto's evidence: with no binding left, the veto refuses those threads. | Delete before the backfills (loses OFFs). Delete everything whose install isn't a bot (would also delete orphan rows, and breaks `channel-store.test.ts`'s install-less fixtures). A one-shot versioned migration (there's no framework for one). Also delete the threads (would let memory learn from threads that were kept out). |
| 2026-11-21 | **`bindBot(b)` takes one argument and reads only the kept switch, then ON.** `lockSwitch` stays in `bindBot` and in `setRemember`. | With no shared bindings, the "live shared binding first" rule (TASK-1179) has nothing to read. The remaining race (a flip through `/bot/remember` against a first bind) is only reachable through the API, and it's benign either way. But the lock is tested and costs nothing, so it isn't the place to save code. The two store-level lock tests are ported, not dropped. | Drop the lock as no longer needed: removes tested concurrency code for no gain. |
| 2026-11-21 | **`ChannelStore.listAll` always goes. `ChannelStore.remove` goes only if TASK-1184 hasn't merged when this lands** (plan Step 0, Case B). | `listAll`'s only caller was `listAvailableChannels`. `remove`'s callers here (`/ax disconnect`, the settings Disconnect, `connectChannel`'s take-back) all go. TASK-1184 (in flight) makes the router call `channels.remove` when Slack refuses a bound channel, so after it merges `remove` is live again. | Keep `remove` for 1184 either way: a dead method if this card lands first (half-wired). |
| 2026-11-21 | **The `ready` settings status drops `channels` outright, with no `channels: []` kept for compatibility.** | The host and the SPA ship in one image, and prod has no real users. A tab left open across the deploy shows "We couldn't load the Slack settings" until it is reloaded. channel-web's new parser ignores a stray `channels` key (Review Focus 5). | Keep sending `channels: []` forever (a dead field). |
| 2026-11-21 | **The agent-settings routes get a narrow `AgentRoutesDeps` (`bus`, `installs: current\|botForAgent`, `channels: listForAgent\|setRemember`, `logger`), and `ChannelDeps` is deleted.** | Invariant 5: with connect and list gone, those routes no longer need the Slack client or the vault. | Keep passing the wide `ChannelDeps`. |
| 2026-11-21 | **The TASK-1170 "bot is live" DM stops listing shared-app channels.** Delete `stillWaiting`, the `channels` dependency, `BOT_LIVE_DM_CHANNELS_MAX`, and `botLiveForOwner`'s channel arguments. | The brief missed it, and it is dead after the removal: no agent has shared-app channels any more. | Leave it in place, always computing an empty list. |
| 2026-11-21 | **`channel-route.ts` stays, with prose changes only.** | The brief's claim is wrong: that file holds no routes. It's the pure sender-tier decider (`decideTier`, `runsAsConnector`) that the bot path uses; for a bot, the connector is its requester. The shared routes are in `agent-routes.ts`. | — |
| 2026-11-21 | **The outsider turn note (`SLACK_NOTE_OUTSIDER`) says "your owner, the team admin who set you up in Slack" instead of "the person who connected this channel".** | Nobody "connects" a channel any more. On a bot, an outsider's held call waits for its requester (or claimer). The model repeats this line to outsiders, and the old wording sends them to whoever happened to `/invite` the bot. | Leave it (inaccurate prose the model echoes to users). |
| 2026-11-21 | **The `teams:list-for-user` optionalCall stays; its degradation text becomes "Admin › Slack's list of bot requests names no team".** It is pinned in `plugin.ts`, `plugin.test.ts` and `presets/k8s/.../preset.test.ts`, and all three change together. | `bot-requests.ts` still calls the hook; the old text was about `/ax connect`. No hook is added, removed or reshaped, so no boundary review is needed. | Drop the hook from `optionalCalls` (it's still called). |
| 2026-11-21 | **Task order: port the preset-k8s composition tests to the agent's own bot first, then the store, router, removals, the DM, channel-web and docs.** The approval-button, memory-switch and tier composition tests are ported, not deleted. | The bot path already works, so porting first keeps every package green after every task. Those features stay on bot channels, and these tests are their canary-level coverage. | Port the composition tests last (preset-k8s stays red across three tasks). Delete the channel composition tests (loses coverage of features that remain). |
| 2026-11-21 | **Delete plugin.test's TASK-1182 e2e describe (the flip/first-bind race through the wiring) and the two TASK-1180 shared-route e2e tests.** | A flip can no longer come before a bot's binding: `/bot/remember` needs the binding to exist, and the shared `/remember` is gone. The store-level lock tests (ported) and the kept-switch tests at store, router and migration level cover what's left. | Port "the bind first" to `/bot/remember`: low value, needs the holder-session choreography. |
