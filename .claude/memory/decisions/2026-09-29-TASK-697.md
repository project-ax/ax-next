## 2026-09-29 — TASK-697 a user-authored connector can read a company-wide credential

| Date | Decision | Rationale | Alternatives |
|---|---|---|---|
| 2026-09-29 | **Fix shape: `credentials:get` gates its GLOBAL-scope step for `account:` refs behind a new service hook `credentials:authorize-global:account`, registered by `@ax/connectors`. No provider registered => the global step is skipped (fail closed).** The connectors provider allows iff the requesting user owns a LIVE connector whose derived credential plan (`deriveCredentialPlan`) contains exactly this ref at `scope:'global'` (i.e. `keyMode:'workspace'`) AND `auth:get-user` says that owner is an admin. | The card's candidate (a) "resolve by (connector row, allowed scopes)" is the only one that closes the read for every reader; (b) "reject a non-admin upsert whose ref already exists at global" is check-then-use (an attacker who creates the connector BEFORE the admin stores the company key keeps the hole) and does nothing for rows already in the store. The hook is the only channel that reaches `credentials:get` without editing `@ax/credential-proxy` (owned by TASK-687 in parallel): the proxy calls `credentials:get({ref,userId})` with nothing else. It also covers every other `credentials:get` caller (proxy open + rotate, mcp-oauth status probe, mcp-client) with no per-caller change. | (a') add `scopes` to the `credentials:get` input and thread it orchestrator -> `proxy:open-session` -> proxy (rejected: edits `@ax/credential-proxy`, collides with TASK-687, and rotate would need it too). (b) namespace `account:` refs by owner (rejected: rewrites every stored user-scope key and the channel-web destination builders; big migration for no extra safety). (c) orchestrator pre-filters refs with `credentials:list` (rejected: check-then-use, and rotate still falls through if the user's own row is deleted mid-session). |
| 2026-09-29 | **The guard requires BOTH `keyMode:'workspace'` (plan scope `global`) AND an admin owner — the admin check happens at READ time, not only at write.** | TASK-698 (admin gate on `/admin/connectors*`) is queued separately and may land after this card, and the model-authored promote path (`connectors:upsert` with the draft's `keyMode`) is not covered by a route gate at all. Read-time admin check makes this card correct on its own, whatever order the two land in, and for rows already in the table. `auth:get-user` is an OPTIONAL call; absent/null/throwing => deny. | Trust `keyMode` alone (rejected: a non-admin can set `keyMode:'workspace'` today through the un-gated admin route AND through the model-authored approve path). Pass `actor.isAdmin` from the routes (rejected: the promote path has no route actor). |
| 2026-09-29 | **The model-authored approve path keeps promoting `keyMode` as proposed (NOT forced to `personal`).** | Measured on prod (read-only): the admin's four workspace connectors (`zendesk`, `salesforce`, `canopy-docs`, `example-com`) all came through that path (`connectors_v1_authored` shows them `workspace`/`active`). Forcing `personal` would break a working flow. The read-time guard already denies a non-admin's model-authored workspace connector the global key. | Force `personal` at promote (rejected: breaks the live flow). |
| 2026-09-29 | **`agent`-scope rows are NOT gated here.** | Team-agent OAuth tokens are stored at `agent` scope on purpose ("sharees each ride on it", `mcp-oauth` callback). Gating them needs a notion of "the same connector as the one attached to this agent" that the owner-scoped connector rows do not carry. Same id-collision property exists there; returned as a follow-up. | Deny `agent` for `account:` refs (rejected: breaks shared-agent OAuth). |
| 2026-09-29 | **The card's "still resolves for the users it is shared with" is tested for the OWNING admin only.** | `connectors:resolve` / `list` / `list-defaults` are owner-scoped (`getByIdNotDeleted(userId, id)`), and the orchestrator resolves every connector under `ctx.userId`; there is no cross-user sharing path for a workspace connector today. The guard is the seam a future sharing feature must extend. | Invent a sharing rule now (rejected: YAGNI, product decision). |
| 2026-09-29 | **`mcp-oauth`'s `clientSecretRef` is a separate arbitrary-ref read (a user-authored OAuth slot names any ref; `begin` calls `credentials:get` on it and the secret goes to a token endpoint the author chose).** Reported as a follow-up, not fixed here. | Different package and code path (`packages/mcp-oauth/src/routes.ts`), and `account:` refs it names ARE covered by this guard; `provider:*`/`mcp:*` refs are not. | Fix in this PR (deferred: widens the review surface of an authorization-boundary card; prod has no oauth slots, so there is no urgency beyond signup). |
| 2026-09-29 | **The hook is NOT declared in `@ax/credentials`' manifest.** | `@ax/connectors` (the provider) has `credentials:delete` in `optionalCalls`; core's `buildCallGraph` counts an `optionalCalls` edge when a producer is loaded, so declaring `credentials:authorize-global:account` on the credentials side closes a cycle and `bootstrap` throws `cycle`. The dynamic `credentials:resolve:<kind>` precedent is called the same way. Test (m) in `account-global-guard.test.ts` boots a connectors-shaped provider and goes red if someone declares it. | Declare it in `optionalCalls` (rejected: cycle). Drop `credentials:delete` from connectors (rejected: loses purge-on-delete). |
