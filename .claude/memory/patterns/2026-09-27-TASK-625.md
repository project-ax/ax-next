- **2026-09-27 (TASK-625): to act on a conversation mid-session from a host plugin, subscribe to `chat:turn-end` (role `assistant`) and read `conversations:get`.** ipc-core persists the turn (`conversations:append-event`, awaited) BEFORE broadcasting `chat:turn-end`; the user turn is persisted by the orchestrator at `agent:invoke`. `conversations:get` turn ids are positions in the append-only display log (stable, the ids the UI keys on). In k8s, `chat:end` fires only when the warm runner is reaped (keepAlive), ~5 min after the last turn. @ax/memory's scheduler (`packages/memory/src/incremental.ts`) is a template: per-conversation promise-chain serialization + unref'd idle timer + durable cursor in `storage:*`.
