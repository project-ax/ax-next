- **`IpcClient.event()` never retries (TASK-1059).** It makes ONE attempt with a 10 s timeout (`ipc-protocol/src/ipc-client.ts`, `const event`), and the runner swallows a non-2xx on `event.turn-end` (agent-runner-core `closeTurn`). So anything the host persists behind `event.turn-end` has to be made durable on the host; a 500 from that persist loses the row, and the host's `event_persist_failed` error line is its only host-side record. `call()`/`callGet()`/the binary calls do use `withRetry`.
- **Supersedes archive `decisions.md:1068` (TASK-1059):** in `withRetry` a 5xx gets at most `MAX_5XX_RETRIES` (3) retries; only connection-level errors run to the `maxElapsedMs` window (and `tool.execute-host` / `tool.pre-call` / `tool.list` cap even those at 3 s).
- **To retry a Postgres write without risking a duplicate row, retry only when Kysely never called back (TASK-1059).** `db.connection().execute(cb)` acquires the connection BEFORE it calls `cb`, so a rejection with `cb` never entered proves nothing reached the database; after hand-over a COMMIT may have landed. Helper: `conversations/src/checkout-retry.ts` `withCheckoutRetry` (waits 250 ms, 1 s; 3 attempts). It reads neither pg-pool's message nor a code, so it does not depend on TASK-1058's checkout-timeout code. Inside the callback use ONLY the pinned connection: on a one-connection pool a nested pool checkout waits out the checkout timeout, and that failure (after hand-over) is not retried.
- **A test that asserts an error message is ABSENT from logs must capture through `createLogger({ reqId, writer })` from `@ax/core` (TASK-1059).** A hand-rolled logger `JSON.stringify`s an `Error` binding to `{}`, so the "no leak" check passes on unfixed code. Log lines on DB failure paths carry `...faultLogFields(err)`, never `err`: the bus copies the inner message into its PluginError wrap.
- **A message is cleaned with `toWellFormedValue` (`@ax/core`) once in the orchestrator (TASK-1059):** U+0000 and lone surrogates become U+FFFD, because Postgres jsonb (display log AND session inbox) refuses both on every retry. Reuse `toWellFormedText` / `stringifyWellFormed` for any new store of untrusted text rather than another regex.
- **`conversations:append-event` has four callers (TASK-1059):** ipc-core's `event.turn-end` persist (re-throws → 500), the orchestrator's user-turn persist (now ends the turn with `conversation:message-not-saved` on failure), and the conversations turn-error / permission-card subscribers (log once at error, codes only).
