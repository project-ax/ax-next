- **2026-09-26 (TASK-551): supersedes TASK-514's "only `chat:start` uses `subscriberTimeoutMs` so far".** The orchestrator now bounds every `chat:end` / `chat:turn-error` / `chat:permission-request` IT fires (`fireChatEvent`, `CHAT_EVENT_SUBSCRIBER_TIMEOUT_MS` = 30 s). Rule of thumb for which fires can be bounded without tripping the TASK-514 microtask trap: a fire the caller AWAITS before it returns keeps its ordering under a bound (all subscribers still finish inside the awaited fire); a fire that RACES the caller (ipc-core's runner-reported chat:end, which resolves agent:invoke's waiter from inside itself) is the one whose later subscribers slip behind the caller.
