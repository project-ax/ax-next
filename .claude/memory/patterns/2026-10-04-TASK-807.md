# Patterns — TASK-807

| Date | Pattern | Why |
|------|---------|-----|
| 2026-10-04 | **A cross-plugin drift guard goes in a package that CI selects when EITHER side changes.** Put the test in the consumer-most package and add the other packages as devDependencies (`pnpm --filter "...[BASE]"` follows devDeps to dependents). Precedent: `channel-web/src/__tests__/credentials-refs-drift.test.ts`; `eslint.config.mjs` exempts `src/__tests__/**` from `no-restricted-imports`. | A guard in a package that is not selected when only one side changes guards nothing (TASK-518). Test-only peer imports need `package.json` devDeps + (for a tsc-checked tree such as channel-web) tsconfig `references`, and a lockfile refresh: `pnpm install --no-frozen-lockfile --offline` adds just the `link:` rows. |
| 2026-10-04 | **Feed a drift test the data the store emits, not raw literals.** Run fixtures through the producing plugin's schema (`CapabilitiesSchema.parse`) before the derivations see them. | Zod strips unknown keys on read, so a field one copy still honours (host `slotDef.account`) is unreachable in production; a raw literal reports a drift that cannot happen, and the parsed form fails if the schema ever starts keeping the field. |
| 2026-10-04 | **A cross-comparison alone is vacuous; pin a table beside it.** Three copies that all return `[]` agree. Assert each against a hard-coded expected ref list AND against each other, and make a documented exception a named field on the fixture (`hostRefs`) rather than a filter that could swallow other drift. | Mutants M1-M6 each reddened a distinct, predicted set of cases, which a compare-only test would not have. |
