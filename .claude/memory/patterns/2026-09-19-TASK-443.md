# patterns — TASK-443

## Focus restore across a PANE SWAP is by identity, not by node

channel-web now has three focus restores and they are not interchangeable.
Pick by whether the target SURVIVES the transition:

| transition | target survives? | use |
|---|---|---|
| Dialog / Sheet open+close | yes | `components/ui/use-opener-restore.ts` (captures `activeElement` at `onOpenAutoFocus`) |
| a card resolving in place | yes (region outlives card) | `lib/consent-focus.ts` (#599 / TASK-427) |
| a pane swap (`open ? <A/> : <B/>`) | **no** | `lib/settings-return-focus.ts` (TASK-443) |

Both older helpers restore a captured NODE, and both correctly refuse a detached
one — `use-opener-restore` literally has `if (!opener || !opener.isConnected) return`.
On a pane swap the opener is ALWAYS detached (destroyed the moment the other pane
mounted), so a node-capture restore is a guaranteed silent no-op. Mark the opener
with a data attribute and re-find its SUCCESSOR after the remount instead.

Settings (`AdminShell`) is a pane swap, not an overlay — `App.tsx` renders
`adminSettingsOpen ? <AdminShell/> : <WorkspaceShell/>`. Easy to misread as a dialog
and reach for the wrong helper.

## The restored-to surface may not be painted yet

Measured on the Settings close: the returning `WorkspaceShell` re-reads its board
and its own `if (loading && !board)` branch paints "Loading your workspace…" with
**no sidebar in it**. So at the close tick there are ZERO marked nodes — a restore
fired from the close handler finds nothing and does nothing.

Fix shape: wait for the opener to be inserted (`MutationObserver` on `document.body`,
`childList + subtree`), and **yield if anything else has taken the keyboard** —
`activeElement !== body` on any mutation aborts the restore. A deadline in
milliseconds would be a guess; "somebody else is standing there" is a fact.

Any surface with an async-loading skeleton has this shape. Check before assuming the
restore target exists on the next commit.

## Arm with a ref, fire from an effect keyed on the STATE that changed

```ts
const armed = useRef(false);
const close = useCallback(() => { setOpen(false); armed.current = true; }, []);
useEffect(() => {
  if (open || !armed.current) return;
  armed.current = false;
  return doTheThing();          // cleanup runs on re-open / unmount — the right times
}, [open]);
```

Keying the effect on a boolean *flag* instead (`settingsJustClosed`) and clearing it
inside the effect is a trap when the effect returns a cleanup: clearing the flag
re-renders, the effect re-runs, and React tears down the cleanup **immediately** —
cancelling the very thing it just started. The ref costs no render and `useResolutionFocus`
in `consent-focus.ts` already uses this shape.
