# TASK-503 — patterns

## A slash-separated path is a BAD repro for "long text overflows its bubble"

Chrome's UAX-14 line breaking already offers a break opportunity around `/`, so
an ordinary slash-separated path wraps on its own even with
`overflow-wrap: normal`. TASK-503's card cited "a ~72-character slash-separated
path" and, measured at 390px, that exact input overflows by **0px** — the card
was right about the bug and wrong about the sample.

What actually loses characters is any long run the breaker **cannot** split: an
id, a token, a base64 blob, a URL query string, a snake_case run, or a path
whose individual segments happen to run long. Measured overflow
(`scrollWidth - clientWidth`) at 390px, before → after `break-words`:

| input | before | after |
| --- | --- | --- |
| bare 101-char path | 77px | 0 |
| URL with query string | 178px | 0 |
| 70-char unbroken token | 238px | 0 |
| long snake_case run | 252px | 0 |
| short slash-separated path | 0 | 0 (no new line) |

Use the unbreakable forms when writing or re-walking an overflow card. A "cannot
reproduce" on a slash path does not clear the bug.

## Probing a layout claim without the cluster

jsdom cannot answer a layout question, and standing up kind for one is heavy. A
static HTML page reproducing just the box under test (the component's own class
declarations, hand-translated), served on a private port and driven by
Playwright MCP at the target viewport, answers it in about two minutes. Measure
`scrollWidth - clientWidth`, not screenshots. Include inputs you expect NOT to
change — the ones measuring 0 → 0 with no new line are what prove the fix costs
nothing elsewhere.

`file://` is blocked in the Playwright MCP browser; serve the page instead. Pick
a port nobody else is on — sibling agents have their own harness servers running.

## `break-words` is enough on a COLUMN flex item, and would not be on a row one

`overflow-wrap: break-word`, unlike `anywhere`, does not reduce a box's
min-content contribution. On a **row** flex item the default `min-width: auto`
would then pin the item to the longest unbreakable token and it still overflows
— that case needs `min-w-0`. On a **column** flex (`flex flex-col items-end`)
the automatic minimum applies to the vertical axis, so horizontal `min-width`
resolves to 0, and a definite `max-w-*` cap makes `break-words` sufficient.
Check which axis before assuming either way.

## Two clamps, two remedies (reinforces TASK-436)

A CSS **clamp** (`truncate`) hides a value that is still in the DOM — that owes
the reader a `title=`. **Wrapped** text clamps nothing, so a `title` there is a
hover-only duplicate of visible text that touch cannot open at all. And
`fenceLine` is neither: it destroys a value at a trust boundary. A layout card
should not reach for any of the three by reflex.
