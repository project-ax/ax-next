## 2026-10-25 — TASK-955 Count Finish by days in the zone its date was set from

- `2026-10-25` (TASK-955) — **Supersedes TASK-951 patterns row 1's "else UTC".** A finish date is counted with `taskTimeZone({ trigger, activeHours, finishByTimeZone })`: cron tz, else active hours tz, else the zone the person's browser reported when they saved the date (stored beside it, `finish_by_time_zone`, schema 14), else UTC. The parameter is required on purpose: a caller that forgets the stored zone fails to compile instead of counting in UTC. Validate a browser's zone with `RoutineTimezoneSchema` on the browser before sending (`'Etc/Unknown'` is what a browser reports when it can't tell, and V8 refuses it), and at the host treat one this runtime can't use as missing rather than refusing the date (the PUT route drops it and logs an ids-only `workspace_finish_by_zone_unusable` warn). Kysely drops `undefined` from an UPDATE's `set`, so write `x ?? null` for a nullable column you mean to clear.
