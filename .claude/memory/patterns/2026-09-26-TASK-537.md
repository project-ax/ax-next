## Patterns

- `2026-09-26` (TASK-537) — **A hand-rolled deadline inside a test body is a second, hidden testTimeout, and raising the config does not reach it.** TASK-400 raised `@ax/test-harness` to `testTimeout: 30_000`, but the mcp-server-stub crash test kept its own `Date.now() + 5000` poll deadline, so it still failed at 5.2-5.4s on CI (runs 36214120993, 36220630082). The proof it was a stall and not a lost message sat in the same log: the neighbouring `echo` test did the identical spawn + initialize and took **9087ms** (idle ~90ms) and passed, because it had no private deadline. When a flake's time is ~5s in a package budgeted at 30s, grep the test body for `Date.now()` / `setTimeout` deadlines before blaming the product.
- `2026-09-26` (TASK-537) — **To reproduce a CI-sized subprocess startup stall locally, preload a stall into only the child.** 42 CPU burners on a 14-core Mac moved the stub's reply from ~73ms to ~226ms, nowhere near CI's 9s. What reproduced the exact CI signature deterministically was `NODE_OPTIONS=--import <file>` where the file does `Atomics.wait(...)` for N ms only when `process.argv[1]` ends with the stub's filename; the vitest processes load it too but skip the stall. With N=7000 the old test failed with `timeout waiting for id=1`, the new one passed.
- `2026-09-26` (TASK-537) — For tests that speak JSON-RPC to a child by hand, use `packages/test-harness/src/__tests__/helpers/json-rpc-stdout.ts`: event-driven, no timer, and it rejects on the child's `close` (not `exit`, which can fire before the last stdout chunk is read) with the exit code and stderr tail.
