- `2026-10-04` (TASK-853) — **"Did main move under this PR?" has a cheap exact answer and an expensive approximate one; use the exact one.** GitHub does not record which `main` a `pull_request` run merged with (the run API returns only `head_sha`; `pull_requests` is empty once merged), so "was CI stale?" can only be inferred from timestamps. "Does the head CONTAIN origin/main?" (`git merge-base --is-ancestor origin/main <head>`) needs no clock and no run metadata, and when true the squash lands exactly the tree CI tested. It is stricter (46/60 recent heads failed it vs 26/60 truly stale), which costs one CI cycle that overlaps the backstop wait. And to prove a `gh pr update-branch` commit carries nothing but main, compare its tree to `git merge-tree --write-tree <main-parent> <pre-update-head>`: equal means a clean mechanical merge; a hand-resolved or "evil" merge differs (a real 2026 local "Merge branch 'main'" commit, e62261b3, differed because it resolved a MANUAL-ACCEPTANCE.md conflict).
