| 2026-11-05 | **Since TASK-1048, `@ax/database-postgres` logs a checked-out client's dropped connection as `database_postgres_client_error`; `database_postgres_pool_error` (the `pool.on('error')` line) covers idle clients only. Both carry `faultLogFields` codes only.** pg-pool removes its idle `'error'` listener at checkout, so before TASK-1048 any client still checked out when Postgres ended its session (a pinned leader, an in-flight query, a transaction) crashed the host. The fix listens on pg-pool's `'acquire'`/`'release'` events. This supersedes reading the TASK-104 archive note (`patterns.md:144`) as "the plugin pool never crashes". | A raw `new pg.Pool` test pool (routines' `fixture()`) still has neither listener, so a test that kills a session builds its db through `createDatabasePostgresPlugin` (see `packages/routines/src/__tests__/tick-session-loss.test.ts`). Other raw pools (session-postgres's second pool) still have the gap. |
| 2026-11-05 | **To prove "no crash" in a DB test, capture `uncaughtException`/`unhandledRejection` for the test's duration and assert the list is empty.** vitest 5 reports nothing while another listener exists, so without the capture a crash shows only as a run-level "Unhandled Error". | TASK-1048 acceptance tests. |
| 2026-11-05 | **Routines tests import workspace deps such as `@ax/database-postgres` from `dist/`: rebuild a changed dependency before running them.** A crash proof against an older plugin = write the old `src` over the committed-clean file, rebuild, run, `git checkout HEAD --`, rebuild, assert `git status --short` is empty. | TASK-1048 Task 2 Step 4. |
| 2026-11-05 | **The tick leader runs `SELECT 1` on its pinned session after every sleep between ticks and steps down (re-elects at once) if it fails.** A test that counts the loop's statements sees one probe per tick after the first, none at shutdown. Killing a backend in a test: `pg_terminate_backend(pid, 10000)` waits for the backend to exit, so a re-election cannot race the old session's lock. | `packages/routines/src/tick.ts` `probeSession`. A refusal carrying a code (a live session's cancel or timeout, or a session that died mid-probe) also logs `routines_tick_leader_stepped_down` with `faultLogFields`; a session that died during the sleep writes only the database plugin's line. |
