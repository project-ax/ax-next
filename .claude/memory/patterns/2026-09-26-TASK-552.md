- **2026-09-26 (TASK-552): a subscriber that does long or side-effecting work should take the third handler arg `{ signal }` and check `signal.aborted` before each committing step** (storage write, network, model call). The bus aborts it exactly at the fire's `subscriberTimeoutMs`; on an unbounded fire it is never aborted. Stopping via `signal.throwIfAborted()` logs `hook_subscriber_aborted` (debug), not a failure. Reference: memory-strata `handleChatStart`. The tier/service hooks take no signal, so a check bounds work to "the step in flight at the bound", not zero.
