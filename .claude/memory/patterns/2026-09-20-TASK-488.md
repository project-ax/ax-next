# TASK-488 — patterns

## A test can be green for a reason unrelated to the one its comment names

`ownership.test.ts`'s "gives two people on ONE agent two different speaker subjects" stayed
**green** with `rewriteSpeaker` mutated to the identity function. Its comment claimed that
without the rewrite "these are one subject, one slot chain, and Bob's arrival CLOSES Alice's
`lives_in`". True of the design — unreachable from that hook, because `memory:remember` sends
no `slot` and a slotless row closes nothing whatever its subject is. So "2 rows, both active"
held either way.

The tell was that the assertion (`toHaveLength(2)` + all `until === undefined`) never
mentioned the thing the comment was about. **When a test's comment names a mechanism, the
assertion should name it too** — here, the subject keys. Rewritten that way, the mutant dies.

This is the "prose claims need verification too" lesson applied to test comments: a confident
comment is not coverage.

## Mutation testing has a structural blind spot for defense-in-depth predicates

Removing the owner predicate from `rowsInRankOrder` (the sqlite fusion path's final row
hydration) reddened **nothing** — all 178 engine tests and all 70 product tests stayed green.
Not because the guard is wrong, but because every id reaching that function already came out
of an owner-filtered channel, so the predicate is never the thing that removes a row **today**.

That is exactly the shape of a guard that is correct now and quietly load-bearing the moment
someone adds a fourth channel or edits `scopeFilter` — and it fails **open**, silently, since
the rows still come back and still look like an answer.

**The fix is not to delete the guard. It is to test it directly**, by handing the function ids
it should refuse rather than ids it will never be given in production. See
`packages/memory-facts-sqlite/src/__tests__/rank-hydration-scope.test.ts`. Include the chunk
boundary: that hydration batches ids in chunks of 500 and binds the owner per chunk, so a
predicate spliced into only the first prepared statement passes every small case and leaks on
the 501st id.

**Generalization:** after a mutation pass, a *surviving* mutant on a security predicate is a
finding, not a pass. Ask "is this unreachable today, or untested?" — if unreachable-today, the
test must construct the reachable-tomorrow case directly.

## Optional-payload hooks need an absent-payload answer

`memory:recall` has no required field, so `{}` is the ordinary call — but an absent payload
dereferenced straight (`input.query`) throws a bare `TypeError` with no plugin, no hook name
and no `code`, while sibling hooks with required fields raise a proper `PluginError` for the
identical mistake. `HookBus.call` types `input` as required, so the caller who actually
reaches it is one crossing a boundary that erases types (an IPC action, a tool argument) —
i.e. the caller least able to do anything with a `TypeError`. Normalize to `{}` at the top of
the handler.
