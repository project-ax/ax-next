# TASK-436 — clamped text must keep a `title`

- **Two kinds of "clamp" live in `channel-web`, and they are not the same bug.**
  A CSS clamp (`truncate` / `line-clamp`) hides characters that are still in the
  DOM; a `fenceLine(value, N)` clamp *destroys* them at a trust boundary and
  writes a literal `…` in their place. Only the second one makes a value
  unrecoverable. Fixing the first is `title={value}`; fixing the second means
  raising the fence's bound, because there is no other copy of what it cut.
- **Do not remove a `fenceLine` bound to "let CSS do it".** The bound is what
  keeps unbounded untrusted MCP/model text off the surface (invariant 5). Raise
  it and move the *layout* job to CSS; never drop it.
- **The bound on a step row is also a bound on the model's own prose.**
  `stepDetail`'s `DETAIL_KEYS` include `prompt` and `description`, which the
  model writes, and the workspace has no thinking gate (J4). That is why
  `STEP_TEXT_MAX_CHARS` is 200 and not the 400 the decision/rail caps use.
- **jsdom has no CSS and no layout**, so never assert that text *is* clamped
  there — the assertion is vacuous by construction. Assert `title` against the
  source string instead.
- `WorkspaceAttachmentChip` deliberately refuses `title=` (a tooltip is
  invisible on touch and to anyone who does not hover) and clamps its filename
  itself. Leave it alone — that is the TASK-431 family, the inverse failure.
