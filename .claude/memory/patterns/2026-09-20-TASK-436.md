# TASK-436 — clamped text must keep a `title`

- **Two kinds of "clamp" live in `channel-web`, and they are not the same bug.**
  A CSS clamp (`truncate` / `line-clamp`) hides characters that are still in the
  DOM; a `fenceLine(value, N)` clamp *destroys* them at a trust boundary and
  writes a literal `…` in their place. Only the second one makes a value
  unrecoverable. Fixing the first is `title={value}`; fixing the second means
  raising the fence's bound, because there is no other copy of what it cut.
- **Do not remove a `fenceLine` bound to "let CSS do it".** The bound is what
  keeps unbounded untrusted MCP/model text off the surface (invariant 5). Raise
  it and move the *layout* job to CSS; never drop it.
- **Once layout moves to CSS, a `fenceLine` cap stops being a layout number
  and becomes purely a security ceiling** — how much reaches the `title`, the
  clipboard and the DOM. So do NOT collapse two caps into one for tidiness:
  review caught that doing so raised the model/tool-authored half from 60 to
  200, and `fenceLine` returns a value UNCHANGED when it fits, which turns a
  masked 60-char prefix into a whole 148-char token. `namesASecret` filters
  key NAMES, not values, so a credential under `value`/`arg`/`data` still
  reaches the fallback. Name cap 200, detail cap 120, and the TEST PINS THE
  ORDERING (`detail < name`), not the numbers.
- **`title` carries the FENCED value, not the raw one, and that is a decision
  to state out loud.** Recovery is bounded at the cap; past it a literal `…`
  remains. The alternative — the unfenced value in a tooltip — hands back
  exactly what the fence exists to bound. Say so in the code and the PR so it
  is a signed-off reinterpretation, not a gap.
- **jsdom has no CSS and no layout**, so never assert that text *is* clamped
  there — the assertion is vacuous by construction. Assert `title` against the
  source string instead.
- `WorkspaceAttachmentChip` deliberately refuses `title=` (a tooltip is
  invisible on touch and to anyone who does not hover) and clamps its filename
  itself. Leave it alone — that is the TASK-431 family, the inverse failure.
- **Audit the SOURCE of a value before adding a `title` to it.** The
  past-conversation title was the one label leaving `routes-workspace.ts`
  unfenced, and it is model-generated; adding a `title` would have given an
  unbounded, un-stripped string a second sink. Fenced at
  `CONVERSATION_TITLE_MAX_CHARS`.
