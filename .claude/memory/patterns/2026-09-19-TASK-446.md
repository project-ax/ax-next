# TASK-446 — heading outlines in channel-web

- **The workspace surface's heading tree is owned by three components, not sprinkled.**
  `AgentView` sets `h1` (the agent's name) and one `sr-only` `h2` per open tab panel
  plus one for the rail; `SectionLabel` (`components/workspace/bits.tsx`) is the
  single `h3` for every section on that surface (rail × 5, Memory × 3, Files × 2).
  `SectionLabel` deliberately has **no `level` prop** — all ten call sites sit one
  level inside an `AgentView`-headed region, so a caller free to pick its own number
  is how the tree acquires a skip.
- **The Settings shell's `h1` is `AdminPaneHeader`'s title**, the only element every
  one of its nine tabs renders. Tab bodies open at `h2`. The eyebrow ("Settings" /
  "Admin") stays a `<span>` — promoting it would put the same two words at the top
  of the outline on every tab.
- **Tailwind preflight is on** (`@tailwind base` in `src/index.css`), so swapping a
  `span`/`div` for `h1`–`h6` while keeping the `className` is a **zero-pixel** change:
  heading font-size, weight and margin are all reset. Changing the element is never a
  reason to restyle, and "must not look like a heading" is `className="sr-only"`.
- **`src/test-utils/heading-outline.ts`** is the shared guard: `headingOutline()`,
  `headingLevels()`, `headingOutlineProblems(root, topLevel = 1)`. It counts
  `role="heading"` too. Pass `topLevel: 2` when asserting a component rendered on its
  own — a tab body is a fragment of someone else's page (`ConnectorsTab` has no `h1`
  because the pane above it does).
- **Reading the outline of a live surface in jsdom is cheap.** A throwaway
  `*.test.tsx` that renders each tab and `appendFileSync`s
  `document.querySelectorAll('h1,h2,h3,...')` measured all 13 surface/tab
  combinations in 2.4s. Note `console.log` from inside a vitest test did **not**
  reach the captured run output here — write to a scratchpad file instead.
