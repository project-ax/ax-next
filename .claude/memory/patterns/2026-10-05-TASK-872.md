# Patterns — TASK-872

- `2026-10-05` (TASK-872) — **A client FIN reaching a TLS socket that is still mid-handshake to its upstream (`targetTls.end()` before `secureConnect`) does not hang — it errors the upstream socket with `Client network socket disconnected before secure TLS connection was established`.** Only a TCP-*pending* upstream swallows the FIN silently. So a "client FIN before established" bug has two presentations (a wait-out-the-timer hang and a prompt-but-mislabelled `tls_error` row); test both — a guard covering only the black-holed TCP case misses the second.
