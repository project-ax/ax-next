## 2026-10-30 (TASK-991) — facts export volume-only; skill-reflection last-pass date from fire records

- **Supersedes `patterns.md:605`'s marker contract.** Skill reflection no longer short-circuits on `.ax/skill-reflection/last-run.json`; the agent writes no file. The host renders `{{lastCompletedRun}}` (`packages/routines/src/template.ts`, filled in `fire.ts`) from the routine's own `routines_v1_fires` rows: newest `ok`/`silenced` run as the row's current owner (`run_as_user_id`), its `fired_at` (run start) as a UTC `YYYY-MM-DD`, or `never`. `error` (incl. `RUN_INTERRUPTED`) never counts. It renders BEFORE the payload pass, so a webhook payload can neither supply nor re-render it. Repeat routines only; task check-ins ignore it.
- **Changing a seeded routine prompt = freeze the old text + a versioned migration keyed on prompt EQUALITY, not `spec_hash`.** `routines:upsert-default` (turning reflection on) replaces `spec_hash` with a real hash, so a hash match skips exactly the deployments running it. Pattern: `reflection-prompt-history.ts` holds the frozen previous seed byte-for-byte; `migrations.ts` v21 `refreshReflectionSeed` rewrites only rows whose prompt still equals it, moves `spec_hash` only from the old seed hash, and bumps `updated_at` so `refreshStale` re-copies into agents' materialized rows. The genuine-v14 fixture in `dual-method-migration.test.ts` proves the frozen text is byte-identical to what deployments hold.
- **Facts export is volume-only.** `@ax/memory`'s `exports.volume` is required when `exports` is set; `memory:export:flush` + `sandbox:memory-mounts` register together, only with a volume. No volume = no file view of facts anywhere (recall still works). `MEMORY_FACTS_EXPORT_ROOT` now lives in `@ax/sandbox-protocol` (on-disk NFS layout), not `@ax/core`; `RUNNER_IMMUTABLE_PREFIXES` is gone.
- **Correction (review): Step 1 compares "on or after", not "after".** Skill reflection short-circuits only when `memory_recall` shows no evidence dated on or after `{{lastCompletedRun}}`. That date is a UTC day, evidence is day-granular, and silenced passes count, so a strict "after" can stop full passes for good (evidence recorded later on a pass's own day is never "after" again). The canary pins the phrase. Also, the run-as filter compares only `run_as_user_id` with the firing row's owner. It has no join on the routine's current owner, so "the row's current owner" above means the firing row's owner.
