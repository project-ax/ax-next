- `2026-10-22` (TASK-908) — **A veto keyed on an id must not also be keyed on who asks, when the producer's cursor survives a refusal.** `memory:pre-capture`'s refusal leaves memory's extraction cursor in place, so a refusal that only fires for `ctx.source === 'routine'` is undone by the first pass under any other source (it reads every skipped turn). Key the veto on the resource id alone. And when the producer bus-skips a slow subscriber (fails open at its timeout), race your own lookup against a shorter deadline and refuse on a miss, so "fails closed" is true; a refusal is cheap exactly because the cursor stays put.
- `2026-10-22` (TASK-908) — **A test harness that answers every `conversations:create` with one id makes conversation-keyed lookups bleed across runs.** `createRoutineHarness` gives every run the same conversation id, so a repeat routine run after a task run "shares" the task's conversation in `isTaskConversation`. Put each run kind's assertion in its own `it` (fresh harness), or the test sees a cross-run match that can't happen in production.
