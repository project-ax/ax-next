# Patterns — TASK-G001 (local provider key replacement)

- `setDestinationCredential` used a generic `HttpError` for HTTP 422, which turned provider validation failures into “We could not reach the server just now.” Keep 422 validation copy local to the credential client; recognize only known OpenRouter reasons and Anthropic codes, use authored fallback copy for unknown or malformed responses, and log only the request path/status. An arbitrary plugin error may echo the key.
- Trim surrounding whitespace from provider API keys before encoding so pasted newlines cannot invalidate HTTP headers. Preserve whitespace for other destinations, where it may be part of the secret. Transport exceptions must also become safe authored copy without retaining the original exception.
- Verified the fix with 16 initially failing regressions, then 28 focused tests and all 3,800 channel-web tests passing, build/typecheck and scoped lint. Rebuilt the local kind image and used standalone Chrome/Playwright (the in-app browser execution tool is unavailable) to submit a deliberately invalid replacement: HTTP 422, readable rejection reason, enabled retry, trimmed provider input, unchanged saved credential metadata, and no key in browser warnings. The existing one-hour admin session remained valid across the rollout.
