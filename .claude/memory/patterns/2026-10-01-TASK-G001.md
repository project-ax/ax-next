# Patterns — TASK-G001 (local provider key replacement)

- `setDestinationCredential` used a generic `HttpError` for HTTP 422, which turned provider validation failures into “We could not reach the server just now.” Keep 422 validation copy local to the credential client; recognize only known OpenRouter reasons and Anthropic codes, use authored fallback copy for unknown or malformed responses, and log only the request path/status. An arbitrary plugin error may echo the key.
- Trim surrounding whitespace from provider API keys before encoding so pasted newlines cannot invalidate HTTP headers. Preserve whitespace for other destinations, where it may be part of the secret. Transport exceptions must also become safe authored copy without retaining the original exception.
- Verified the fix with 16 initially failing regressions, then 28 focused tests and all 3,800 channel-web tests passing, build/typecheck and scoped lint. Rebuilt the local kind image and used standalone Chrome/Playwright (the in-app browser execution tool is unavailable) to submit a deliberately invalid replacement: HTTP 422, readable rejection reason, enabled retry, trimmed provider input, unchanged saved credential metadata, and no key in browser warnings. The existing one-hour admin session remained valid across the rollout.
- Admin model discovery must have no agent scope. `agentId: '@ax/model-policy'` passed the credential facade's nonempty check, then failed the store's owner-ID validation before global lookup. Use the credential facade's existing empty-agent convention for these admin requests, retaining the authenticated user ID and user → global precedence.
- A stubbed `credentials:get` cannot catch that context/store mismatch. The k8s composition regression boots the real model-policy routes, OpenRouter plugin, credentials facade, and database credential store over in-memory SQLite. Global-only discovery was RED while personal-key discovery passed; both are GREEN after the fix. Model-policy 94 and preset 225 tests, builds and scoped lint pass. The rebuilt local image returned 444 live OpenRouter models using the user's saved key; browser search rendered all 444 and removed the missing-key message without changing the policy or credentials.
- The user explicitly extended TASK-G001 to the Helper model picker and requested only enabled models. Use the saved model policy's allowed refs as the authority and the shared catalog for labels, rather than credential-provider seed lists. Carry canonical refs through selection and saving: bare IDs cannot distinguish providers and can strip OpenRouter's nested vendor segment. A saved helper outside the enabled list gets a warning and disabled Save until an enabled replacement is chosen; never rewrite it on load. Catalog failure may fall back to refs, while policy/setting failure requires retry.
- Helper-picker regressions were RED against the original implementation, then all 3,799 channel-web tests passed with the final fix and updated settings-shell fixture. Scoped lint and the local image build passed. Desktop and compact browser verification found four choices matching the four enabled refs and catalog labels, no horizontal overflow, and an unchanged helper setting. Settings loading needs an explicit loading state to avoid briefly presenting an empty-policy warning.
