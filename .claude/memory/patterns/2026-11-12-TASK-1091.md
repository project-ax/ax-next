# TASK-1091 — AgentContext.source and audience across the IPC boundary (supersedes the TASK-181 section in patterns.md)

**Supersedes** the stale "AgentContext.source across the IPC boundary (TASK-181)" section in `patterns.md`.

- `audience` rides the same chain as `source`: sandbox-protocol, sandbox-k8s/subprocess, session-inmemory/postgres, `session:resolve-token`, ipc-core auth, both listeners. A field missing from any hop is silently absent on the runner-side ctx.
- Both session plugins normalize fail-closed: an unknown stored source becomes `'external'` (session-postgres used to map it to `'user'`), and an unknown audience becomes `'shared'`.
- Both `session:resolve-token` output schemas must list `audience`, and it is required. A `z.object` returns schema strips unknown keys (fail-open), and a `z.enum` that lacks `'external'` rejects every IPC call.
- Consumers ask `isAttendedTurn(ctx)` and `audienceOf(ctx)` from `@ax/core`, never `!== 'routine'`.
