## 2026-10-03 — TASK-756

- **A probe rate limit belongs at the hook every probe passes through, not in one route.** `connectors:describe-tools` (@ax/mcp-client) is reached by Retry, `?refresh=1` on the channel-web tools route, and the connectors admin route. A cooldown on Retry alone was bypassable (flagged by the automated security review, then confirmed). The bound (`CHECK_COOLDOWN_MS`, per (user, connector)) now lives in describe-tools and gates EVERY check: inside the window, a call with any row for its agent, fresh or stale, forced or not, is served from that row. Only a never-checked row is checked. Merely downgrading `force` is not a bound, because a stale row for another agent still probes.
- **"Nothing was sent" must be structural if a limiter relies on it.** describe-tools reads every server's credential (pass 1) before listing any server (pass 2), so `credential-unavailable` guarantees no server was asked. That is the only reason forgetting a blipped attempt's window is safe.
- **Testing "forgets the window" needs a second row that the window would otherwise serve.** With no cached row, the next call probes regardless, so the test passes either way.
