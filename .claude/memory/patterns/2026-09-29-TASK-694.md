- **Turn a "remember to pass the flag" convention into three checks at different depths (TASK-694).** A text scan of the file (only the pinned definitions may name the tool), a BEHAVIOURAL run (execute each target with recording stand-ins for the CLIs first on PATH, against a throwaway kubeconfig whose default is a fake prod, and assert every recorded argv carries the pin), and a docs scan. Each depth catches something the others cannot: the text scan misses a variable that was redefined without its flag, the behavioural run misses a snippet nobody executes, and only the run proves a target refuses BEFORE `docker build`. Every scanner gets a self-test on synthetic input so it cannot pass vacuously.
- **To prove a pin with a real kubectl, use loopback fake API servers, not a mock (TASK-694).** Two `http.server`s (one per "cluster") log request lines and answer 404; a throwaway kubeconfig points the fake-prod context at one and `kind-ax-next-dev` at the other, with the fake prod as the DEFAULT. Run the OLD Makefile and the new one: before, the requests land on the prod server (8 hits, kind 0); after, kind 8, prod 0. It reproduces the incident's shape with no possible route to a real cluster, because every address in the kubeconfig is 127.0.0.1.
- **When a guard EXCLUDES a file, include the part of it that matters, by section (TASK-694 review).** I left `deploy/README.md` out of the docs scan as "a generic any-cluster doc", and the reviewer found the incident's own command, bare, in its "Deploy to a local kind cluster" section. The fix was a section-scoped entry (`{file, section}`: blank every line outside the heading so line numbers survive) plus an assertion that the section still exists, because a renamed heading would blank to nothing and pass. An exclusion by file is a claim about every line in it; check the claim per section.
- **A scanner that skips `#` lines has a hole exactly where instructions hide (TASK-694 review).** `#   kubectl -n ax-next get secret …` is a command the reader is told to run, parked behind a comment marker. Skip a comment only if it is not a commented-out command (tool followed by a flag or a known verb); prose that merely names the tool stays skipped.
- **A pinned variable that expands empty is a fail-OPEN pin (TASK-694 review).** `kubectl --context $(EMPTY) get pods` swallows `get` as the context value. A variable meant to force a choice must `$(error …)` when the choice is missing, and a target list a test relies on should be ENUMERATED from the Makefile, not typed, so a new target cannot be forgotten.
