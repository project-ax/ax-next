## Patterns

- `2026-09-26` (TASK-549) — **An injected `timeoutMs` default in a test helper is a hidden deadline too.** `docker-preflight.test.ts`'s `startConsumer(…, timeoutMs = 3_000)` sat under a 30s testTimeout. On CI (run 36225259523) the overflow tests' `exec node` child took more than 3s to start, so they got the timeout branch instead of the failed-probe branch. Same class as TASK-537's `Date.now() + 5000`. When a test asserts a NON-timeout branch, give it a budget just under testTimeout. Keep small budgets only for the tests whose assertion IS the timeout, because they cannot flake the wrong way.
- `2026-09-26` (TASK-549) — The TASK-537 stall-preload repro works for a shell stub that `exec`s node, and the test can do it itself. `vi.stubEnv('NODE_OPTIONS', '--import=<file-url of a tmp .mjs doing Atomics.wait(…, 3500)>')`. The vitest worker is already running, so only children inherit it. No argv gate is needed, because the stub's non-node branches never start node.
