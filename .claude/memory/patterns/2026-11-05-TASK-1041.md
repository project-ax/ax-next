# TASK-1041 — patterns

- **To make ONE real SQL statement fail in a routines DB test, use `failQueries(/regex/, error, times)` from `packages/routines/src/__tests__/support/fail-query.ts` (TASK-1041).** It patches `pg.Client.prototype.query` (promise form only — the only form Kysely calls) and returns a restore fn; call it in a `finally`. Unlike a fake `db`, the real pool and Kysely's release-on-throw run, so it proves the connection goes back. Sibling of `support/slow-database.ts`.
- **`runTickLoop` now requires `logger: Pick<Logger, 'warn'>` (TASK-1041).** Any new caller or test of the loop passes one; `createLogger({ reqId, writer })` from `@ax/core` with a capturing `writer` gives JSON lines a test can parse. A failed election logs `routines_tick_election_failed` (codes only) and retries at `min(tickIntervalMs·2^(n−1), electionRetryMs)`; a tick's own failure still logs the raw `[ax/routines] tick error:` stderr line and adds no election line.
- **`repeat-plugin-start.test.ts`'s `../tick.js` mock is an overridable `vi.hoisted` `loop.run` (TASK-1041).** Use `loop.run.mockImplementationOnce(...)` to make the plugin's scheduler loop reject; the plugin logs `routines_tick_loop_died` with `faultLogFields` only.
