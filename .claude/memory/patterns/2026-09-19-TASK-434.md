# TASK-434 — patterns

## A Map-keyed accumulator makes SHAPE assertions blind to duplicate INPUTS

`reciprocalRankFusion` accumulates `score += 1/(k+rank+1)` into a `Map` keyed by id. That
means **the output shape is identical whether or not an id was fed in twice** — same entry
count, same ids present, only the *score* differs.

A test written against that function asserted `fused).toHaveLength(2)` and that both ids
were `toBeDefined()`. Its name was "does not let a re-indexed row outrank an equally-relevant
single-indexed one". A mutation run (delete the FTS de-dup `DELETE`, so a re-indexed fact
lands twice) proved it **could not fail**: the doubly-indexed row still yields exactly two
entries with both ids present, just carrying `1/61 + 1/62` instead of `1/61`.

**The rule: when the accumulator dedupes, assert the accumulated VALUE, not the collection's
shape.** Here that is the two adjacent RRF terms:

```ts
expect(fused[0]!.score).toBeCloseTo(1 / 61, 10);
expect(fused[1]!.score).toBeCloseTo(1 / 62, 10);
```

Generalizes past RRF to anything that folds a list into a keyed structure — `groupBy`, a
`Set`, an upsert, a counter map, `INSERT OR REPLACE`. The fold is exactly what erases the
evidence a shape assertion would need.

## How the vacuous test was caught: predicted-vs-actual mutation counts

It was not caught by reading it. The builder's report **predicted which tests each mutation
would redden** — that prediction is the load-bearing artifact. Deleting the de-dup `DELETE`
reddened **one** test where **two** were predicted, and the gap is what sent me to read the
second one.

So: **ask every implementing agent to predict, per test, what reddens — then run the mutation
and diff the prediction against reality.** A matching count tells you little; a *mismatch* is
a precise pointer at either a vacuous test or a misunderstood implementation, and it costs one
test run to find. Neither half works alone — the prediction without the run is a guess, and the
run without the prediction just shows you some red and you move on satisfied.

Recorded mutations for this package (all restored; each reddens only its own guard):
| mutation | reddens |
|---|---|
| `schema.ts` — drop `DELETE FROM <fts> WHERE id = ?` | both `fact-index` de-dup cases |
| `recall.ts` — `ORDER BY bm25(...)` → `... DESC` | the sparse-orientation case only |
| `producers.ts` — drop `vector.length === dimensions` | the wrong-dimensionality degrade case |
| contract `index.ts` — drop `\|\| a.id.localeCompare(b.id)` | the two RRF determinism cases |
