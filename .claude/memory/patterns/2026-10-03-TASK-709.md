## 2026-10-03 — TASK-709

- **A "Try again" that wraps a non-idempotent server write plus follow-up steps in ONE `try` must record the write's result before the follow-ups run, and skip the write on retry.** Otherwise a failure in a follow-up (hydrate, a callback) looks exactly like a failed write, and the retry repeats it (in FirstRunAutoCreate it made duplicate agents). Keep the result in a ref that is never cleared, and set it before any `cancelled` guard: it is a fact about the server, not view state. Test pattern: have the second mock of the write return a DIFFERENT id, so a re-POST shows up both as a call count and as the wrong id reaching `onDone`.
