# Patterns — TASK-575

- **Adding a second vitest config to an out-of-process package now gets it checked.** `out-of-process-test-timeouts` discovers it by filename or by a package.json `--config`, and charges it only the files its `include`/`exclude` select. Give it both `testTimeout` and `hookTimeout`; a bare teardown under a long-budget test needs `hookTimeout >= that budget`. If the guard reports the config "not readable" because of `projects` / `dir` / `includeSource` / a `!` include, teach `readConfigBudgets` the shape — do not exempt the package.
- **A helper file no config includes is charged to every config** (it can register hooks for any test that imports it). If that over-read ever reddens a config spuriously, narrow the helper's reach explicitly rather than dropping unclaimed files.
- **Resume-from-WIP note:** the stalled builder's single WIP commit held complete production code; what it lacked was the config fix and fixture tests. Running the guard first (one expected red) was the fastest way to tell "incomplete" from "done but unverified".
