- `2026-10-04` (TASK-845) — **A resolver captured INSIDE a mock (`mockImplementation(() => new Promise(r => { finish = r }))`) is only real once the code under test has CALLED the mock — and a call made from a `useEffect` can land a macrotask after the commit you just waited on.** Layout effects (focus moves) run in the commit; passive effects (the fetch) run when React's Scheduler gets back to them, and after a >5ms render slice it yields via `setImmediate`, while RTL's `asyncWrapper` resumes your test after `setTimeout(0)`. Under CI load the test resumes first, calls the still-no-op `finish()`, and the component waits forever (FactsMemory "Forget → Undo" flake, 2 hits on 10-04). Fix shape: build the deferred promise up front (`const p = new Promise(r => { finish = ... }); mock.mockImplementationOnce(() => p)`) AND `await waitFor(() => expect(mock).toHaveBeenCalledTimes(n + 1))` before resolving. To reproduce such a race on demand, `vi.spyOn(performance, 'now')` returning real time + a growing skew (plus ~2ms real burn per call) forces every Scheduler slice to yield — it took this flake from 0/120 under a 28-busy-loop CPU load to 40/40.
