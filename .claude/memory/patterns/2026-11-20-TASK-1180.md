# Patterns — TASK-1180

- **2026-11-20 (TASK-1180): a privacy setting that must follow a resource to its next owner is kept when it's SET, not copied at the hand-off.** channel-slack keeps the agent's memory switch for each channel in `channel_slack_v1_memory_switches` (agent_id, channel_id). `setRemember` writes it in the same statement as every binding the agent has in that channel. A team agent's own bot's first bind reads: the live shared binding, then the kept switch, then ON. So go-live needs no hook, and a Disconnect before the bot exists can't lose an OFF. Any new writer of `remember` must keep that one-statement rule. `upsert`'s insert is the deliberate exception: a fresh connect starts ON and writes no kept switch.
- **2026-11-20 (TASK-1180): a "backfill from live rows" misses the rows already deleted.** Round-1 review caught that the boot backfill read only live bindings, so an OFF disconnected before deploy was lost. The surviving evidence was in thread rows (`not_remembered`), which outlive every Disconnect. Before writing a backfill, ask what deleted the source rows before this deploy, and what evidence of them survives. Both backfill steps only move a kept switch toward off (`ON CONFLICT … DO UPDATE … WHERE kept.remember AND NOT EXCLUDED.remember`).
- **2026-11-20 (TASK-1180): status `botChannels` is present only when the route's own `liveOwnBot` read finds the bot live**, the same rule as TASK-1168's `answered` set. A test that sets `bots.answers.status` to live without `state.bot` gets no `botChannels`. The bot channel switch is `POST /settings/slack/:agentId/bot/remember`, with the same `manages()` gate as the shared toggle. The shared `/remember` answers `409 own-bot` only for channels the bot has already bound.
