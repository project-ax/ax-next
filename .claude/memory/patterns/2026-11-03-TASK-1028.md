- **A route's PluginError catch keys off the codes that hook THROWS TO REFUSE, never `instanceof PluginError` alone (TASK-1028 audit).** `HookBus.call` wraps every non-PluginError as `PluginError{code:'unknown', cause}`, so a bare `instanceof` reads a store crash as "not found" / "forbidden" / "bad request". The refusal codes, verified 2026-11-03: `agents:resolve` → `not-found`, `forbidden`; `conversations:get` / `get-by-req-id` → `not-found`, `forbidden`; `connectors:get` → `not-found`, plus `invalid-payload` for a non-slug id; `auth:require-user` → `unauthenticated`; `session:create` → `invalid-payload`, `duplicate-session`. Everything else: `ctx.logger.error('<event>', { hook, err })` and 500 `{error:'internal'}`. Since TASK-1028 the core logger writes an Error's `code` and one level of `cause` as name/code/stack-frames. It never writes the cause's message, so an outer wrapper with fixed text keeps a provider-authored inner message out of the logs. For a bus-wrapped fault, `{ err }` is therefore enough: the wrapper's own message already carries the inner text. When writing the test, stub the hook with a RAW `Error`, and only on the real HookBus (it does the wrapping). The mcp-oauth route tests use a fake bus that passes raw throws through, so they build the wrapped `PluginError{code:'unknown', cause}` themselves (`wrappedFault`). A raw Error there would pass against the unfixed code. Known remaining instance: about 30 `auth:require-user` gates still map any PluginError to 401.
- **zsh: never name a shell variable `path`.** It is tied to `$PATH`, so `path=$(scripts/memory-write-target.sh …)` (the CLAUDE.md memory recipe) wipes PATH for the rest of that command, and `mkdir` / `dirname` become "command not found". Use `target=` instead.
