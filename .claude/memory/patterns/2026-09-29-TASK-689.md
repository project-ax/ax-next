- **A turn you hide from the THREAD is not hidden from the model, the title generator, or the raw transcript (TASK-689).** `buildThread` in `routes-workspace.ts` is the single producer of what the SPA draws, so a one-line `continue` there hides the kickoff turn consistently across reload, other devices, Find and jump-to-message. But `@ax/conversation-titles` builds its prompt from the raw transcript (`conversations:get` → `buildPrompt`, labelled `User:`/`Assistant:`), the model reads it too, and `GET /api/chat/conversations/:id` still returns it. So a hidden turn's WORDS shape the conversation's auto-title — keep a reserved marker plain English (no `[tag]` that could leak into a title), and verify titles in the browser walk. The title plugin cannot import the marker (invariant #2); a shared marker would be a transcript-schema change, which was declined (`Turn` is `{turnId, turnIndex, role, contentBlocks, createdAt}`, history is the SDK jsonl, `conversations:append-turn` was deleted on purpose).
- **`SetupShell`'s `CardTitle` is a `<div>` — a screen built on it has no heading unless you add `role="heading"` (TASK-689).** Radix `DialogTitle` is an `<h2>`, so swapping a dialog for a `SetupShell` card silently drops the page's only heading. Fixed once in `SetupShell` (also fixes the wizard steps and "Setting up your agent…").
- **A gate that REPLACES the tree makes a "dialog" a page, and the honest primitive follows (TASK-689).** `App.tsx`'s bootstrap gate unmounts the workspace, so the add-agent "dialog" was a modal over a blank scrim with a live-looking ✕ and no app behind it. Name and build it for what it is (`SetupShell` card + explicit Cancel + its own Escape listener, since Radix no longer supplies one) — and that also lets a failure card have an exit that the old shared card lacked.
- **An optimistic bubble appended to a re-read thread draws twice when the read already holds that turn (TASK-689).** `AgentView` appended `sent` to `detail.thread`; the server's re-read can already include the in-flight user turn, so a first message rendered twice until the stream ended. `hasDurableCopy` compares the TAIL of the transcript (same text AND same file count) so an older identical "yes" behind an agent reply cannot suppress a new one. It was general (every `pendingReply` path), not a kickoff quirk. Once the bubble is dropped for a hidden turn, the durable thread is empty between `onDone` and the re-read landing — `AgentConversation` needs `settling` to keep "Nothing here yet" from flashing after the greeting.
