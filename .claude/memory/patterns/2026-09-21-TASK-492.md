# TASK-492 — patterns

## 2026-09-21 — Parity-testing against `dem-memory` without installing it

`dem-memory` is not a workspace package and has no `node_modules`, so its
modules can't be imported (types.ts hits `zod` at module scope). The working
pattern for a BEHAVIOURAL parity test: `transpileModule` (the `typescript`
devDep) the needed DEM source files to JS, rewrite the `from "zod"` specifier
to a two-line Proxy stub (`const p = new Proxy(function(){}, {get:()=>p,
apply:()=>p}); export const z = p;`), write them to a tmpdir, and
`await import(pathToFileURL(...))`. Type-only imports erase themselves;
dynamic `import("ai")` inside unused functions never runs. Drift in DEM turns
into a red test, not a stale copy. `packages/memory/src/__tests__/evidence.test.ts`
has the loader.

## 2026-09-21 — Agent scope keys are HASHED — seed legacy rows via `agentScopeKey`, not a literal

Both facts backends store `agent_key` as
`sha256(JSON.stringify([agentId])).slice(0,16)`, never the raw id. A migration
test that seeds an old-shape table and then recalls through the plugin must
rekey the seeded row with `agentScopeKey({ agentId })` — `'agent:a'` will
never match and the row is silently invisible.

## 2026-09-21 — `vitest` needs workspace dists — run `pnpm build` (or tsc --build) after checkout

Fresh worktree + `pnpm install` alone leaves `Failed to resolve entry for
package "@ax/..."` collection errors. `pnpm exec tsc --build
packages/<pkg>` builds references transitively; `pnpm build` builds all.
