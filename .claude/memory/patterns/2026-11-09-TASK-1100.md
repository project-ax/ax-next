# TASK-1100 — mirroring an external list: a full crawl must start from empty

**Pattern.** When a host plugin mirrors a remote list (here, the MCP Registry) with
`updated_since` incremental sync, deletions only arrive in the incremental feed. A
FULL crawl (no `updated_since`) never mentions servers deleted since the last
crawl. So any full crawl that starts with rows already present has to clear them
first. That covers a first sync that failed partway, a clock that went back, and a
source change. Otherwise a moderated or removed listing is served forever.
`packages/connector-directory/src/sync.ts` resets before a full crawl. Caught by
the ax-code-reviewer, not the plan.

**Pattern.** A timer-driven outbound fetch in a host plugin should default to OFF
when its env var is unset, with the Helm chart turning it on. Twenty-odd preset
tests boot the full preset from fixture env. With unset-means-on, they would all
call the real network seconds after boot.

**Gotcha.** `pnpm -r --no-bail run test` on a loaded laptop can fail Docker-backed
packages with "Waited 40000 ms for a container start slot". That's contention, not
your diff. Re-run those packages one at a time (`pnpm --filter <pkg> test`) before
debugging anything.
