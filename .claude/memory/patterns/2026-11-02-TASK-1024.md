- **A Node body reader that only listens for `data` / `error` / `end` can hang forever, in two ways.** (1) The request was destroyed or ended BEFORE the listeners attached: its last event already fired. (2) A bare `destroy()` with no error AFTER attach emits only `'close'`. The fix: before attaching, check `req.destroyed` (reject with `req.errored` if it is set) and `req.readableEnded`, and ALSO reject on `'close'` behind the settled latch. Normal flow emits `end` and then `close`, so the late `close` is a no-op. Probed on Node 24: all five shapes hung in `@ax/ipc-core` body.ts before TASK-1024. To test it, race the read against a ~500 ms timer, so a regression fails as "hung" instead of as a vitest timeout. `@ax/http-server`'s `readBodyCapped` had the same close-only gap when this was written.
- **Mapping a service-hook PluginError to HTTP: key the 400 off the owning package's exported code list (`MANIFEST_CODES`), never "any PluginError".** Everything else is a host fault. Log it on `ctx.logger` (structured, with the reqId) and answer `{error:'internal'}`, the same body as the http-server catch-all. Never echo `err.message` on that path (TASK-1024, agents promote).
