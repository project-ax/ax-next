# TASK-836 — patterns

- **Copy-then-delete moves fail to "two copies", never "zero" — so the repair is a duplicate cleanup, and "live wins" is the safe rule.** When the two crash points (retire killed after its copy, restore killed after its copy back) leave the SAME observable state, don't try to finish "the" interrupted move: you cannot tell which one it was. Keep the copy readers use, then purge the other, and let a still-wanted retire happen again later.
- **A destructive repair step needs a row claim, not the advisory lock.** `@ax/blob-gc`'s lock is efficiency-only. Before purging a retired duplicate, `claimLive` refreshes `last_put_at`; `markRetired`'s `last_put_at < cutoff` guard then keeps any concurrent retire off that sha. Reuse this shape for any new GC step that deletes bytes.
- **Simulate a crash, not an error, in GC tests:** wrap the real store with `unmarkRetired: async () => {}` (the process died before its undo ran) and make the fake backend do step one then throw. An error alone runs the catch-path undo and tests a different state.
