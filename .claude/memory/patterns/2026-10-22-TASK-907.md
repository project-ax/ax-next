# TASK-907 patterns

- 2026-10-22: **Postgres errors quote the text they refuse.** A JSONB write of a string holding a lone UTF-16 surrogate fails with `22P02 invalid input syntax for type json`, and the error's detail includes the offending text. Any model-written field that reaches a `jsonb` column can therefore carry the model's own words into an error path (logs, a 503 body, a receipt). TASK-907 refuses lone surrogates in report text before the write (`packages/routines-contract/src/definition.ts`). Do the same for any new model-written field that is stored as jsonb, or catch and rethrow with ids only. TASK-906's brief has the same gap (follow-up card TASK-917).
- 2026-10-22: **Model-facing tool output is a separate audience from the service view.** TASK-907 kept `routines:list`/`routines:get` unchanged for the UI, and projected the model tools' output (`routine_list`, `routine_update`) through strict output schemas that leave the agent's notes out, and that show `task` only to the routine's owner (`ctx.userId`). The strict schema is what makes the omission enforceable: the return-schema check refuses a stray key, so a later view change can't quietly re-add it.
