- `2026-10-04` (TASK-865) — **A "the timer does NOT fire" test on real timers is a wall-clock race, and a busy-wait reproduces it deterministically.** If a test needs real I/O to finish inside an N-ms window, add `{ const t = Date.now() + 2*N; while (Date.now() < t) {} }` at the point the window opens. A loop stall runs the timers phase before the poll phase, so the timer wins every time. That gives a 5/5 repro of what CI shows only now and then. The fix is `vi.useFakeTimers({ toFake: ['setTimeout', 'clearTimeout'] })`, which leaves socket I/O, `setImmediate` and `Date` real. Then wait for an I/O-level proof that the phase is over, and only then `vi.advanceTimersByTime`. Add a `vi.spyOn(globalThis, 'setTimeout')` guard that the code under test armed its timer on the fake clock. Without it, a later `node:timers` import makes the test pass without testing anything. Don't use `vi.waitFor` under fake timers: it advances the fake clock itself. Poll with `setImmediate` instead.
