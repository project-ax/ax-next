# TASK-1170 — Slack DMs for bot requests (patterns)

- 2026-11-20 — **Side effects of a locked domain step go AFTER the lock, as a `void`ed promise that never rejects.** Shape: the closure passed to `lock.run` returns `{ reply, opened | made }` (what it did), and the caller fires `void dms.opened(...)` once `lock.run` resolves. Assigning a captured variable inside the closure trips TS narrowing. The notifier wraps its own work as `lifetime.track(work).catch(log)`, so the guarantee is tested where it lives, not at every call site. Prove it with a "watched lock" (records whether it was held when the notice fired) and a never-settling fake (the reply must still come). Example: `packages/channel-slack/src/bot-requests.ts` + `__tests__/bot-requests.test.ts`, `bot-callback.ts`.
- 2026-11-20 — **To find an AX person in Slack, re-prove the match; never trust one lookup.** `users.lookupByEmail` (id only) → `admitSender` (users.info: full member, confirmed email) → `auth:find-user-by-email` on Slack's CONFIRMED email must answer the same AX user id. Use the SAME rule for whom you DM and who may click, so everyone told can act. `packages/channel-slack/src/bot-request-dms.ts` `memberFor`, `bot-request-click.ts`.
- 2026-11-20 — **A new Slack button on the shared install = a new `action_id`, read in `interactions.ts` only for `install.kind === 'shared'`, with its own gate file.** `answers.ts` is the approval-prompt gate only (keys on the in-memory prompt registry). A URL button still sends a `block_actions` payload: give it its own action id and let `readClick` ignore it (empty 200).
- 2026-11-20 — **A redraw of a DM needs the IM's `D…` id from `chat.postMessage`'s answer**, not the user id you posted to (`slack-api.ts postDirect` returns `{ channel, ts }`).
