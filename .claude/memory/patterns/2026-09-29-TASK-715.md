- `2026-09-29` (TASK-715) — **A credential the operator pays for is protected where it is UNLOCKED, not where it is used.** Code in the sandbox is indistinguishable from the runner at the proxy (same session token, same placeholder, same host), and a scrubbed-env child reads `/proc/<ppid>/environ` as the same uid, so neither a rate cap nor an env scrub bounds dollars. What can: (1) splice the key only into a per-provider endpoint allowlist (`PROVIDER_ENDPOINTS[p].inferenceRequests`; everything else on the host goes out with the placeholder inert), (2) meter every response at the proxy, (3) stop splicing past a ceiling. Every path that can substitute has to pass the same policy: enumerate them (`grep replaceAll`) before believing a gate is complete.
- `2026-09-29` (TASK-715) — **Two independent measurements of one thing are combined with GREATEST, never added.** Spend = `GREATEST(SUM(runner-reported), SUM(proxy-measured)) + SUM(helper)`: no double count of an honest turn, a proxy parse miss falls back to the runner's figure, a direct call shows as the excess. Compare window SUMS, not per bucket (a per-bucket GREATEST under-counts when the two meters land in different minutes). Anything only ONE meter can see (host helper calls) is added outside the GREATEST.
- `2026-09-29` (TASK-715) — **Bridge a sync byte path to an async ledger with a per-USER cache of one bit and one counter.** `ProviderMeterHub` (credential-proxy) keeps `{blocked, inFlight}` per user (not per session, so N sessions multiply nothing), seeded by an awaited status call at session open, refreshed in the background (stale-while-revalidate: the admit that triggers a refresh still passes, the next one sees the answer), and updated by the verdict every `record` call returns. Newest ledger answer wins (sequence numbers). A failed check blocks (fail closed); the refusal is a 429, which both SDKs retry, so a database blip heals itself.
- `2026-09-29` (TASK-715) — **An unanswered or unreadable admitted request is billable, estimated from its size.** The unit of accounting is the request the FRAMER admitted (FIFO of outstanding requests, nth response settles nth request); whatever is outstanding when the tunnel ends is settled with `usage: null`, so an aborted stream, a desynced response or a dropped connection is never free. Error statuses, `count_tokens` and GETs cost nothing.
- `2026-09-29` (TASK-715) — **A tunnel that matters for accounting must always END.** Two hangs found by test: a client that dies without close_notify makes the TLS wrapper emit `end` but never `close` (pass the EOF on to the upstream), and a peer that vanishes without FIN/RST never signals at all (idle timeout on both sockets). Missing either leaks an in-flight slot until the user is stuck at their cap.
