# TASK-1116 — better-auth sign-up gate (patterns)

- 2026-11-13 — **better-auth 1.7's endpoint context `path` is the ROUTE PATTERN, not the request path.** A hook sees `/callback/:id` on every OAuth callback (`dispatchAuthEndpoint` sets `path: endpoint.path`), so `context.path.includes('/callback/google')` was never true and the Google domain check it guarded silently never ran from the 1.7.7 bump (#1065) on. Never gate on `context.path`. To decide who may sign up, link or sign in, use `user.validateUserInfo`: better-auth runs it before create-user, link-account and OAuth sign-in, and names the provider in `source.oauth.providerId` (on link and sign-in `user.id` is the EXISTING local user, while `user.email`/`emailVerified` are the provider's). Example: `packages/auth-better/src/identity-gate.ts`.
- 2026-11-13 — **To drive a REAL better-auth OAuth callback in a test (no kind, no real Google), spy `globalThis.fetch` and answer the provider's endpoints.** better-fetch reads `globalThis.fetch` per call. Google's token endpoint can return an UNSIGNED id_token (jose `UnsecuredJWT`), because Google's callback only decodes it; only the client-posted ID-token path verifies a signature (serve a JWKS for that one). For GitHub answer the token, `/user/emails` and `/user` endpoints, matching `/user/emails` BEFORE `/user` (shared prefix). Throw on any other https URL. Then POST `/auth/sign-in/social`, take `state` from the authorize URL and the `ax_better_auth.state` pair from the joined Set-Cookie, and GET `/auth/callback/<provider>?code=…&state=…` with `redirect: 'manual'`. Harness: `packages/auth-better/src/__tests__/support/fake-idp.ts`. Read a hole test's first failure before marking it `it.fails`: a stubbed fetch can fail for harness reasons (`invalid_code` in the location means the token exchange threw).
- 2026-11-13 — **Send a fresh `X-Forwarded-For` on every better-auth request in a test.** better-auth limits `/sign-in*` and `/sign-up*` to 3 per 10 s per IP and path, keys that on a single-IP `X-Forwarded-For`, and its memory limiter store is module-level, so every test in a file shares it; without a fresh address the 4th sign-in in a file answers 429. `freshClientIp()` in the fake-idp harness gives one per call.
