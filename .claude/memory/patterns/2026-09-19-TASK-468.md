## 2026-09-19 — TASK-468 — pinning a runnable doc block: keyed markers + a control

Adds to the pattern `yolo-ship-review-range-origin-main.test.js` established (extract a
fenced block from a skill doc and EXECUTE it, rather than grep the prose). Three things
that were not obvious the second time around:

**1. Key the extractor on an inert marker, not on a command inside the block.** The
sibling guard measured a wrong red count because its extractor was keyed on the very
command a mutant edited — extractor and subject moved together. Here each block carries
`# ax-mutation-restore: precondition` / `: restore`; no mutant of the protocol touches
them, and a mutant that deletes a block makes extraction return `undefined`, which the
runner turns into a loud failure instead of a skipped test.

**2. A behavioural assertion about "the safe way works" is half a test.** `restore keeps
a commit that landed during the window` asserts the sibling's fix survives — which it
also would if the restore did nothing at all. The fixture therefore carries a **CONTROL**
that performs the unsafe restore on an identical repo and asserts the fix is *gone*,
exit status 0. Without it the assertion passes vacuously.

**3. Construct mutants that actually execute.** Replacing `git checkout -- "$F"` with
`cp "$BACKUP" "$F"` reddened 3 tests but NOT the one that matters, because `$BACKUP` was
unbound, the copy failed, and the file was left at HEAD — right answer by accident. The
honest mutant was `git show HEAD~1:"$F" > "$F"`: a restore that *succeeds* at writing a
stale snapshot. It reddened 5, including the incident case. **A mutant that errors out is
not a mutant; it is a no-op wearing one's costume.**

Also reconfirmed (TASK-454): `logicalLines` must filter whole-line comments **before**
joining `\`-continuations. The other order lets `# a note \` swallow the code line below
it, and the structural scan then never sees a piped `git`, while both shells run it.

Harness notes: put fixture "backup" files **outside** the throwaway repo (a whole-repo
`git status --porcelain` assertion sees an untracked `backup.copy` and fails); substitute
the block's single `F=` placeholder mechanically and pin `F=`-line counts structurally so
the substitution cannot start meaning something else.
