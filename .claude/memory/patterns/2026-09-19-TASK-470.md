# TASK-470 — splice a delimited block in pure shell, and gate the write

**Pattern: splice with parameter expansion, not `awk`/`sed`.** For an append-only block
fenced by unique `START`/`END` markers, this is byte-identical under bash and zsh
(measured both), carries newlines and backslashes verbatim, spawns nothing, and has no
exit status to forget to check:

```bash
nl='
'
case "$body" in
  *"$START"*"$END"*) nb="${body%%"$END"*}${entry}"$'\n'"${END}${body#*"$END"}" ;;
  *"$START"*)        echo "label: REFUSED (block START without END; body untouched)"; return 3 ;;
  *)                 nb=$(printf '%s\n\n%s\n%s\n%s' "$body" "$START" "$entry" "$END") ;;
esac
```

**Pattern: never write a value you did not verify.** Before the mutation, assert a
property the correct result must have — for an append, *it grew and both markers
survived*:

```bash
case "$nb" in *"$START"*"$END"*) ;; *) echo "label: REFUSED (…)"; return 3 ;; esac
[ "${#nb}" -gt "${#body}" ] || { echo "label: REFUSED (splice did not grow the body)"; return 3; }
```

The point is not the specific check — it is that the *only* way to reach the success
echo is through a value that passed it.

**Pattern: a new failure class gets its own rc and its own wrapper label.** rc 2 =
malformed id (caller bug), rc 3 = refused write, rc 0 = everything best-effort.
`auto-ship-hb.sh` branches on rc before its `rc != 0 → transient` catch-all, because a
data-loss near-miss wearing the "rate-limit blip" label is the same silence the caller
class was invented to remove.

**Pattern: flatten the confirmation echo, not the payload.** The wrapper matches
`^<label>: skip (` line-wise against the helper's stdout. Once entries may be
multi-line, a second line of caller text reading `foo: skip (x)` would relabel a landed
write as transient. The card keeps real newlines; only the echoed confirmation is
flattened with `tr '\n' ' '`.

**Testing skill-doc shell: extract the heredoc and RUN it.** `extractHeredocs()` in
`scripts/__tests__/autoship-skill-shell-hazards.test.js` pulls the real
`cat > … <<'SH'` blocks; pair them with a `gh` stub (a tiny node script) that
round-trips the card body through a state file, and assert on *the stored body*. That
turns a doc scan into behavioural coverage, under bash **and** zsh. Static scans stay
alongside it for the environments where `jq`/`zsh` are unavailable.

## Reviewer finding: a length-and-markers gate is not an integrity proof

The first version of the fix spliced with `${body%%"$END"*}` — the **first** end marker
**anywhere** in the body. A card whose human description merely *quotes* the end marker
above the block captured the splice: the entry landed in the human prose, the gate
passed (the body did grow, both markers were present), and the helper printed success.
`awk '$0==end'` matched whole **lines** and never did that, so replacing awk with a
substring match was a regression the gate was structurally unable to see.

Two corrections, both cheap, both worth copying:

1. **Anchor the inner marker to the outer one.** Split at `START` first, then take the
   first `END` in the remainder:
   `pre="${body%%"$START"*}"; rest="${body#*"$START"}"` → splice inside `rest`.
2. **Refuse caller text that carries a delimiter.** An entry containing `START` or `END`
   plants a second marker inside the block and moves every later splice. `return 3`,
   write nothing. Not hypothetical when the tool writes cards *about* its own markers.

The general lesson: a write gate proves the specific property it checks and nothing
more. "Grew, and still has both markers" rules out the *total* loss; it says nothing
about *where* the bytes went. Say which of the two the prose is claiming — a reviewer
read the original wording as an integrity guarantee, and was right to.
