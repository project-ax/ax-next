- **2026-09-29 (TASK-697): a vault ref that embeds a USER-CHOSEN identifier must not be walked through every scope.** `account:<connectorId>` is named by whoever authors the connector, so "same ref" never meant "same connector". The vault's fixed user -> agent -> global chain is only safe for refs whose name an operator controls (`provider:*`). For a user-chosen ref, gate the wider scope on a question only the owning plugin can answer ("does this user own a live connector whose plan puts exactly this ref at global scope, and is the owner an admin?"). The seam is a service hook in the vault's own namespace (`credentials:authorize-global:account`, registered by `@ax/connectors`, same precedent as `credentials:resolve:mcp-oauth`); no provider registered means skip the scope (fail closed).
- **2026-09-29 (TASK-697): check role at READ time, not only when the row was written.** A `keyMode:'workspace'` row can reach the store by several paths (un-gated admin route until TASK-698, the model-authored approve path, legacy data); asserting the owner is an admin where the key is read makes the read correct whatever order the write-side gates land in, and for rows already stored.
- **2026-09-29 (TASK-697): for an authorization regression across plugins, seed the "bad row" through the hook, not the route.** A route-level setup (`POST /admin/connectors` as a non-admin) silently turns into a 403 the day the sibling gate lands and the test starts failing for the wrong reason. `connectors:upsert` with a comment saying how such a row can get there keeps the test about the read.
