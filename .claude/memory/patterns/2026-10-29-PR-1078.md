# PR-1078 — minimal Agent Tasks pages (patterns)

- **An icon-only button needs its tooltip trigger on a wrapper, always.** `Button` has `disabled:pointer-events-none`, and a disabled button can't take focus, so a Radix tooltip on the button itself never opens once it's disabled. A faded icon then says nothing to sighted users. `IconAction` (`components/workspace/task-bits.tsx`) always renders a `<span>` trigger that becomes focusable only while the button is disabled.
  - Wrapping only while disabled looked simpler, but it remounted the button whenever it went busy. That broke node identity and 7 focus-after-press tests.
  - It takes an optional `reason`, which is how the disabled reason (`actionNote`) reaches the tooltip.
- **Sticky only sticks inside its parent.** A `sticky top-0` row inside a short `<header>` scrolls away with the header. On the task page, the mobile top row (nav trigger, back link, actions) is a direct child of the long column. From `md` up that column becomes a grid, and the row's wrapper is `md:contents`.
- **Don't reorder with `display:contents` + `order-*`.** Below the breakpoint the visual order and the DOM/focus order diverge (WCAG 1.3.2/2.4.3). Put the DOM in the mobile order, then place cards on the desktop grid explicitly (`lg:col-start/row-start/row-span`).
- **New soft-tint text sites trip `theme-contrast.test.ts` on purpose.** "finds the warning tint exactly where TASK-445 measured it" lists every file that paints `bg-warning-soft` + `text-warning`. A new site needs its file added to that list, even when the pair is already measured. Two branches sharing a base commit each need the identical line; they merge cleanly.
- **`make dev-fast` restarts the kind host, which kills any running `kubectl port-forward`.** Restart the port-forward after every push. To verify on kind, mint the cookie with `scripts/kind-login.sh` (untracked, main checkout). Playwright MCP only reads script files under the main checkout's `.playwright-mcp/`, not a worktree's. A screenshot taken right after `mouse.wheel` can catch a half-painted frame; set `scrollTop` on the scroll container instead.
- **The run-failure wire carries no reason code.** `runFailureText` (`lib/task-updates.ts`) matches the routines store's two exact sentences (`RUN_CLOSED`, `RUN_INTERRUPTED` in `packages/routines/src/store.ts`) and words them plainly, as "check-in" or "run". If the store's wording changes, this mapping falls through to showing the raw text.
- **Local channel-web runs:** 6 server test files need `DOCKER_HOST` and fail to load without it (not real failures). `pnpm test:scripts` needs `presets/memory` built. Build `@ax/channel-web^...` once in a fresh worktree before running `tsc`.
