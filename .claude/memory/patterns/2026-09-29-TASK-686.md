- **Under `keepAlive`, `chat:end` is the REAPER's event, not the reply's — any "is this agent busy" signal must end on `chat:turn-end` (TASK-686).** The k8s preset runs the orchestrator with `keepAlive: true`: a turn completes on `chat:turn-end` and the runner stays warm, so `chat:end` (and anything keyed on it) trails the reply by the whole idle window (default 5 min). `@ax/agent-activity` forgot on `chat:end` alone and the header pill, sidebar row, Today strip and rail all read "Working" after the reply, surviving a reload (server-side state). Two traps in the fix: (1) name the turn by `payload.reqId`, NOT `ctx.reqId` — the IPC boundary restamps `ctx.reqId` on every runner request, and the runner echoes the originating `agent:invoke` reqId in the payload (the same id `resolveWaiterFor` uses); a test that reuses the `chat:start` ctx for the turn-end passes against the wrong read, so fire the turn-end on a DIFFERENT ctx.reqId. (2) A set of turn ids that only ever lets a record go EARLIER (chat:end/turn-error still forget the whole agent) keeps the old "never pinned on Working" safety argument intact; a refcount gating the forget does not.
