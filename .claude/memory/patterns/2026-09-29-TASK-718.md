# TASK-718 — patterns worth reusing (2026-09-29)

- **Deleting an agent is a fan-out over `agents:deleted`, and each plugin deletes ITS OWN rows.** There is no FK from any table to `agents_v1_agents` (invariants 2 and 4), so the database never notices a missing cleanup. The shape to copy is `@ax/routines`' subscriber: validate `payload.agentId` (non-empty string), delete `WHERE agent_id = $1` in ONE transaction, `ctx.logger.error('<pkg>_purge_for_deleted_agent_failed', ...)` and swallow. Key on `agent_id` ALONE, never on `owner_user_id`: a team agent has rows for several users and an owner-scoped delete strands the rest. A store method that deletes must throw on an empty key BEFORE any SQL.
- **Rows keyed only on a conversation id are cleaned by a second hook, `conversations:purged { conversationIds }`** (fired by `@ax/conversations` AFTER its purge commits, at most 500 ids per fire; `@ax/attachments` subscribes). Push the ids after commit rather than making a second plugin read conversations' table: it is order-independent, and a subscriber never sees ids whose deletion could still roll back.
- **`agents:deleted` is fired with `subscriberTimeoutMs` (150 s).** `HookBus.fire` is sequential and unbounded by default, and the k8s reclaim subscriber waits on a pod, so one wedged subscriber would hold the delete request open AND keep every later cleanup subscriber from running. Subscribers run in plugin INIT order (sandbox-k8s registers before chat-orchestrator), so never assume one cleanup runs before another.
- **The reclaim pod is root with `drop ALL` + `DAC_OVERRIDE` + `FOWNER`.** The runner's root chown init hands `/export/<agentId>` to uid 1000 but the export ROOT stays root-owned, so a uid-1000 `rm -rf` removes the contents and is refused the final unlink (`Permission denied`, exit 1, empty directory left). Reproduce it in seconds with the prod image on a Docker volume: root-owned `/export`, `chown -R 1000:1000 /export/agt_X`, then the old command with `--user 1000:1000 --cap-drop ALL`. Same shape as `buildUserFilesChownInit` (root + the one capability the job needs; the export is `no_root_squash`).
- **A destructive one-shot pod needs the exit code POSITIVELY known.** `watchPodExit` returns `code: null` for a pod that vanished (404) or reported nothing, and `runOneshotPod` treated null as success. Cleanup passes `requireExitCode: true`. The pod's stderr rides `terminationMessagePolicy: FallbackToLogsOnError` into `containerStatuses[0].state.terminated.message` (no `pods/log` round trip, no extra RBAC); carry only its bounded, control-character-stripped tail into the log.
- **The end-to-end proof asks the DATABASE, not a table list.** `presets/k8s/src/__tests__/agent-delete-cleanup.test.ts` goes through the real `agents:delete`, then scans `information_schema.columns` for every `agent_id` / `conversation_id` / `session_id` column and counts rows that mention the deleted agent's ids, with a second seeded agent that must lose nothing. It resolves sibling plugins through their built `dist/`, so a mutant needs `pnpm --filter <pkg> build` before the run, and again after the restore.
- **A static guard for "every X has a Y" has to run in `scripts/`, not in one plugin's tests.** CI's PR test job only runs the packages a PR changes. `scripts/__tests__/agent-keyed-tables-are-cleaned.test.js` parses every `CREATE TABLE` (resolving `${TABLE}` constants and `ALTER TABLE ... ADD COLUMN`) and requires a cleanup or a `KEPT_ON_PURPOSE` entry with a reason.
