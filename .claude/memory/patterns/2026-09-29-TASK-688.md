- **2026-09-29 (TASK-688): "stop the turn" and "end the session" are different inbox entries — `interrupt` vs `cancel`.** `cancel` makes `nextMessage()` return null, the loop drains, the runner emits `chat-end` and exits; it never aborts an in-flight model call or tool (claude-sdk pulls ahead so a mid-turn `cancel` only closes the SDK's input stream; aisdk does not read the inbox mid-turn at all). Do not add "if a turn is running, cancel means interrupt": the idle reaper's cancel races a new message (`orchestrator.ts` "narrow race" comment) and would turn a graceful shutdown into a mid-turn abort.
- **2026-09-29 (TASK-688): the runner shell owns ONE inbox reader (`ensureRead`/`takePulled` in `run-runner.ts`).** Two concurrent `inbox.next()` calls share the cursor and would both be handed the same entry, so anything that must hear the inbox while a loop is busy (Stop) goes through the shell, never a second poller. Entries are buffered in order; `interrupt` is consumed by the router; an `interrupt` with no turn active is dropped; one that lands before the loop registered is latched; a `cancel`/honoured `idle-timeout` seals the reader (a fake that answers `cancel` forever otherwise spins the watcher into an OOM — mutant M8 crashed the worker rather than failing a test). `idle-timeout` from a read that started BEFORE the wait began is discarded and re-armed (sequence numbers, not clocks).
