# TASK-437 — patterns (channel-web / Radix / jsdom)

## Radix `Tabs`: `aria-controls` is unconditional, `TabsContent` is not

Verified in `@radix-ui/react-tabs@1.1.21`. If you render `Tabs` + `TabsList` +
`TabsTrigger` and skip `TabsContent`, you get **N dangling `aria-controls` and zero
tabpanels** — silently, because nothing warns. And rendering `TabsContent` only for
the OPEN tab fixes just one of the N.

The shape that actually works: one `TabsContent` per tab, all `forceMount`, children
supplied only for the open one, and an explicit `hidden` on the closed ones.

**The explicit `hidden` is load-bearing, not defensive.** Radix computes
`hidden: !present`, and `present` is `true` for anything force-mounted — then it
spreads your props over the top. Omit `hidden` and the closed panels render *visible*.

## `hidden` and Tailwind display utilities fight, and the utility wins

Tailwind 3.4.19 preflight:
`[hidden]:where(:not([hidden="until-found"])) { display: none }`. `:where()` adds
nothing to specificity, so that rule is **(0,1,0) — exactly a `flex` utility**. Ties
go to source order and utilities are emitted after preflight, so:

    <div class="flex" hidden>   <!-- renders VISIBLE -->

Never put a display utility on an element you are hiding with the `hidden` attribute.
jsdom loads no CSS, so **no jsdom test can catch this** — assert on the class list, not
on computed style.

## Radix roving focus moves focus in a `setTimeout` — `waitFor` it

`@radix-ui/react-roving-focus` defers the actual `.focus()` to a `setTimeout`, so
after `fireEvent.keyDown(tab, { key: 'ArrowRight' })` the focus has **not** moved when
`fireEvent` returns. A synchronous `expect(document.activeElement)` reads the previous
element and fails against working code. Wrap it:

    await waitFor(() => expect(document.activeElement).toBe(next));

## Radix puts the tab strip's single tab stop on the TABLIST, not the active tab

On mount `currentTabStopId` is `null`, so **every** `TabsTrigger` reads
`tabindex="-1"` and the `role="tablist"` element carries the `tabindex="0"`. Asserting
`0` on the selected trigger fails against correct code. Assert it on the tablist.

## Testing Library: `getAllByRole` THROWS on zero matches

Useful here — it means a test calling `getAllByRole('tabpanel')` cannot silently pass
on a document with no tabpanels. Also: role queries drop `hidden` elements by default,
so pass `{ hidden: true }` when the thing you are counting is deliberately hidden.
