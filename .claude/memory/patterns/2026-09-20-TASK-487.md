# TASK-487 — patterns from the mutation pass on `@ax/embeddings`

| Date | Pattern | Why it generalizes |
|---|---|---|
| 2026-09-20 | **A failure-table suite can credit one guard for another guard's work. Test the status check with a VALID body.** Deleting `if (!response.ok) return undefined` from `@ax/embeddings`'s `postJson` left all 137 tests green, because every non-2xx fixture in both driver tables (`HTTP 500`, `HTTP 403`, `HTTP 429`) also carried a body that failed the *shape* check a moment later. Two independent guards, one observable outcome, and the tests could not tell them apart. The fix is a fixture that isolates each: a non-2xx carrying a **well-formed** body, plus a 200 control carrying the same body so the fixture itself cannot be the reason. | This is the generic shape of an `it.each` failure table: fixtures are written to be *obviously* bad, so they trip several guards at once and pin none of them individually. Any `if (!ok) return` followed by validation has it. Realistic trigger, not a toy: an authenticating proxy answering 403 with a cached payload, a gateway 503 echoing the last good response, a 429 alongside a partial result. |
| 2026-09-20 | **Distinguish an equivalent mutant from a coverage gap before writing a test for it — and when it is equivalent, fix the COMMENT.** Two of the three survivors here could not be killed by any test: `validate.ts`'s `isNullish` is redundant because every call site pairs it with `!Array.isArray` (already false for `null`), and `cohereRerank`'s arity and `seen` duplicate checks are both redundant because a short answer and a duplicated index each leave a HOLE in the sparse score array, which `for..of` yields as `undefined` and `validateScores` rejects. Contriving a test for an unobservable difference is theater. What was actually wrong was the prose: the closing comment claimed *"`seen` already proves full, distinct coverage, so this can only fire if the loop stops doing what it says"* — exactly backwards about which guard fires. | A survivor is evidence about the *tests* OR about the *comments*, and telling which is the whole value of the pass. Defense in depth is fine and the redundant guards should stay; a comment that misidentifies the load-bearing guard is the thing that gets someone to delete the wrong line during a refactor. |
| 2026-09-20 | **Predict before mutating, then diff the prediction — the wrong predictions are the findings.** 8 mutations, 5 killed as predicted, 3 survived; **2 of the 3 survivors were predicted to be killed**. Predicting "the duplicated-index fixture pins the `seen` check" and watching it stay green is what surfaced the redundancy; running the mutation without a prediction would have produced a shrug and a green checkmark. | The card mandates this and it earned its place twice on this branch. The prediction is the hypothesis; the run is the experiment. A pass with no recorded prediction cannot be wrong, which is why it teaches nothing. |
| 2026-09-20 | **`pnpm-lock.yaml` changing is NOT the same as adding a dependency.** A new workspace package always adds an importer stanza naming already-resolved versions. Check for `resolution:` lines in the lockfile diff — zero of them means zero new tarballs, whatever the `+16 lines` in `--stat` suggests. A handoff here reported "lockfile untouched", the diff showed +16, and both were describing the same harmless stanza. | Cheap, decisive check for the supply-chain section of the security note, and it stops a reviewer burning a cycle on a false alarm. `git diff origin/main...HEAD -- pnpm-lock.yaml \| grep -E '^\+.*resolution:'` |
| 2026-09-20 | **Match sibling packages' devDep specifiers exactly; "pin dependencies exactly" is about runtime deps.** `@types/node ^25.6.0` / `typescript ^6.0.3` / `vitest ^5.0.1` are byte-identical across `memory-facts-sqlite`, `llm-openrouter`, `web-tools` and now `embeddings`. Pinning these harder than the siblings would resolve a second copy of typescript/vitest into the store for no security gain. | The card's pin-exactly instruction targeted the runtime tree a reference impl would have dragged in (`google-auth-library`, a reranker SDK) — none of which shipped. Reading it as "pin the shared toolchain differently from every sibling" inverts the intent. |
