# Patterns — TASK-567

- **Test budgets are parsed too now.** `scanTestTimeouts` in `scripts/hook-timeout-scan.mjs` returns the hook fields plus `testDeclared` / `testUnreadable` / `bareTeardowns`. A new test-timeout spelling (e.g. an imported budget constant, `{ ...opts }`) lands in `testUnreadable` and reddens `out-of-process-test-timeouts` — teach the scanner, do not exempt.
- **The bare-teardown rule does NOT cover `@ax/auth-better`'s local Docker-teardown timeout.** auth-better declares no `it()` budgets (testTimeout 60_000 == hookTimeout 60_000), so it passes both before and after. The rule catches the shape "a test asks for more time than its teardown gets"; a teardown that is simply slow under a budget matching its tests is a different defect.
- **Timing a teardown explicitly is not an escape from a hookTimeout raise when the teardown needs MORE than hookTimeout:** the hook rule (`hookTimeout >= max declared hook budget`) then reddens. The honest fix for a long-test package with bare teardowns is almost always the config line.
- **The guards read only `vitest.config.ts`.** A package with a second config (`presets/k8s/vitest.config.k8s-e2e.ts`) has its files counted against the main config, and the second config's own budgets are unchecked.
