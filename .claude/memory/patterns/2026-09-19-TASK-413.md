## 2026-09-19 — TASK-413 the workspace contract makes every backend prove tenant isolation

- `2026-09-19` (TASK-413) — **AN ISOLATION TEST MUST NAME WHICH FIELD PARTITIONS, AND THE ONLY PROOF IS A WRONG-FIELD MUTANT.** Varying `userId` AND `agentId` together proves rows are not pooled and says nothing about the key — it passes under `agentId`, under `userId`, and under the pair. The measurement that settles it is three mutants, not one: pooled (**3 red / 13 green**), partitioned on `userId` alone (**4 red / 12 green** — it fails BOTH directions, which is the signal the assertions are aimed at a field and not merely at non-pooling), and partitioned on the pair `(userId, agentId)` (**1 red / 15 green**, the red being "two users of the SAME agent share ONE tree"). The pair-mutant is the one the sibling `runIndexContract` used to wave through for months. Every ctx pair in an isolation case should vary EXACTLY ONE field.
- `2026-09-19` (TASK-413) — **A "TEST-ONLY ADAPTER" THAT IGNORES `ctx` IS A POOLED BACKEND WEARING A COSTUME.** `@ax/workspace-git-server`'s `plugin-test-only.ts` pinned one workspaceId per instance so contract scenarios got clean histories; its own header called that a convenience. Mutating it back (one line: `const id = namespace`) reddens exactly the three isolation-direction cases against the **real** git wire — same 3/13 split as the in-memory mutant. If a shim exists so the suite can skip a property, the suite is not testing that property on anything.
- `2026-09-19` (TASK-413) — **A TIMED-OUT `it` IS COUNTED IN `Tests N failed`, SO "0 ASSERTION FAILURES = INFRA" MIS-FILES IT.** `presets/k8s` reported `Tests 12 failed | 172 passed` on a host whose Docker daemon was dead (`docker info` exiting 124) — which reads as a real product failure under the usual heuristic. Every one of the twelve was `Error: Test timed out in 60000ms` / `180000ms` with **zero** expected/received diffs, in two files that boot `PostgreSqlContainer` inside the `it` rather than in `beforeAll`. The sharper marker: **look for an expected/received diff, not for the `Tests N failed` column.** No diff + a Docker-dependent file + wall-clock equal to the declared timeout = infra. A genuine product race shows you two values.
- `2026-09-19` (TASK-413) — **WHEN A TEST MUST COVER "EVERY FIELD OF X", MAKE THE COMPILER ENFORCE IT: `Required<Omit<Options, …excluded>>`.** A helper whose overrides are all-optional lets a newly-added field go unvaried and silently unpinned — the mechanism that put `(agentId, conversationId)` and then `(agentId, source)` green in this PR, twice. Typing the one completeness case's overrides as `Required<Omit<NonNullable<Parameters<typeof h.ctx>[0]>, 'userId'|'agentId'|'reqId'|'logger'>>` turns "someone must remember" into a build break, and the short `Omit` list becomes the explicit, reviewable record of which fields were judged non-identity. **PROVEN, not assumed:** adding `tenantId?: string` to `MakeAgentContextOptions` failed `pnpm build` at exactly the two case-7 literals with TS2345, and `context.ts` was restored md5-verified. Test the guard the same way you test the code — a type-level claim is executable too.
