- **Which edits cancel a saved Repeat's waiting app updates is exactly `REPEAT_CONFIGURATION_FIELDS` in `@ax/routines-contract` (kind, promptBody, webhook, conversation, silenceToken, silenceMaxChars) since TASK-1037.** These are the fields `repeatConfigurationHash` covers, pinned against the hash in routines' `independent-definition.test.ts` (a new editable field fails that test until someone decides). Both editors (TaskForm, Settings' RoutineForm) read `cancelsWaitingUpdates` from `useRoutineDraft` and show "Saving these changes cancels any app updates still waiting to run." by Save; TaskForm leaves a switch to a task kind to the kind-switch notice. The flag diffs the definition the save sends. `draftDefinition` returns the loaded webhook untouched while the event filter still says what was loaded (key order and a stored `events: []` included); a rebuilt webhook read as a change, so an untouched form was dirty (Save sent an empty patch, which the host refuses) and showed a false notice while invalid, and a stored `[]` was sent with a name-only edit, cancelling the queue. Changing the list or the hash's body changes every stored `configuration_hash` and cancels every waiting update at deploy.

The schedule check is by reference, so a schedule picked while it was a task stays. Its ref is written outside the `setForm` updater, which React may call twice.
