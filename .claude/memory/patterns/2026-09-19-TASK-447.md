## 2026-09-19 — TASK-447 patterns: diagnosing a "two surfaces disagree" card

- `2026-09-19` (TASK-447) — **For a counting discrepancy, read BOTH producers before touching either, and ask what each one is a count OF.** Here `decisions:count` (`packages/decisions/src/plugin.ts`) is *decisions raised in a window* and the Activity feed (`packages/channel-web/src/server/routes-workspace.ts` → `activity`) is *events that were settled*, merged from **two** unrelated sources. Once that was written down, the card's "make the count derive from the feed's collection" was visibly unsatisfiable — a feed carrying routine fires can never have the length of a decision count. The useful question is not "which number is wrong" but **"what is each one a count of"**; two right answers to two different questions still leaves a real defect, and here the defect was a missing row, not a wrong integer.
- `2026-09-19` (TASK-447) — **A rendering union with a value no producer emits is a strong signal about intended semantics.** `ActivityKind` carried `'dismissed'` with an icon and a tone, and grepping every `kind:` assignment in the route showed only `stopped | done | approved`. The renderer had been built for a row the producer never made. When a card asks "which surface is right", look for this shape — it is evidence, where architecture comments are only argument.
- `2026-09-19` (TASK-447) — **Allow-list vs complement is the fail-open/fail-closed question, and it is worth asking of every status filter.** A list of what to INCLUDE drops what it forgets, silently, with nothing on the surface to say a row went missing. Stating the rule as the complement of a small, well-understood set (`OPEN_STATUSES`) plus an **exhaustive switch with a `never` arm** turns the next omission into a build error. Same shape bit the wire mapper in the same file: `outcome === 'failed' ? A : B` is an allow-list with two slots, and everything new lands in the default. A `Record<Union, …>` is the fix in both languages.
