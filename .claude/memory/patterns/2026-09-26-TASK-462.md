# Patterns — TASK-462

- **Hook timeouts in the two timeout guards are PARSED, not regex-matched** (`scripts/hook-timeout-scan.mjs`, TypeScript compiler API). This supersedes the regex descriptions in the `patterns.md` TASK-410 row and the `decisions.md` TASK-323 rows (`HOOK_WITH_TIMEOUT` close-brace `\n\s*\}`, `UNREADABLE_HOOK_TIMEOUT`) — those name code that no longer exists. If you need to change how hooks are found, change the helper; both guards import it.
- **Correction to the TASK-410 row's "semantically broken vitest, occurs nowhere":** the nested-hook under-read did not need a nested HOOK. Any multi-line `setTimeout(() => { ... }, 50);` statement inside a hook body ended the lazy regex match the same way, and a `beforeAll(..., 120_000)` read as **50** (MEASURED against the regex at `be8fc794`). The defect class was "anything inside the body that closes `}, x);`", which is ordinary code.
- **When replacing a scanner, replay the old one beside the new one over the live corpus and explain EVERY diff before accepting it.** Here: 35 in-scope packages, 29 equal, 6 lower, 0 higher; every lower one was the old regex running past a bare hook to an `it(..., N)` budget (checked per file). A drop is only safe once you can say which number it was.
