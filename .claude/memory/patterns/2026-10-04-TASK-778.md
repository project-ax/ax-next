# TASK-778 — patterns

- **Any read path that mutates state behind a bookkeeping table must be reconciled where the table acts.** Blob restore-on-miss (D3) happens inside `blob:get`/`blob:stat` with no notice to `@ax/blob-gc`, so `blob_gc_v1_blobs.state` can say `retired` while the bytes are live. Every destructive step that trusts that row must re-probe the backend first (the purge pass does `blob:stat {restore:false}` after `blob:purge`). Found only by an end-to-end canary on a real fs backend; the unit fake did not model a read-restore.
- **A probe that must not undo the GC passes `restore: false` to `blob:stat`.** Default `blob:stat` restores a retired blob. Release/accounting checks (`@ax/disk-quota` `bytesGone`) must use `restore: false`, which reports a retired blob as present (bytes exist until purge). Writers about to reference a sha (`artifacts:publish-blob`) want the default (restore).
- **Removed-hook regression tests need a recording stub for the removed hook.** Branding's old delete was best-effort (`try { blob:delete } catch {}`); with the hook simply unregistered, a "never deletes" test passes against the OLD code. Register a recorder for `blob:delete` in the test bus so a regression is seen.
