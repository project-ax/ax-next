# Patterns — CONNMODAL-1 (metadata-driven remote MCP connector modal)

- The connector form now asks only for name + URL; `/api/connectors/oauth/discover-hosts` returns `auth: 'oauth' | 'none' | 'other'` (+ `clientRegistration: { cimd, dcr }` for oauth) and the form derives sign-in and client method from it. `none`/`other` are returned only when the resource answered AND no later metadata request succeeded — Gmail answers GET with 405 yet has OAuth, so "status != 401" alone would misclassify it. Blocked hosts, timeouts and unreachable servers stay failures.
- `auto` registration already prefers CIMD over DCR server-side; the UI never needs to ask. CIMD also needs AX's public origin to be HTTPS — on kind (`http://0.0.0.0:9090`) a CIMD+DCR server like Linear correctly shows the DCR copy.
- shadcn `Field` (vertical) applies `[&>*]:w-full` to direct children: a `variant="link"` Button placed directly inside stretches and centers its text. Wrap it in a plain `<div>`; `self-start` does not help.
- Live classification fixtures that worked from kind on 2026-10-02: Linear (oauth, cimd+dcr), `api.githubcopilot.com/mcp/` (oauth, neither → custom client), `gitmcp.io/docs` (none), `api.anthropic.com/v1/models` (other: 401 without OAuth metadata — not an MCP server, only exercises the branch).
