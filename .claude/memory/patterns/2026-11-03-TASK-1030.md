- **An HTTP route gate that calls `auth:require-user` answers its catch with `answerRequireUserFailure(ctx, res, err, '<area>_require_user_failed')` from `@ax/core` (TASK-1030), then returns.** Only `PluginError{code:'unauthenticated'}` becomes a 401. Anything else (a bus-wrapped store fault `unknown`, `timeout`, `no-service`) is logged as `{ hook, err }` and answered with 500 `{error:'internal'}`. Don't hand-roll `instanceof PluginError` → 401 or a bare `catch {}` → 401: that is the bug all 30 gates had. The one gate left on a different rule is mcp-oauth's `requireUser`, which also maps `forbidden`/`not-found` to 401 (TASK-1028). For a test, throw a RAW `Error` from the stub on the real `HookBus`. Several plugins build their own ctx with the default stdout logger, so their tests capture the log line by spying on `process.stdout.write` and parsing JSON. A gate's 500 does not change what the SPA shows on boot: `getSession()` reads any non-OK `/admin/me` as signed out, deliberately (`lib/http.ts`).
