- **2026-09-29 (TASK-690): to meter or veto a single-registrant service hook, make it a FACADE, not a check every caller remembers.** `blob:put` is now `registerBlobPutFacade` in `@ax/core` (veto `blob:pre-put { size }` -> backend `blob:put-internal` -> notify `blob:stored { sha256, size }`), the same shape as `registerWorkspaceApplyFacade`. Callers keep calling `blob:put`, a future caller cannot skip the limit, and backends register the `-internal` hook. A plugin cannot intercept another plugin's service hook, so the chokepoint has to be built into the registration.
- **2026-09-29 (TASK-690): measure what the disk actually holds; ledger what has no owner.** A git repo grows by history and block overhead, so a running sum of bundle sizes drifts from the volume (and double-counts a parent-mismatch retry). `workspace:usage {} -> {bytes}` asks the backend and the plugin re-measures after each `workspace:applied` (off the critical path) and in a periodic sweep, which also backfills repos that pre-date the feature. Content-addressed blobs have no owner, so the ledger row is `(owner, sha256) -> size` written at `blob:stored`; re-putting the same bytes is idempotent.
- **2026-09-29 (TASK-690): a veto that must reach the model has to be prose, and must ride the answer the runner already forwards.** Reuse the `workspace:pre-apply` veto path (`recoverable:false` + reason) instead of a new wire field; write the reason for the agent to relay ("tell the person their storage is full"), not as a code. For HTTP callers, map `PluginError code 'rejected'` to a 413 that carries the same sentence; for callers that redact plugin messages (I9, `skill.propose`), send a fixed sentence.
- **2026-09-29 (TASK-690): the gate is not a reservation, and that is a decision, not an oversight.** N simultaneous writes by one owner can all pass; overshoot is bounded by concurrent writes x the per-write cap (about 3 MiB per commit, 25 to 100 MiB per upload) and the next check refuses. Say so in the design note; exactness would need a reservation row and cleanup on every failure path.
