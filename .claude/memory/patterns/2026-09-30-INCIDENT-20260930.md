- 2026-09-30 (ROOT CAUSE of the personal-agent "That reply didn't finish", found via the sdk_turn_failed diagnosis above): every resumed turn died with `No conversation found with session ID`. With a durable user-files mount the SDK runs with cwd=HOME=`/files` (run-runner `homeDir` = `userFilesRoot ?? workspaceRoot`) and reads `projects/<slug(cwd)>/<sid>.jsonl`, but `createJsonlTranscriptSource(env.workspaceRoot)` wrote the resume-restore under `slug(/agent)` — a dir the SDK never opens. Turn 1 works (the SDK writes its own `-files/` copy), so only a later turn in a FRESH pod breaks. The earlier "local resume succeeds" probe proved only that the bytes were valid: it invented a temp cwd and put the file at that cwd's slug, so it could not see a slug mismatch. Fix: `createJsonlTranscriptSource(workspaceRoot, sdkCwd)` slugs by the SDK cwd; `main()` passes the same `userFilesRoot ?? workspaceRoot` as `query({ cwd })`; a wiring test pins the two together. Real-SDK repro (cwd=files, restore via workspaceRoot → error; fixed wiring → success) reproduces the exact prod string. Lesson: when a resume probe passes but prod fails, diff the probe's cwd/HOME/slug against the recorded `cwd` in the transcript itself (here `"cwd":"/files"`).
