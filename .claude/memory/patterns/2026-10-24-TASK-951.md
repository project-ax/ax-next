- `2026-10-24` (TASK-951) — **A calendar date (no time of day) crosses as `YYYY-MM-DD` text and is counted with the contract's calendar helpers, never as a JS `Date` instant.** Store it as TEXT, not a Postgres `date`: pg-types 2.2.0 parses OID 1082 into a `Date` at the host's local midnight and nothing in the repo sets a type parser. Count days with `calendarDateIn(at, tz)` + `calendarDaysBetween(from, to)` (difference of two `Date.UTC` midnights, so a 23/25-hour DST day still counts as one), in the task's zone from `taskTimeZone(row)` (cron tz, else active hours tz, else UTC) — all in [[packages/routines-contract/src/finish-by.ts]]. Spell a date with an explicit locale and `timeZone: 'UTC'` on `${date}T00:00:00Z`. A stored value that matches the format but is no real day (`2026-02-30`) must be read through the full rule (`RoutineFinishBySchema.safeParse`) and treated as none: V8 rolls it into March, and `2026-02-32` makes `Intl.DateTimeFormat#format` throw `RangeError` mid-render.
