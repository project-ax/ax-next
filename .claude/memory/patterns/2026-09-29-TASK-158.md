- `2026-09-29` (TASK-158) — **Per-session egress isolation lives in ONE function: `authenticateCaller(proxyAuthHeader, sessions)` in `@ax/credential-proxy` `listener.ts`.** Both `handleHTTPRequest` and `handleCONNECT` call it FIRST (before URL/target parsing, DNS or any upstream connect) and then use the returned `callerSession` for the allowlist check, the `allowedIPs` override, the `bypassMITM` decision and audit stamping. A new egress path in the listener must take its session from `callerSession`, never re-scan `sessions` by hostname — that re-scan is exactly the OR-across-sessions bug and there is now no helper that does it.

- `2026-09-29` (TASK-158) — **Real-client behaviour against a proxy that wants credentials (MEASURED-BY-PROBE, this card):** with `http(s)_proxy=http://ax:<token>@host:port`, curl, wget, python urllib/http.client, npm and undici (`new ProxyAgent(process.env.HTTPS_PROXY)`, i.e. the real `proxy-bootstrap.cjs`) send `Proxy-Authorization` PREEMPTIVELY; `git` (libcurl `anyauth`) sends the first request/CONNECT bare and only retries with credentials after a `407` carrying `Proxy-Authenticate`. So a refusal for a missing token must be a 407 WITH a challenge header; a 403 breaks git. Expect one unattributed `proxy-auth` audit row per git operation — that is the handshake, not an attack.
