# TASK-992 — pin the blob root, require the durable /files home, kind NFS (patterns)

- **To pin a chart value on a `--reuse-values` release, fail the render and print the exact `--set`.** `helm upgrade --reuse-values` renders with the OLD release's values, so a new values.yaml default never reaches prod. `validateBlobBackend` refuses an empty `blob.fs.root` and prints `--set blob.fs.root=<workspace.mountPath>/blobs`. The operator passes it once, and from then on the live values carry it. Read anything that may be absent through `dig`/`default` (nil-pointer otherwise). Runbook: deploy/GKE.md §4d.
- **On kind, busybox `mountpoint -q` reports a mounted PVC as NOT a mountpoint** (measured live, rc=1, on the memory-nfs pod). A guard built on it crash-loops. Read `/proc/self/mountinfo` instead (deploy/kind/memory-nfs/entrypoint.sh).
- **Since TASK-992, every owned session needs a `sandbox:resolve-mounts` resolver that returns a `role: 'user-files'` mount.** Both sandbox providers throw `home-unavailable` otherwise. Test compositions that chat through `@ax/sandbox-subprocess` must load `@ax/workspace-localdir`; k8s unit tests need a stub resolver. Use a server like `files.example.invalid` that does not alias the `/memory` export, or the pod-spec overlap refusal masks the case under test.
- **The k8s preset env loader now requires `AX_BLOB_FS_ROOT` (for fs) and `AX_FILESTORE_SERVER` + `AX_FILESTORE_EXPORT_PATH`.** Every new env fixture needs all three. `createK8sPlugins` requires `config.blob`.
