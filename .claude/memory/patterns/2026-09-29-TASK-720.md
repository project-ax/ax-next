# TASK-720 — patterns (large runner→host saves; a per-turn notice that reaches the person)

- **2026-09-29 (TASK-720): to raise a runner→host payload size, move the action to the BINARY channel; do not try to shrink the payload.** `BINARY_ACTIONS` in `@ax/ipc-core` `dispatcher.ts` takes a raw octet-stream REQUEST body up to `MAX_BLOB_BODY_BYTES` (100 MiB) with metadata as query params, while JSON actions are capped at `MAX_FRAME` (4 MiB, and base64 costs a third on top). The transcripts (`session.append-transcript`) made this exact move before; the workspace save was the last JSON holdout. Pattern to copy: keep the JSON action registered and share one handler core, so sandboxes from the previous release survive a host rollout, and export the cap (`WORKSPACE_COMMIT_BUNDLE_MAX_BYTES`) so the client can refuse before sending.
- **2026-09-29 (TASK-720): a too-large upload must fail LOUDLY, never "kept".** The old path swallowed the 413 (and the `EPIPE` the dropped socket produced) as `kept`, so `refs/heads/baseline` never advanced and every later bundle still carried the same bytes — a permanent silent wedge, and deleting the file did not help because the commit was still in range. A retryable-looking transport error is the dangerous case: classify it, do not just catch it.
- **2026-09-29 (TASK-720): ONE TURN EMITS TWO `event.turn-end`s (role='tool' then role='assistant', same reqId) when there were tool results — and channel-web's SSE `done` subscriber closes the stream on the FIRST one.** Any field that must reach the browser has to ride the FIRST one (put it on both; `usage` stays assistant-only because it is metered and would double-charge). A save can only be refused on a turn that wrote files, i.e. one that ran tools, i.e. one that emits the tool turn-end first — so an assistant-only field is invisible on exactly the turns it matters for. Each half's tests passed while the seam lost the notice.
- **2026-09-29 (TASK-720): when a re-sync re-pins the runner's local `baseline` ref, every exit must report `currentParentVersion`, not `input.parentVersion`.** The caller tracks that value and builds the next turn's thin bundle against it; a stale one desyncs the runner from the host. Assign it only after the re-sync returns, so the throw path is correct by construction.
